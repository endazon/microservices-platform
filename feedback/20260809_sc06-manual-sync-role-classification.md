## 現状（計画書の記述 / As-Is）

**破壊的操作の列挙が 2 箇所にあるが、どちらにも「手動同期」が無い。**

| 箇所 | 破壊的操作として列挙されているもの |
| --- | --- |
| `:124`（§共通シェル・アクセス制御の割当） | 登録・**更新**・無効化・再変換・文書の編集や削除 |
| `:282`（§SC-05「管理系 3 画面の閲覧ロール」・裁定 Q19） | 登録・無効化・再変換・文書の編集/削除（**更新が入っていない**） |

一方 **§SC-06 §アクション（`:290`）は「登録・設定変更・手動同期」を画面のアクションとして挙げている。**
つまり**手動同期は画面の操作として確定しているのに、破壊的操作かどうかの分類だけが無い。**

`:291` の SC-06 §アクセス制御 は「**閲覧は管理者・運用者。登録・更新・無効化は管理者限定**」であり、
ここでも手動同期に触れていない。

## 問題点 / あるべき姿（To-Be）

**実装は「列挙に無いものをどちらに寄せるか」を自分で決めざるを得ない。**
どちらに倒しても実害の向きが違うため、実装側の裁量で決めてよい種類の判断ではない。

| 倒し方 | 起きること |
| --- | --- |
| 運用者にも開く（現行実装） | 運用者が SC-10 で異常に気づいたとき、**その場で再同期して一次対応できる**。ただし手動同期は外部システムへ実際に接続し取り込みを走らせるので、「読み取り専用の操作」ではない |
| 管理者限定にする | 一次対応のたびに管理者を待つ。**Q19 が「運用者が原因画面へ入れないと一次対応が成立しない」として閲覧を開いた趣旨と噛み合わない可能性がある** |

**実装側の見立ては「運用者に開いたままが妥当」**である（Q19 の趣旨＝運用者の一次対応の成立を優先する）。
ただしこれは**運用ロールの方針**であって実装の判断ではないため、**計画側の裁定を仰ぐ。**

### 副次: `:124` と `:282` の列挙が食い違っている（軽微）

`:124` は「更新」を含み `:282` は含まない。**SC-06 §アクセス制御（`:291`）が「更新」を明記しているため
実装上の解釈は割れない**が、同じ「破壊的操作」の定義が 2 箇所にあって内容が違うのは
**計画が 2026-08-05 に SC-05 §主要素 で解消したのと同じ型の内部矛盾**である。
**列挙を 1 箇所に置いて他方から参照する**のが安全である。

## 実装で判明した経緯

**PR #627**（#534 データソース更新 API ＋ #537 同期健全性）で、新設する `PUT` / `PATCH` の認可を
決める際に破壊的操作の列挙を引いたところ、次の 2 点が同時に判明した。

1. **既存の `POST /datasources` と `DELETE /datasources/{id}` が計画（管理者限定）より広い**
   （`admin` ＋ `operator`）。これは**計画が明確なので実装側の是正**であり、
   実装側 issue **#628** として起票済み（本 PR の射程外・`IADR-0116` 規約 4）。
2. **手動同期（`POST /datasources/{id}/sync`）はどちらとも判断できない**（本フィードバック）。
   #628 の受け入れ基準にも「手動同期の扱いを判断して記録する。不明なら裁定へ回す」と書いた。

**PR #627 が新設した `PUT` / `PATCH` は計画どおり管理者限定で実装している**（新しい口を、計画に
反していない状態で生むため）。本フィードバックは既存の口の分類だけを対象とする。

## 提案（計画への反映案）

- 反映先候補: **UC・画面更新**（`05_screens/01_screens.md` の §共通シェル `:124` と
  §SC-05「管理系 3 画面の閲覧ロール」`:282`、および §SC-06 §アクセス制御 `:291`）
- 提案内容:
  1. **手動同期を破壊的操作に含めるか否かを明記する。** 実装側の推奨は
     **「含めない（運用者にも開く）」**——Q19 が閲覧を開いた理由（運用者の一次対応の成立）と揃うため。
     含めない場合は「**手動同期は取り込みを走らせるが、既存データを壊さないため運用者に開く**」のように
     **理由も併記する**と、次に読む人が同じ判断を再現できる。
  2. **破壊的操作の列挙を 1 箇所に集約する**（`:282` を正とし `:124` は参照にする等）。
     現状は `:124` と `:282` で列挙が違う。
  3. あわせて **SC-05 / SC-07 の同種の操作**（再変換の実行など）についても、
     「実行系だが破壊的ではない」ものがあれば同じ基準で分類できるようにする。
