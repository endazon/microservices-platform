# 環流: `NFR` 採番に、メタ作業へ当たる番号が無い

- **出所**: 実装リポ #688（PR #687 の AI レビューが起点）／ 実装 ADR: `IADR-0179`
- **対象**: planning#295（`NFR-01`〜`NFR-27` の採番）／ planning#304（裁定: 新規参照から採番付きを使う）
- **起票状況**: 下記 §起票状況 を参照

## 事実（実装側の実測。走査基準: planning `2cf0795`）

**`NFR-01`〜`NFR-27` の 27 件を全数で読んだ。すべて「稼働する製品」の要件である。**

| 区分 | 番号 |
| --- | --- |
| 性能 | `NFR-01`〜`04` |
| 可用性 | `NFR-05`〜`06` |
| スケーラビリティ | `NFR-07`〜`08`, `27` |
| セキュリティ | `NFR-09`〜`18` |
| 運用・保守 | `NFR-19`（可観測性）／`NFR-20`（デプロイ）／`NFR-21`（障害検出〜復旧） |
| 拡張性 | `NFR-22`〜`26` |

**「運用・保守」の 3 件も対象は稼働中のシステム**であり、
**文書・規約・検査器の統制を扱う番号は 1 件も無い。**

## なぜ計画側の関心事か

planning#304 の裁定は「**新規参照から採番付きを使う**」と定めたが、
**「該当する番号が在ること」を前提にしている。**

実装側では**規約整備・検査器の追加・必読規約の減量といったメタ作業が継続的に発生する**。
2026-08-09 以降に着地した `NFR` スコープのコミット 24 件のうち、
**採番付きは 3 件（`NFR-09` / `NFR-19` / `NFR-21`）で、残り 21 件は無採番**である
（うち 19 件がメタ作業、2 件は製品作業が裸の `NFR` を併記したもの）。

**実装側は「当たる番号が無いメタ作業は無採番のまま」と決めた**（`IADR-0179` 決定 1）。
**無理に付けると実在しない対応づけを作り、トレーサビリティとしては無採番より劣化する**ためである。

## 計画側への相談事項

1. **この読み（当たる番号が無ければ無採番）で相違ないか。**
2. **文書・規約の統制を扱う NFR を新設するか。** 新設するなら実装側は採番付きへ移す。
   **実装側では番号を作らない**（採番は計画リポの領分。`IADR-0179` 決定 2）。
3. 新設しない場合、**planning#304 の裁定文へ但し書きを足すか**（「該当する番号が在るとき」）。

## 実装側の状態

- `.claude/rules/traceability.md`「起点 ID の種別」節へ**無採番の但し書きを明記済み**
- 根拠（27 件の内訳）は `docs/how-to/plan-id-range-history-annex.md` §4
- **既存参照の遡及書き換えはしない**（planning#304 の指示どおり）
