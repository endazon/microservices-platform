## 問題点 / あるべき姿（To-Be）

**1 は文脈上「前提 ADR の状態」だけを指していると読めるが、文面は「着手を止めていた条件」全体を
指している。** 実装側の着手ゲート（`IADR-0119` 決定 2）は FR ごとに条件を分けており、

| FR | 着手条件 | 2026-08-07 時点 |
| --- | --- | --- |
| FR-17 / FR-18 | ADR-0033・0034・0035 の `Accepted` | **満たす** |
| FR-19 / FR-20 | ADR-0036・0037 の `Accepted` **＋ Wiki.js の個人スコープ可視性の前提検証の完了** | **満たさない**（後段が未了） |
| FR-21 | 計画側が当該要求を `fixed` 扱いにすること | **満たさない**（起案段階のまま） |

**この誤読は既に発生している。** 実装リポの issue（microservices-platform#586）本文の解除表は、
FR-19 / FR-20 の issue を「ADR-0036/0037 が `Accepted`」を根拠に**解除**と分類していた。
実装側が起案段階の要求へ着手すると、`IADR-0119` が防ごうとした手戻り（前提が覆った場合に
実装・テスト・スキーマ・移行手順が破棄される）がそのまま起きる。

**あるべき姿**: 1 の文を「**前提 ADR の状態に起因する条件**は解消している」と限定し、
**FR-19 / FR-20 は Wiki.js の前提検証が残ること・FR-21 は要求そのものが起案段階であること**を
同じ場所に明記する。
