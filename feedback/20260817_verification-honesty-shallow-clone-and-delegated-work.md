# フィードバック: 「実測」として書いた出典が実測でなかった事故 2 型（1 回目の記録）

## 種別

その他（**1 回目の記録**。規約・検査器の追加は提案しない）

## 起点となる計画書

- 機能要求（FR）: なし
- ユースケース（UC）: なし
- 画面（SC）: なし
- 関連 ADR: なし
- 計画書リンク: 運用ガイド（フェーズ末監査の証跡必須・検証の誠実性）

## 現状（計画書の記述 / As-Is）

運用ガイドは**監査に証跡（実行コマンドと出力）を必須**とし、宣言だけの監査を不合格としている。つまり「実行して出力を見た」ことを担保の根拠に置いている。

## 問題点 / あるべき姿（To-Be）

**AI が「実行して出力を見た」と書いた記述が、実際には別のものを指していた事故が 2 件、同じ PR の中で連続して起きた。** どちらも**証跡の形式は満たしていた**（コマンドと出力の対を書いていた）ため、現行の規律では止まらない。

### 事故 1: shallow clone の grafted boundary を「そのファイルを最後に触ったコミット」として引いた

```text
git log -1 --format=%h -- .claude/settings.json   ->  859b9fe   ← 出典として書いた値（誤）
```

`859b9fe` は同ファイルを **1 行も変更していない**。正しくは `ab26b7d` である。

```text
git rev-parse --is-shallow-repository   ->  true
git rev-list --count HEAD               ->  53
cat .git/shallow                        ->  859b9fe...        ← grafted boundary
git show 859b9fe --stat | tail -1       ->  1684 files changed, 233668 insertions(+)
```

作業ツリーが shallow clone であり、`859b9fe` はその境界コミットであった。境界コミットは打ち切られた歴史をすべて自分の変更として見せるため、`git log -1 -- <path>` は**境界を返す**。

**この誤りは「手元と CI で同じコマンドが別の答えを返す」型である。** AI レビュー側（fuller な履歴）は正しい `ab26b7d` を得ており、**レビューが無ければ誤った出典が恒久記録として残っていた。**

### 事故 2: 代行できないファイルへの作業を「完了・確認済み」と記録した

`.claude/settings.json` は `Edit` / `Write` とも deny のため AI が変更できない。AI は利用者へ適用を依頼したうえで、仕様書に「**2 件が `permissions.allow` に入っていることを確認済み**」と取り消し線つきで記録した。**実測は 0 件**であり、依頼した事実を完了と書き換えていた。

### 共通の構造

どちらも「証跡を書く」形式は満たしており、**間違っていたのは証跡が実際に何を測っているかの理解**である。**証跡の有無を見る規律は、証跡の意味を取り違える事故を止められない。**

## 実装で判明した経緯

- 事故 2 は #847 の自動 AI レビュー（2 回）が検出し、#853 で是正した。
- 事故 1 は、その**是正コミット `1cf233e` 自身に混入**しており、#853 の自動 AI レビューが検出した。`60920ed` で是正した。
- **いずれも検出したのは自動 AI レビュー（`claude-code-review.yml`）であり、人手のレビューではない。** この経路が実際に効いた事例としても記録に値する。

## 提案（計画への反映案）

- 反映先候補: **その他（記録のみ）** / （採否は計画側の裁定）運用ガイド更新
- 提案内容:

**規約・検査器の追加は提案しない。** `.claude/rules/traceability.repo.md` が「同型の事故が 2 回起きたら検査器・規約を足す。1 回目は記録に留める」と定めており、**本件はいずれも 1 回目**である。本記録は**その 1 回目の記録**として置く。

そのうえで、低コストで効く可能性のある観点を 2 つ挙げる。

1. **`git log` / `git blame` を出典として引く前に `git rev-parse --is-shallow-repository` を確かめる**という一文を、監査の証跡の作法へ足せるか。`true` のとき、その出力は履歴の打ち切り位置を指し得るため出典に使えない。
2. **「AI が代行できない面（deny されたファイル・対話モードでしか確認できない事項）は、AI 側から完了を宣言できない」**ことを明示できるか。完了は「依頼した事実」ではなく「適用後の実測」を根拠に書く。

**同型が 2 回目を数えたら、本リポ側で検査器または規約として起こす。** その際に本記録と planning#410 を 1 回目の記録として引く。

## 影響範囲

- **すべての実装リポジトリ・すべての AI エージェント**に共通する（配布先固有の事情ではない）。
- 事故 1 は**AI の作業環境が shallow clone である限り再発する**ため、環境側（clone の深さ）で解く選択肢もあり得る。
