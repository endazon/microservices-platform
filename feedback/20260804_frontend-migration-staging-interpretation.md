## 現状（計画書の記述 / As-Is）

`13_frontend-stack.md` §実装への移行方針（2026-07-30 裁定）の表に、次の 1 行がある（**原文**）。

| 項目 | 方針 |
| --- | --- |
| 進め方 | **一括で移行する。** 段階分け・並行運用は行わない |

同じ表には「旧画面は**完全に削除する**（`home` ＋ `sc01-search` 〜 `sc11-config` の 13 画面）」
「認証は ADR-0032 の BFF セッション方式への移行と**同一の作業**として行う」も並ぶ。
同 ADR-0031 の追補にも同趣旨の記述がある。

## 問題点（提起時）

「段階分け」が**何の段階分けを禁じているか**が読み取れず、少なくとも 2 通りに読めた。

| 解釈 | 意味 |
| --- | --- |
| **A. 並行運用の禁止** | 旧スタックと新スタックを**同時に生かさない**。各系統（ルーティング・HTTP クライアント・CSS 体系・認証）は 1 度だけ切り替える。PR / issue の分割は制約に含まれない |
| **B. 変更単位の分割禁止** | 移行に関わる変更を**1 つの PR / issue で行う**（9 系統 ＋ 画面 13 枚 ＋ BFF 認証 #439 を単一 PR に入れる） |

どちらであるかで PR 構成と作業順序が根本的に変わるため、着手前に確認が要った。

## 裁定（2026-08-04・利用者）

> **「段階分けは認めます。最終的に一括になっていれば問題なし」**

### 確定解釈

1. **禁じられているのは並行運用**である（上表の解釈 A）。各系統は**1 度だけ切り替え**、2 つのルータ・
   2 つの API クライアント・2 つの CSS 体系が同時に存在する状態を作らない。
2. **PR / issue の分割は認められる**。分割の規約は実装側の
   [IADR-0116](../docs/adr/IADR-0116_reimplementation-branching-and-pr-policy.md) 規約 4・5 に従う。
3. **「一括」は最終状態に対する要求**である。途中の段では新旧の系統が時期をずらして切り替わってよいが、
   **移行完了時点でスタックが計画どおり一括で入れ替わっていること**が条件となる。

### 完了条件（この裁定が満たされたと言える状態）

**第 2〜5 段をすべて消化し、`13_frontend-stack.md` §採用技術一覧と実装が完全に一致すること。**具体には
次のすべてを満たした時点で「一括移行が完了した」とみなす。

- ルーティングが **TanStack Router** に置き換わり、`react-router-dom` がワークスペースから消えている（第 2 段）
- 旧 13 画面（`home` ＋ `sc01-search` 〜 `sc11-config`）が**削除**され、Bulletproof React ＋ shadcn/ui ＋
  orval 生成フックで**再実装**されている（第 2 段 / #452）
- 認証が **BFF セッション方式**（ADR-0032）へ移行し、`oidc-client-ts` がワークスペースから消えている
  （第 3 段 / #439）
- 採用技術一覧の残り（Zustand / TanStack Table / ECharts / RHF + Zod / dayjs / Lingui / Storybook /
  Knip / Plop / Renovate / Husky + lint-staged / Commitlint）が導入されている（第 4・5 段）
- go-live はフロントエンド移行と BFF セッション移行の**完了を待つ**（計画どおり。ADR-0032 の追補）

段の定義と順序は [IADR-0121](../docs/adr/IADR-0121_spa-stack-migration-staging.md) 決定 1 と
[作業仕様書 §段階分割](../docs/specs/20260804_issue-446_spa-foundation-stack-migration.md) を正とする。

## 実装で判明した経緯

issue #446（SPA 基盤の再実装）の着手時に、この 1 行と実装リポジトリの既存規約
[IADR-0116](../docs/adr/IADR-0116_reimplementation-branching-and-pr-policy.md) 規約 4「1 PR が大きくなる
場合は issue を分割する」・規約 5「既存実装は各 issue の範囲内で置換する。リポジトリ規模の一括削除は
行わない」が**正面から衝突する**ことに気付いた。実装側は解釈 A を暫定採用して 5 段へ分割し
（IADR-0121 決定 1）、その論拠を添えて本件を提起した。論拠は次の 4 点である。

1. **文言の並び**。「段階分け・**並行運用**は行わない」と 2 語が並び、直前の文脈（実装が旧スタックのまま
   13 画面進んでいる状況）からは「旧新を並行させない」ことが主題と読める。計画書は実装リポジトリの
   ブランチ戦略を定めていない。
2. **計画書自身が段階を含意している**。同じ表が「認証は ADR-0032 への移行と**同一の作業**として行う」と
   述べる一方、その ADR-0032 のサーバ側（#439）は未着手である。文字どおり 1 PR にすると、BFF の
   セッション実装が終わるまでフロントの移行を 1 行も始められない。
3. **IADR-0116 規約 4・5 との整合**。実装リポジトリは「人間がレビューできる変更単位を維持する」
   （CLAUDE.md 目的）ために子 issue 1 件 = PR 1 本を規約化している。解釈 B は develop 上の退行検出器
   （カバレッジ ratchet 等）が効く前提とも噛み合わない。
4. **二重作業の回避**。ルータ差し替えは knowledge の 13 画面（実装 6 ＋ テスト 7 ファイル。実測）の
   書き換えを伴うが、その 13 画面は #452 が作り直す。分離すると同じ画面を 2 回書く。

裁定はこの解釈を追認した。

## 提案（計画への反映案）— **残タスク**

- 反映先候補: **要求更新**（`06_technical/13_frontend-stack.md` §実装への移行方針 の表へ裁定を 1 行追補）
- 提案内容（追補案の文面。裁定の転記）:

  > **［2026-08-04 裁定］「段階分け・並行運用は行わない」の「段階分け」は、旧スタックと新スタックの
  > 並行運用を禁じるものであり、実装リポジトリ側の PR / issue 分割は含まない。**
  > 各系統（ルーティング・HTTP クライアント・CSS 体系・認証）は 1 度だけ切り替え、**最終状態が
  > 一括移行の完了（本書 §採用技術一覧と実装の完全一致）であること**を条件とする
  > （利用者裁定「段階分けは認めます。最終的に一括になっていれば問題なし」）。分割の規約は
  > 実装側の `IADR-0116` に従う。

  併せて ADR-0031 の追補にある同趣旨の記述にも同じ注記を添える。
  なお同節末尾の「移行完了の定義・テストの作り直し・カバレッジしきい値（ラチェット）の扱いは未確定で
  あり、実装引き継ぎ時に確定する」については、実装側が
  [IADR-0121](../docs/adr/IADR-0121_spa-stack-migration-staging.md) と
  [作業仕様書](../docs/specs/20260804_issue-446_spa-foundation-stack-migration.md) で確定値を与えた
  （移行完了の定義＝本書「§完了条件」、カバレッジ床は下げず実測に合わせて引き上げ）。計画側の追補で
  参照先として指しておくと、以後の実装 issue が同じ論点を繰り返さずに済む。

- **状態**: 計画リポジトリへの反映操作（issue 起票 / PR）は**利用者の操作待ち**。実装側の作業は
  本裁定で確定しており、待ちはない。

## 影響範囲

- **実装側**: 影響なし。#446（第 1 段）は裁定と同じ解釈で完了しており、第 2 段以降も予定どおり
  issue を分割して進める（[IADR-0116](../docs/adr/IADR-0116_reimplementation-branching-and-pr-policy.md)
  規約 4 に従い #454 のチェックリストへ追加する）。
- **計画側**: 採用技術一覧・旧画面の完全削除・go-live 条件は**変更しない**。追補は解釈の明文化のみで、
  決定内容に手を入れない。
- **今後の監視点**: 裁定の「最終的に一括」は上記「§完了条件」で判定する。第 2〜5 段のいずれかが
  無期限に滞留すると、旧スタックの残骸（`react-router-dom` / `oidc-client-ts`）が長期に残り、
  裁定の条件を満たさない状態が続く。各段の起票時に本書の完了条件を参照すること。
