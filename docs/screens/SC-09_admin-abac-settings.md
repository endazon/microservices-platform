## 画面概要・目的

利用者属性・文書属性（属性辞書）とアクセスポリシー（利用者属性 × 文書属性 → 許可アクション）を管理する画面。
保存前にポリシーを検証し、矛盾・構文エラーを**検証結果**として表示する。

- ルート: **`/admin/abac`**（05_screens §共通シェル「ルートパス」）
- 左ナビ: 「管理」グループの **「ABAC設定」**（hi-fi の左レール表記に合わせた。従前の実装は「管理者設定」だった）
- アクセス: **`platform-admin` のみ**（[[IADR-0040]]。operator も不可）。
  権限外はルート・ナビとも非表示（`RequireRole` → `NotFound` で存在秘匿。[[IADR-0009]]）。
  サーバ側 `/bff/admin/authz` も `AdminOnly`（BFF・後段の二重ゲート）。

| 属性ラベル | 任意 | テキスト | — |
| 許可値 | 任意 | テキスト（カンマ区切り） | 空要素を落として配列にする |

| ポリシー名 | 必須 | テキスト | 空のあいだは保存ボタンが `disabled` |
| 対象アクション | 必須 | 選択 | **`read` / `analyze` / `manage` の 3 値**（同上） |
| **対象属性**（条件） | 任意 | 選択 | **定義済み属性のみ**（属性辞書の `key` を選択肢にする。計画の入力表 2 行目） |

利用者条件・文書条件への振り分けは自動である（`buildConditions()`。純関数）。

## 主要素・振る舞い

### 属性体系（属性辞書）

- 一覧（キー・ラベル・スコープ〔`Tag`〕・許可値・必須／任意）。0 件は「属性は登録されていません。」。
- 追加フォーム → `POST`。成功で入力を空にし、一覧を `invalidateQueries` で取り直す。
- 行の削除 → `DELETE`。**参照中は 409** で拒否され、理由を `Alert`（`warning`）で示す（[[IADR-0006]]）。
  **固定文言（拒否の理由）＋ `ApiError.details`（参照元のポリシー名）を併記する**——詳細を捨てると
  「先に見直す」対象を利用者が自力で探すことになる（[[IADR-0040]] 決定 2 が透過中継の目的として挙げた
  「参照競合（409）が失われずに SPA へ届く」）。

### ポリシー定義

- 一覧（名前・条件〔要約〕・状態〔`StatusBadge`〕・操作〔有効化／無効化・削除〕）。0 件は「ポリシーは登録されていません。」。
- 追加フォーム → `POST`。**成功・失敗はどちらも検証結果パネルへ出す**（画面の 2 か所に散らさない）。
- 有効／無効切替 → `PATCH …/{id}/active`。削除 → `DELETE`。

### 検証結果

| 状態 | 表示 |
| --- | --- |
| 未保存（既定） | 「保存前に構文・矛盾を検証します。保存すると認可判定へ即時反映されます。」 |
| 保存成功 | `Alert`（`success`・`role="status"`）「ポリシーを保存しました。認可判定へ即時反映されます。」 |
| 保存失敗（400） | `Alert`（`danger`・`role="alert"`）＋ サーバの詳細（`ApiError.details`）を列挙 |
| 保存失敗（その他） | 同上（既定文言へフォールバック） |

**操作結果は直近の 1 件だけを出す**（[[IADR-0127]] 決定 7 と同じ形）。新しい操作を始める前に
成功メッセージと全ミューテーションの状態を捨てる（`beginOperation()`）——
TanStack Query は「別のミューテーションが成功した」ことでは他方の `isError` を戻さないため、
放置すると成功バナーと古い失敗バナーが並ぶ。

## 実装しない要素の理由

**(a) FR の着手保留（[[IADR-0119]]）— 辺の型辞書**

計画 §SC-09 の当該節は見出し自体が「**辺の型（値集合）の管理（起案・2026-08-02。FR-17・ADR-0033 決定3）**」であり、
画面一覧（`:55`）も SC-09 の関連要求に **FR-17** を挙げる。初期値集合（中核 5 種・推奨追加 4 種・将来検討 2 種）・
対称／非対称の別・逆向きの表示語・`related` フォールバック・削除拒否／改名の規則は、**すべて ADR-0033
（状態 `Proposed`）に由来する**。[[IADR-0119]] 決定 2 の着手条件は前提 ADR が **`Accepted`** になることであり、
`Proposed` は満たさない。**値集合だけを先に作ることもしない**（値集合そのものが ADR の内容である）。

**(b) 契約の不在**

| 要素 | 契約の実測 |
| --- | --- |
| **タグ辞書** | `/bff/admin/authz` にあるのは `attributes` と `policies` の 2 群だけで、**タグ辞書の値集合を返す口が無い**。計画が確定した規則（参照 1 件以上は削除拒否・**使用件数 N の提示**・改名は既存文書が追随）は**そのすべてが契約側の機能**であり、画面だけでは満たせない |
| **検証ボタン**（dry-run） | 検証は `POST /policies` の応答（400 `ValidationProblem`）としてのみ得られる。**保存せずに検証する口が無い**。ローカルで代用すると「検証は通ったのに保存で矛盾が出る」ことになり、かえって誤解を生む |
| **自由記述の条件式** | `AbacPolicyDto.UserConditions` / `DocumentConditions` はいずれも `Dictionary<string, List<string>>`。**`<=`（機密区分の順序比較）も「含む」も表現できない** |

**(c) 他 issue の射程**

- 「MCPクライアント管理 →」（418）: 遷移先 **SC-12 のルートが未実装**（#445 待ち）。
  存在しない先へのリンクを置くと、押下時に `NotFound`（＝存在秘匿と同じ画面）が出て、
  **権限の問題と未実装の問題が区別できなくなる**。

| 用途 | エンドポイント | 応答 |

| ポリシー削除 | `DELETE /bff/admin/authz/policies/{id}` | 204 |

- BFF は要求本文・`Authorization` を AuthorizationService へ透過し、応答（status・本文）をそのまま返す。
  400 / 409 の詳細は `ApiError.details` に抽出され画面に表示される（[[IADR-0040]]）。
- **orval 生成フックで呼ぶ**（#506 で契約が揃い、**#519** で載せ替えた。[[IADR-0135]] 決定 1）。
  **400 / 409 の Problem 詳細は載せ替えの影響を受けない**——非 2xx を投げるのはどちらの経路でも
  `apiRequest` だからである。
- キャッシュキー: 生成キー `['/bff/admin/authz/attributes']` / `['/bff/admin/authz/policies']`。
  変更操作の成功後は該当キーを `invalidateQueries` する（手書きの再取得を持たない）。

## 権限・表示条件

- **`platform-admin` のみ**（[[IADR-0040]]）。`RequireRole` 配下で、権限外は **`NotFound`**（存在秘匿）。
  **未知パスの `NotFound` と markup が一致する**ことをテストで固定する（#490 が確立した作法）。
- **権限外では BFF を呼ばない**（要求の有無から画面の存在を推測させない）。
- 左ナビは `requiresAnyRole: [platform-admin]`・`group: 'admin'`。
- 認可の実効境界はサーバ側であり、UI は表示制御と存在秘匿のためだけに用いる。
