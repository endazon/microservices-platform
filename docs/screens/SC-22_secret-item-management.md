# 画面仕様書: 秘密情報・接続設定の管理

> 🔴 **未設定の判定はプロパティ単位ではなく項目単位である。** 計画はこの項目単位の判定で要素を満たすと裁定した
> （2026-09-15。裁定の記録は trace ブロックの計画 issue）。プロパティ単位の空欄は出さず、「設定済み」の限界は画面の注記で示す。

## 画面概要・目的

**Git に置けない秘密情報**（API キー・接続秘密・通知の webhook）を、運用者が画面から 1 項目ずつ投入・更新する画面である。
構成（認証基盤の宣言・パイプライン・公開ツールの許可リスト）は扱わない —— それらは Git 経由を維持する。

- ルート: `/admin/secrets`
- アクセス: **運用者・システム管理者に限る**。権限外にはメニュー・画面自体を出さない（権限ガードが未検出画面を描く）。
  境界層も同じ 2 ロールに限り、未認証は 401・権限外は 403 を返す。
- 🔴 **値は書き込み専用である。** 保存後は画面からも境界層からも読み出せない（読み出しの口そのものが無い）。
- 🔴 **一括再投入の口は無い。** 1 回の操作で書くのは 1 プロパティだけである。
- 扱う項目の集合は `deploy/bootstrap/sc22-secret-items.json` の `items[]` だけ（6 項目・21 プロパティ）。
  認証基盤と対で書くべき秘密・稼働中のデータストアの資格情報は対象外である（同ファイルの `deferred[]` / `excluded[]`）。
- **プロパティには入力の形がある**（同ファイルの `properties[]` の `kind` / `sensitive`）: 値をそのまま書く／パスワードを受けて MD5 だけを保存する（証券会社のログイン）／
  値を入力せず鍵を生成する（OpenD の RSA 鍵）。秘密ではない環境固有の ID（Discord のサーバー・チャンネル・許可する利用者・対応表）も、Git に置かない値としてここで扱う。
- 保存が成立すると、同期先への**即時同期を依頼する**（定期同期を待たずに Pod へ届ける）。依頼できたかを画面に出す。
- 🔴 **項目ごとに「いま効いている供給元」（画面／画面以外／確認できない）を出す。** 環境固有の ID は画面と Git（配備時の設定）のどちらからも設定でき、
  効くのは配備時のスイッチが選んだ一方だけである。これが無いと「書いたのに効かない」が静かに起きる。
  **画面は供給元を推測しない** —— 境界層が配備の結果（下の「供給元の示し方」）を読んで返し、判定できなければ「確認できない」と出す。
- **書き込むと消費側（その値を読むアプリケーション）が再起動する。** 再起動を伴う項目では、送る前に**確認の段**を置き、再起動する消費側と
  断たれ得る処理の種類を出す。**その確認をもって再起動の確認とする**（書き込みとは別の再起動の操作は置かない）。止めてよいかを判断できるのは止める本人だけだからである。

### 状態の示し方（色だけで意味を持たせない）

| 値 | 表示 | 意味 |
| --- | --- | --- |
| 設定済み | 成功（チェック）＋最終更新日時 | 保管先に値の**版**がある。🔴 **各プロパティに空でない値が入っていることは意味しない** |
| 未設定 | 警告 | 保管先に値が無い（項目ごと無い、または現在の版が削除されている）。🔴 **現在の版が削除されている項目は、この画面から更新できない**（先に版の復元が要る。下の「失敗の表示」） |
| 取得できない | 危険 | 状態を取れなかった（保管先の権限・障害）。**未設定とは区別する** |

### 最終更新者

- **この画面から更新した版が現在の版であるときだけ**、その利用者名を出す。版の番号だけでなく**版の作成時刻も一致する**ことを確かめる
  （保管先で項目を消して作り直すと版の番号は 1 から振り直されるため、番号だけでは別の版に古い名前が付き得る）。
- コンソール（退避手段）や初期投入が書いた版は「**記録なし**」と出す。**誤った名前を出さない**ことを優先している。
- 「誰がいつ更新したか」の正本は監査ログである。

### 供給元の示し方

境界層は、項目ごとに**同期先の ExternalSecret がクラスタに在るか**を Kubernetes API で確かめて返す。
画面の経路（保管先 → 外部シークレット同期 → Secret）が効くのは同期先が在るときだけであり、同期先を描くかどうかは
配備時のスイッチが決める —— したがって有無は**配備時のスイッチの事実そのもの**である。ExternalSecret の本文も Secret も読まない。

| 値 | 表示 | 意味 |
| --- | --- | --- |
| 画面 | 成功（チェック） | 同期先が在る。この画面で書いた値がアプリケーションへ届く |
| 画面以外 | 警告 | 同期先が無い（API が「無い」と答えた）。値は画面以外（手で作った Secret・配備スクリプト・Git など）から来ており、**この画面で書いた値は反映されない** |
| 確認できない | 中立（情報） | 判定できなかった（クラスタへの接続が構成されていない・拒否された・届かない）。🔴 **「画面」にも「画面以外」にも倒さない**。境界層が値を返さないときも同じ。**同期を無効にした構成（本番の既定）では全項目がこれになる** —— 表示の不具合ではなく、判定できないという事実の表現である |

- 🔴 **表示名は「画面以外」であり「Git」ではない。** 判定の中身は「同期先が無い」であり、値の出どころが Git とは限らない（「Git」と出ると利用者は Git を直しに行く）。
  境界層が返す値は識別子として `git` のまま据え置いている（値を変えると通信の契約を壊す。表示だけの問題なので値は変えない）。
- 🔴 **「画面以外」の項目への書き込みは拒否しない。** 送る前にフォームへ「書いても反映されない」旨を出し、保存後も同期の成否ではなく「反映されない」旨を出す。
- 「確認できない」の項目は、書いた値が反映されるかをこの画面からは言えない旨を出す。

### 消費側の再起動と書き込みの確認

**書き込みの確認を、消費側の再起動の確認とする。** 再起動を伴う（伴い得る）項目では、送信の押下ではまだ送らず確認ダイアログを開く。
確認して初めて送り、即時同期と自動の作り直し（配備した環境の場合）が続く。🔴 **書き込みとは別の再起動の操作は置かない**
（置くと境界層に消費側を再起動する権限が要る。境界層の権限は増やさない）。初期フォーカスは取消に置く。

| 項目 | 再起動する消費側 | 断たれ得る処理 | 確認ダイアログの本文 |
| --- | --- | --- | --- |
| 外部 LLM の API キー | LLM ゲートウェイ | 検索・質問応答・分析での外部 LLM の呼び出し | 確認して書き込むと、即時同期のあとで消費側が**自動で再起動される**（自動再起動を配備した環境の場合）。配備していない環境では、再起動するまで書いた値は反映されない |
| メール送信の認証情報 | メール中継 | 通知メール（パスワード再設定など）の送信 | 同上 |
| Wiki 同期の API キー | Wiki 同期 | Wiki.js との文書の同期 | 同上 |
| 株式自動売買の外部 API キーと通知 | 株式自動売買のアプリケーション | 売買・市場データと開示情報の取得・Discord への通知 | 同上 |
| moomoo 証券のログイン情報・OpenD の RSA 鍵 | OpenD | moomoo 証券との接続（発注・約定と相場の受信） | **この書き込みでは OpenD は再起動しない。** 反映するには書き込み後に手動で再起動する（コマンドを示す）。手動の再起動は稼働中の処理を中断し、SMS または画像の認証を再び求められることがある |
| （上の表に無い項目） | — | — | 再起動される**ことがある**（断定しない） |

- どの本文にも「再起動は稼働中の処理を中断する。止めてよい時機か確かめてから書き込む」を添える。
- 供給元が「**確認できない**」項目は、自動の作り直しの本文を「再起動するかは断定できない。同期先がある環境では再起動されることがある」に替える。
- 供給元が「**画面以外**」の項目では確認ダイアログを出さずに送る（書いても Secret が変わらず、再起動も起きない）。
- **鍵の生成の確認はこの確認の段に統合する**（2 度確認させない）。生成では、再起動の本文に加えて「保管先の鍵が新しい鍵に置き換わり、OpenD が新しい鍵を読み込むまで（手動で再起動するまで）、OpenD と同じ鍵で接続するクライアントとの間で鍵が食い違う」旨を出す。供給元が「画面以外」でも生成は確認を通すが、その場合は同期先が無いため
  「生成した鍵は OpenD にもクライアントにも届かない（再起動しても届かない）」と書き、再起動の本文は出さない。生成の確定ボタンは破壊的な操作として示す（保管先の鍵が置き換わる）。
- **書き込み後の表示**にも、自動の作り直しの項目（と表に無い項目）は「自動再起動を配備していない環境では、再起動するまで反映されない」、OpenD の項目は「OpenD を手動で再起動するまで反映されない」を添える。
- 画面は、自動の作り直しが配備されているかを検出しない（検出には境界層の権限の追加が要る）。文言を「配備した環境の場合」と限定し、断定しない。

## 表示・入力項目

| 項目 | 種別 | 必須 | 初期値 | 形式・制約 | 説明 |
| --- | --- | --- | --- | --- | --- |
| 更新するプロパティ | 選択 | 必須 | 項目の最初の書けるプロパティ | 項目が持つ**書けるプロパティだけ** | 同じ項目に同居する構成値（宛先ホスト等）は選択肢に出ない |
| 新しい値 | パスワード入力（マスク） | 必須 | 空 | 1〜8192 文字 | 書き込み専用。ブラウザに保存させない |
| 新しい値（確認のためもう一度） | パスワード入力（マスク） | 必須 | 空 | 新しい値と完全一致 | 貼り付けの誤りを保存前に捕まえる（前後の空白も比べる） |
| 新しい値（秘密ではない ID のプロパティ） | テキスト入力（平文） | 必須 | 空 | 1〜8192 文字 | 秘密ではない旨を添える。入力が見えるため確認入力は求めない。**書き込み専用なのは同じ** |
| パスワード／パスワード（確認のためもう一度）（MD5 で保存するプロパティ） | パスワード入力（マスク） | 必須 | 空 | 1〜8192 文字・完全一致 | 「MD5 に変換した値だけが保存される」旨を添える。平文は保存しない |
| （鍵を生成するプロパティ） | 入力欄なし | — | — | — | 「生成」→ 確認ダイアログ →「生成して書き込む」。鍵は画面にも応答にも出ない |
| 更新の理由 | テキスト | 任意 | 空 | 500 文字以内 | 監査ログへ残る。値そのものを書かないよう注記する |

| 新しい値 | 空 | （送信ボタンは押せない） |

## アクション・イベント

| 操作 | 挙動 | 遷移先 |
| --- | --- | --- |
| 行の「更新」 | その項目の更新フォームを開く | — |
| 「このプロパティを更新する」 | 供給元が「画面以外」なら、1 プロパティだけを保管先へ書く（部分更新。同じ項目の他のプロパティは消えない）。それ以外は**まだ送らず、書き込みの確認（＝再起動の確認）を開く** | 確認ダイアログ |
| 「生成」（鍵を生成するプロパティ） | すぐには送らない。鍵が置き換わる旨と再起動の確認を 1 つの確認ダイアログで出す | 確認ダイアログ |
| （確認ダイアログの）「書き込む」／「生成して書き込む」 | 1 プロパティだけを保管先へ書く（生成は境界層が鍵を作って書く。値は送らない）。成功したら**入力を空に戻し**、書き込み後の版・**即時同期を依頼できたか**・再起動するまで反映されない旨を示し、一覧を引き直す | — |
| （確認ダイアログの）「やめる」・Esc・背景 | 確認を閉じる（送らない） | — |
| 「閉じる」 | フォームを閉じる（入力は破棄される） | — |

**失敗の表示**:

| 状況 | 表示 |
| --- | --- |
| 保管先が構成されていない・接続できない（一覧） | 「秘密情報の項目を取得できませんでした。」＋ 保管先の稼働を確認する旨。**表を描かない** |
| 保管先が構成されていない・接続できない（更新） | 「……接続できません。値は保存されていません。」 |
| 保管先が書き込みを拒んだ | 「……書き込みを受け付けませんでした。値は保存されていません。」 |
| 現在の版が保管先で削除されている（一覧では「未設定」） | 「この項目の現在の版は保管先（Vault）で削除されています。……コンソールから版を復元してから、もう一度更新してください。値は保存されていません。」 |
| 保存は成立したが、即時同期を依頼できなかった | 成功の表示に加えて「……即時同期を依頼できませんでした。アプリケーションへの反映は定期同期（最大 1 時間）を待ちます。」（**値は保存されている**） |
| 保存は成立したが、項目の供給元が「画面以外」 | 成功の表示に加えて「保管先への書き込みは完了しましたが、この項目は画面以外（手で作った Secret・配備スクリプト・Git など）から供給されているため、書いた値はアプリケーションに反映されません。」（同期の成否の文言も再起動の文言も出さない） |

**現在の版が削除されている項目へは、画面から書かない。** 画面の書き込み権限（部分更新と「無いときだけ作る」）では
削除された版の上へ書く手段が無く、その手段（項目の全置換）を足すと同じ項目に同居する構成値を消せてしまうためである。
運用者は[運用 Runbook](../operations/secret-item-console-injection-runbook.md) の失敗の分岐に従い、コンソールで版を復元してから画面で更新し直す。

**値の確認のための確認ダイアログは置かない。** 2 度目の入力がそのまま値の確認であり、保管先は旧版を保持するので書き直しで戻せる。
**確認ダイアログを置くのは、再起動を伴う（伴い得る）項目と鍵の生成である**（上の「消費側の再起動と書き込みの確認」）。
前者は書き込みが保管先の外（消費側の再起動）で稼働中の処理を断つため、後者は保管先の鍵が置き換わるためである。
どちらも**1 つの確認ダイアログ**に出し、2 度確認させない。

## 計画（モックアップ・画面設計）との対応

## 未決事項

- 認証基盤と対で書くべき秘密（`deferred[]`）を画面で扱うか。
- 本番の消費側の作り直し方（自動の作り直しはローカルにしか配備していない）。決めるときは、作り直しを**利用者が確認した書き込みを契機とするものに限る**（仕組みが自ら時機を選ぶ方式は採らない）。それまで本番では、書いた値は消費側を再起動するまで効かない。
- 供給元の判定は稼働クラスタで未実測である（自動試験は Kubernetes API の偽物に対する固定。テスト仕様書の手動の項）。
