# 画面仕様書: MCP クライアント登録管理

> **［実装状態］`status: completed` は「本仕様書が記述する範囲の実装とテストが揃った」ことを表す**
> （`docs/README.md` 運用ルール 6）。
> 🔴 **計画の要素のうち 2 つは実装していない**（「登録 → 認可サーバーのクライアント作成」と
> 「有人アカウントの上限を超えない」の検証）。理由は §計画（モックアップ・画面設計）との対応 に
> 「しない」「一部する」として書いた。**繰り延べであって放棄ではない。**

## 画面概要・目的

MCP サーバーへ接続できるクライアント（外部 AI エージェント）と、そこへ公開しているツールを
管理するための画面である。

- ルート: `/admin/mcp-clients`
- アクセス: **システム管理者ロール限定**。運用者も不可。権限外には画面の存在を示さない
  （権限ガードが未検出画面を描く。存在秘匿）。サーバ側も境界層と後段の二重ゲートで管理者限定を強制する。

## レイアウト / 主要素

| # | 要素 | 実装 |
| --- | --- | --- |
| 1 | 登録クライアント一覧（クライアント / 種別 / 認証 / 属性 / 状態 / 操作の 6 列） | ヘッドレスの表（並べ替えのみ登録）＋ 共有 UI の表構造 |
| 2 | クライアント登録フォーム（ID・表示名・種別・属性割当） | 入力＋選択。無人のときだけ属性の入力欄が出る |
| 3 | 無効化・再有効化 | 各行のボタン。状態に応じて片方だけを出す |
| 4 | 公開ツール一覧（実効構成の参照） | **読み取りのみ。** 変更の入口を置かない |
| 5 | 構成のずれ（ドリフト） | 1 件以上あるときだけ警告として出す |
| 6 | 呼び出し監査ログへの導線 | ログ基盤への外部リンク。**未設定なら導線を出さず所在を文言で示す** |
| 7 | 空状態 / 取得失敗 | **別々に描き分ける**（「1 件も無い」と「引けない」は別の意味である） |

### 状態の示し方（色だけで意味を持たせない）

状態は共有 UI の状態バッジで示す。**色 ＋ アイコン ＋ テキスト**の 3 点セットが型で強制される。

| 値 | 表示 | 意味 |
| --- | --- | --- |
| 有効 | 成功（チェック） | 接続・ツール実行を受け付ける |
| 無効（即時接続拒否） | 危険（バツ） | **次の呼び出しから**拒否される。後段は登録簿を毎回引き、キャッシュを挟まない |

**「無効」だけでは「いつから効くのか」が読めない**ため、文言に即時性を含めている。

## 表示・入力項目

| 項目 | 種別 | 必須 | 初期値 | 形式・制約 | 説明 |
| --- | --- | --- | --- | --- | --- |
| クライアント ID | テキスト | 必須 | 空 | 任意文字列 | 認可サーバーのクライアント ID（トークンの発行元識別子）と同じ値を入れる |
| 表示名 | テキスト | 必須 | 空 | 任意文字列 | 一覧に出る人間向けの名前 |
| クライアント種別 | 選択 | 必須 | 有人 | 有人 / 無人の 2 値 | 有人は認可コード + PKCE、無人はクライアント資格情報 |
| 属性（キー） | 選択 | 無人時必須 | 未選択 | **属性辞書の利用者スコープの項目のみ** | 文書スコープの属性は主体へ割り当てない（意味が反転する） |
| 属性（値） | 選択 | 無人時必須 | 未選択 | **選んだ属性の許可値のみ** | 値域の正は辞書であり、画面へ焼き込まない |

## バリデーション

| 項目 | 条件 | エラーメッセージ |
| --- | --- | --- |
| クライアント ID | 空でないこと | クライアント ID は必須です。 |
| 表示名 | 空でないこと | 表示名は必須です。 |
| 属性割当 | 無人のとき 1 件以上 | 無人（サービスアカウント）には ABAC 属性の割当が必須です。 |
| 属性割当（禁止された値） | **サーバ側が判定する** | 後段の拒否理由をそのまま表示する（中立化しない） |

🔴 **禁止された属性割当（無人アカウントへ個人資料を読ませる割当）は画面では判定しない。**
判定は後段の 1 つの検証関数に閉じており、登録経路と差し替え経路の両方がそこを通る。
画面側に写すと 2 つ目の判定が生まれ、**片方だけが緩む**。画面は拒否理由（問題詳細）を出すだけである。

## アクション・イベント

| 操作 | 挙動 | 遷移先 |
| --- | --- | --- |
| 登録 | 入力規則を満たせば登録要求を送る。成功後は一覧を無効化して引き直す | 同一画面 |
| 無効化 / 再有効化 | 状態を切り替える。**次の呼び出しから効く** | 同一画面 |
| 属性を追加 | 選んだキーと値を割当の候補へ積む（同じキーは後勝ち） | 同一画面 |
| 呼び出し監査ログ | ログ基盤を別タブで開く。未設定なら導線を出さない | 外部 |

## 権限・表示条件

- **システム管理者ロールのみ**が到達できる。権限外では未検出画面を描き、左ナビにも項目を出さない。
- 認可の実効境界はサーバ側にある。画面のガードは表示制御と存在秘匿のためだけに用いる。

## 計画（モックアップ・画面設計）との対応

| 計画側の要素 | 実装 | 満たしていない条件 / 理由 | 計画側の該当箇所 |
| --- | --- | --- | --- |
| 登録クライアント一覧（種別・状態） | する | — | `01_screens.md:496` |
| クライアント登録 | **一部する** | **登録先はプラットフォーム側の登録簿だけである。** 計画の「登録 → 認可サーバーのクライアント作成」は実装していない —— 後段 API に認可サーバーへ書き込む口が無く、作成には管理用の資格情報とクライアント種別ごとのテンプレートの決定が要る。**別の決定が要る作業であり、繰り延べる。** | `01_screens.md:496`・`01_screens.md:502` |
| 無効化（即時に接続拒否） | する | — | `01_screens.md:502` |
| 無人アカウントの ABAC 属性割当（機密区分上限・アクセス可能タグ） | **一部する** | 割当そのものと「**定義済みの属性・許可値のみ**」は満たす。**「有人アカウントの上限を超えない」は実装していない** —— 身元を返す契約（`/bff/auth/me` 相当）が**ロールしか返さず、登録者本人の属性上限を返さない**。画面側だけで近似すると「通ったのに実際は超えている」形になり、**信頼できない検証は無いより悪い**（計画自身が別画面で同じ判断をしている）。**サーバ側にもこの検証は無い。** 契約に上限が載った時点で、後段と画面の両方へ入れる。 | `01_screens.md:499` |
| 公開ツール一覧（実効構成の参照） | する | 実効ツールと構成のずれを表示する。**変更の入口は置かない** | `01_screens.md:496`・`01_screens.md:502` |
| 呼び出し監査ログへの導線 | **一部する** | 導線は出すが、**遷移先はログ基盤（外部）である。** アプリ内に監査ログ画面は無く、計画にもその画面は無い。接続先は実行時設定から取り、**未設定なら導線を描かず所在を文言で示す**（存在しないリンクを描かない） | `01_screens.md:496` |
| システム管理者ロール限定 | する | 画面（存在秘匿）・境界層・後段の 3 層 | `01_screens.md:503` |
| 操作を監査ログに記録する | **一部する** | **ツールの呼び出し**は後段が監査ログへ記録する。**管理操作（登録・無効化・属性割当）の監査記録は後段に無い** —— 記録の実体（誰が・いつ・何を）は監査記録の基盤側の決定であり、本作業では入れていない | `01_screens.md:503` |
| モックの「＋ クライアント登録」ボタン（別ダイアログ） | **一部する** | フォームは**同一画面に常時展開**している。ダイアログにしていないのは、入力規則（無人時の属性必須）を出し分ける必要があり、常時展開のほうが規則の適用を見せやすいためである。**要素は欠けていない** | `mockups/hi-fi/sc-12.html` |
