## 画面概要・目的

MCP サーバーへ接続できるクライアント（外部 AI エージェント）と、そこへ公開しているツールを
管理するための画面である。

- ルート: `/admin/mcp-clients`
- アクセス: **システム管理者ロール限定**。運用者も不可。権限外には画面の存在を示さない
  （権限ガードが未検出画面を描く。存在秘匿）。サーバ側も境界層と後段の二重ゲートで管理者限定を強制する。

## レイアウト / 主要素

| # | 要素 | 実装 |
| --- | --- | --- |
| 1 | 登録クライアント一覧（クライアント / 種別 / 認証 / 属性 / 状態 / 操作の 6 列） | ヘッドレスの表（並べ替えのみ登録）＋ 共有 UI の表構造 |
| 2 | クライアント登録フォーム（ID・表示名・種別・リダイレクト URI・属性割当） | 入力＋選択。有人のときだけリダイレクト URI の入力欄が、無人のときだけ属性の入力欄が出る |
| 3 | 無効化・再有効化 | 各行のボタン。状態に応じて片方だけを出す |
| 4 | 登録済みクライアントの属性の差し替え | 無人の行だけに出す。現在値を読み込んでから編集し、**集合ごと置き換える** |
| 5 | 公開ツール一覧（実効構成の参照） | **読み取りのみ。** 変更の入口を置かない |
| 6 | 構成のずれ（ドリフト） | 1 件以上あるときだけ警告として出す |
| 7 | 呼び出し監査ログへの導線 | ログ基盤への外部リンク。**未設定なら導線を出さず所在を文言で示す** |
| 8 | 空状態 / 取得失敗 | **別々に描き分ける**（「1 件も無い」と「引けない」は別の意味である） |

### 状態の示し方（色だけで意味を持たせない）

状態は共有 UI の状態バッジで示す。**色 ＋ アイコン ＋ テキスト**の 3 点セットが型で強制される。

| 値 | 表示 | 意味 |
| --- | --- | --- |
| 有効 | 成功（チェック） | 接続・ツール実行を受け付ける |
| 無効（即時接続拒否） | 危険（バツ） | **次の呼び出しから**拒否される。後段は登録簿を毎回引き、キャッシュを挟まない |

**「無効」だけでは「いつから効くのか」が読めない**ため、文言に即時性を含めている。

## 表示・入力項目

| 項目 | 種別 | 必須 | 初期値 | 形式・制約 | 説明 |
| --- | --- | --- | --- | --- | --- |
| クライアント ID | テキスト | 必須 | 空 | 任意文字列 | 認可サーバーのクライアント ID（トークンの発行元識別子）と同じ値を入れる |
| 表示名 | テキスト | 必須 | 空 | 任意文字列 | 一覧に出る人間向けの名前 |
| クライアント種別 | 選択 | 必須 | 有人 | 有人 / 無人の 2 値 | 有人は認可コード + PKCE、無人はクライアント資格情報 |
| リダイレクト URI（［2026-10-09 追加］） | 複数行テキスト（1 行 1 件） | 有人時必須 | 空 | 1〜10 件。`https` か、ループバックの `http://127.0.0.1` / `http://[::1]` | 認可サーバーが**完全一致**で照合する。前後の空白と空行は落として送る。無人では入力欄を出さず、送らない |
| 属性（キー） | 選択 | 無人時必須 | 未選択 | **属性辞書の利用者スコープの項目のみ** | 文書スコープの属性は主体へ割り当てない（意味が反転する） |
| 属性（値） | 選択 | 無人時必須 | 未選択 | **選んだ属性の許可値のみ** | 値域の正は辞書であり、画面へ焼き込まない |

## バリデーション

| 項目 | 条件 | エラーメッセージ |
| --- | --- | --- |
| クライアント ID | 空でないこと | クライアント ID は必須です。 |
| 表示名 | 空でないこと | 表示名は必須です。 |
| 属性割当 | 無人のとき 1 件以上 | 無人（サービスアカウント）には ABAC 属性の割当が必須です。 |
| リダイレクト URI | 有人のとき 1 件以上 | 有人にはリダイレクト URI が 1 件以上必要です。 |
| リダイレクト URI | 10 件以下 | リダイレクト URI は 10 件以下にしてください。 |
| リダイレクト URI | `https` かループバックの `http://127.0.0.1` / `http://[::1]`。ワイルドカード・フラグメント・利用者情報・`localhost` は不可 | リダイレクト URI は https か、ループバックの http://127.0.0.1 / http://[::1] に限ります（ワイルドカード・フラグメント・localhost は使えません）。 |
| リダイレクト URI | 重複しないこと | リダイレクト URI が重複しています。 |
| 属性割当（禁止された値） | **サーバ側が判定する** | 後段の拒否理由をそのまま表示する（中立化しない） |

🔴 **禁止された属性割当（無人アカウントへ個人資料を読ませる割当）は画面では判定しない。**
判定は後段の 1 つの検証関数に閉じており、登録経路と差し替え経路の両方がそこを通る。
画面側に写すと 2 つ目の判定が生まれ、**片方だけが緩む**。画面は拒否理由（問題詳細）を出すだけである。

［2026-10-09］**リダイレクト URI の形は画面でも送る前に検査する**（入力の打ち間違いをその場で示すため）。これは属性割当と違い、
統制の判定（誰に何を許すか）ではなく値の形の検査である。**最終の判定は後段が持ち**、写しが食い違えば後段の 400 が理由を名指しして返り、画面はそれを出す。

## 無人アカウントの属性の判定（本画面は事前に示さない）

🔴 **本画面は「その値を割り当てられるか」を事前に示さない。** 判定は**後段だけ**が持つ。

- 本画面と境界層が担うのは**値域の絞り込み**（属性辞書に定義済みの属性・許可値だけを選ばせる）までである。
- **画面が判定しても、API を直接叩けば素通しになる。** 「検証がある」と読める UI を置きながら
  実際には統制が無い状態は、**検証が無いことより悪い。**
- 身元を返す口は `clearance` / `department` を**返さない。** 属性の正は認可サービスであり、
  画面へ配ると「画面が持つ値」と「判定に使う値」の 2 つができる。**不在は退行防止テストで固定してある。**
- 代償として、利用者は**登録を試みるまで割り当て可否が分からない。** その緩和策が次である。

### 拒否理由の描き方

後段は 400（RFC7807）で拒み、本文に**どの値が外れたか**を値そのもので載せる。境界層はそれを
透過し、本画面は登録フォームと属性変更フォームの**それぞれのエラー欄に本文として**出す。

| 欄 | `data-testid` | 出るもの |
| --- | --- | --- |
| 登録フォームのエラー | `registration-error` | 例: `clearance の値 'confidential' は割り当てられません（…）` |
| 属性変更のエラー | `attribute-edit-error` | 例: `tags の値 'finance' は割り当てられません（…）` |

🔴 **中立化しない**（「権限がありません」へ丸めない）。管理者が自分で直せる情報であり、
**事前に示せないことの唯一の緩和策**である。`title` 属性ではなく画面上のテキストとして出す。

### 🔴 タグを配る経路は現状成立しない（2026-09-05 の実測）

**利用者スコープの属性辞書に `tags` が無い。** 開発環境の初期投入データが持つ利用者スコープの
キーは取扱可能区分と所属部門の 2 つだけであり、**タグは文書スコープの概念として定義されている**。

したがって現状は次のようになる。

- 利用者へタグを割り当てようとすると、利用者管理の画面が「属性辞書に定義されていません」で拒む。
- **登録者は誰もタグを持てない**ので、無人アカウントへのタグ割当は**常に**
  「登録者が持つタグは ありません」で拒まれる。**判定は安全側に倒れている**が、
  「規則が働いている」のではなく「入力が存在しない」だけである。
- **本画面の属性入力にタグ欄を出すこと自体は誤りではない**（辞書へタグが登録された時点で成立する）。
  辞書を実装側で足すことはしない —— 属性辞書は管理者が定義するものである。

**符号化は先に揃えてある。** タグのような**集合値の利用者属性**は、認可サーバーの多値属性を正の器と
し、1 キー 1 値の契約へはカンマ区切りで載せる。連結と分割の規則は共有契約に 1 つだけ置き、
利用者管理の辞書照合も**要素ごと**に行う。従前は 3 者（認可サーバー・利用者管理・後段の判定）で
表現が食い違い、**多値が先頭 1 値へ静かに畳まれていた**（拒否理由が実際より狭い集合を告げていた）。

## 認可サーバーへの書き込み（無人・有人）

🔴 **登録簿は、認可サーバーへ書いた値の写しである。** 判定に使うのは認可サーバーのサービスアカウントの属性だけであり、
認可サービスが判定のたびに引き直す。後段は次の順で書く。

1. **検証**（個人資料の割当禁止 ＋ 登録者の集合の部分集合）。外れたら **認可サーバーへ何も書かずに** 400 で拒む。
2. 登録簿に同じクライアント ID があれば 400（従来どおり）。
3. **認可サーバー**: 機密クライアント（サービスアカウントつき・人の流れは閉じる）を作る → サービスアカウントの利用者が
   認可サービスと同じ照会（利用者名の完全一致）で引けることを確かめる → 属性を書く → 読み戻して確かめる。
4. **登録簿**へ書く。

| 起きたこと | 応答 | 認可サーバー | 登録簿 |
| --- | --- | --- | --- |
| 検証の外れ | 400（外れた値を名指し） | 何も書かない | 書かない |

  ［2026-10-09］**ループバックは port の明示が必須**（例: `http://127.0.0.1:53123/callback`）。port なしは入力の検査で止め、後段も 400 で拒む。
