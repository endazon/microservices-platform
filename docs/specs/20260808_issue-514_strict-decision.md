# 仕様書: `--strict` の是非を決める（#514）

> 本 issue は**実装ではなく是非を決める**もの。決定は [[IADR-0130]] の追補として残す。

## 起点

- 起点 issue: **#514**（親 #454）／起点 ID: **NFR**
- [[IADR-0130]] §フォローアップ 4 が切り出した検討事項
- 分類（[[IADR-0141]] 決定 4）: **「ADR の決定に触れる／規約を改定する」**

## 母集合（[[IADR-0141]] 決定 1）

**走査基準**: `origin/develop` = `e2cf25e`（#604 マージ後）。

| 軸 | 対象 | 実測 |
| --- | --- | ---: |
| 1 | `docs/tests/` の Markdown | **29 ファイル** |
| 2 | 床 `test-spec-coverage-baseline.json` の対 | **70 対 / 17 ファイル** |
| 3 | `--strict` の候補 | **4 案**（候補 1・2・3 ＋ 字義どおりの A2） |
| 4 | 変異 | **6 種**（無変異・M0・M1a・M2a・M3・M5） |
| 5 | `docs/tests/` を触った git 履歴 | **21 コミット全件** |
| 6 | 仕様書が挙げる `src/` パスの実在 | **67 件中 3 件が不在** |

**除外**: フロント（[[IADR-0130]] 決定 5 が対象外と定めた）／`docs/specs/`・`feedback/`（書いた時点の記録）。

## 決定: **`--strict` を入れない**

### 根拠 1: 追加検出力が実測でゼロ

**実際に起きた唯一の欠陥（`5ce3ec9` / #503）を、現行検査は 8 対の `regressed` で fail させる。**
`--strict` が追加で捕まえるのは **M1a / M2a という一度も起きていない型**だけである。

さらに **`5ce3ec9` では節は「消失」しておらず「置換」されていた** —— 節数は
SC-05 が 6→8、SC-06 が 5→7、SC-07 が 6→8 と**増えている**。
したがって「節数のラチェット」という低コスト代替も**この事例を検出できない**。

### 根拠 2: 候補 1 は正当な編集で偽陽性を出す

「表を含む節からの参照だけを数える」案は、**表を同内容の箇条書きへ書き換えただけで fail** する（M5）。
判別子が言及の所在と**無相関**であることも実測した ——
見出し配下の言及 85 件のうち**表セル内のみ 23 / 散文のみ 62 / 両方 0**。
つまり「その節のどこかにパイプ行があるか」しか見ておらず、設計として筋が悪い。
加えて導入時に **26 対 / 6 ファイルの書式統一を強制**する。これは [[IADR-0130]] 決定 5 が
フロントを対象外にした理由（「fail が別件の書式統一を強制する」）と**同型の弊害**である。

### 根拠 3: 候補 3 は §限界 2 を塞がないのに床が膨らむ

節見出しをキーに含める案は **M3（表を全削除し散文だけ残す）で緑**のまま ——
[[IADR-0130]] §限界 2 を塞がない。塞ぐのは §限界 5 だけである。
一方で床は **70 → 85 対（+21%）**に膨らみ、**日本語見出し文字列**（issue 番号入り 2 件・全角括弧）を
JSON 床の一次キーへ持ち込む。**見出しの改名で偽陽性**が出る（M0 / M4 で実測）。
履歴上の偽陽性 0 件は、**改名 3 件がたまたまフロント見出しだった**ことによる小標本の値であって
「起きにくい」証拠にならない（**#510 の復帰コミット自身が見出しを 2 本改名している**）。

### 根拠 4: 候補 2 は共有語彙が存在しない

参照を担う見出しは異なり 24 件で、**うち 19 件が単一ファイル固有**。
許可リスト化は「語彙を作る」ではなく「29 ファイルの見出しを書き換える」作業になる。

### 代替手段: 向き (a) を先行させる

**`--strict` が対象とする欠陥は 1 件も発生していないのに、向き (a) の欠陥は 3 件が実在して待っている。**

```
docs/tests/ が挙げる src/ パス 67 件のうち実在しないもの:
  docs/tests/FR-01_data-source-catalog.md:87
  docs/tests/FR-06_document-crud-versioning.md:70
  docs/tests/FR-07_data-range-analysis.md:77
  いずれも KnowledgePlatform.IntegrationTests（実在は Knowledge.IntegrationTests）
```

人の手当ては既に条文化済みである（`docs/tests/TEST_STRATEGY.md:299-302`）。

## ついでに是正すること

**[[IADR-0130]] §フォローアップ 1 の「1 件見つかった」は実測 3 件**で過小だった。
向き (a) の優先度判断の根拠が実際より弱く記録されており、**#514 の判断に直接効く数値**なので直す。
**参照点は 1 つに畳む**（新しい値を別の場所に足さない）。

## 新 IADR の要否: **不要。追補で足りる**

決定 1〜6 のいずれも変えない。新 IADR を起こすと「記載被覆の判定単位」の参照点が 2 つに割れ、
[[IADR-0141]] の「参照点を 1 つに畳む」に反する。ただし**追補は必須**（#514 の完了条件）。

## ［2026-08-08 追記 / #607 レビュー］引き直した 2 点と、作業中に見つけた検査の穴

### 1. 「フェーズ末に 1 回」という裁定が、リポジトリのどこにも書かれていなかった（🟡）

**指摘の裏取り**: `grep -rn "フェーズ末"` → **0 件**（レビューの実測と一致）。
PR 本文はこの裁定を根拠に「本 PR 単独ではクロス監査を走らせていない」と述べていたが、
**裏付けが口頭の裁定にしか無く、第三者が検証できない状態だった**。

**是正**: [[IADR-0141]] 決定 4 へ日付つき追記ブロックとして書き残した
（フェーズ＝複数 issue の束・**PR は束ねない**（1 issue = 1 PR）・分岐はフェーズ末の 1 回に当てる）。
**単位（1 対象あたり）は変えていない。変わったのは「いつ走らせるか」だけである。**

### 2. 追補が依拠した 2 件が `related_ids` / §関連 に無かった（🟡）

[[IADR-0138]]（「検出しないこと」を節として明示し先行 ADR を Supersede せず補完する書式）と
[[IADR-0141]]（参照点を 1 つに畳む・母集合の引き直し）を追加した。
**同じファイルの中で引用の作法が 2 通りになっていた**（IADR-0118 / IADR-0122 は載せてあった）
というのが指摘の本体であり、これは妥当である。

### 3. ブランチ名 `docs/NFR-514-strict-decision`（🟢・是正しない）

規約の書式は `<種別>/<起点ID>-<概要>` であり、`NFR` に issue 番号を連結した `NFR-514` は
厳密には起点 ID ではない。**既 push のため改名しない**（PR を張り替えることになる）。
コミット件名・PR タイトルは規約どおりで機械検査も通っている。
**同じ形は他の作業ブランチでも使っており**（`chore/NFR-563-...` / `chore/NFR-581-...`）、
直すなら規約側で「`NFR` は issue 番号での識別を許す」と定めるのが筋である。**本 PR では扱わない。**

### 4. ★ 作業中に見つけた検査の穴: `check-doc-links.js` は**同一ディレクトリのベア相対リンクを一切見ない**

本 PR で §関連 へ足したリンクのファイル名を**間違えた**（`IADR-0138_error-message-spec-scope.md`。
実在は `IADR-0138_coverage-exclude-generated-code.md`）。**`node scripts/check-doc-links.js` は緑のままだった。**

原因は `isBrokenRef` の `looksRelative` 判定で、`./` `../` で始まるか `/` を含むものしか相対リンクと
見なさない。**`IADR-0138_x.md` のような同一ディレクトリのファイル名だけの形は素通りする。**

母集合を引いた（追跡下の `*.md`・submodule と `planning/` を除く）:

```
同一ディレクトリのベア相対リンク: 244 件
うち破損: 0 件（本 PR の 1 件を直した後）
```

**是正の後始末は不要だが、穴は開いたままである**——244 件が無検査であり、
`docs/adr/` の §関連 はほぼこの形で書かれている。**別 issue として起票し、本 PR では直さない**
（本 PR は文書のみの決定であり、検査器の改修を混ぜると [[IADR-0141]] 決定 4 の分類が重くなる）。
