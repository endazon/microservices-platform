## 判断

### ★ 判断 1: **確定済み引用が 0 件でも、見出しはスタブとして残す**

[IADR-0173](../adr/IADR-0173_annex-extraction-keeps-heading-stubs.md) 決定 1 に**例外を作らない。**

**根拠は 2 つ。**

1. **「今は引かれていない」は「今後も引かれない」ではない。**
   段 1 の対象（`PR タイトル…の検査`）も、**引いていたのは `IADR-0145` の 1 件だけ**だった。
   **1 件でも確定済みなら壊せない**のだから、**0 件と 1 件の差は「まだ書かれていないか」だけ**である。
2. **例外を作ると規則が形骸化する。** 「確定済み引用が 0 なら消してよい」を許すと、
   **毎回引用を数え直す運用**になる。**数え損ねた 1 件が事故になる**（#686 で走査式を誤って
   1 件取りこぼした実績がある）。

### ★ 判断 2: **別紙は新規ファイルにする**（既存の別紙へ追記しない）

既存の別紙は [`docs/how-to/commit-message-rules-annex.md`](../how-to/commit-message-rules-annex.md)（**コミットメッセージ規約の詳細**）である。

| | |
| --- | --- |
| 既存の別紙が扱うもの | **書く側**の規約詳細（PR タイトル検査・bot 除外） |
| 本節が扱うもの | **生成物（CHANGELOG）を直す側**の仕組み（`changelog-overrides.json` の使い方） |

**読む場面が違う。** 前者は「PR を出すとき」、後者は「**過去コミットの誤記に気づいたとき**」である。
**1 ファイルに混ぜると「いつ読むか」が曖昧になり、別紙化の目的（読む量の制御）を損なう。**

### ★ 判断 3: **規範は入口に残す** —— 「履歴は書き換えない」

節の冒頭は**規範**である:

> トレーサビリティは**既存の git 履歴を書き換えないこと**を大前提とする。過去コミットの起点 ID
> やスコープに誤記があっても `rebase`／force push で修正してはならない。

[IADR-0173](../adr/IADR-0173_annex-extraction-keeps-heading-stubs.md) 決定 2 のとおり**別紙へ出さない。**
**誤記に気づいた人が最初に必要とするのは「直し方」ではなく「rebase してはいけない」**である。

> **★ `CLAUDE.md` の「破壊的な git 操作は行わない」と重複ではない。**
> あちらは一般則、**こちらは「誤記があっても」という例外の否定**である。
> **一般則だけだと「誤記の是正は正当な理由だ」と読まれうる。**

### 判断 4: **`paths` は使わない**

[IADR-0172](../adr/IADR-0172_required-rules-slimming-plan.md) 決定 5。**「CHANGELOG の誤記に気づいたとき」はファイルパスで表現できない。**
