## 判断

### ★★ 判断 1: **`.claude/rules/traceability.md` のパスは変えない**

**改名も移動もできない。** 軸 c のとおり **28 件のリンクが確定済みの記録から張られている**
（`docs/specs/` 22 ＋ `docs/adr/` の IADR 本体 6。**索引 `README.md` の 1 件は可変なので数に入れない**）。
`.claude/rules/traceability.md` 自身と [IADR-0166](../adr/IADR-0166_status-vocabulary-and-record-rewrite-boundary.md) が
**確定済みの記録の書き換えを禁じている**ため、**リンクを追随させる手段が無い。**

> **★ これは「やらない方がよい」ではなく「やれない」である。**
> パスを変えると `check-doc-links.js`（548 件を検査）が**確定済み記録 28 件で赤くなり、
> 直す方法が規約上存在しない**状態になる。

**したがって減量は「ファイルを分ける」のではなく、
**当該ファイルを入口として残し、中身を別紙へ出して指す**形でしか実現できない。**

### ★ 判断 2: **`paths` による絞り込みは、一部の節にしか使えない**

`paths` の絞り込みは実在する機構である（計画リポの `.claude/rules/adr.md` が
`paths: - "**/07_adr/**/*.md"` を使っている。実測）。

**しかし `paths` は「どのファイルを編集するか」でしか条件を書けない。**

| 節 | `paths` で表現できるか |
| --- | --- |
| 残す箇所と書式（コード内コメント） | **できる**（対象の拡張子・ディレクトリで絞れる） |
| **コミットメッセージの機械チェック** | **できない** —— **「コミットするとき」はファイルパスではない** |
| 起点 ID の種別 / ID 修飾 | **できない**（あらゆる編集で要る） |

**最大節（29%）に `paths` は効かない。** ここは**別紙化＋導線**で扱うほかない。

### ★ 判断 3: **削る前に、機械側にあるかを 1 つずつ突合した**

最大節「コミットメッセージの機械チェック」13,552B の規範と、対応する機械:

| 規範 | 機械 | |
| --- | --- | --- |
| 許可する種別 / 起点 ID の書式 / 末尾 PR 番号 | `check-commit-messages.js`（30,754B） | **機械が強制** |
| FR / UC / SC の実在性（#579） | 同上（レンジは `check-test-traceability.js` を再利用） | **機械が強制** |
| ADR / IADR の実在性 | 同上（submodule 未取得時は skip） | **機械が強制** |
| 検査対象から除外する自動コミット | 同上 | **機械が強制** |
| PR タイトル（スカッシュ後件名）の検査 | `.github/workflows/pr-title.yml` | **機械が強制** |
| クロスリポジトリの issue / PR 番号の修飾 | `check-cross-repo-refs.js`（44,198B。型 A のみ） | **機械が強制** |
| **採番衝突時の改番手順（4 項目の追随）** | **—** | **★ 人の手順。機械は無い** |

**この節はほぼ全部「機械が強制していることの説明」である。**
**ただし「採番衝突時の改番手順」だけは違う。** `check-adr-numbering.js` は
**欠番・重複は見るが「改番時に何を追随させるか」は見ない**（実測）。

> **★ 導線なしで別紙化すると統制が消える。** 機械が止めない規範を「参照時にだけ読む」場所へ
> 動かすなら、**「いつ読むか」を入口側に必ず残す。**

### 判断 4: **本 issue は計画の確定まで。実施は子 issue へ**

#623 基準 5 の文面は「**計画を立てる**（…**実施は子 issue に分割してよい**）」である。
**本 PR では 1 行も移動しない。** 段ごとの実施は子 issue が持つ。

> **★ 計画と実施を同じ PR に入れない**（[IADR-0116](../adr/IADR-0116_reimplementation-branching-and-pr-policy.md) 規約 1）。
> 移動は差分が大きく、**計画の妥当性と移動の正しさが同じレビューで混ざる。**

## ★ 明示する限界

- **別紙化しても総量は減らない。減るのは「毎セッション読む量」だけである。**
  基準 5 の目的（読み込み量の制御）とは合致するが、**「総量削減」と書くと事実と違う。**
- **50KB 目安への到達は本 issue では検証できない。** 移動していないため。
  **到達の確認は最終段の子 issue が持つ。**
- **「毎セッション必読」の集合は狭義を採った**（`CLAUDE.md` ＋ `traceability.md`）。
  **広義（参照文書も含む 132,685B）を採るなら計画ごと作り直しになる。** 根拠は IADR-0172 決定 1。
- **#622 の仕様書が書く「約 131KB」の内訳は復元できなかった。**
  広義の集合で当時 120 KiB まで再現したが**一致していない**。**再現できていないものを「再現した」と書かない。**
