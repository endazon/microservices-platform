> **★ 表は節全体（6,769B）と一致する。** 各行は行末の空行を含めた実測であり、**「合計 − 規範」で
> 出せる量を出していない**（#690 の 🟡 の教訓。見出しと空行を出せる側に数えてしまう）。

**出せるのは 1,790B。** 残りは規範である —— **ID を付け替えない ／ 旧 ID の隣に後継を置く ／

frontmatter を持たないファイルは注記 ID だけ ／ 母集合は live に限り確定済み記録は書き換えない。**
**いずれも書く側が事前に知らないと成果物が壊れる**（[IADR-0173](../adr/IADR-0173_annex-extraction-keeps-heading-stubs.md) 決定 2）。

[IADR-0172](../adr/IADR-0172_required-rules-slimming-plan.md) 決定 3 が「残す」と分類した `## 起点 ID の種別`（9,717B）の内訳:

## 判断

### ★★ 判断 1: **段 5 を追加し、総括を 1 段ずらす**

軸 b の実測により、**[IADR-0174](../adr/IADR-0174_slimming-projection-requires-stage4.md) 決定 2 と
[IADR-0175](../adr/IADR-0175_slimming-requires-claude-md-reduction.md) 決定 2 の「段 4 で尽きる」は誤りだった。**

**総括の時点だけを段 5 の後へずらし、「それまで `CLAUDE.md` に手を付けない」はそのまま維持する**
（[IADR-0176](../adr/IADR-0176_entry-slimming-recap-block-level-classification.md) 決定 3）。

> **★ ずらす代わりに「段 4 で総括してしまう」案は採らない。**
> **必要量は入口の残余 6,985B ぶんだけ動く。** 動く幅を残したまま `CLAUDE.md` を削ると、
> **削りすぎるか足りないかのどちらかになる。**

### ★ 判断 2: **導線は 1 本にまとめ、節末へ置く**

段 4 で出した 3 塊は**見出しを持たない**ので、[IADR-0173](../adr/IADR-0173_annex-extraction-keeps-heading-stubs.md) 決定 1 のスタブ義務は掛からない。
**塊ごとに導線を置くと 3 本ぶん入口が太る**ので、**節末に 1 本**にまとめた（3 行 / 469B）。

### 判断 3: **別紙は新規ファイル**（`docs/how-to/`）

既存 3 本とは**読む場面が違う**。本別紙は「**CI にこの検査を足せないか考えるとき**」
「**Superseded 引用の書式の射程を変えたいとき**」に読む。

### ★ 判断 4: **切り出した文の「下記」を別紙側で直した**

塊 B の原文は「（**下記のとおり** `docs/specs/` 等はそれで外れる）」であり、**下記** は入口の「母集合」段落を指す。
別紙では直後に来ないので「（**入口の「母集合」のとおり** …）」へ改めた。
**指示語の指す先が移動で変わる場合は、移動先で解決する**——原文のまま運ぶと**別紙の中で宙に浮く。**

### 判断 5: **`paths` は使わない**

[IADR-0172](../adr/IADR-0172_required-rules-slimming-plan.md) 決定 5。**「Superseded な ADR を引くとき」はファイルパスで表現できない。**

## 着地の実測

**commit 基準: develop `f905d3b` からの差分。**

| | 実測 |
| --- | ---: |
| 入口 `.claude/rules/traceability.md` | **35,811 → 34,490B**（**−1,321**） |
| `CLAUDE.md` | 23,524（変更なし） |
| **必読合計** | **59,335 → 58,014B** |
| 別紙 `docs/how-to/adr-supersede-citation-annex.md`（新規） | 4,245B |
| **50,000 まで** | **8,014** |

**切り出した 3 塊は 1,790B、着地は −1,321B。** 差 **469B** は**入口へ残した導線 3 行**である。

**見込みとの差**: [20260811_issue-691](./20260811_issue-691_id-qualification-annex.md) は
「段 4 も段 3 と同じ規範比率（32%）なら実効 約 −2,000B」と見込んでいた。
**実測の規範比率はより高く**（出せたのは節 6,769B のうち 1,790B = **26.4%**）、**実効は −1,321B** であった。
**見込みは 679B 過大**である。

### ★★ 総括の下ごしらえ —— **入口を尽くしても 50,000 に届かない（上限側の実測）**

| | バイト |
| --- | ---: |
| 50,000 までの不足（段 4 着地後） | 8,014 |
| **入口に残る識別済みの候補**（軸 b の 3 塊） | 6,985 |
| **差** | **1,029 不足** |

**上表は導線を 1 バイトも残さないという、実現しない仮定での計算である。**
**実際には段 1〜4 のいずれも導線を残しており**（段 3 は 503B、段 4 は 469B）、**差はさらに開く。**

**→ `CLAUDE.md` から出す必要があるのは 1,029B 以上**である
（[IADR-0176](../adr/IADR-0176_entry-slimming-recap-block-level-classification.md) 決定 4）。
**上限は段 5 の着地で確定する**（同 決定 3）。

> **★ 「1,029B 以上」は下限であって必要量ではない。**
> 段 5 の 6,985B が**すべて出るとは限らない**——本段でも、候補として挙げた塊は全部出たが、
> **候補の選定そのものが節の 26.4% しか拾えなかった。**
> **必要量の確定は段 5 の後**（[IADR-0176](../adr/IADR-0176_entry-slimming-recap-block-level-classification.md) 決定 3）。
