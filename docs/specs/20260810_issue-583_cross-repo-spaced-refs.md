## 判断

### 判断 1: **本物の 1 件を是正する**

`.github/workflows/doc-links-planning.yml:6` の `ai-stock-trading #104` → **`AST#104`**。

### ★ 判断 2: **検査対象を `.md` 外へ広げ、除外は `scripts/` の 1 本にする**

**名指しの除外リストにしない。** 実測すると、名指しは
`check-cross-repo-refs.js` → `scripts.repo.test.js` → `changelog-overrides.json` と**3 つに膨らみ**、
**次に検査器を足したら静かに古くなる**（本リポが繰り返してきた型そのもの）。

**`scripts/` を丸ごと除外する。** 理由:

- **`scripts/` は検査器・そのフィクスチャ・baseline / overrides が住む場所**であり、
  **違反の文字列を書くことが仕事**である
- **人が読む散文は `docs/`（`.md`。既に対象）・`.github/`・`deploy/` にある** ——
  #583 が「散っている」と書いた先もそこである

**この除外で、走査対象は追跡ファイル 1574 件から `scripts/` の非 Markdown 61 件を引いた 1513 件になり、
是正後の違反は 0 件になる**（`.md` だけだった従来は 619 件）。

#### ★★ 例外: **`scripts/` の `.md` は除外しない**（初版の回帰を是正した）

**初版は `scripts/` を丸ごと外し、`scripts/README.md` を走査対象から落としていた**
（PR #679 レビュー 🟡）。**是正前は見えていたファイル**であり、
**「広げる」変更が同時に狭めていた。** 落ちた `.md` は**全数で 1 件、違反 0 件**。

**実害は出ていないが直す。** `scripts/README.md` は**人が読む散文**であり、
判断 2 が「対象に残す」と書いた側そのものである。
**`.md` は引用がインラインコード除外で守られる**ので、除外の根拠がそもそも当てはまらない。

**「ディレクトリ 1 本」の形は保つ** —— 例外は「拡張子 `.md` は常に対象」の 1 行で、
**ファイルを名指ししない。**

> **★ レビュー指摘の事実関係は自分で引き直した。** 指摘は
> 「`scripts/README.md` は `AST#24` / `planning#148` 等の参照を**多数含む**」と書いたが、
> **検査器の判定式で数えると違反は 0 件**である（含まれているのは**正しい詰めた形**）。
> **回帰そのものは実在する**が、**「見逃していた違反がある」わけではない。**

### ★ 判断 3: **除外の限界を書く**（黙って飛ばさない）

**`scripts/` の中の「コード中コメント」に本形が書かれても検出しない。** これは既知の限界である。
（**`scripts/` の `.md` は検査する** —— 判断 2 の例外。限界は非 Markdown に限る。）

**「検査していない」と「違反 0 件」を読み分けられるようにする**（#546 / #664 / #674 の型）——
**検査器は除外した件数をログに出す。**

### 判断 4: **`.md` の除外（インラインコード・フェンス）は `.md` 外へ持ち込まない**

`.yml` / `.js` / `.json` に「インラインコード」の概念は無い。
**`--markdown` の除外は `.md` にだけ効く**という現状を変えない。
**`scripts/` の除外（判断 2）が、その役割を代わりに果たす。**
