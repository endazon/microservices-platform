# 作業仕様書: 環流記録の `status` 追随と突合検査（#737）

## 起点

- **NFR**（文書統制。**当たる番号が無い＝場合 ②** なので無採番・環流しない。[IADR-0179](../adr/IADR-0179_unnumbered-nfr-for-meta-work.md) 決定 1）
- 起点 issue: **#737**。実装 ADR: **[IADR-0193](../adr/IADR-0193_feedback-status-sync-check.md)**

> **★ 値の基準時点は develop `bed8a6e` / planning `main` = `130a109`（2026-08-14 実測）である。**

## ★★ 母集合 —— 実測で引いた

### 軸 a: **`feedback/*.md` を全数で突合した**（`README.md` / `TEMPLATE.md` を除く）

| | 件数 |

### ★ 軸 b: **不一致 16 件の内訳を読んだら、2 種類あった**

**「不一致＝陳腐化」ではなかった。**

| 種別 | 件数 | 内容 |

> **★ 記録ファイル経路と GitHub Issue 経路は等価である**（`feedback/README.md` §経路ごとの証拠。planning#319）。
> **計画側 `draft/feedback/` に写しが無いことは、伝達していないことを意味しない。**
> **検査器がこれを不一致として数えたら、恒久的な偽陽性が 3 件残る。**

| **#504 の取り下げと計画側の裁定が別語になった** | **1** | `20260709_sc11-wireframe-drawio`（実装 `rejected` / 計画 `accepted`） |

**10 件すべて、計画側の裁定は #721 のマージ（2026-08-15 02:35 JST）より前に下りている**（実測）。

### ★ 軸 d: **`20260709_sc11` は結論が一致しており、食い違っているのは語だけである**

**`status` は計画側の裁定を表す**（planning#323 / [IADR-0187](../adr/IADR-0187_status-vocabulary-follows-upstream-adjudication.md) 決定 1）**のだから、語は計画側に合わせる。**
**陳腐化した `status_note`（「計画側原典は open（planning 未追随）」）は、当時は正しく、いま偽である。**

## 判断

### ★★ 判断 1: **#721 が確かめた軸が旧語彙のものだった、と原因を記す**

**[IADR-0187](../adr/IADR-0187_status-vocabulary-follows-upstream-adjudication.md) 決定 2 は移行前に「本当に伝達済みか」を全数で確かめている。**
**確かめたのは `dispatched` の軸であって、`status` の軸ではない。**

> **★ 語彙を差し替えるときは、値だけでなく「何を確かめるか」も差し替わる。**

### 判断 2: **突合は機械検査にする。今回が同型 2 回目である**

| # | 同型の事故 |
| --- | --- |
| 1 | **AST#477 / `AST/IADR-0188`** —— 実装側 18 件が `open`、計画側は `accepted`（**同じ向き・同じ原因**） |
| 2 | **本件** —— 本リポで 10 件 |

**`feedback/README.md` が「この語彙を検査する機械は無い。値の誤りは沈黙する」と明記していた**ところの、その沈黙である。

### 判断 3: **写しが無い記録を不一致にしない。ただし黙って捨てない**

**両経路が等価である以上、写しの不在は正常である。** **件数を出力に出し、突合できた件数が 0 なら fail する**（#664 の門）。

### 判断 4: **pin を前進させる。前進に伴う追随の要否を先に実測する**

**#721 は pin だけ進めて追随を伴わなかった。** 本 PR は逆に、**追随のために pin を進める必要がある**
（`20260709_sc11` の裁定は `130a109` で入ったため、pin が `915981a` のままだと検査が観測できない）。

| 確かめたこと | 結果 |
| --- | --- |
| `tools/impl-handoff-kit/` の差分 | **空** —— **キット追随は不要** |
| `projects/microservices-platform/` の差分 | **空** —— **ID レンジの引き直しは不要**（`.claude/rules/traceability.md` は触らない） |

### 変異試験（5 変異すべて検出）→ **`--self-test` として恒久化した**

| # | 変異 | セッション中 | **CI 恒久** |
| --- | --- | --- | --- |
| R1 | **記録の `status` を計画側と食い違わせる**（追随漏れの本体） | ✅ | ✅ |
| R2 | 記録 0 件（走査が空振り） | ✅ | ✅ |
| R3 | **突合できる写しが 0 件**（検査が実質何も見ない） | ✅ | ✅ |
| R4 | **写しを持たない記録を不一致に数える**（偽陽性を作る） | ✅ | ✅ |
| R5 | 索引を記録として数える | ✅ | ✅ |

> **★ R4 は全体実行では「突合が実際に回っている」テスト（先に走る）が発火した。**
> **「検出した」ことと「狙った検査が検出した」ことは別**（#713 の教訓）なので、
> **狙ったテストの判定式だけを単独で評価し直して確かめた。**

#### ★★ 当初は「手で変異させた」だけで、CI には恒久化されていなかった（#738 レビュー 🟡）

**最初にコミットしたテストは、実データに対して `main()` が 0 を返すことしか見ていなかった。**
**全記録が同期している限り、`implStatus !== planStatus` を `===` に取り違えても緑のままである。**
R2〜R5 も**ソース文字列にガード文言が含まれるか**という静的検査にとどまっていた。

> **★ 「変異試験で検出を確認した」と PR に書けるのは、その変異を CI が拒むときだけである。**
> **セッション中に手で確かめたことは、次の変更を守らない。**

**是正**: `compare(implDir, planDir)` を**経路を引数に取る形へ分離**し、
**`--self-test` が R1〜R5 を fixture で駆動する**ようにした（本リポの既存イディオム。
`check-plan-id-qualification.js` 等が同じ形を採っている）。**自己試験 10 件。**

**さらに、自己試験そのものが利くことを回帰テストで固定した** ——
`scripts.repo.test.js` が**`!==` → `===` を注入した変異体を一時ファイルへ書き出し、
自己試験が非 0 で落ちることを確かめる**（落ちなければテストが失敗する）。

**`--self-test` は fixture で駆動するため `planning` 未 populate でも実効する** ——
**実データ走査が skip される CI でも、この 1 本だけは必ず何かを検査している。**

### 規則 8 で引き直したもの

**「34 本」「この語彙を検査する機械は無い」で全追跡ファイルを走査した。**

| ファイル | 判定 | 対応 |
| --- | --- | --- |
| `scripts/scripts.repo.test.js` の検査器ラチェット | **偽になる**（34 本） | **35 へ前進させた**（宣言を促す設計どおり） |
| `feedback/README.md` | **偽になる**（「この語彙を検査する機械は無い」） | **`status` の突合だけが検査される旨へ改めた。値そのものの妥当性が沈黙することは残るので、そちらは残した** |
| `scripts/kit-sync-classification.json` の `feedback/README.md` | **不足になる**（デルタが 1 つ増えた） | **種別 3（本リポにしかないスクリプトの説明）を併記した。先頭の番号は 2 のままなので内訳 1:4 / 2:1 / X:13 は不動** |
