## 判断

### ★★ 判断 1: **50KB は入口の別紙化だけでは届かない**

**段 3 の実効は約 −2,700B**（2,898 − 導線約 200）。**[IADR-0174](../adr/IADR-0174_slimming-projection-requires-stage4.md) の見込み（段 3 後 約 52,766B）は、節 9,117B が丸ごと出る前提だった。**

**実測では 32% しか出ない。**

**段 4（「残す箇所と書式」6,768B）が同じ規範比率なら実効は約 −2,000B。**
**着地は約 57,335B で、50,000 まで約 7,335B 不足する。**

**→ `CLAUDE.md`（23,524B）の減量が「想定」から「確定事項」になる**（[IADR-0175](../adr/IADR-0175_slimming-requires-claude-md-reduction.md) 決定 1）。

> **★ 段 4 の規範比率は未実測である。** 上の「同率仮定」は**計算であって実測ではない**。
> **段 4 の着手時に測る。**

### ★ 判断 2: **ADR に可変の数値を断定させない**（#690 の反省）

**[IADR-0174](../adr/IADR-0174_slimming-projection-requires-stage4.md) は入口ファイルのサイズを本文へ書いた。**
**その ADR 自身を編集するとサイズが変わり、自分の記述が古くなる** —— 自己参照的で構造的に不安定である。
**実際にレビュー 3 巡ぶんの是正を要した。**

**[IADR-0175](../adr/IADR-0175_slimming-requires-claude-md-reduction.md) では:**

| | |
| --- | --- |
| **測り方（コマンド）を書く** | 誰でも今の値を出せる |
| 数値を書くときは | **「commit `8cd47a3` 時点の実測」と基準を明記** |

**作業仕様書の §着地の実測 は時点の記録なのでそのままでよい。**

### 判断 3: **別紙は新規ファイル**（`docs/how-to/`）

既存 2 本（`commit-message-rules-annex.md` / `changelog-overrides-annex.md`）とは**読む場面が違う**。
本別紙は「**他プロジェクトの ID / 番号をどう書くかで迷ったとき**」に読む。

### 判断 4: **`paths` は使わない**

[IADR-0172](../adr/IADR-0172_required-rules-slimming-plan.md) 決定 5。**「他リポの番号を書くとき」はファイルパスで表現できない。**
