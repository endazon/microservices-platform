### ★ 実害は「無認証で投稿できる」だけではない

`FeedbackEndpoints.cs:44` が **`userId = http.User.Identity?.Name ?? "anonymous"`** としており、
`FeedbackDbContext.cs:25` が **`(AnswerId, UserId)` にユニーク索引**を張っている。

**この 2 つが噛み合うと、無認証の投稿は全員が `"anonymous"` という 1 行を共有する。**
すなわち**無認証の投稿者どうしが互いの評価を上書きし合う**——「1 利用者 1 件」の upsert が、
匿名に対しては「**全匿名で 1 件**」として働く。指標の汚染に加えて**他人の投稿の改変**にあたる。

**コード自身がこの是正を #521 の担当と明記している**（`FeedbackEndpoints.cs:38-43` の
`［2026-08-07 / #586］` 追記。「**是正は #521 が持つ**——`RequireAuthorization` の追加は挙動の
変更であり、独立した PR とテスト（401）が要る」）。

### 軸: 誰がこの口を呼ぶか / 誰がこの応答を読むか

- **投稿**: SC-01 の画面（認証済み利用者）。**匿名の機械クライアントは想定しない**（計画が明記）。
- **統計**: SC-10 の運用ダッシュボード。#544（PR #648）で**画面の閲覧ロールは運用者へ開いてある**
  ので、統計 API もそこへ揃える（計画 `05_screens:431` が「本画面全体の閲覧ロールと揃える」と明記）。
- **画面側の追随は不要**と見込むが、**SC-01 / SC-10 が無認証を前提にしていないか実測してから確定する**。

## 判断

### 判断 1: **両層**で塞ぐ（[[IADR-0044]] 多層防御）

BFF だけに付けると、サービスへ直接到達できる経路（クラスタ内・将来の別クライアント）が空いたままになる。
`GET /feedback`（一覧）が既に `AdminOnly` を持つのに `stats` と `POST` だけ無い、という**同一ファイル内の
不揃い**でもある。

### 判断 2: 投稿は「**認証のみ**」でありロールを要求しない

計画は「**認証を要する**（匿名投稿は許さない）」であって、ロールの限定は書いていない。
**書かれていない制限を足さない**——一般利用者がフィードバックを送れなくなると FR-08 が成り立たない。
`RequireAuthorization()`（ポリシー無し）を使う。

### 判断 3: 統計は **admin ＋ operator**

計画 `05_screens:431`。BFF は群に `RequireAuthorization()`（認証）を、`/stats` に
`RequireRole(Admin, Operator)` を重ねる——[[IADR-0128]] 決定 1 の **AND 合成**で実効は admin ＋ operator。
**#647 の検査器がこの形を解けることは実装済みで確認済み**（群 × 端点の積）。

### 判断 4: `anonymous` フォールバックは**消す**

`RequireAuthorization` を付ければ到達しないが、**残すと「認可を外したときに静かに匿名共有へ戻る」**。
[[IADR-0039]] 決定 3（無認証 401）と揃え、`Identity.Name` が無ければ 401 相当で弾く。

### 判断 5: 保留 —— 既存の `"anonymous"` 行の扱い

**本 PR では移行しない。** 既存データに `userId = "anonymous"` の行が残り得るが、
**データ移行は別の資源**であり（[[IADR-0139]]）、本番データの有無も把握していない。
**申し送りに残し、必要なら別 issue を起票する。**

## テスト（受け入れ基準の写像）

計画の受け入れ基準（`02_requirements:209-210`）をそのまま写す。

| # | 受け入れ基準 | テスト |
| --- | --- | --- |
| 1 | **投稿端点が無認証で 401** | BFF・Service の両層 |
| 2 | **統計は認証済みでも運用者・管理者以外は 403** | 両層。一般利用者で 403 |
| 3 | 運用者・管理者は統計を取得できる | 権限別の**対**で固定 |
| 4 | 認証済み利用者は投稿できる | 退行防止（狭めすぎていないこと） |
| 5 | 同一利用者の 2 回投稿が 1 件のまま | **既存実装で満たされている**ことを確認する回帰 |
| 6 | `x-roles` と実効ロールが一致する | `check-bff-authz-docs`（#647）が CI で見る |

**変異試験**: 各 `RequireAuthorization` を外すと対応するテストが落ちることを実測し、復旧後に緑を確認する。
