### ★ 判断 2: **保留理由が環境観測だったものは、それが失効したことを記録へ残す**

**「起票した」だけ書いて理由を消さない。**
**なぜ 4 日据え置かれたのかが消えると、同じ据え置きが再発しても気づけない**（IADR-0180 決定 2）。

### 判断 3: **`status` は `triaged` にする。語彙の定義には踏み込まない**

**`feedback/README.md` は手順を書くが、`open` / `triaged` / `accepted` / `rejected` の意味を定義していない。**
値域は #700 の検査器が固定しているだけである。

**本作業は「起票済みだが裁定前」を `triaged` と読む**（2026-08-11 に planning#312 / planning#313 で採った読みと同じ）。
**定義の新設は別 issue とする** —— **規約が無いものを 37 件へ一括適用しない**
（#706 で `related_ids` について同じ判断をした）。

### 判断 4: **実装 ADR を作らない**

**新しい判断をしていない。** 既存の決定（`docs/README.md` 運用ルール 5 / IADR-0180 / IADR-0115）を
**そのまま適用しただけ**である。**適用のたびに ADR を作ると、決定と実施の区別が消える。**

### ★★ 判断 5: **本作業中に「偽の緑」を踏んだ —— #683 の実例として記録する**

**本書を新規作成した直後に検査器を全数走らせ、すべて OK を得た。**
**しかしその時点で本書は `git add` 前であり、走査対象に入っていなかった。**

`check-cross-repo-refs.js` は走査対象を **`git ls-files`（追跡下）** から引く。
**untracked のファイルは存在しないのと同じ**であり、**違反があっても緑が返る。**

**実際に本書には「列挙形の修飾漏れ」が 3 箇所あった**（`planning#314 / #315 / #316` 等）。
**気づけたのは `check-commit-messages.js` がコミット本文の同じ形を検出したからで、
ファイル側の検査器は最後まで緑だった。**

> **★ 検査器に欠陥は無い。** `git add` 後に走らせ直すと**同じ 3 箇所を正しく検出する**（実測・陽性対照）。
> **欠陥は検証の順序**にある —— **新規ファイルを作った回は、`git add` してから検査器を走らせる。**
>
> **これは #683「差分ベースの検査器がコミット前実行で偽の緑を返す」と同じ根であり、
> 本作業で planning#316 へ環流した知見 1（「新設直後は untracked なのでローカルでは見えず、
> コミット後の CI で初発火する」）そのものである。** —— **環流した当人が同じ日に踏んだ。**

**本 issue では検査器を変更しない**（#683 の射程）。**実例として記録するに留める。**
