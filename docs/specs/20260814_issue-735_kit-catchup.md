## ★★ 自分のコミット本文が同じ規約に落ちた

### ★ allowlist では解けなかった —— **squash マージとは構造的に噛み合わない**

**最初は `scripts/commit-allowlist.json`（category B）へ登録した。** 同ファイルの説明が
「プッシュ済み・force push 禁止のため書き換えられないコミット」を対象と述べており、字面は一致する。

**しかし CI が落ちた。** 同ファイルの規約 2 が
**「各エントリは git 履歴に実在し、統合ブランチから到達可能であること（rebase 後の幻 SHA を残さない）」**
を求めており、`scripts.test.js` がこれを機械検査するためである。

| 状態 | `commit-messages` | `scripts-tests`（幻 SHA 検査） |
| --- | --- | --- |
| entry あり | **緑**（skip される） | **赤**（develop から到達不能） |
| entry なし | **赤** | 緑 |

> **★ 本リポは squash マージである。** **PR ブランチのコミット SHA は develop へ載らない** ——
> **したがって PR ブランチ上のコミットを allowlist へ入れると、マージ後に必ず幻 SHA になる。**
> **allowlist が対象にできるのは「既に統合ブランチに在るコミット」だけである。**

**両立しないことを実測で確かめたうえで、利用者の裁定により件名・本文を書き換える方を採った**
（対象は未マージの自ブランチのみで、共有履歴を壊さない。2026-08-14）。
**allowlist は汚さずに済んだ。**

**なお squash マージでは、この本文自体が develop へ載らない** ——
**統合ブランチに残るのは PR タイトル ＋ マージ時に書く本文である。**

### ★ `pr-size.yml` で踏みかけた誤り

**固有デルタの説明を `EXCLUDES: >-` の折りたたみスカラーの中へ書こうとした。**
**YAML の折りたたみスカラーでは `#` はコメントではなく値の一部**であり、
**そのままだとコメント行が pathspec に混ざって除外が黙って壊れる。**

**キー宣言の外（`env:` 直下のコメント）へ移し、`EXCLUDES` の実値を組み立てて `#` が入っていないことを確かめた。**
**回帰テストで固定した**（この型は目視では気づきにくい）。

### ★★ 規則 7 を守らず、撤廃した上限を 2 箇所に残した（#739 レビュー 🔴）

**巡数の上限を撤廃しておきながら、`docs/DEFINITION_OF_DONE.md` に上限がそのまま残っていた。**
