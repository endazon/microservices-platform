# 作業仕様書: required status check の設定手順（#705）

## 起点

- **NFR**（運用保守。**メタ作業なので無採番**。[IADR-0179](../adr/IADR-0179_unnumbered-nfr-for-meta-work.md) 決定 1）
- 起点 issue: **#705**（**#623 の子**・受け入れ基準 **3**）。実装 ADR: **[IADR-0182](../adr/IADR-0182_required-check-contexts-and-blocked-record.md)**

> **★ 値の基準時点は develop `5933894` / planning pin `2cf0795`（2026-08-11 実測）である。**

## ★★ 母集合 —— 3 軸で引いた

### 軸 a: **手順書は既に在る。新設ではなく是正である**

`docs/operations/` に該当の Runbook は無いが、**`docs/ai-workflow.md` §「必須チェックの有効化」が既に手順を持つ**
（UI 経路・推奨する必須チェック・`paths:` フィルタの注意・bot スキップの扱い）。

**新しい手順書を作らない。** 作れば**同じ内容が 2 箇所**になり、
[IADR-0141](../adr/IADR-0141_audit-rounds-and-population-drawing.md)（単一情報源）に反する。**既存節を正す。**

### ★★ 軸 b: **推奨されている必須チェック名の半分は、そもそも存在しない**

PR #704 が report した **check 名 28 件を全数**で引き、既存節の推奨と突き合わせた。

| 既存節が「必須に」と挙げるもの | check として実在するか |
| --- | --- |
| **`CI`** | **存在しない**（`ci.yml` の**ワークフロー名**にすぎない） |
| **`Security`** | **存在しない**（`security.yml` の**ワークフロー名**） |
| `image-build` | 実在する |
| `pr-title` | 実在する |
| `CodeQL` | 実在する（`Analyze (csharp)` とは別の集約 check） |

**GitHub の従来型ブランチ保護が要求するのは「check の名前」であり、「ワークフローの名前」ではない。**
`ci.yml` が report するのは `build-and-test` / `lint` / `doc-links` … という**ジョブ側の名前**である。

> **★ 手順書どおりに設定すると develop が恒久的にマージ不能になる。**
> **`CI` という名の check は永久に report されないので、必須指定は永久に pending のままになる。**
> **同じ節が 12 行下で「`paths:` フィルタ付きを必須にすると永久 pending になる」と警告している** ——
> **原因は違うが結果は同じ事故**であり、**警告文の側が原因を `paths:` に限定して書いていた。**

### ★★ 軸 c: **`claude-review` を今のまま必須にすると、再オープンした PR が詰む**

`pull_request` で起動する全ワークフローの `types:` を**全数**で引いた。

| | 件数 |
| --- | ---: |
| `reopened` を含む | **8** |
| **含まない** | **1**（**`claude-code-review.yml` だけ**） |

**再オープンされた PR では `claude-review` が report されない。**
**必須にすれば、その PR は永久にマージできない。**
**キットの `claude-code-review.example.yml` も `[opened, synchronize]` であり、これは継承した欠陥である。**

## 判断

### ★★ 判断 1: **設定変更そのものは blocked:human。ただし「できない」の中身を分けて書く**

**「できない」と書く前に実測した**（[IADR-0180](../adr/IADR-0180_blocked-judgments-expire.md) 決定 1）。

| 経路 | 実測（**2026-08-11**） | 種別 |
| --- | --- | --- |
| MCP の GitHub ツール | branch protection / ruleset を扱うツールが**無い**（`ToolSearch` を 2 通りの語で全数確認） | **能力の不在** |
| `gh` / `hub` CLI | **どちらも入っていない**（`command -v`） | **能力の不在** |
| GitHub API を直接叩く | **セッション指示が禁じている**（GitHub 操作は MCP ツール経由に限る） | **規則による禁止** |

> **★ 3 つ目は能力ではない。** **能力の不在と規則の禁止を混ぜて「できない」と書かない** ——
> **前者は環境が変われば消え、後者は指示が変わらない限り残る。**
> **再検証の手順と「最後に測った時点」を添える**（IADR-0180 決定 2）。

### ★ 判断 2: **手順書は新設せず、`docs/ai-workflow.md` の既存節を正す**

**別紙も Runbook も作らない**（軸 a）。**正すのは 4 点**である。

1. **`CI` / `Security` を実在する check 名へ置き換える**（`build-and-test` / `lint` ほか）
2. **`build-and-test` と `claude-review` を明記する**（`#623` 基準 3 が名指ししている）
3. **API 経路を併記する**（UI しか書かれていない）
4. **「推奨設定」であって「現在そうなっている」ではないことを明示する**

> **★ 4 点目は planning の裁定（2026-08-08 / planning#286）そのものである** ——
> **「統制を定めた」と「統制が働いている」が同じ文書内で読み分けられない書き方をしない。**
> 既存節は「これにより……マージされない」と**断定**しているが、**実際には配備されていない**
> （本 PR までの全 PR が、承認レビュー無しでマージできている）。

### ★★ 判断 3: **`claude-review` を必須にできる状態にしてから、必須候補として書く**

`claude-code-review.yml` の `types:` へ **`reopened` を足す**（1 行）。

**これは文書ではなく前提条件の是正である。** **足さずに「必須にせよ」と書けば、
手順書どおりにした人が詰む** —— 軸 b で見つけた誤りと**同じ型の被害**を、こちらは書く前に潰せる。

**他の 8 ワークフローはすべて `reopened` を持つ**ので、揃えるだけで例外が無くなる。

### ★ 判断 4: **必須にできるのは「レビューが走ったこと」であって「指摘が無いこと」ではない**

`claude-review` は **🔴 の指摘があっても exit 0 で success を返す**（判定は人＝本セッションが行う）。
**必須にして担保できるのは「レビューが完走した」ことだけ**である。

**`#623` の文言は「claude-review **完了**」であり、これと一致する。**
**「必須にすれば 🔴 が止まる」と読まれないよう、手順書に明記する。**

### ★★ 判断 5: **検査器を足す —— 同型 2 回目の条件を満たした**

**「必須にすると永久 pending になる」型の事故は、これで 2 件目**である。

| # | 原因 | 出所 |
| ---: | --- | --- |
| 1 | `paths:` フィルタで起動しない | 既存節の警告（**文書のみ**） |
| 2 | **`types:` に `reopened` が無く再オープンで起動しない** | **本 issue の実測** |

`CLAUDE.md`「**検査器・規約の追加は同型の事故が 2 回起きたら**」の条件を満たす。
**`pull_request` で起動する全ワークフローが `reopened` を含むことを回帰テストで固定する**
（実測で **8 / 9** が既に満たしており、1 件直せば 9 / 9 になる）。

> **★ `paths:` の側は検査器にしない。** `frontend.yml` などは**意図して** `paths:` を持ち、
> **必須にしないことで正しく運用されている**。**機械的に禁じると正当な設定を壊す。**

### 判断 6: **キットへ環流する（2 件）**

| # | 内容 |
| ---: | --- |
| 1 | `docs/ai-workflow.md` の必須チェック名が**ワークフロー名になっている**（`CI` / `Security`） |
| 2 | `claude-code-review.example.yml` の `types:` に **`reopened` が無い** |

**どちらもキット由来**であり、**他の実装リポも同じ地雷を踏む。**
