# 仕様書: 引継資料の環境前提を「実測の手順」へ改める

## 起点となる ID（トレーサビリティ）

- 起点 issue: **#617**（親 #454）／起点 ID: **NFR**
- 対象: [`docs/how-to/session-handoff.md`](../how-to/session-handoff.md)（#613 で新設・#615 で是正）
- 分類（[[IADR-0141]] 決定 4 ＝ **監査強度**の分岐）: **記録の追随のみ**
  → **全面 1 巡で打ち切り**（決定を 1 つも作らず、既存の決定と現状を指すだけ）

## 問題

§4.5「**この実行環境でできないこと（実測）**」が、**環境固有の観測**を
**恒久的な制約**として書いていた。§2 には「必ず古くなる」という但し書きがあるが、
**§4.5 には無く**、むしろ「陳腐化しにくい節」の側に置かれていた。

**実害が出た** —— §2 は #554 / #556 / #562 の 3 件を「**AI だけでは完結しない**」として保留し、
フェーズ B を打ち切る根拠にしていた。**3 件とも別環境では実施でき、同日中に着地した**
（#616 / #618 / #619）。

## やったこと

1. **§4.5 を全面改稿**。表題を「この実行環境でできないこと」→「**環境によって変わること —— 着手前に自分で実測する**」へ。
   **能力の一覧ではなく実測の手順書**にした（4 項目それぞれに**実測コマンドと期待出力**を書いた）。
   あわせて実測で判った副次的な事項（`pnpm` が PATH に無いときの `npx --yes pnpm@<版>` 代用、
   Playwright のブラウザ取得）を添えた。
2. **§4.5 の末尾に §3 との切り分けを明記**。「環境に依って変わること（§4.5）」と
   「どの環境でも破らないこと（§3）」を**同じ表に混ぜない**。
3. **§2 のフェーズ B を「完了」へ**更新し、**なぜ一度打ち切られたか**を残した
   （状態だけ直すと同じ判断が再発する）。
4. **§5 型 8 へ「第 3 の形」として追記**。**型 9 として独立させなかった** ——
   型 8 は「限界の言明を誤る」型そのものであり、分けると**同じ教訓を 2 箇所に持つ**（型 3）ため。
   issue は「型 8 に畳むか独立させるか判断せよ」と求めており、**畳む方を選んだ理由を書いた**。
5. **§6 から「#562 の CI 結線」を解消済みとして取り消し線**にし、
   **論点として登録したこと自体が型 8 の第 3 の形だった**と明記した。
6. **§7 を書き換え**。「`gh` は使えない」という断定を消し、**手順 1 を「§4.5 の 4 つを実測せよ」**にした。
   shallow クローンの注記も「環境による」へ改めた（full clone では通常どおり ff-merge できる）。
   手順 4 を**フェーズ C** へ更新し、**手順 2 の参照違い（「§2 の検査器」→「§4 の検査器」）も直した**。
7. **［#621 レビュー 🟡 を受けて］§4.5 から実測値の直書きを外した。**
   E2E の期待出力を `13 passed` と書いていたが、**これは本書自身が §5 型 3 で戒めている型そのもの**
   （条文へ実測値を埋めると、テストを 1 本足しただけで黙って古くなる）である。
   **改稿した当の節で踏んでいた。** `全件 passed（failed 0）` へ緩めた。
8. **［同 🟡］`gh` が無い環境でも `workflow` スコープを測れるようにした。**
   表 2 行目の実測が 1 行目（`gh` の有無）に暗黙依存しており、**`gh` が無いと 1 項目だけ実測不能**
   のまま残っていた。**捨てブランチで実際に push してみる**手順を併記した
   （拒否は push の時点で起きるので、これが唯一の確実な判定である）。
9. **［#621 レビュー 🟡 の引き直しで判明］§3 から「`.github/workflows/` は編集できない」を外し、
   §4 の冒頭を書き換えた。** §3 は**絶対に破らない制約**の節であり、
   認証に依る観測（`workflow` スコープの有無で変わる）を置く場所ではない。
   **同じ言明を §3（恒久）と §4.5 の表 2 行目（環境依存）の両方へ置いていた**ため、
   型 8 第 3 の形と型 3 を同時に踏んでいた。§4 の冒頭「編集できないため相乗りしている」も
   「**既存の結線の由来**であって新しい検査への制約ではない」という書き方へ改めた
   （#562 が実際に `frontend.yml` へジョブを足している）。
   **[[IADR-0140]] 決定 2 は point-in-time の記録なので改めない。**
   なお `CLAUDE.md` は **#163（`a967f59`）以来**「GitHub App 権限では編集不可／ワークフロー変更は
   ローカルの `workflow` スコープでコミット・プッシュする」と**代替手段まで含めて**書いており
   （`git log -L165,165:CLAUDE.md` で実測）、**本書がその片側だけを写して断定にしていた**のが誤りだった。
