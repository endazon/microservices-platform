### ★ 🔴 は「この PR 自身が、自分の入れた規約の逆をやった」型である

#612 は **「スカッシュ件名から ID を落とすな」という検査と条文を入れた PR** である。
その同じ PR の着地件名が、**実体を伴わない ID を足していた**。

**条文が片側しか書いていなかった**（「落とすな」だけで「足すな」が無かった）。
**穴を作った条文を書いた PR 自身が、その穴を踏んだ。**

**機械では捕まらない** —— `check-landed-subjects.js` が見るのは**実在性**であり、
`FR-12` / `SC-07` はどちらも実在するので通る（実測: 着地件名 319 件で違反 0）。
**落とした ID も足した ID も、機械は同じ理由で見られない。**

### 🟡-3 について —— 監査対象の母集合も引き直すべきだった

## ［2026-08-08 追記 / #615 レビュー 🟡］自分の規則に自分で反していた

**是正として足した `scanPrecondition` の変異試験 3 件が、浅いクローンでは偽の失敗で落ちた。**

原因は `scanPrecondition` が **`git rev-parse --is-shallow-repository` というアンビエントな環境状態を
先に見る**こと。浅いクローンでは `skip` が返り、**変異試験が本来検証したい merge-base の分岐へ
一度も入らない**。CI は `fetch-depth: 0` なので通るが、**ローカルで叩いた開発者には
「テストが壊れている」と見える**。

**これは偽陽性である。** 私自身が §5 型 5 に「**検出漏れは開示してよいが偽陽性は必ず塞ぐ**
（他人の PR を止めるため）」と書いた直後に、同じ規則へ反した。

**是正**: `scanPrecondition(baseline, ref, opts)` の `opts.isShallow` で注入できるようにし、
自己試験は環境を見ない。**副産物として skip 側の分岐も初めてテストで踏めるようになった**
——「浅いクローンなら skip」は実装にあるだけで、**誰も確かめていなかった**（自己試験 13 → 14 件）。

**テストが環境状態に依存していないかを、テストを書いた時点で確かめる。**
