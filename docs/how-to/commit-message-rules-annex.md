## PR タイトル（スカッシュ後件名）の検査（再発防止）

スカッシュマージで develop に載る件名は「**PR タイトル + 半角スペース + `(#番号)`**」であり、PR コミット
（`base..HEAD`）の範囲に含まれないため、上記のコミット件名チェックだけではすり抜ける
（ブランチ名由来の規約外件名がそのまま統合ブランチへ載る事象が実際に起きている）。これを防ぐため `pr-title.yml` が PR タイトルを規約
`種別(起点ID): 要約` に照合し、違反ならマージ前に CI を失敗させる。

- 検査ロジックは `check-commit-messages.js` の単一件名モード（`--title` / `--author` 引数、
  `PR_TITLE` / `PR_AUTHOR` 環境変数）で、`validateSubject` を再利用する（規約の単一情報源）。
- `pull_request` の `opened/edited/reopened/synchronize` で起動し、タイトル後編集も再検査する。
- **除外は「作成者の名前」で行う**（#524）。ワークフローは `PR_AUTHOR`
  （`github.event.pull_request.user.login`）を渡すだけで、`dependabot[bot]` 等かどうかの判定は
  `check-commit-messages.js` の `BOT_AUTHORS`（`isBotAuthorName`）が担う。Revert・`[skip ci]` も
  同スクリプトが除外する。
  - **ジョブ条件で `user.type != 'Bot'` を使ってはならない。** それは dependabot だけでなく
    **GitHub App が人の代わりに作成した PR（`claude[bot]`）まで除外**し、この検査が `skipped` になる
    （PR #523 で実測）。スカッシュ後件名は develop に恒久的に残り、`base..HEAD` 検査にも含まれず、
    force push 禁止で事後修正もできないため、規約違反の件名が入る経路が空く。
    `scripts/scripts.repo.test.js` が全ワークフローを走査してこの判定の再混入を止める。

#### ★ スカッシュ件名を書き直すときは、スコープの ID を 1 つも落とさない（#579）

**上記の検査は「PR タイトル ＝ スカッシュ後件名」を前提にしているが、その前提は破れる。**
マージダイアログ（GitHub UI・API の `commit_title`）で件名を**書き直せる**からである。

**実際に破れた**（#568・`bc7bc8e`）。

| | 文字列 |
| --- | --- |
| PR タイトル（`pr-title.yml` は green） | `feat(FR-12,SC-07): ConversionJobDto にデッドレター標識と試行上限を追加する` |
| **develop に載った件名** | `feat(FR-12): 変換ジョブのデッドレター標識と試行上限を契約へ追加する (#568)` |

**`SC-07` が消えている。** 同 PR は SC-07 の画面仕様書・テスト仕様書・実装を実際に改変しており、
**恒久履歴とそこから生成される `CHANGELOG.md` から SC-07 が辿れなくなった**
（force push 禁止のため件名は事後修正できない。`changelog-overrides.json` の `remap` で生成物のみ是正した）。

**要約は書き直してよい。スコープの ID は落としてはならない。**
複数 ID なら**併記のまま**運ぶ（`feat(FR-12,SC-07): ...`）。

- **機械検査**: `scripts/check-landed-subjects.js`（`--self-test` あり）が、**実際に載った件名**を
  規約へ照合する（`scripts.repo.test.js` 経由で `ci.yml` の `scripts-tests` に載る）。
  **既存履歴は `scripts/landed-subject-baseline.json` のラチェットで据え置き、新規混入だけを落とす。**
- **ただし、この事故そのものは機械で検出しない**（**「できない」ではない**。下記）。落ちた後の件名 `feat(FR-12): ...` は
  **それ自体が完全に規約適合**であり、「落ちた」と判定するには PR タイトルとの突合が要る。
  **PR タイトルはリポジトリの中に無い。** 検査が捕まえるのは**書式違反**と**実在しない起点 ID** の
  2 型だけで、どちらも**恒久履歴に入ってから**気づく事後検知である。
  **ここは書き手（マージを実行する人・AI）が守る。**
  - **［2026-08-08 追記 / フェーズ末クロス監査］「できない」は言い過ぎだった。**
    **変更パス由来の FR/UC/SC ID がスコープに在るか**は、PR タイトルなしで判定できる。
    実測（着地件名 319 件・**走査基準: develop `2cd8508` 時点**）: **26 件ヒットし、`bc7bc8e`（実際の事故）を含む**。
    **採らない理由は「できない」ではなく「偽陽性 25/26 で方向が合わない」**である
    —— pin 更新や横断的な是正 PR が、触ったファイル名の ID を大量に拾う。
    **これは本ファイルが `AST` の近傍規則で既に採っている言い方と同じである**
    （「近傍規則になり偽陽性が避けられないため検査しない」）。[[IADR-0145]] 決定 3 の追記。
- **最も確実なのは、件名を書き直さないことである。** 書き直す必要があるなら、
  **先に PR タイトルを直してからマージする**（そうすれば `pr-title.yml` が検査する文字列と
  着地する文字列が一致する）。

> **［2026-08-08 追記 / フェーズ末クロス監査］★ 対になる規則: 実体を伴わない ID をスコープへ足さない。**
>
> 上の条文は「**落とすな**」しか書いておらず、**逆向きの誤り（足す）を止めていなかった。**
> **その穴を、この節を書いた PR 自身（#612）が踏んだ。**
>
> | | |
> | --- | --- |
> | 着地件名 | `feat(NFR,FR-12,SC-07,IADR-0145): スカッシュ着地件名を検査し、FR/UC/SC の実在性を機械化する (#612)` |
> | 実際に触ったもの | `scripts/` の検査器と `docs/adr/` `docs/specs/` `.claude/rules/`。**FR-12 / SC-07 の成果物は 1 つも触っていない**（実測） |
> | 両 ID が現れる唯一の場所 | `scripts/changelog-overrides.json` の **`bc7bc8e` 用 remap の値** |
>
> **他コミットの記録を是正する作業で、是正対象の ID を自分のスコープへ引き写してはならない。**
> 起点 ID は**自分の作業**のものであり、是正対象は**本文で参照する**。
> 正: `feat(NFR,IADR-0145): …（#568 の FR-12,SC-07 の記録も remap で是正）`。
>
> **先例は既にあった** —— #596（`78c9753`）は同じく remap で他コミットの記録を是正する作業だが、
> 対象の scope（`NFR,IADR-0116`）を継承せず `fix(NFR,IADR-0140)` を名乗っている。**#612 だけが破った。**
>
> **実害**: `CHANGELOG.md` で **FR-12 / SC-07 を辿る読み手に、変換ジョブと無関係な検査器の PR が
> 「新機能」として二重計上される**（`bc7bc8e` の正当な行と並んで出ることを実測）。
> `changelog-overrides.json` の `b421761` が「**新たな誤帰属を避ける**」として禁じている型と同じである。
>
> **機械では捕まらない。** `check-landed-subjects.js` が見るのは**実在性**であり、
> `FR-12` / `SC-07` はどちらも実在するので通る（実測: 着地件名 319 件で違反 0。**走査基準: develop `2cd8508` 時点**）。
> **落とした ID も足した ID も、機械は同じ理由（PR タイトルが無い・実体との突合が要る）で見られない。**
> **ここは書き手が守る。**

**事前防止と事後補正の使い分け**: `pr-title.yml` は**マージ前**の予防（規約外件名を止める）。
万一すり抜けて develop に規約外件名が入った場合は、履歴不変の原則（force push 禁止）に従い、
下記 CHANGELOG 生成時の `changelog-overrides.json`（`action: "remap"`）で**生成物のみ**是正する。
前者が第一防衛線、後者が最終手段という役割分担。

## 検査対象から除外する自動コミット

- **自動コミットの著者**: `dependabot[bot]` / `renovate[bot]` / `github-actions[bot]` 等の bot 著者。
- **マージコミット**: `--no-merges` により除外。
- **自動生成・リバート**: 件名に `[skip ci]` を含むコミット、および `Revert "..."`。

除外リストは `scripts/check-commit-messages.js` の `BOT_AUTHORS` と同時に更新する。
