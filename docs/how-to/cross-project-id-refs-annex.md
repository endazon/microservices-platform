## 計画大改定で重なり方が変わった

  重なり方は次のとおり変化した。**修飾の欠落がどちらの誤りとして現れるかが変わる**ため区別する。
  - **`FR-16`〜`FR-20`**: 従来は AST にしか無く、裸で書けば「計画書に存在しない ID」＝**参照切れ**として目立った。
    MSP 側に同番号が生まれたことで**双方に存在し意味の異なる ID** へ変わり、修飾の欠落は**誤帰属**
    （別プロジェクトの要求へ静かに紐づく）として現れる。検査で捕まらないのはこの型である。
  - **`FR-01`〜`FR-15` / `UC-01`〜`UC-07` / `SC-01`〜`SC-03`**: 改定前から双方に存在する（従来どおり誤帰属）。
  - **`FR-21` / `FR-22` / `UC-08`〜`UC-11` / `SC-04`〜`SC-21`**: MSP にしか無い（**`FR-22` は［2026-08-07 / #599］で追加**。AST の採番は `FR-01..20` なので衝突しない）。**`SC-18`〜`SC-21` は AST 側に対応 ID が
    存在しないため衝突しない**（将来 AST が採番を伸ばせば上の「誤帰属」型へ移る）。

  裸の ID は必ず MSP を指す。
- **issue / PR 番号の修飾**: **短縮形に寄せる**（フルパス形式と混在させない）。
  `AST#NNN`（ai-stock-trading）・`planning#NNN`（project-planning）。GitHub の自動リンクを効かせたい

## どこで自動リンクが効くか

    **`.md` では裸の `#NNN` も短縮形の修飾も自動リンクにならない**——`.md` でリンクになるのは
    フルパス形式だけである。したがって `.md` での違反は「表記ゆれ（機械的突合の不安定）」であり、
    **誤リンクという実害が出るのは issue / PR / コミットメッセージの本文**である。
  - **意図的に誤例を書くときはインラインコードかコードフェンスに入れる**（上の「誤:」の行がその形）。
