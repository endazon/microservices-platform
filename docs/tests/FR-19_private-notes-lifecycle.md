# テスト仕様書: 個人資料のライフサイクル・容量・版保持

## テスト対象・範囲

文書サービスの個人資料端点・容量規則・版保持・定期処理（自動物理削除・通知検知）。
**対象外**: 画面・BFF・通知サービス側の受け皿・~~露出トグル ON の消費側~~。
**［2026-08-28 追記］このうち BFF は実装され、認可は `Platform.Bff.Tests` の
`BffPrivateNoteEndpointTests` が固定している**（本書の対象は文書サービス側のままである）。
**［2026-08-28 追記］「AI の入力に含める」トグルの供給側（属性への写し・既定値）は本書の
対象に入った**（下記 15〜17）。**消費側（検索と AI 回答の分離）は依然として対象外**であり、
検索側は検索サービスの、AI 回答側は AI 分析サービスのテストが持つ。
**グラフ表示トグルの消費側は未着手のままである。**

実体: `DocumentService.Api.Tests` の `PrivateNoteQuotaTests` / `PrivateNoteLifecycleTests` /
`DocScopeValidationTests`（結合テスト。InMemory ＋ 記録用スタブ）。

## テスト観点

- 🔴 否定形（拒否・不可視・非算入）は陽性対照（許可・可視・算入）と対で置く。
- 時刻依存（90 日・7 日・週次）は定期処理へ `now` を渡して検証する（実時間へ依存しない）。
- 通知は記録スタブで発火の有無・回数・ペイロード（件数・閾値・期限のみ）を固定する。

## テストケース一覧（計画の受け入れ基準からの写像）

| # | 受け入れ基準 | テスト |
| --- | --- | --- |
| 1 | 同一資料を繰り返し編集しても使用量は最新版 1 件分から増えない | `版履歴は使用量に算入されない` |
| 2 | 論理削除で使用量は減らず、完全削除で当該資料の分だけ減る（解放容量の提示つき） | `論理削除では使用量が減らず完全削除で減る` |
| 3 | 80% / 95% の跨ぎで各 1 回警告・下回ると再武装・宛先は本人のみ | `容量警告は80と95の跨ぎで各1回発火し下回ると再武装する` |
| 4 | 100% で新規作成のみ拒否・更新は成功・完全削除で自力復帰 | `満杯時は新規作成のみ拒否され更新は通り完全削除で復帰する` |
| 5 | 上限を跨ぐ新規作成の拒否（跨がない新規作成は通る） | `上限を跨ぐ新規作成は拒否され跨がない新規作成は通る` |
| 6 | 上限は管理者のみ変更可・1 TB 上限・既定 1 GB | `上限は管理者が変更でき1TBを超える値は拒否される` / `既定の上限は1GBである` |
| 7 | 新規作成の既定値（スコープ属性・所有者・最も厳しい機密区分・トグル OFF） | `SC19からの作成は本文なしで既定値つきで作られる` |
| 8 | 論理削除は 90 日間復元でき、90 日経過で自動物理削除・事後通知（件数のみ） | `論理削除から90日経過で自動物理削除され事後通知が発火する` |
| 9 | 完全削除 7 日前の別建て通知が 1 回だけ | `完全削除の7日前通知は1回だけ検知される` |
| 10 | 週次通知は件数と最短期限のみ・7 日間隔 | `週次の削除通知は7日間隔で件数と期限のみを運ぶ` |
| 11 | 版保持は「直近 50 版かつ 90 日」の両条件を外れた版だけが古い順に消える | `版履歴は直近50版かつ90日の両方を外れた版だけが消える` |
| 12 | 一括完全削除・解放容量の合計・監査は件数のみ | `一括完全削除は合計の解放容量を返し監査は件数のみ残る` |
| 13 | 他者の資料へ削除・復元・完全削除・露出変更が届かない（存在秘匿）＋所有者の陽性対照 | `他者の資料はSC19の削除復元完全削除から到達できない` |
| 14 | スコープ属性の値域検証・一般経路での個人資料作成の拒否・欠落の非巻き込み | `DocScopeValidationTests` 全件 |
| 15 | 新規の個人資料は 3 トグルがすべて OFF・公開範囲は非公開（共有 0 件）・機密区分は最も厳しい区分 | `新規の個人資料は3トグルOFFかつ非公開かつrestrictedで作られる` |
| 16 | 「AI の入力に含める」トグルの変更が文書属性へ写る（ON / OFF の両方向・他の既定属性を巻き込まない） | `AI入力トグルの変更が文書属性へ写る` |
| 17 | 露出トグルの変更では版が進まない（版は編集の回数だけ保持するという規則を守る） | `露出トグルの変更では版が進まない` |

> **15 は登録経路が 2 本あるため 2 か所で測る。** もう 1 本（同期経由の新規作成）は
> `ObsidianSyncProtocolTests` の `同期経由の新規作成はフェイルセーフ既定で作られる` が持つ。
