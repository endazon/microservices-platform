# テスト仕様書: 秘密情報・接続設定の管理

## テスト対象・範囲

**画面・境界層（`/bff/secrets`）・保管先（Vault）の書き込み権限の字面**である。

**対象外（送り先つき）**:

| 事項 | 理由・送り先 |
| --- | --- |
| 🔴 **実 Vault への疎通** | 自動試験は**保管先の偽物**（k8s 認証・KV v2 の metadata / 部分更新 / 作成を写したもの。削除・破棄された版への部分更新は 404、既に在る項目への作成は権限不足の 403 を返す）に対する固定である。**「緑である」ことは「稼働クラスタで書ける」ことを意味しない。** 稼働クラスタでの確認は手動（T-40）で行う |
| 同期（保管先 → 外部シークレット同期 → Secret）の反映 | 別の経路（読み取り専用の同期）であり、本画面は触れない。反映の確認は運用 Runbook の手順で行う |
| 監査ログの保持・閲覧 | 記録は構造化ログであり、閲覧はログ基盤側 |

## テスト観点

1. 🔴 **値がどこにも出ないこと**（応答・監査・ログ）。**陽性対照と対で置く** —— 偽物の保管先に値が届いていることを先に確かめる。
2. 🔴 **描いてはいけないものが無いこと**（値の列・一括再投入の口・値の読み出し）。
3. **1 回に 1 プロパティだけを部分更新で書くこと**（同居する構成値を消さない）。
4. **項目の集合の外へ書けないこと**（境界層の 400 と、保管先の権限の字面の両方で）。
5. **ロール限定が 2 層で効くこと**（画面の存在秘匿・境界層）。
6. **失敗を空や成功に縮退させないこと**（保管先が無い・届かない・拒否した）。
7. **起動時に項目の集合を読めなければ起動しないこと**（fail-closed）。
