## 受け入れ基準 5 つの写像（**この節が本書の主眼である**）

計画・issue #600 が挙げる受け入れ基準は 5 つある。**うち 4 つ（AC-2〜AC-5）は送出側の振る舞いである。**

| AC | 受け入れ基準 | 状態 | テスト |
| ---: | --- | --- | --- |
| AC-1 | 実装 ADR に 5 点（送出主体・アプリ内通知の実体・メール経路・送信レート・発火の検知）が決定として書かれている | **満たした** | 文書レビュー（通知サービスの実装 ADR 決定 1〜5）。機械検査は無い |
| AC-2 | **本文が件数と期限のみで構成される**（タイトル・本文・検索語・回答内容が混入しない） | **満たした**（契約・文言・送出側の 3 面） | **T-01（契約テスト）** ＋ **T-02（文言テスト）** ＋ **T-17〜T-19**（送出側の応答・メール本文・監査ログ） |
| AC-3 | **所有者本人以外へ届かない** | **満たした** | **T-09**（否定形。一覧・未読件数・既読化・管理者ロールの 4 面） |
| AC-4 | **メールが送れなくてもアプリ内通知が届く**（従属しない） | **満たした** | **T-10**（失敗・例外・SMTP 未設定・宛先未解決の 4 面） |
| AC-5 | **送信上限を超える通知が静かに落ちない**（監査ログ・運用ダッシュボードで観測できる） | **満たした** | **T-11**（`sent` / `deferred` / `dropped` / `failed` の 4 結末と上限到達事象） |

> **AC-3〜AC-5 に「代わりのフロントテスト」を置いていない。** 置くと**満たしていない基準を満たしたように
> 見せる**ことになる。**フロントで確かめられるのは「契約にその形が無い」ことまでである。**
> 送出側が入った現在も、この分担は変えていない —— **同じ基準を 2 か所で数えない。**

> **★ 発火の結線は 2026-08-28 に入った（T-24〜T-28）。**
> ①②③ の契機そのものの検知は個人資料側のテスト（削除の 3 段・容量の 80/95・トークン期限）が
> 既に固定しており、**本書が新たに足したのはその先** —— **送出の面・fail-open・発火記録と送出の
> 順序・計器**である。**T-09〜T-11 は引き続き「通知が作られたあと」の振る舞いを検証している。**

## テスト対象・範囲

- **対象**: BFF 契約（`docs/api/openapi.yaml` の `/bff/notifications*` と `NotificationDto` ほか）、
  アプリ内通知の受け皿（`src/platform/frontend/src/components/notifications/`）、
  表示文言の組み立て（ja / en）、
  **送出側**（`src/platform/backend/Services/NotificationService/`。宛先の限定・既読化・メール outbox・
  送信レート制御・保持期間）。
  **発火側**（`src/knowledge/backend/Services/DocumentService/`。送出の面・fail-open・発火記録と
  送出の順序・計器）。
- **対象外**: **通知サービスの配備**（compose / Helm）、**BFF 端点の実装**、**SMTP リレーの実体**
  （送出側の実装 ADR 決定 5。**#600 / #451 で追跡**）。

## テスト観点

1. **契約の不変条件**（AC-2 の骨格）: **スキーマにタイトル／本文に相当する項目が無い**。
2. **文言の組み立て**: 件数・閾値・期限だけから文言ができ、**ja / en の両方が揃っている**。
3. **描画**: 未読件数・一覧・既読化・空状態・取得失敗の縮退。
4. **アクセシビリティ / 表示規約**: **色だけで意味を持たせない**（色 ＋ アイコン ＋ テキスト）。
5. **通信**: orval 生成フック経由であること（**手書き HTTP クライアントを使わない**。ESLint も止める）。
6. **宛先の限定（送出側）**: **他人の通知が読めない・既読化できない・未読件数に混ざらない**。
   **ロールでは開かない**（管理者でも他人の通知は読めない）。
7. **メールからの独立（送出側）**: メールが失敗・例外・未設定・宛先未解決のいずれでも
   **アプリ内通知が残る**。
8. **送出の観測（送出側）**: 4 つの結末が**状態・監査ログ・メトリクス**に残る。
   **繰り越しが行き止まりにならない**（翌日に送られる）。
9. **発火の結線（発火側）**: **送る本文が件数・閾値・期限だけ**である。**受け口が落ちていても
   業務処理が失敗しない**（任意の例外・非 2xx・タイムアウト）。**発火記録が送出より先に確定して
   いる**（再起動で重複発火しない）。**届かなかったことが計器に載る**。

## 未決事項

1. **E2E（Playwright）は置いていない。** BFF 端点と通知サービスの配備が入るまで、
   画面に通知が出る筋道が無いためである。
2. **BFF 端点のテストは無い。** 端点そのものが未実装であり、契約だけが載っている。
3. **配備（compose / Helm）の検査は無い。** 通知サービスは配備対象に入っておらず、
   **送出は到達しない**（結末 `unreachable`）。配備が入るまでは計器がその状態を示す。
4. **受け口（T-21〜T-23）は 2026-08-28 に、発火の結線（T-24〜T-28）は同日に追加した。**
