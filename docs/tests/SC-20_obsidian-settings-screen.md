## 観点

- 🔴 否定形（他人の端末に到達できない・平文が一覧に出ない・承認ステップが無い・自動更新が無い）は
  **陽性対照と対で**置く ——「常に 404」「常に空」の実装でも陰性だけなら緑になる。
- **失効は通す側で固定する。** 個別失効は端末紛失時の唯一の防御線であり、
  文書側のポリシー整備状況に依存して塞がってはならない。**画面側でも状態を理由に隠さない。**
- **自動更新（リフレッシュ）の口が存在しないこと**は、API の一覧に現れないことと、
  画面に導線が無いことの両方で担保する。
- 🔴 **時刻は固定する**（残り日数・期限切れの境界が「いま」に依存するため）。
- 🔴 **「外す」と「削除」は、文言と要求の両方で見る。** 確認文が「削除ではない」と言っていることに加え、
  **資料を消す口を 1 つも叩いていない**ことを確かめる（文言だけ直して口が残る実装を通さない）。
- 🔴 **自動解決の不在は 3 択の存在と対で置く。** 3 択が描かれない実装でも、陰性だけなら緑になる。
- **区画は表示名（`region` のアクセシブル名）で引く。** 同じ語が複数の区画に現れるため、
  画面全体で引くと別の区画の要素を掴む。
- 🔴 **同じ 0 件に 2 つの意味があるときは、両側を置く。** 履歴 0 件の案内は端末の最終同期の有無で
  分かれるため、**片側だけでは「常に同じ文言を出す実装」でも緑になる**。
  それぞれのケースで**もう片方の文言が出ていないこと**まで見る。

## ブラウザ E2E で見ていること・見ていないこと

- **見ている**: ビルド成果物の上でルート単位の遅延チャンクが実際に読み込まれ、画面が描かれること。
  経路の取り違え（パスの改名）は**ここでだけ落ちる** —— 未認証の往復では見分けられない（受け皿が
  認証ガードの配下に居るため）。変異試験で 2 件が落ちることを実測した。
- 🔴 **見ていない**: 後段の実応答との一致。セッションと BFF 応答はネットワーク層のスタブであり、
  **契約の写しであって後段ではない。** 実基盤を伴う実行は別 issue（#466）が持つ。
