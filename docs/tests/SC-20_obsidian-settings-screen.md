# テスト仕様書: Obsidian 連携設定画面

## テスト対象・範囲

> **`status: in-progress` の理由**: 画面そのもの（フロントエンド）と Obsidian プラグイン本体は
> 未実装である。現段階のテストは**画面が呼ぶ API の挙動**（端末一覧・トークンの発行と再発行・
> 個別失効・一括失効・露出 3 トグル）と、その**認可**を固定している。
> 画面実装の issue が UI テスト（固定文言・確認ダイアログ・状態の描き分け）を本書へ追記する。

- 同期プロトコルそのもの（マニフェスト・push・pull・削除の伝播）の写像は
  [FR-20_obsidian-sync](FR-20_obsidian-sync.md) が正である。本書は**設定画面が触る面**を扱う。
- 同期トークンは**ブラウザセッションとは別系統の資格情報**であり、画面はトークンで API を呼ばない。

## 実体

| 層 | テストクラス | 主に固定していること |
| --- | --- | --- |
| BFF（認可） | `BffPrivateNoteEndpointTests` | 無認証は 401 ／ 他人の端末は 404（403 にしない）／ 平文トークンは発行応答にだけ現れる ／ 失効は文書ポリシーの有無に依存しない |
| 文書サービス | `SyncDeviceTokenTests` | 有効期限 30 日・手動再発行のみ ／ 個別失効・一括失効 ／ 他人の端末に到達できない |

## 観点

- 🔴 否定形（他人の端末に到達できない・平文が一覧に出ない）は**陽性対照と対で**置く ——
  「常に 404」「常に空」の実装でも陰性だけなら緑になる。
- **失効は通す側で固定する。** 個別失効は端末紛失時の唯一の防御線であり、
  文書側のポリシー整備状況に依存して塞がってはならない。
- **自動更新（リフレッシュ）の口が存在しないこと**は、API の一覧に現れないことで担保する
  （有効期限は、失効操作を忘れた場合の最終的な歯止めである）。

## 画面実装時に追加する検証（先取りの台帳）

| # | 観点 |
| --- | --- |
| 1 | 端末一覧が「有効（残り日数）／期限切れ間近（残り 7 日以内）／期限切れ／失効」を区別して表示する |
| 2 | トークンは発行直後に一度だけ表示し、再表示できない（再発行の導線を同じ行に置く） |
| 3 | 期限切れ後もプラグイン設定には旧トークンが残る旨の固定文言が表示される |
| 4 | 一括失効の確認ダイアログに復元不可である旨が表示される |
| 5 | 同期対象フォルダの指定 UI の隣に、業務関連資料としての扱い（退職時 30 日）の固定文言がある |
| 6 | 露出 3 トグルが独立に設定でき、既定はいずれも OFF である |
