# テスト仕様書: MCP クライアントを登録・管理する

## 本書の射程

**バックエンドの管理 API だけを扱う。** 管理画面は本作業の射程外であり、画面を実装する作業が
着手する時点で画面のテスト仕様書を起こす。認可サーバー（Keycloak）側のクライアント登録も
射程外であり、本書が扱うのは**プラットフォーム側の有効・無効と属性割当**である。

## フローの写像

| フロー | 手順 | 検査 |
| --- | --- | --- |
| 基本 1 | クライアントを登録し、無人アカウントへ属性を割り当てる | 登録・一覧が動く。種別は有人 / 無人の 2 値で、不正値は拒否する |
| 基本 2 | 公開ツール構成（許可リスト）を確認する | 実効ツール一覧と構成ドリフトを返す |
| 基本 3 | 実効ツール一覧と登録クライアントを提示する | 管理者だけが参照できる |
| 例外 | スキーマ検証に失敗した変更 | 適用しない（起動時に失敗させる） |

## 受け入れ基準

| # | 観点 | 期待 |
| --- | --- | --- |
| 1 | 管理者以外のアクセス | 拒否する |
| 2 | クライアントの無効化 | **次の呼び出しから即座に**拒否される。キャッシュを挟まない |
| 3 | 🔴 無人アカウントへ**個人資料を読ませる属性割当** | **登録時も差し替え時も拒否**する |
| 4 | 個人資料以外の属性割当 | 通る（陽性対照） |
| 5 | 初期公開範囲外のツールを許可リストへ書く | スキーマ検証で拒否する |
| 6 | 公開名の重複 | スキーマ検証で拒否する |

### 3 を 2 経路とも検査する理由

登録時だけを塞ぐと、あとから属性を差し替えて禁止された割当を作れてしまう。
実装は検証関数を 1 つに共用しているが、**共用していること自体はテストで固定できない**ため、
両方の経路から呼んで拒否されることを確かめる。

## 未実施
