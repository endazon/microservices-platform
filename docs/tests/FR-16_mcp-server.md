# テスト仕様書: MCP サーバー統合

## 本書の射程

**本書が扱うのは MCP サーバー本体である。** 各サービス側のツール自己申告エンドポイントと、
外部エージェント向け画面は射程外であり、それぞれの担当作業が着手する時点で拡張する。

| 範囲 | 扱い |
| --- | --- |
| 公開許可リストと自己申告の突合（実効ツール一覧） | **本書** |
| ツール呼び出しの統制（登録確認・公開確認・除外・越境・監査） | **本書** |
| **サービスアカウント実行時の個人資料の一律除外** | **本書（中核）** |
| MCP クライアント登録管理 API | **本書** |
| 各サービスのツール自己申告エンドポイントと実行口 | 射程外（各サービスの再実装作業）。［2026-09-27］本サービスからの実行の送り方（宛先の決め方・失敗の畳み方）は本書（下記「ツールの実行（gRPC）」） |
| クライアント登録管理の画面 | 射程外（フロントエンド） |
| 入口のルーティング・レート制限 | 射程外（デプロイ資材） |

## 起点となる計画書（トレーサビリティ）

- 機能要求: プラットフォームの機能を MCP サーバーとして外部 AI エージェントへ公開できること。
  公開ツールは各サービスの自己申告と宣言的な公開構成（許可リスト方式）から動的に構成され、
  実行は利用者・サービスアカウントの権限スコープ内に限定され、応答はデータ越境ポリシーで
  文書単位にフィルタされる
- ユースケース: 外部 AI エージェントからナレッジを利用する／MCP クライアントを登録・管理する
- 関連 ADR: 宣言的公開構成とサービス自己申告による動的ツール連携／**サービスアカウント実行では
  個人資料を一律で対象外とする**（所有者の個人資料であっても含めない）／個人資料を表す
  文書スコープ属性の新設（属性キーと 2 値）／属性ベース認可（deny-by-default・存在秘匿）

## 🔴 中核の受け入れ基準 — サービスアカウント実行時の個人資料

計画は「**同じツールを同じ引数で呼んでも、有人実行と無人実行で結果が変わる**」と明記している。
したがって**否定形テストだけでは足りず、陽性対照と対で置く**。

| # | 観点 | 期待 | 種別 |
| --- | --- | --- | --- |
| N-1 | サービスアカウント実行 | 個人資料が応答に一切現れない | 否定形 |
| N-2 | **所有者本人**のサービスアカウント実行 | 個人資料が応答に一切現れない | 否定形 |
| N-3 | 除外した文書の件数 | **件数にも含まれない**（件数自体がサイドチャネルになるため） | 否定形 |
| N-4 | 検索・文書取得・グラフ探索の**全経路** | いずれの経路でも現れない | 否定形（経路網羅） |
| P-1 | 有人実行 | **同じ個人資料が返る** | 陽性対照 |
| P-2 | 文書スコープ属性を**持たない**文書 | サービスアカウントでも**返る** | 陽性対照 |
| P-3 | 組織文書 | サービスアカウントでも返る | 陽性対照 |

### P-2 が無いと何が分からなくなるか

判定を「個人資料である」（集合帰属）で書いたか、「組織文書でない」（否定）で書いたかは、
**否定形テストだけでは区別できない**。文書スコープ属性は新設で実データが無く、既存文書へ
遡及付与しない方針であるため、否定で書くと**属性を持たない組織文書が一斉に落ちる**。
P-2 はその違いだけを見るテストである。

## 公開統制の受け入れ基準

| # | 観点 | 期待 |
| --- | --- | --- |
| A-1 | 申告はあるが許可リストに無いツール | 一覧に現れず、呼び出しもできない |
| A-2 | 許可リストが空 | 公開ツールは 0 件（既定は非公開） |
| A-3 | 許可リストに無いツールの呼び出し | **「不明なツール」として拒否**する（「権限が無い」と区別させない） |
| A-4 | 公開宣言に対して申告が無い | 構成ドリフトとして報告し、**公開しない** |
| A-5 | 越境分類を欠く申告 | 公開しない |
| A-6 | AI 分析系・要約系のツールを許可リストへ書く | スキーマ検証で拒否する（初期公開範囲外） |
| A-7 | 公開名の重複 | スキーマ検証で拒否する |
| A-8 | 🔴 検証に落ちる構成でサービスを起動する | **要求を受ける前に落ちる**。エラーログを吐きながら稼働し続けない |
| A-9 | 正しい構成（ただし収集先がすべて到達不能） | **落ちない**（陽性対照。収集の一時失敗は次の周期へ持ち越す） |
| A-10 | 構成ファイルが存在しない | **落ちない**。公開 0 件として起動する（「壊れている」と「まだ何も公開していない」を区別する） |
| A-11 | 🔴 同じサービスの同じツール名の申告が 2 つある（［2026-09-27 追加］） | 突合は**落ちない**。そのツールだけを公開せず（どちらかを推測しない）重複の構成ドリフトとして現れ、**他のサービスのツールは公開される**。同じ入力では結果が変わらない |

### 🔴 A-8 について —— 「例外を投げること」と「サービスが止まること」は別の主張である

検証ロジックが例外を投げることは A-6 / A-7 が押さえている。**その例外が実際にサービスを止めるか**は
別の主張であり、押さえていないと次のことが起きる。常駐処理の中で例外が握り潰されても
CI は緑のままで、**壊れた構成のまま Web サーバーが起動し、ヘルスチェックも緑**になる。
公開ツールは 0 件だが、それは「公開していない」のと外形上は区別できない ——
**「公開されているつもりの公開されていない」状態が、エラーログだけを吐きながら継続する。**

常駐処理の開始は要求の受け付けを塞がない（開始要求はその完了を待たずに返る）。
したがって「検証を定期実行に任せる」設計では起動時 fail-fast は原理的に成立せず、
**要求を受ける前に一度だけ同期的に検証する**必要がある。A-8 / A-9 はこの対で固定している。

## クライアント登録管理の受け入れ基準

| # | 観点 | 期待 |
| --- | --- | --- |
| C-1 | 登録・一覧・無効化 | 管理者が実行できる |
| C-2 | 管理者以外 | 登録管理 API へアクセスできない |
| C-3 | クライアントの無効化 | **次の呼び出しから即座に**拒否される（キャッシュを挟まない） |
| C-4 | 未登録クライアント | 実行を拒否し、公開ツール一覧も返さない |
| C-5 | サービスアカウントへ個人資料を読ませる属性割当 | **登録時も差し替え時も拒否**する |
| C-6 | 個人資料以外の属性割当 | 通る（陽性対照） |

### 無人アカウントの属性は登録者が持つ集合の部分集合であること（［2026-09-03 追加 / #1185］）

**判定は後段（本サービス）が持つ。** 画面と境界層は値域の絞り込みまでを担う。
🔴 **順序の語（「上限を超えない」）では書けない** —— 本モデルは序数比較を排除しており、
機密区分のあいだに上下は定義されていない。**集合帰属で書く。**

| # | 観点 | 期待 |
| --- | --- | --- |
| C-7 | 登録者の集合外の機密区分を割り当てる | 400 で拒否し、**外れた値そのもの**を本文へ名指しで載せる |
| C-8 | 登録者より**狭い**機密区分を割り当てる（陽性対照） | 通る（同一値限定にしない） |
| C-9 | 登録者が持たないタグを混ぜて割り当てる | 400 で拒否し、**外れた値だけ**を列挙する（持っている値を混ぜない） |
| C-10 | 属性差し替えで集合外の値へ変える | **登録と同じ判定・同じ文言**で拒否する |
| C-11 | ロールが管理者でも自分の機密区分の外を配る | 拒否する（**ロールと機密区分は別の軸**） |
| C-12 | 登録者の属性を解決できない | 拒否する（deny-by-default）。**「持っていない」とは書かず「解決できなかった」と書く** |
| C-13 | 本規則の対象キーを含まない属性の登録（陽性対照） | **解決できなくても通る**（無関係な経路を認可サービスの可用性に従属させない） |
| C-14 | 集合の表記ゆれ（順序・余白・大小文字） | 同値として扱う（集合であって列ではない） |

## 自己申告（各サービスが実装する側）の受け入れ基準

供給元は 3 サービスである。文書取得系・検索系・グラフ探索系（読み取り）に限り、
要約系と AI 分析系は供給しない。

| # | 観点 | 期待 |
| --- | --- | --- |
| D-1 | 申告端点に到達する | 200 を返し、サービス名と申告の配列を持つ |
| D-2 | 申告した個々のツールが載る（陽性対照） | 文書取得系 2 / 検索系 1 / 探索系 3 の名前がそれぞれ現れる |
| D-3 | 申告の 5 項目（［2026-09-27 改訂］実行先の URL を外した） | 名前・説明・入力スキーマ・必要スコープ・越境分類がすべて非空 |
| D-4 | 個人資料を対象とする候補（否定形） | **申告に現れない**（候補としては実在させ、規則で落ちることを測る） |
| D-5 | 個人資料でない候補（陽性対照） | 残る。**文書スコープを持たない候補も残る** |
| D-6 | 要約系・AI 分析系（否定形） | 申告に現れない |
| D-7 | 探索ツールの入力スキーマ | ホップ数の既定 2・上限 3 が現れる |
| D-8 | 🔴 実行先の URL（［2026-09-27 改訂］旧: 実行口の基底 URL を構成で上書きできる） | 申告の JSON の各ツールのキーが 5 項目ちょうどで、**実行先の URL を持たない**（ワイヤのキーで測る） |

## 収集 → 実効カタログの結合（実サービス）

**実サービス 3 本を in-process で起こし、実際の HTTP 応答を収集して突合まで通す。**
コンテナを要らない形にしてあるのは、コンテナを要る試験は日次と統合ワークフローでしか走らず、
**プルリクエストでは一度も実走しない**からである。

| # | 観点 | 期待 |
| --- | --- | --- |
| I-1 | 3 サービスから申告を集める | 3 件そろう（1 件でも欠けたら落ちる） |
| I-2 | 公開構成の 6 件が個々に載る（陽性対照） | 公開名の集合が構成と一致し、説明・スキーマ・スコープ・越境分類も運ばれる |
| I-3 | 申告のある公開宣言 | 構成ドリフトが**出ない**（沈黙） |
| I-4 | 申告の無い公開宣言（否定形） | 構成ドリフトが**発火**し、公開されない |
| I-5 | 個人資料のツールを構成が要求した場合（否定形） | 申告が無いので公開されず、ドリフトとして現れる |

## gRPC での申告と収集（［2026-09-26 追加］）

申告の口は REST と gRPC を対で持ち、本サービスは宛先ごとに輸送を選んで集める。**待受はすべてループバック**
（申告元の実 Kestrel と、収集器を測る代役のホスト）であり、0.0.0.0 では待ち受けない。

| # | 観点 | 期待 |
| --- | --- | --- |
| G-1 | 供給元 3 サービスの gRPC 面をサービス間トークンで呼ぶ（陽性対照） | REST と**同じ申告**（5 項目・順序とも）が返り、サービス名が空でない |
| G-2 | トークン無しで呼ぶ（否定形） | `UNAUTHENTICATED` |
| G-3 | 管理者の利用者トークンで呼ぶ（否定形） | `PERMISSION_DENIED`（利用者トークンの転送で面が開かない） |
| G-4 | 面の型の認可 | 呼び出し側サービスの資格情報を要求するポリシーを宣言している |
| G-5 | サービス間トークンで収集する | 5 項目とも申告元のとおりに戻る |
| G-6 | 宛先ごとの輸送選択 | 宛先 = REST と gRPC の構成のキーの和・構成の順序を保つ。gRPC のアドレスが在る宛先だけ gRPC（両方なら gRPC）、空のアドレスは REST |
| G-7 | 資格情報の拒否・検証できないトークン・トークン取得失敗（否定形） | 申告なし（公開しない）。**Error** で記録する |
| G-8 | 待ち受けの無い宛先・空のサービス名（否定形） | 申告なし。Warning。**他の宛先の収集は止まらない** |
| G-9 | 何も返さない宛先 | REST の HTTP クライアントのタイムアウトで打ち切られ、申告なしになる |
| G-10 | 呼び出し側の取り消し | 申告なしへ畳まず、取り消しとして外へ出る |
| G-11 | 登録 | gRPC の構成が無い配備は gRPC の収集器もトークン発行側も登録しない。在る配備は両方を登録する。構成が在るのに収集器が無ければ**ホストが起動しない**（本番の起動処理のまま確かめる。例外を投げることと、それがホストを止めることは別の主張である。陽性対照として、収集器が在れば起動する） |
| G-12 | 並走中の 2 つの形 | proto の項目名・数が REST の JSON と一致する |
| G-14 | 🔴 規約は 5 項目（［2026-09-27 追加］） | proto の申告の項目は 5 つで、旧 `endpoint` の番号 4 は使われていない。DTO にも実行先の URL が無い |
| G-15 | 🔴 旧い申告元（［2026-09-27 追加］） | gRPC の番号 4・REST の `endpoint` に URL を載せた申告は、その項目を読み飛ばして 5 項目だけが戻る（申告なしにしない。代役が番号 4 を実際にワイヤへ載せていることも確かめる） |
| G-16 | 🔴 名乗りの結び付け（［2026-09-27 追加］） | 封筒の `service` が収集先の名前と違う申告は REST・gRPC とも**拒否**され（Error）、その名では 1 件も集まらない。名乗りを偽らない他の宛先の申告は集まる。偽った宛先にも実際に問い合わせている（対照） |
| G-13 | 配備の配線（helm・compose・本番の起動処理） | REST の収集先すべてに同じホストの h2c の宛先があり、宛先は h2c ポートを宣言し、h2c リスナを立て、申告の口が gRPC の面を対で張る |

## ツールの実行（gRPC）（［2026-09-27 追加］）

ツールの実行は gRPC で**申告したサービス**へ送る。宛先は申告したサービスとツール名だけで決め、申告の中身の URL は使わない。
受け口（各サービスの実行口）の無い宛先は拒否で終わることを本番の起動処理のまま固定する。［2026-09-27 追記］受け口は検索サービスが最初に持った（下の「実行口（受け口）」）。待受はすべて 127.0.0.1 である。

| # | 観点 | 期待 |
| --- | --- | --- |
| X-1 | 申告したサービスへの実行（陽性対照） | 公開構成で突き合わせたサービスの h2c アドレスへ、サービス間トークンで届く。要求のツール名は**申告名**（公開名ではない）。別のサービスには届かず、もう一方のサービスのツールはもう一方へだけ届く。応答は共通エンベロープへ戻る（本文・参照リンクの有無を含む） |
| X-2 | 🔴 旧い申告元の URL（中心の観点） | REST の `endpoint`・gRPC の番号 4 に URL を載せた申告を本物の収集器と突合で公開し、実行しても、**その URL へ接続が 1 本も張られない**（URL の側に待受を置き、受け付け待ちの接続が無いことで測る）。実行は申告したサービスへ届く |
| X-3 | 🔴 受け口の無い宛先 | `UNIMPLEMENTED` → 拒否（「実行口がまだありません」）。配線の誤りではないので Warning |
| X-4 | 経路の無い宛先 | どこへも送らず拒否。文言に内部のサービス名・アドレスを含めない |
| X-5 | 何も返さない宛先 | 構成の期限（`Mcp:ToolExecutionTimeoutSeconds`）で打ち切り、拒否（時間切れ） |
| X-6 | 呼び出し側の取り消し | 拒否へ畳まず、取り消しとして外へ出る |
| X-7 | 資格情報の拒否・トークン取得失敗（否定形） | 拒否。**Error** で記録する |
| X-8 | 待ち受けの無い宛先 | 拒否（到達不能）。Warning |
| X-9 | 要求の組み立て（［2026-09-27 改訂］） | 申告名・引数（空は空のオブジェクト）・**利用者文脈（利用者と操作）だけ**を運ぶ。属性・必要スコープ・除外制約・宛先を運ぶ項目を持たない（旧 `scope` の番号は予約済みで項目として存在しない） |
| X-10 | 応答の 2 つの形 | 応答の proto の項目名・数が共通エンベロープの JSON と一致する |
| X-11 | 期限の構成 | 既定 30 秒・1 未満は 1 秒。本番の構成ファイルに既定値で並んでいる |

## 収集の期限と常駐処理の寿命（［2026-09-26 追加］）

収集の時間切れ 1 回で MCP サーバーのプロセス全体が止まっていた不具合の是正に伴う観点である。
**汎用ホスト（既定の「常駐処理の例外でホストを止める」挙動のまま）で本物の常駐処理と本物の REST の収集器を動かす** ——
例外がホストを止めるかどうかは、常駐処理を直接駆動しても観測できない。待ち受けは 127.0.0.1 だけである。

| # | 観点 | 期待 |
| --- | --- | --- |
| R-1 | 接続を受けて何も返さない宛先（期限 1 秒） | 時間切れは申告なしへ畳まれる。**ホストは止まらず**（停止の通知が発火しない）、**次の周期の収集も起きる** |
| R-2 | 接続を拒否する宛先（対照） | 同じくホストは止まらず次の周期も収集する。記録された失敗は拒否であって時間切れではない |
| R-3 | 収集器から停止要求でない取り消しが漏れる | 周期の失敗として記録し、次の周期へ進む（ホストは止まらない） |
| R-4 | 停止要求 | 周期は静かに終わる（例外で終わらない） |
| R-5 | 収集の HTTP クライアントの期限 | 構成で与えられ、既定 10 秒、1 未満は 1 秒。gRPC の期限は同じ値を引く（G-9） |
| R-6 | 本番の構成ファイル（［2026-09-27 追加］） | 収集の期限のキーが周期のキーと並んで既定値（10 秒）で明示されており、読み込んで登録を通すと期限が 10 秒になる |
| R-7 | REST の収集中の呼び出し側の取り消し（対照。［2026-09-27 追加］） | 本物の HTTP クライアントが呼び出し側の取り消しを表す形（呼び出し側の取り消しを持つ、時間切れと同じ型の例外）のまま外へ出る。申告なしへ畳まず、収集の失敗として記録しない |
