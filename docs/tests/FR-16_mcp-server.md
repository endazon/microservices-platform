# テスト仕様書: MCP サーバー統合

## 本書の射程

**本書が扱うのは MCP サーバー本体である。** 各サービス側のツール自己申告エンドポイントと、
外部エージェント向け画面は射程外であり、それぞれの担当作業が着手する時点で拡張する。

| 範囲 | 扱い |
| --- | --- |
| 公開許可リストと自己申告の突合（実効ツール一覧） | **本書** |
| ツール呼び出しの統制（登録確認・公開確認・除外・越境・監査） | **本書** |
| **サービスアカウント実行時の個人資料の一律除外** | **本書（中核）** |
| MCP クライアント登録管理 API | **本書** |
| 各サービスのツール自己申告エンドポイントと実行口 | 射程外（各サービスの再実装作業） |
| クライアント登録管理の画面 | 射程外（フロントエンド） |
| 入口のルーティング・レート制限 | 射程外（デプロイ資材） |

## 起点となる計画書（トレーサビリティ）

- 機能要求: プラットフォームの機能を MCP サーバーとして外部 AI エージェントへ公開できること。
  公開ツールは各サービスの自己申告と宣言的な公開構成（許可リスト方式）から動的に構成され、
  実行は利用者・サービスアカウントの権限スコープ内に限定され、応答はデータ越境ポリシーで
  文書単位にフィルタされる
- ユースケース: 外部 AI エージェントからナレッジを利用する／MCP クライアントを登録・管理する
- 関連 ADR: 宣言的公開構成とサービス自己申告による動的ツール連携／**サービスアカウント実行では
  個人資料を一律で対象外とする**（所有者の個人資料であっても含めない）／個人資料を表す
  文書スコープ属性の新設（属性キーと 2 値）／属性ベース認可（deny-by-default・存在秘匿）

## 🔴 中核の受け入れ基準 — サービスアカウント実行時の個人資料

計画は「**同じツールを同じ引数で呼んでも、有人実行と無人実行で結果が変わる**」と明記している。
したがって**否定形テストだけでは足りず、陽性対照と対で置く**。

| # | 観点 | 期待 | 種別 |
| --- | --- | --- | --- |
| N-1 | サービスアカウント実行 | 個人資料が応答に一切現れない | 否定形 |
| N-2 | **所有者本人**のサービスアカウント実行 | 個人資料が応答に一切現れない | 否定形 |
| N-3 | 除外した文書の件数 | **件数にも含まれない**（件数自体がサイドチャネルになるため） | 否定形 |
| N-4 | 検索・文書取得・グラフ探索の**全経路** | いずれの経路でも現れない | 否定形（経路網羅） |
| P-1 | 有人実行 | **同じ個人資料が返る** | 陽性対照 |
| P-2 | 文書スコープ属性を**持たない**文書 | サービスアカウントでも**返る** | 陽性対照 |
| P-3 | 組織文書 | サービスアカウントでも返る | 陽性対照 |

### P-2 が無いと何が分からなくなるか

判定を「個人資料である」（集合帰属）で書いたか、「組織文書でない」（否定）で書いたかは、
**否定形テストだけでは区別できない**。文書スコープ属性は新設で実データが無く、既存文書へ
遡及付与しない方針であるため、否定で書くと**属性を持たない組織文書が一斉に落ちる**。
P-2 はその違いだけを見るテストである。

## 公開統制の受け入れ基準

| # | 観点 | 期待 |
| --- | --- | --- |
| A-1 | 申告はあるが許可リストに無いツール | 一覧に現れず、呼び出しもできない |
| A-2 | 許可リストが空 | 公開ツールは 0 件（既定は非公開） |
| A-3 | 許可リストに無いツールの呼び出し | **「不明なツール」として拒否**する（「権限が無い」と区別させない） |
| A-4 | 公開宣言に対して申告が無い | 構成ドリフトとして報告し、**公開しない** |
| A-5 | 越境分類を欠く申告 | 公開しない |
| A-6 | AI 分析系・要約系のツールを許可リストへ書く | スキーマ検証で拒否する（初期公開範囲外） |
| A-7 | 公開名の重複 | スキーマ検証で拒否する |

## クライアント登録管理の受け入れ基準

| # | 観点 | 期待 |
| --- | --- | --- |
| C-1 | 登録・一覧・無効化 | 管理者が実行できる |
| C-2 | 管理者以外 | 登録管理 API へアクセスできない |
| C-3 | クライアントの無効化 | **次の呼び出しから即座に**拒否される（キャッシュを挟まない） |
| C-4 | 未登録クライアント | 実行を拒否し、公開ツール一覧も返さない |
| C-5 | サービスアカウントへ個人資料を読ませる属性割当 | **登録時も差し替え時も拒否**する |
| C-6 | 個人資料以外の属性割当 | 通る（陽性対照） |

## データ越境の受け入れ基準

| # | 観点 | 期待 |
| --- | --- | --- |
| E-1 | 越境マトリクスの各行 | 機密区分 × 送信先ティアの表どおりに判定する |
| E-2 | 送信不可の文書 | 本文を落とし、参照リンクのみを返す |
| E-3 | 「条件付き可（要承認）」 | 承認経路が実装されるまでは**不可へ倒す** |
| E-4 | 機密区分の欠落・未知の値 | セルフホスト以外へは送らない（安全側） |

## 変異試験（本書の検査が実際に落ちることの確認）

**否定形テストは「落ちること」を確かめないと意味を持たない。** 次の 5 つの変異で確認する。

| 変異 | 期待される結果 |
| --- | --- |
| 応答側の除外を素通しにする | N-1〜N-4 が落ちる |
| 判定を否定（組織文書でない）で書き換える | **P-2 が落ちる**（否定形テストは全部通る） |
| 要求側の除外制約を常に立てない | 下流へ制約を渡す観点が落ちる |
| 許可リストを無視して申告をすべて公開する | A-1〜A-5 が落ちる |
| 無効化の判定を外す | C-3 が落ちる |

## 未実施・残件

- ツール一覧変化のクライアントへの通知は未実装である（実効一覧の版は進むが配信しない）。
- 各サービスの自己申告エンドポイントが未実装のため、**実サービスとの結合は未検証**である。
  収集側は到達不能を「申告なし」として扱い、構成ドリフトへ倒すことだけ確認している。
