# テスト仕様書: 検索・質問する

## 本書の位置づけ

**既にあるテストと計画の受け入れ基準を突き合わせた記録である。** 本書を起こした作業はテストを
1 件も足していない。突き合わせで見つかった穴は「未実施」節に理由つきで書き、必要なものは
別 issue へ切った。写像の規約（テスト直前のコメントに起点 ID を書く）はテスト戦略が正本である。

## 計画の逐語（本書が写像する対象）

- 事前条件: 認証済み。利用者属性が解決できる。
- 事後条件: **権限内の文書のみ**を対象に、**出典付き**の回答が提示される。
- 基本フロー: (1) 質問／キーワードを入力 → (2) 認可で権限スコープを解決 → (3) ハイブリッド検索を
  **属性フィルタ付き**で実行 → (4) 取得チャンクを文脈に LLM で回答を生成 → (5) **出典**（Wiki／
  原本リンク）付きで返す。
- 代替フロー: キーワード検索のみで結果一覧を返し、AI 回答を省略する。
- 例外フロー: **LLM が不調な場合は検索結果のみを返す（縮退運転）**。

## フローの写像

| フロー | 手順 | 検査すること |
| --- | --- | --- |
| 基本 1 | 質問／キーワードを入力する | 空白のみでは送信できない。**クライアントは権限スコープを送らない** |
| 基本 2 | 認可で権限スコープを解決する | 未許可なら**空**を返す（deny-by-default）。クライアントが送ってきたスコープは無視する |
| 基本 3 | ハイブリッド検索を属性フィルタ付きで実行する | 語彙一致とベクトル類似の**両方**を融合する。属性フィルタは検索・候補値列挙の双方へ同じ規則で効く |
| 基本 4 | LLM で回答を生成する | 用途を分けてゲートウェイを呼ぶ。文脈番号と出典番号が一致する |
| 基本 5 | 出典付きで返す | 出典は 1 始まりの連番。Wiki 出典と文書出典を取り違えない |
| 代替 | キーワード検索のみ・AI 回答を省略 | モードを 3 値から選べ、選んだ側の検索系だけを叩く。結果一覧から文書詳細へ辿れる |
| 例外 | LLM 不調 | **出典は残したまま**縮退文言を返す。画面はキーワード検索へ落ちる |

### T-24 を陽性対照として置く理由

境界（BFF）で資格情報の伝播を外すと、認可の効いた否定形テストは**全部 401／空のまま緑**になる。
否定形だけでは検出力が無いので、必ず対で置く。

## 未実施（しない／一部する）

- **性能（検索 p95・RAG 初回応答）は本書では測らない。** 別のテスト仕様書（性能・負荷試験）が
  引き受ける。ここで重複して書くと、床の正本が 2 つになる。
- **実 Qdrant・実 LLM を通した end-to-end は一部しかしない。** 統合テストは Testcontainers に
  依存し、Docker daemon の無い環境では skip される（skip のまま緑になる）。したがって
  「統合テストが緑」を「実体で通った」と読んではならない。
- **ストリーミングの中断・再接続の網羅は一部する。** 中断を誤りとして表示しないことは検査するが、
  再接続の再開位置は契約が無いため検査しない。
