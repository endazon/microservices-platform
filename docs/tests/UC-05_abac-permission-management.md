# テスト仕様書: ABAC 権限を管理する

## 本書の位置づけ

**既にあるテストと計画の受け入れ基準を突き合わせた記録である。** 本書を起こした作業はテストを
1 件も足していない。穴は「未実施」節に理由つきで書いた。

## 計画の逐語（本書が写像する対象）

- 事前条件: **管理権限を持つ**。
- 事後条件: ポリシーが反映され、**検索・回答・閲覧に適用される**。利用者へ割り当てたロール・
  ABAC 属性が **Keycloak・属性ストアへ反映され認可判定に適用される**。**無効化した利用者の
  全セッションが失効している**。
- 基本フロー: (1) 属性体系・タグ・ポリシー（利用者属性 × 文書属性）を定義する → (2) 保存し、
  認可判定に適用する → (3) 個々の利用者へロール・ABAC 属性を割り当て、必要に応じてアカウントを
  無効化する → (4) Keycloak・属性ストアへ反映し、**即時反映**する。無効化時は当該利用者の
  **全セッションを即時失効**させる。
- 例外フロー: **矛盾するポリシーは保存前に検証し、エラーを返す**。

## フローの写像

| フロー | 手順 | 検査すること |
| --- | --- | --- |
| 事前条件 | 管理権限 | 管理 API は管理者だけ。運用者・一般利用者は拒否。画面は**存在ごと隠す** |
| 基本 1 | 属性体系・タグ・ポリシーを定義する | 値域・重複・スコープを検証する。参照されている属性は消せない |
| 基本 2 | 保存して認可判定に適用する | 保存したポリシーが即座にスコープ解決へ効く |
| 基本 3 | ロール・ABAC 属性を割り当て、無効化する | 割当は**値域内**に限る。空の割当は拒否。**利用者の作成口は存在しない** |
| 基本 4 | 反映し、無効化で全セッションを失効させる | 無効化は**セッションも失効**させる。有効化は何も失効させない |
| 例外 | 矛盾するポリシー | 保存前に検証してエラー。**試し検証（保存しない）**が保存と同じ判定を返す |

### T-15 を置く理由

「試し検証」が保存と別の判定器を使っていると、**画面で通ったのに保存で落ちる**（またはその逆）。
保存しないことと、同じ入力に同じ判定を返すことを**対で**固定する。

### T-26 を置く理由

無効化がセッションを失効させることだけを測ると、**常に全セッションを失効させる実装**でも緑になる。
有効化では失効しないことを陽性対照として置く。

## 未実施（しない／一部する）

- **Keycloak の稼働を要する経路は測らない。** ロール割当の実反映・セッション失効の実挙動は
  認可サーバーが要り、CI はこれを起動しない。テストは記録スタブに対して「失効を要求したこと」まで
  確かめる。**「要求した」を「失効した」と読んではならない。** 稼働環境で実際に届いていない件は
  #1101 が追っている（本書では新たに起票しない）。
- **ログイン・多要素・パスワード再設定は本書の射程外。** それぞれのテスト仕様書が持ち、
  写像の残件として allowlist の `pending` に載っている（本作業では触らない）。
- **ポリシー反映が検索・回答・閲覧へ効くことは、本書では入口までしか測らない。** 実際に効くことは
  検索・分析・Wiki 閲覧のテスト仕様書がそれぞれの経路で測る。**同じ床を 4 箇所に置かない。**
- **運用ダッシュボードは関連画面として触れるだけ**である。集計・可観測性の受け入れ基準は
  運用ダッシュボードのテスト仕様書が持つ。
