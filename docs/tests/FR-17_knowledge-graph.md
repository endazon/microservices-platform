# テスト仕様書: 知識グラフ（型付き辺・ホップごとのアクセス制御）

## 起点となる計画書（トレーサビリティ）

- 機能要求: 文書間のリンクを保持し、被参照を含めて探索できること。関係の種類と出所を区別して保持し、探索結果は利用者のアクセススコープ内に限ること。**判定はホップごとに行い**、閲覧権のない文書への辺は件数・匿名ノードを含め一切返さないこと
- 関連する裁定: 知識グラフのデータモデルと格納先／グラフ探索時のアクセス制御強制方式／属性ベースアクセス制御／所有者ベースの裁量制御

## テスト対象・範囲

- 対象: `AbacNodeFilter`（許可スコープの評価意味論）、`AuthorizedNode`／`GraphViewResponse`（**型ゲート**）、`GraphAccessResolver`（認可サービス障害時の縮退）、`EdgeType`／`Edge`／型の初期値集合（辞書の性質）、**辺と辺の型のスキーマが持つ DB 層の制約**、および**本文からのリンク抽出・既定型への写像・自動抽出の辺の差分更新**。
- 対象外: 多ホップ探索と表示上限（別issueへ分割）、辺の型辞書の API、属性同期、提案。

## テスト観点

- **deny-by-default**: 許可ポリシーが無ければ何も可視でない。認可サービスが応えないときも同じ側へ倒れる。
- **評価意味論の一致**: フィルタ間 AND・値集合内 OR・**属性欠落は不一致**・大文字小文字を無視。Wiki 閲覧側のフィルタと同じ規則であること。
- 🔴 **型ゲートが回避不能であること**: 許可判定を経ずにノードを展開する経路、および濾していない結果を直列化する経路が、いずれも**構築できない**こと。ゲートが後から緩められたら落ちること。
- **辞書の性質**: 改名しても既存の辺が 1 行も書き換わらないこと。初期値集合が入り、冪等で、改名を巻き戻さないこと。
- 🔴 **DB 層の防壁が「宣言されている」ではなく「発火する」ところまで見えていること**: 参照ありの型の削除拒否・名前の一意・辺の重複防止は、いずれも実データベースでしか発火しない。**拒否されたことと、拒否した制約の名前まで**見る。あわせて、**張っていない外部キーが後から生えていないこと**をカタログで固定する（書き込みでは反証できないため）。
- **対称関係の正規化**: 向きの違う 2 通りの書き込みが同一行に落ちること。方向型は向きを保つこと。
- **書き手が表明した意味が落ちないこと**: 一般参照・特定箇所への参照・埋め込み・明示指定の 4 通りが、それぞれ別の既定型へ届くこと。**すべて既定の関連型へ丸まったら赤くなる**こと。
- 🔴 **差分更新が消してよいものだけを消すこと**: 再取り込みで消えるのは**当該文書の本文から自動抽出した辺だけ**であり、利用者が付けた辺・承認済み提案の辺・**他文書の本文から抽出した辺**は残ること。対称関係は始点欄が抽出の起点を表さないため、**起点欄を見ずに絞ると他文書由来の辺まで巻き込む**。
- 🔴 **本文が取得できないときに辺を触らないこと**: 取得不能を空の本文として扱うと「全リンクが消えた」と解釈され、**当該文書起点の辺が静かに全消しになる**。表示側の読み取りと違い、ここは代替本文へ縮退してはならない。
- **辞書に無い型を捨てないこと**: 既定の関連型へ丸めたうえで、件数として観測できること（**0 が正常**）。丸めた事実が数に出ないなら、規定外の記法が入り続けても気付けない。
- **再取り込みが冪等であること**: 同じ本文なら行が入れ替わらず、本文が変わっていない更新では本文取得そのものが起きないこと。
- ⚠ **未強制の明示**: 所有者に基づく判定が**まだ効いていない**ことを固定し、前提が解消されたら気付けること。

## 実装マッピング

- `AbacNodeFilterTests`（T-01〜T-09）
- `GraphTypeGateArchitectureTests`（T-10〜T-14）
- `GraphAccessResolverTests`（T-15〜T-19）
- `EdgeTypeDictionaryTests`（T-20〜T-28）
- `EdgeTypeEndpointsTests`（T-31〜T-38。**アプリ層のガードのみ**）
- `UserAuthoredEdgeTests`（T-41〜T-46。**ここで効いているのはアプリ層の事前検査だけ**。同じ重複を DB 層で拒む `ux_edges` は次の `EdgeTypeDbGuardTests` が受け持つ）
- `EdgeTypeDbGuardTests`（T-39 / T-40 / T-47 / T-48。**実 PostgreSQL を起動する結合テスト**）
  - **単体テストでは原理的に測れない層である。** 単体側は EF の InMemory プロバイダを使っており、
    **InMemory は一意索引も外部キーも強制しない**。変異試験 G-1 の実測（アプリ層のカウントを外すと
    500 ではなく **204 で黙って消えた**）が、この層が一度も効いていなかったことを示していた
  - **スキーマは起動時マイグレーションが作ったものを見る**（モデルからの直接生成を使わない）。
    そうしないと「マイグレーションが削除規則を正しく出力しているか」を測れない
  - 🔴 **削除は、参照している辺を 1 件も読み込んでいない文脈から行う**（T-39）。同じ文脈で親子を
    作ってから親を消すと、**O/R マッパが変更追跡の側で先に例外を投げ、削除文が 1 度も発行されない**
    —— 例外は出るのにデータベースには届かず、**防壁を確かめたつもりで何も確かめていない**状態になる
    （初版がこの形で落ちたのを実測した）。**本番の削除経路も辺を追跡しない**（使用件数はスカラの件数
    集計で数える）ので、この形が実態とも一致する
  - 🔴 **実行されるのは統合ワークフロー（`integration.yml`。develop への push ＋ 日次 ＋ 手動）だけである。**
    PR の CI は実コンテナを要するテストを除外するため、**PR の段階では走らない**。
    加えて Docker daemon が無い環境では skip される —— **「緑だった」は「実行された」の証拠にならない。**
    確認は統合ワークフローの生の出力で、対象が `Passed` として現れることと skip 件数まで読む
- `AbacUnenforcedAxisTests`（T-29〜T-30。**所有者に基づく判定が効くようになったら赤くなる**。そのときは削除せず、強制されたことを確かめる形へ書き換える）
- `ObsidianLinkParserTests`（T-49〜T-54 の抽出側。**純粋関数であり、データベースも購読も要らない**）
- `EdgeTypeResolverTests`（T-49〜T-53 の型解決側と T-55・T-55P・T-56。**辞書は引数で渡す** —— 型の集合は実行時に変わるものであり、テストも「そのときの辞書」を渡して測る）
  - 既定型の名前が初期値集合の既定型と一致することを 1 件で固定している。**層をまたぐため定数を共有できず、値が割れても構文上は通ってしまう**（本文からの抽出が黙って辺を作らなくなる形で壊れる）
- `LinkEdgeSyncTests`（T-55〜T-64。**購読ハンドラ経由の統合**。計測は試験用の計器工場と測定リスナで実測する）
  - 🔴 **差分の否定形（T-57・T-62）には必ず陽性対照を置く**。「消えていない」は、そもそも辺が入っていなくても緑になる
  - T-63 は**識別子の大小関係そのものを 1 行で主張してから**測る。前提が崩れると正規化が起きず、テストが何も測らない状態で緑になる
