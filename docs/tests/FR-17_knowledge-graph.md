# テスト仕様書: 知識グラフ（型付き辺・ホップごとのアクセス制御）

## 起点となる計画書（トレーサビリティ）

- 機能要求: 文書間のリンクを保持し、被参照を含めて探索できること。関係の種類と出所を区別して保持し、探索結果は利用者のアクセススコープ内に限ること。**判定はホップごとに行い**、閲覧権のない文書への辺は件数・匿名ノードを含め一切返さないこと
- 関連する裁定: 知識グラフのデータモデルと格納先／グラフ探索時のアクセス制御強制方式／属性ベースアクセス制御／所有者ベースの裁量制御

## テスト対象・範囲

- 対象: `AbacNodeFilter`（許可スコープの評価意味論）、`AuthorizedNode`／`GraphViewResponse`（**型ゲート**）、`GraphAccessResolver`（認可サービス障害時の縮退）、`EdgeType`／`Edge`／型の初期値集合（辞書の性質）。
- 対象外: 多ホップ探索と表示上限（別issueへ分割）、辺の型辞書の API、属性同期、リンク抽出、提案。

## テスト観点

- **deny-by-default**: 許可ポリシーが無ければ何も可視でない。認可サービスが応えないときも同じ側へ倒れる。
- **評価意味論の一致**: フィルタ間 AND・値集合内 OR・**属性欠落は不一致**・大文字小文字を無視。Wiki 閲覧側のフィルタと同じ規則であること。
- 🔴 **型ゲートが回避不能であること**: 許可判定を経ずにノードを展開する経路、および濾していない結果を直列化する経路が、いずれも**構築できない**こと。ゲートが後から緩められたら落ちること。
- **辞書の性質**: 改名しても既存の辺が 1 行も書き換わらないこと。初期値集合が入り、冪等で、改名を巻き戻さないこと。
- **対称関係の正規化**: 向きの違う 2 通りの書き込みが同一行に落ちること。方向型は向きを保つこと。
- ⚠ **未強制の明示**: 所有者に基づく判定が**まだ効いていない**ことを固定し、前提が解消されたら気付けること。
