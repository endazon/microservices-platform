# テスト仕様書: 知識グラフ（型付き辺・ホップごとのアクセス制御）

## 起点となる計画書（トレーサビリティ）

- 機能要求: 文書間のリンクを保持し、被参照を含めて探索できること。関係の種類と出所を区別して保持し、探索結果は利用者のアクセススコープ内に限ること。**判定はホップごとに行い**、閲覧権のない文書への辺は件数・匿名ノードを含め一切返さないこと
- 関連する裁定: 知識グラフのデータモデルと格納先／グラフ探索時のアクセス制御強制方式／属性ベースアクセス制御／所有者ベースの裁量制御

## テスト対象・範囲

- 対象: `AbacNodeFilter`（許可スコープの評価意味論）、`AuthorizedNode`／`GraphViewResponse`（**型ゲート**）、`GraphAccessResolver`（認可サービス障害時の縮退）、`EdgeType`／`Edge`／型の初期値集合（辞書の性質）、**辺と辺の型のスキーマが持つ DB 層の制約**、および**本文からのリンク抽出・既定型への写像・自動抽出の辺の差分更新**、**所属 1 件の単独クラスタを要約と未要約の計数から外すこと**（2026-09-27〜）、**日次のクラスタ検出が前回の成功から 1 日ごとに回り、再起動で取りこぼさないこと**（2026-10-04〜）、**同じタグを持つ文書の組を結ぶ辺・Wiki の文書ページへのリンクの解決・後から届いた相手へのリンクの張り直し**（2026-10-09〜）。
- 対象外: 多ホップ探索と表示上限（別issueへ分割）、辺の型辞書の API、属性同期、提案。

## テスト観点

- **deny-by-default**: 許可ポリシーが無ければ何も可視でない。認可サービスが応えないときも同じ側へ倒れる。
- **評価意味論の一致**: フィルタ間 AND・値集合内 OR・**属性欠落は不一致**・大文字小文字を無視。Wiki 閲覧側のフィルタと同じ規則であること。
- 🔴 **型ゲートが回避不能であること**: 許可判定を経ずにノードを展開する経路、および濾していない結果を直列化する経路が、いずれも**構築できない**こと。ゲートが後から緩められたら落ちること。
- **辞書の性質**: 改名しても既存の辺が 1 行も書き換わらないこと。初期値集合が入り、冪等で、改名を巻き戻さないこと。
- 🔴 **DB 層の防壁が「宣言されている」ではなく「発火する」ところまで見えていること**: 参照ありの型の削除拒否・名前の一意・辺の重複防止は、いずれも実データベースでしか発火しない。**拒否されたことと、拒否した制約の名前まで**見る。あわせて、**張っていない外部キーが後から生えていないこと**をカタログで固定する（書き込みでは反証できないため）。
- **対称関係の正規化**: 向きの違う 2 通りの書き込みが同一行に落ちること。方向型は向きを保つこと。
- **書き手が表明した意味が落ちないこと**: 一般参照・特定箇所への参照・埋め込み・明示指定の 4 通りが、それぞれ別の既定型へ届くこと。**すべて既定の関連型へ丸まったら赤くなる**こと。
- 🔴 **差分更新が消してよいものだけを消すこと**: 再取り込みで消えるのは**当該文書の本文から自動抽出した辺だけ**であり、利用者が付けた辺・承認済み提案の辺・**他文書の本文から抽出した辺**は残ること。対称関係は始点欄が抽出の起点を表さないため、**起点欄を見ずに絞ると他文書由来の辺まで巻き込む**。
- 🔴 **本文が取得できないときに辺を触らないこと**: 取得不能を空の本文として扱うと「全リンクが消えた」と解釈され、**当該文書起点の辺が静かに全消しになる**。表示側の読み取りと違い、ここは代替本文へ縮退してはならない。
- **辞書に無い型を捨てないこと**: 既定の関連型へ丸めたうえで、件数として観測できること（**0 が正常**）。丸めた事実が数に出ないなら、規定外の記法が入り続けても気付けない。
- **再取り込みが冪等であること**: 同じ本文なら行が入れ替わらず、本文が変わっていない更新では本文取得そのものが起きないこと。
- 🔴 **単独クラスタを要約しないこと・未要約に数えないこと**: 所属 1 件のクラスタは要約の対象外である。要約の生成と未要約の計数の**両方**が同じ判定の入口を通ること。**陽性対照**（所属 2 件以上は従来どおり対象になる）を必ず並べる。
- 🔴 **日次の検出が再起動で止まらないこと**: 周期の位相は前回の**成功**に付く。起動から 1 日を数える形では、毎日作り直される Pod で検出が永久に走らない。成功の記録は**検出の保存と同じ保存**で書き、失敗した周期は記録しない。期限の判定は排他リースの内側で読み直す（新旧 2 つの Pod が両方走らない）。**陰性（期限内なら起動では走らない）と陽性（期限切れ・記録なしなら起動の待ちの直後に走る）を必ず対で並べる。** 最後の成功の時刻は計器で読め、記録が無い間は値を出さない。
- 🔴 **共有タグの辺が裁定どおりに張られ、二乗で膨らまないこと**: 同じタグを持つ 2 文書の間に既定の関連型・出所は自動抽出の辺が**組あたり 1 本**でき、タグを外すと消える。大小文字・前後の空白だけが違うタグは同じタグである。**文書数が上限を超えるタグからは辺を作らない**（上限ちょうどは作る）。上限を**跨いだ**ときは、受信した文書を含まない組も増減する。タグだけの更新で本文を読みに行かない。
- 🔴 **他の出所の辺と重ならず、互いを消さないこと**: 本文のリンクが同じ関係を表明すれば共有タグの行を引き取り、リンクが消えたら**同じ行**が共有タグの辺へ戻る（同じ保存の中で同じ一意キーの行を消して入れ直さない）。本文のリンクの差分は共有タグの辺に触れない。利用者付与・承認済みの辺には重ねず、利用者付与・承認が共有タグの行を引き取ったら、タグを外しても消えない。
- 🔴 **Wiki のリンクを文書 ID で解決すること**: サイト内の絶対パス・ロケール接頭辞つき・URL の形の文書ページへのリンクが文書 ID で解決し、存在しない ID は未解決に数える。題名とは突き合わせない。先頭がスラッシュのサイト内パスを外部 URL として捨てない。
- 🔴 **後から届いた相手へ張り直すこと**: 先に届いた文書のリンクは、相手が届いた・改名された・同名が増えた／消えたときに、起点の本文を読まずに張り直す（構文の別・アンカーを保つ）。**この機能より前に保存した、構文の別を持たない行**の起点は張り直さない（既存の辺も消さない）。
- 🔴 **共有タグの辺も閲覧権の判定を同じ門で通ること**: 閲覧権の無い文書との共有タグの辺は、近傍にも件数にも現れない（陽性対照つき）。
- ⚠ **未強制の明示**: 所有者に基づく判定が**まだ効いていない**ことを固定し、前提が解消されたら気付けること。
