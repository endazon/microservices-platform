### ナレッジ健全性の指標

**4 つの規則（全体集計・ロール限定・個人資料除外・件数のみ）を、それぞれ独立に固定する。**
1 つでも欠けると存在秘匿が崩れるため、まとめて 1 本のテストにしない。

> **観測値の受け口は `/internal/...` にあり、認可を課さない。** 生産者は利用者 JWT を持たない
> 定期処理であり、統制は mTLS ＋ ネットワーク分離である（**認可ではない**）。
> **統制が働いていること自体はここでは測れない** —— 機械検査が押さえているのは
> 「host 公開しない」「Service は既定 ClusterIP」の 2 点だけである。

### 陳腐化文書数の生産（GraphService 側。#1186）

🔴 **中心は T-48 である** —— タグを付け替えただけの文書が件数から消えないこと。
**陰性テストは必ず陽性対照と対で置く**（前進しないことだけを測ると、一度も前進しない実装でも緑になる）。

| ID | 対象 | 内容 | 期待 |
| --- | --- | --- | --- |
| T-45 | GraphService | 本文更新が 181 日前（境界の外側） | 陳腐として報告される |
| T-46 | GraphService | 本文更新が 179 日前（境界の内側） | 含まれない |
| T-47 | GraphService | 本文更新が**しきい値ちょうど** | 含まれない（ちょうどを含めると警告が 1 日早く出る） |
| T-48 | GraphService | 🔴 200 日前に本文更新＋**昨日タグを付け替えただけ** | **依然として含まれる**（自分の改善作業で消える指標は測定ではない） |
| T-49 | GraphService | 200 日前に本文更新＋**昨日本文を編集**（陽性対照） | 含まれない |
| T-50 | GraphService | 個人資料 / 組織文書 / 属性なし / 綴りの大小 | 文書スコープが正しく添う（陽性対照つき） |
| T-51 | GraphService | **該当が 0 件** | 空のスナップショットを送り、**しきい値は添える** |
| T-52 | GraphService | 構成なし | **180 日**で判定する |
| T-53 | GraphService | 構成で 90 日 | **90 日**で判定し、報告に添えるしきい値も 90 |
| T-54 | GraphService | 構成が 0 以下（不正） | **既定へ倒す。起動は落とさない**。報告値も倒した後の 180 |
| T-55 | GraphService | 送出本文（しきい値つき） | `indicator` / `observations` / `thresholdDays` の 3 項目ちょうど |
| T-56 | GraphService | 送出本文（しきい値なし。陰性対照） | 2 項目のまま（受け口は欠落を「しきい値なし」として扱う） |

**ドメイン側**（`GraphDocumentBodyUpdatedAtTests`）は前進規則そのものを固定する ——
指紋が変われば前進する（陽性対照）／メタデータのみの更新では前進しない（本裁定の中心）／
指紋 null は「不明」であり変更ではない／順序ガードが先に効く／同一指紋の再配信では動かない。
