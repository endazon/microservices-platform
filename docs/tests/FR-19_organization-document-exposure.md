# テスト仕様書: 露出の 3 属性を 3 つとも除外にした組織文書

> 機能（FR）単位で作成する。計画リポジトリの受け入れ基準とユースケースのフローをテストケースへ写像する。

## テスト対象・範囲

露出の 3 属性（横断検索 `search_exposure`・ナレッジグラフ `graph_exposure`・AI の入力 `ai_input`）を
**3 つとも `excluded` にした組織文書**が、どの消費面にも載らないこと。利用者の裁定（2026-10-10）で、
別システム（生成 AI 株取引）の承認待ちの報告書（ドラフト）をこの形で保存すると決まった。
文書詳細画面では ABAC の範囲で閲覧でき、索引・検索・AI 回答・グラフ・MCP・Wiki には載らない。

| 範囲 | 扱い |
| --- | --- |
| 判定（単一情報源の述語） | **本書** |
| 取り込み（チャンクの生成と撤収） | **本書** |
| 検索の出口（横断検索の用途・AI の入力の用途） | **本書** |
| AI 回答の文脈の選別 | **本書** |
| グラフの同期（ノードの生成と撤収） | **本書** |
| Wiki 同期（Wiki.js への反映と撤去） | **本書** |
| MCP の文書一覧と個別の取得 | **本書**（ケースの本体は [MCP サーバーのテスト仕様書](FR-16_mcp-server.md) の X-70） |
| 個人資料の露出 | 射程外（[個人資料のライフサイクル](FR-19_private-notes-lifecycle.md)・[Wiki 同期の除外](FR-19_private-note-wikijs-exclusion.md)） |
| 作成時の検証 | 射程外 —— 組織文書の露出キーは従来どおり受け付ける（拒否すると保存できない） |

## テスト観点

- 🔴 **否定形には陽性対照を対で置く。** 同じ器で、露出キーの無い組織文書（既存の文書と同じ形）と、含めるへ戻した組織文書が載ることを示す。
  「全部落とす」実装と「露出を見ない」実装のどちらも、否定形だけなら通す。
- **含める → 除外は、絞り込みではなく撤収である**（チャンク・ノード・Wiki ページの実体を消す）。除外 → 含めるで再び載る。
- **一部だけ除外した組織文書は従来どおり載る**（判定の粒度は索引の門と同じ「1 つでも含めれば載せる」）。
- 個人資料の既存の振る舞い（Wiki の既存ページを残す二層目・MCP の一覧に出る）を変えない。

## 変異試験（実測値）

| 変異 | 実測 |
| --- | --- |
| Wiki の述語を「個人資料でない」だけにする（露出を見ない） | **4 件が落ちた**（Wiki サービスの試験のうち OE-11 の 2 状態・OE-12・OE-13）。陽性対照（OE-14・OE-15・露出キーの無い組織文書）は緑のまま |
| MCP の一覧の述語を常に真にする | **OE-16 が落ちた**（文書サービスの MCP の実行口の試験 46 件中 1 件） |

## テストデータ

- 組織文書は機密区分 internal・文書スコープ属性を組織文書の値にし、露出の投影を 3 属性まとめて付ける（1 つでも書き漏らさない）。
- MCP の試験の文書は**その試験の利用者が所有する restricted** にする。器の DB は同じコレクションの試験で共有され、他の利用者に見える文書を足すと
  「MCP の一覧の件数が REST と一致する」試験（X-59）を壊す。
