# テスト仕様書: データソースを登録・同期する

## 本書の位置づけ

**既にあるテストと計画の受け入れ基準を突き合わせた記録である。** 本書を起こした作業はテストを
1 件も足していない。穴は「未実施」節に理由つきで書いた。

## 計画の逐語（本書が写像する対象）

- 事前条件: **接続情報（認証情報は Vault 管理）**が用意されている。
- 事後条件: 取得した原本が**変換・取り込みに渡る**。
- 基本フロー: (1) 管理者がソース（**ファイルサーバー／Wiki／SaaS／業務 DB**）を登録する →
  (2) システムが**定期的**に原本を取得し、変換へイベント送出する。
- 代替フロー: **手動同期**を実行する。
- 例外フロー: **接続失敗時は再試行し、継続失敗はアラートする**。

## フローの写像

| フロー | 手順 | 検査すること |
| --- | --- | --- |
| 事前条件 | 接続情報を預ける | **認証情報は応答へ出さない**（伏せ字）。伏せ字を書き戻しても保存済みの値を壊さない。資格情報つき接続 URI は登録そのものを拒否する |
| 基本 1 | 4 種のソースを登録する | 4 種すべてに差分検出（増分）と原本取得の実装がある。必須属性は登録時に埋まる |
| 基本 2 | 定期的に取得しイベントを送る | **単一書き手**である（同時に 2 つ走らない）。周期は設定から入り、既定は安全側。成功時だけ基準時刻を進める |
| 事後条件 | 変換・取り込みへ渡る | 同じ事象を複数の購読者が受け取る。取り込みは決定的なチャンク ID を作り、再取り込みで重複しない |
| 代替 | 手動同期 | 管理者・運用者が実行できる。ロール無しは 403 |
| 例外 | 接続失敗 | 基準時刻を**進めない**。誤りは伏せ字にして保存する。**再試行上限に達したところでアラート状態**になり、成功で解除される |

### T-08 を置く理由

伏せ字の書き戻しを一律に「保存済みの値を保つ」と解釈すると、**利用者が本当に書き換えたつもりの
編集が黙って捨てられる**。伏せ字と一致するときだけ保持し、編集されていたら拒否する。

## 未実施（しない／一部する）

- **Vault そのものの運用（封印解除・ローテーション）は測らない。** 本書が測るのは
  「資格情報がアプリの応答・保存・ログへ漏れない」ことだけである。
- **アラートの通知経路（誰にどう届くか）は測らない。** 本書が測るのはアラート**状態**への到達と
  解除である。通知は運用・可観測性の文書が引き受ける。
- **取り込み 1 万件/時 の性能は測らない。** 性能・負荷試験のテスト仕様書が持つ。
- **実 PostgreSQL / 実 RabbitMQ を通した検査は一部しかしない。** 統合テストは Testcontainers に
  依存し、Docker daemon の無い環境では skip される（skip のまま緑になる）。
- **外部 SaaS・業務 DB の実接続はしない。** 接続子は記録スタブで検査する。実接続は資格情報と
  外部可用性に依存し、CI で再現できない。
