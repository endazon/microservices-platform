# テスト仕様書: AI 分析を依頼する

## 本書の位置づけ

**既にあるテストと計画の受け入れ基準を突き合わせた記録である。** 本書を起こした作業はテストを
1 件も足していない。穴は「未実施」節に理由つきで書いた。

## 計画の逐語（本書が写像する対象）

- 事前条件: 認証済み。**対象範囲に対する閲覧権限がある**。
- 事後条件: 分析結果が**出典付き**で提示される。
- 基本フロー: (1) 分析対象（**タグ／部門／プロジェクト**／検索条件）と分析内容を指定する。
  **候補は権限内に限る**。**「フォルダ」は 2026-08-05 に削除した**（文書属性に `folder` が無く、
  フォルダは取り込み時に属性へ写像されて消えるため、絞り込みの軸として存在しなかった）
  → (2) 認可で対象範囲を権限内に限定する → (3) LLM ゲートウェイ経由で分析を実行する
  → (4) 結果と出典を返す。
- 代替フロー: 機密区分の高いデータは外部 API へ送信せず、セルフホスト LLM で処理する。
- 例外フロー: 対象が権限外の場合は**対象から除外**する。**権限の有無は利用者に開示しない**
  （「権限が無い」と「該当が無い」を区別させない存在秘匿）。

## フローの写像

| フロー | 手順 | 検査すること |
| --- | --- | --- |
| 基本 1 | 分析対象と分析内容を指定する | 軸は**タグ／部門／プロジェクトの 3 つだけ**でフォルダ軸を持たない。候補値は**到達可能な文書に出る値だけ**で、件数を漏らさない |
| 基本 2 | 対象範囲を権限内に限定する | 範囲は権限を**狭めるだけ**で広げない。範囲が権限外なら**全拒否** |
| 基本 3 | LLM ゲートウェイ経由で実行する | 用途を「分析」として呼ぶ（質問回答と用途が混ざらない）。分析の種別がプロンプトへ反映される |
| 基本 4 | 結果と出典を返す | 出典番号と文脈番号が一致する。AI 未使用なら「使っていない」と言う |
| 代替 | 機密区分の高いデータ | 越境が拒否されたときも**出典は残し**縮退文言を返す |
| 例外 | 対象が権限外 | 除外する。403 を返さず、**「該当なし」と同じ見え方**にする |

### T-23 を置く理由

「権限が無い」と「該当が無い」を同じに見せる規則を、**障害まで同じに見せる**方向へ広げると、
利用者は壊れた検索を「結果なし」と読んでしまう。存在秘匿の対象は**権限**であって障害ではない。

## 未実施（しない／一部する）

- **セルフホスト LLM への振り分けそのものは本書では測らない。** 経路の決定（機密区分 → 送信先）は
  LLM 送信経路のテスト仕様書が引き受ける。本書が測るのは「拒否されたときに縮退し、出典を失わない」
  という利用者側の観測である。**両方に床を置くと、どちらが正本か分からなくなる。**
- **候補値の絞り込みの検査は検索側のテスト仕様書と共有する。** 同じ属性値列挙 API を分析画面が
  再利用しており、テストは検索側の起点 ID コメントを持つ。**同じテストを 2 度数えないため**、
  本書は対応関係だけを記録する。
- **性能（分析の応答時間）は測らない。** 性能・負荷試験のテスト仕様書が持つ。
- **実 LLM を通した end-to-end はしない。** 統合テストは Testcontainers に依存し、Docker daemon の
  無い環境では skip される（skip のまま緑になるので「実体で通った」と読んではならない）。
