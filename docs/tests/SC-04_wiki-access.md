# テスト仕様書: Wiki 閲覧画面

> **［2026-09-03 全面改訂］** 画面が Wiki.js への外部リンク 1 本から、ページツリー・本文・検索を基盤 SPA が描く形へ

> 失効し、下の表へ置き換えた。後段（前段ゲートウェイの ABAC・存在秘匿・BFF の透過）は UC のテスト仕様書が測る。

## 起点となる計画書（トレーサビリティ）

- 機能要求: 正規化文書を Wiki サービスで閲覧できること／ABAC アクセス制御 ／ ユースケース: Wiki で閲覧する
- 受け入れ基準の所在: Issue #1200 ／ `.ai-context/specs/20260903_issue-1200_sc04-wiki-screen-via-bff.md`

## テスト対象・範囲

- 対象: `features/sc04-wiki`（ページツリー・本文・検索・状態の描き分け・sanitize）、`lib/wiki-pages`（権限内台帳の索引。
  検索／チャット質問画面・文書詳細画面の導線が使う）。
- 対象外: WikiService の ABAC・存在秘匿・Wiki.js 委譲（UC のテスト仕様書 T-01〜T-52）。BFF の透過（同 T-42〜T-52）。

## テスト観点

- 取得経路: 一覧・本文（スラッグ／文書 ID）・検索のすべてが `/bff/wiki/*` を通り、**外部リンクが 1 本も無い**。
- 存在秘匿: 一覧の空・検索の 0 件・本文の 404 を**中立**に描く（「権限が無い」と言わない）。**陽性対照**として権限内が見える。
- 故障: 502 を空で隠さない（`role="alert"`）。
- sanitize: Wiki.js の構造は残し、スクリプト・メディア・`target` は落ち、ページ間リンクは `/wiki?doc=` へ書き換わる。
- URL: `?page=` / `?doc=` / `?q=` が単一情報源。`page` が `doc` に勝つ。
- 認証: 未認証 `/wiki` → `/login`。
