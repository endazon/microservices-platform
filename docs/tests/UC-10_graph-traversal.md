# テスト仕様書: 関係を辿って根拠に到達する

## 起点となる計画書（トレーサビリティ）

- ユースケース: 起点となる文書から関係を辿り、権限内の文書だけで構成された近傍を得る。深さは既定 2・上限 3
- 事前条件: 認証済みであること。利用者属性が解決できること。起点文書の閲覧権限があること
- 例外フロー: 権限のないノードへの辺は**応答のどの形でも返さない**（件数・匿名ノードを含む）。利用者は「リンク切れ」と「権限不足」を区別できない（受け入れ済みの副作用）

## テスト対象・範囲

- 対象: 起点ノードの読み取り経路における**存在秘匿**と、認証・認可の縮退。
- 対象: 起点ノードの読み取り経路における**存在秘匿**、認証・認可の縮退、**多ホップ展開・表示上限・深さ上限の拒否**。
- 対象外（別issueで追加する）: 根拠検索への統合（BFF 公開を含む）。

> **［2026-08-22 追記］多ホップ探索が入り、T-08〜T-10 を実装した。** 深さ 0 までだった段階から、
> 展開・表示上限・深さ上限の否定形と**その陽性対照**まで覆う範囲へ広がった。

## テスト観点

- **存在秘匿**: 権限なし／複製が未到達／文書が存在しない、の 3 経路が**応答として区別できない**こと。状態コードだけでなく本文とヘッダまで一致すること。
- **拒否の選択**: 権限がないときに 403 を返さないこと（403 は「存在はする」ことを漏らす）。
- **deny-by-default**: 許可ポリシーが無ければ起点自体も見せないこと。
- **認証**: 未認証は 401（存在秘匿の前段）。
- **対照群**: 見えるものは見えること（全経路が 404 になって検査が空振りしていないことの担保）。
