# テスト仕様書: 外部 AI エージェントからナレッジを利用する

## 本書の射程

**MCP サーバー側の統制だけを扱う。** 各サービスのツール実行口は未実装であり、
本書は「MCP サーバーが下流の応答をどう扱うか」を偽の下流で固定する。

## フローの写像

| フロー | 手順 | 検査 |
| --- | --- | --- |
| 基本 1 | 公開ツール一覧を取得する | 実効一覧（許可リスト ∩ 自己申告）だけが返る |
| 基本 2〜3 | ツールを引数付きで呼び、主体の権限スコープを解決する | 登録簿から主体種別を解決する。トークンの申告は採らない |
| 基本 4 | 対象サービスがツールを実行する | 申告された実行口へ委譲し、実行スコープを渡す |
| 基本 5 | 文書単位に送信可否を判定し応答をフィルタする | 越境マトリクスどおりに本文の可否を決める |
| 代替 | 送信不可の文書 | 本文を返さず参照リンクのみを返す |
| 例外 1 | 未登録クライアント・無効トークン | 実行を拒否する。一覧も空で返す |
| 例外 2 | 権限外の文書 | 応答に一切含めない（存在秘匿。下流の責務であり本書では扱わない） |
| 例外 3 | 🔴 **サービスアカウントによる実行** | **個人資料を一律で対象外とする。所有者の個人資料であっても含めない** |

## 🔴 例外 3 の検査（本ユースケースの中核）

計画は「**同じツールを同じ引数で呼んでも、有人実行と無人実行で結果が変わる**」と明記している。
したがって否定形と陽性対照を対で置く。詳細な観点表は
[MCP サーバー統合 テスト仕様書](FR-16_mcp-server.md)の中核の受け入れ基準に置き、本書では
**ユースケースのフローとの対応**だけを示す。

| 観点 | 期待 |
| --- | --- |
| サービスアカウント実行（検索・文書取得・グラフ探索の全経路） | 個人資料が現れない |
| 所有者本人のサービスアカウント実行 | 個人資料が現れない |
| 有人実行（同じツール・同じ引数） | 個人資料が返る（陽性対照） |
| 除外した文書の件数 | 全体件数からも外れる |

## 未実施

- 実サービスとの結合（各サービスのツール実行口が未実装）。
- 認可判定そのもの（本サービスは判定を持たず各サービスへ委譲する）。
