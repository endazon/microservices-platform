# テスト仕様書: 文書を正規化変換する

## 本書の位置づけ

**既にあるテストと計画の受け入れ基準を突き合わせた記録である。** 本書を起こした作業はテストを
1 件も足していない。穴は「未実施」節に理由つきで書いた。

## 計画の逐語（本書が写像する対象）

- 事前条件: 原本が取得済み。
- 事後条件: 本文が Markdown 化され、**図が PlantUML/Mermaid 化または画像保持**される。
- 基本フロー: (1) 変換サービスが原本を受領する → (2) **pandoc で本文を Markdown 化する** →
  (3) 図を LLM（Vision）でコード化する。**不可分は画像として保持する** → (4) 正規化結果を
  文書管理へ登録する。
- 代替フロー:
  - **補正（Phase 1 は「図のコード化のやり直し」に限る）**。**補正版を正とする**。再変換は
    補正を破棄する前に**警告し、明示確認を求める**。
  - **変換ジョブの状況照会**。状態は **`queued` / `processing` / `succeeded` / `failed` の 4 値**。
  - **失敗した変換の再実行**。**実行権限は管理者ロールに限り**、回数上限は設けない。同一ジョブの
    再変換は**直列化**し、**実行中の要求は拒否**する。
- 例外フロー: 本文変換・資産保存の恒久失敗は再試行し、**継続失敗はデッドレターへ送る**。
  **図コード化（LLM）の失敗は画像保持へ縮退**し、後日の人手補正・再登録でコード化する。

## フローの写像

| フロー | 手順 | 検査すること |
| --- | --- | --- |
| 基本 1 | 原本を受領する | 受領でジョブが `processing` になり、試行回数が 1 から始まる |
| 基本 2 | pandoc で Markdown 化する | pandoc が無ければ**縮退せず落ちる**（fail-closed）。実行時イメージに pandoc が入る |
| 基本 3 | 図をコード化する／画像保持へ縮退する | コード化できれば埋め込む。できない・越境拒否なら**画像として保持** |
| 基本 4 | 文書管理へ登録する | 決定的な文書 ID で正規化結果と資産を発行する |
| 代替（照会） | 状況を照会する | **4 値ちょうど**。未知の状態は隠さず**そのまま**出す |
| 代替（補正） | 図を補正して再登録する | 画像埋め込みがコードブロックへ置き換わり、**ABAC 属性を保ったまま**再公開される |
| 代替（再変換） | 失敗ジョブを再実行する | 管理者だけ。失敗以外は 409。**補正があるジョブは明示確認まで 409** |
| 例外 | 恒久失敗 | 試行上限で**デッドレター印**が立つ（状態は変えない）。再処理で印が消える |

### T-03 を「明示に限る」として置く理由

縮退の逃げ道が既定だと、**pandoc が入っていない実行時イメージでも緑のまま出荷できる**。
実際にそうなっていたのが本 UC の直近の是正である。逃げ道は明示の設定でだけ開く。

### T-44 を置く理由（T-41 の陽性対照）

T-41 は**陰性の結論**（一時パスが 0 件）である。これだけを測ると、**画像参照を全部消す実装**でも
緑になる。「残ってはいけないものが残っていない」の隣に「残るべきものが残っている」を対で置く。

### T-41〜T-43 の入力について

図抽出は本文中の画像参照を一時ディレクトリの絶対パスへ書き換えるが、そのディレクトリは
変換直後に消える。この綻びは**変換器を実走させて初めて観測された**ため、テストの入力は
**稼働クラスタで実変換して採取した綴り**をそのまま使っている。想像で書くと、属性が改行を
またぐタグのような実際の形を取りこぼす。実変換を要するのは端から端までの 1 件だけで、
そこは未導入環境では真の Skipped になる。

### T-31・T-28 を置く理由

デッドレター印・確認要求はどちらも「立つ」ことだけを測ると、**常に立つ実装**でも緑になる。
立たない場合を対で置く。

## 未実施（しない／一部する）

- **本文 Markdown 全体の編集（次の段）はしない。** 計画が段を分けており、画面側にも実装が無い。
  **「無いこと」を固定するテスト**だけを置いている（T-39）。
- **実 pandoc を走らせる検査は一部しかしない。** 変換の実行はプロセス起動の記録スタブで測り、
  実行時イメージに pandoc が入ることは構成の検査で測る。**両者は別の事実**であり、片方だけでは
  出荷物が動く保証にならない。
- **LLM（Vision）による実コード化はしない。** 外部モデルに依存し CI で再現できない。
  コード化できたとき・できなかったときの**分岐**だけを測る。
- **デッドレターの実配送（ブローカー側）は測らない。** 印が立つところまでである。
- **性能（変換のスループット）は測らない。** 性能・負荷試験のテスト仕様書が持つ。
