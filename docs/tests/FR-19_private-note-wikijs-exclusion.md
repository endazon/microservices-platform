# テスト仕様書: 個人資料の Wiki.js 同期除外

## 🔴 本書の射程は個人資料の同期除外に限る

**本書は個人資料そのものの機能を網羅しない。** 保存容量・版履歴・同期トークン・画面・Obsidian 連携は
**別 issue（大玉）の担当**であり、そちらが着手する時点で本書を拡張するか別の仕様書を起こす。

**本書が扱うのは「文書が個人資料であるとき、Wiki サービスへ同期しない」ことだけである。**

| 範囲 | 扱い |
| --- | --- |
| 個人資料の判定と Wiki 同期の除外 | **本書** |
| 保存容量（1 GB / 1 TB・段階警告・完全削除） | 射程外（大玉 issue） |
| 版履歴（直近 50 版かつ 90 日） | 射程外（同上） |
| 同期トークン（30 日・手動再発行・7 日前通知） | 射程外（同上） |
| 画面（一覧・共有設定・容量表示） | 射程外（同上） |
| 閲覧側の個人スコープ（所有者・共有先の判定） | 射程外。**契約が選言を表現できないため成立しない**（別 issue） |

## 起点となる計画書（トレーサビリティ）

- 機能要求: 利用者が自身の個人資料を作成・管理し、公開範囲を自ら設定できること
- ユースケース: 自分の資料を作成・管理し、公開範囲を自ら設定する／Wiki で閲覧する
- 関連 ADR: 個人資料は Wiki エンジンへ同期せず本文編集は外部エディタ経路に限る（D-01）／
  個人資料を表す属性の新設（属性キーと 2 値）／所有者ベースの裁量制御（評価は集合帰属）

## 判定軸

**文書スコープ属性が個人資料の値を持つこと**を判定軸とする。綴りは計画側が確定させたものをそのまま用いる。

🔴 **判定は集合帰属で書く。「組織文書でない」で書いてはならない。**

| 書き方 | 結果 |
| --- | --- |
| スコープ属性が個人資料の値**である**なら除外 | ✅ 正しい |
| スコープ属性が組織文書の値**でない**なら除外 | 🔴 **属性を持たない既存文書がすべて該当し、組織文書の同期が一斉に止まる** |

**属性は新設のため実データに 1 件も無く、既存文書へ遡及付与しない方針**であるため、
**否定で書くと既存 2,368 件が全滅する。**

## テストケース

対象: `WikiService.Tests.DocumentSyncConsumerTests`

🔴 **否定形には陽性対照を対で置く。** 「常に早期 return する実装」も「スコープ属性を一切見ない実装」も、
否定形だけなら通す。

| # | ケース | 種別 | 期待 |
| --- | --- | --- | --- |
| 1 | スコープ属性＝個人資料 | 否定形 | Wiki へ push されない・同期メタデータが作られない |
| 2 | スコープ属性＝組織文書 | **陽性対照（1 と対）** | 従来どおり push とメタデータ upsert が起きる |
| 3 | **スコープ属性が欠落** | **陽性対照（本命）** | **従来どおり同期される**。実データ 2,368 件がこの形 |
| 4 | 個人資料の再配信 | 冪等 | 状態が変わらない・push されない |
| 5 | 個人資料かつアーカイブ状態 | 境界 | **アーカイブ伝播は通る**（除外はアーカイブ分岐より後に置く） |
| 6 | 組織文書として同期済みの文書が個人資料へ変わる | **上流が破れたときの後段（二層目）** | 既存ページは残り、以後更新されない（下記） |

### ケース 6 は「起こり得る遷移」ではない —— 上流が塞いだ後の二層目である

**計画はスコープ属性を作成時に確定する属性と定め、更新経路に変更要求の拒否を課した。**
実装も着地しており、値の変更・既存値の削除・後からの新規付与の 3 つが 1 本の一致判定で閉じている。
**したがってこの遷移は API からは起こせない。**

**それでもケース 6 を残す。** 上流の門が回帰したときに、Wiki サービスが黙って挙動を変えないことを
固定するためである。**消去の分岐は足さない** —— 起こり得ない遷移のための消去は、
上流が破れたときに**気づかせずに証拠を消す**方向に働く。

> 🔴 本ケースの読み方は 2026-09-05 に改めた。従前は「計画が未裁定なので現状の観測を固定するだけ」
> と書いていたが、裁定は 2026-08-23 に降りていた。

## 変異試験（実測値）

**本テスト群が実際に落ちることを変異で確かめた。** 実測は作業仕様書に記録している。

| 変異 | 実測 |
| --- | --- |
| 除外条件を外す | **3 件が落ちた**（1・4・6）。陽性対照 2・3 は緑のまま＝**除外が広がっていない**ことも同時に示す |
| 判定を「組織文書でない」へ変える | **10 件が落ちた**（ケース 3 を含む） |

### 🔴 ケース 3 の役割は検出ではなく診断である

**当初は「ケース 3 だけが誤りを検出できる」と想定したが、実測では既存テスト 7 件も巻き添えで落ちた**
（それらのフィクスチャがスコープ属性を持たないため）。

**検出そのものは既存テストでも起きる。** ただし既存テストは「**機密区分を検証しているテストが
push 0 件で落ちる**」形になり、**なぜ落ちたのかを言わない**。
**ケース 3 だけが「属性の欠落を個人資料と誤判定してはならない」という理由つきで落ちる。**

**想定が外れた事実を、値の側を直さず記録する。**
