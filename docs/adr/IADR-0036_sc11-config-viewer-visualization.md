# IADR-0036: SC-11 構成ビューアの可視化方式（グラフ描画ライブラリ非導入）

- 状態: Accepted
- 日付: 2026-07-08
- 決定者: claude（実装）

## 起点・関連

- 関連する計画書 ID: SC-11（構成ビューア）／ FR-15（構成情報の可視化）／ ADR-0018（Composable Architecture）
- 関連する実装仕様書: `docs/screens/SC-11_configuration-viewer.md`（**未決事項 4: グラフレイアウト方針**の解決）
- 関連 ADR: [[IADR-0029]]（構成情報 API 配置・ドリフト分類）／ [[IADR-0033]]（SPA 基盤・依存最小）／ [[IADR-0035]]（ロール別 nav・存在秘匿）

## コンテキストと課題

SC-11 は実効構成（パイプライン段・イベント接続・ポート選択・コネクタ）を可視化する。SC-11 仕様書の
未決事項 4 は「段/イベント増大時の可読性・自動レイアウト・折りたたみのレイアウト方針を実装時に確定する」。
データソース `/bff/admin/config`（`EffectiveConfigDto`）はデータ量が小さい（初期は段 5・イベント 6 程度）。
受け入れ基準は「実効構成が**グラフ・一覧として**閲覧できる」であり、必ずしも自動レイアウトの有向グラフ
描画を要求しない。

## 検討した選択肢

- **A. グラフ描画ライブラリを導入しない。CSS の段チェーン＋表＋折りたたみで表現する**（採用）
  - パイプラインを `consumer → [outputs]` の縦（または横）チェーンとして CSS で描画し、イベント接続・
    ポート・コネクタは表で示す。無効段はグレーアウト、ドリフトは行/ノードの強調（#138）。
- B. 有向グラフライブラリ（mermaid / dagre / react-flow 等）を導入して自動レイアウト描画する
  - リッチだが依存が増える。基盤の「依存最小・環境非依存ビルド」（IADR-0033）方針に反し、バンドルも増大。
    小さいデータ量に対して過剰。
- C. サーバ側で画像/mermaid を生成して埋め込む
  - BFF 変更が必要。参照専用の内部画面に見合わない。

## 決定

グラフ描画ライブラリは**導入しない**。実効構成は次で表現する:
- **パイプライン段**: `service / consumer` を節点、`input → outputs` を明示した縦チェーン（CSS）。無効段（`enabled:false`）はグレーアウト。
- **イベント接続**: `event → publishers / subscribers` の表。
- **ポート選択**: `port / implementation / target` の表。
- **コネクタ**: `name / enabled` の一覧。
- **可読性・スケール**: 各領域は折りたたみ可能なセクションとし、件数が増えても縦スクロールで追える。
将来データ量が大きく可読性が損なわれた場合に限り、選択肢 B を再検討する（本 ADR を Superseded 化）。

## 理由

- 基盤の依存最小・環境非依存ビルド（IADR-0033）を維持できる。SC-10 でチャートライブラリを避けた判断と一貫する。
- 受け入れ基準「グラフ・一覧として閲覧できる」を、依存を増やさず満たせる。
- 内部運用者向けの参照専用画面であり、対象規模が小さいため自動レイアウトの費用対効果が低い。

## 結果

- 良い影響: 依存追加なし。SC-11 の #137（グラフ）・#138（ドリフト）・#140（アクセス制御）を軽量に実装できる。
- 悪い影響・トレードオフ: 段/イベントが将来大規模化した場合、CSS チェーンでは配線の把握が難しくなる可能性。その時点で選択肢 B を再検討する。
- フォローアップ: SC-11 仕様書の未決事項 4 を「解決（本 IADR）」へ更新する。
