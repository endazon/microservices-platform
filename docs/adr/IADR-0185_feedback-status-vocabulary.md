# IADR-0185: `feedback/` の `status` 語彙（#712）

- 状態: Accepted
- 日付: 2026-08-13
- 決定者: claude（実装）

> **［2026-08-14 追記 / #721］★ 決定 1・決定 2・決定 4 は [IADR-0187](./IADR-0187_status-vocabulary-follows-upstream-adjudication.md) が差し替えた。**
> **本 ADR が環流した planning#323 の裁定が下り、`status` は「伝達したか」ではなく
> 「計画側の裁定がどこまで進んだか」を表すと確定した**（伝達は `dispatched:` / `planning_issue:` 鍵が担う）。
> **`triaged` は廃され `awaiting-decision` になった。**
> **本 ADR の決定は 1〜4 であり、そのうち決定 3（キット原文の取り込み＋CI ジョブ名の固有デルタ）だけが引き続き有効である。**

## 起点・関連

- **NFR**（文書統制・運用保守。メタ作業なので無採番。[IADR-0179](./IADR-0179_unnumbered-nfr-for-meta-work.md) 決定 1）
- 実装 issue: **#712**（出所: #707 判断 3 / #710 の射程外宣言）
- 作業仕様書: [20260813_issue-712](../specs/20260813_issue-712_feedback-status-vocabulary.md)

## 文脈 —— **語彙を検査で閉じたが、意味を書かなかった**

`feedback/*.md` の frontmatter は `status` を持ち、**#700 が値域を 4 語へ閉じた**
（`scripts/scripts.repo.test.js`）。しかし**各値が何を意味するかはどこにも書かれていない。**

| 何が | どこに |
| --- | --- |
| 値域（`open` / `triaged` / `accepted` / `rejected`） | **`scripts.repo.test.js` の検査だけ** |
| 既定値 `open` | `feedback/TEMPLATE.md` の frontmatter |
| **各値の意味・遷移・判断の主体** | **どこにも無い** |

**`feedback/README.md` は `status` という語を 1 度も使っていない**（実測: 出現 0 回）。
同ファイルは**キットの節「【最重要】記録を作るだけでは計画へ届かない」（19 行）も丸ごと欠いている** ——
**#710（PR #711）で検査器そのものは取り込んだのに、それを説明する節を取り込まなかった。**

### ★★ 実測 —— **`open` と `triaged` は実務で同義に崩れていた**

`feedback/` の記録を**全数**で走査した（`README.md` / `TEMPLATE.md` を除く）。
**「伝達の証拠」は検査器 `inspect()` の判定をそのまま用いた**（`planning_issue:` 鍵 / 他リポ issue URL /
本文の「起票済み」のいずれか）。

| status | 件数 | 検査器が認める伝達の証拠 | `## 起票状況` 節 |
| --- | ---: | ---: | ---: |
| `accepted` | 26 | 10 | 4 |
| `triaged` | **7** | 6 | 6 |
| **`open`** | **3** | 2 | **3** |
| `rejected` | 2 | 0 | 0 |
| **合計** | **38** | 18 | 13 |

> **★★ #712 の本文も引き継ぎ資料も「37 件 / `triaged` 6 件」と書いていたが、実測は 38 件 / 7 件である。**
> 落ちていたのは `20260811_pr-size-400-vs-mandatory-specs.md` の 1 件。
> **[`.claude/rules/traceability.md`](../../.claude/rules/traceability.md) 規則 8 の「報告された件数は母集合ではない」の再演**であり、
> **起票時の件数をそのまま引き写さず、着手時に測り直したことで捕まえた。**

**`open` の 3 件はいずれも伝達済みである**（3 件とも `## 起票状況` 節を持ち planning を参照する）。
**つまり実務の `open` は「未伝達」ではなく「裁定待ち」を意味しており、`triaged` と区別が付いていない。**
**一方 `scripts/check-feedback-dispatched.js` は `status: open` を「未伝達の疑い」と読む。**

## ★★ 決定 1: **`status` は「伝達したか・裁定はどうなったか」の 1 軸とし、`open` を「未伝達」と定義する**

**2 つの読みがありうるので、機械の読みに合わせる側を採る。**

| 案 | `open` の意味 | 結果 |
| --- | --- | --- |
| **A（採用）** | **未伝達**（伝達したら `triaged` へ） | **検査器の読みと一致する** |
| B | 裁定待ち | 実務の慣行には合うが、**検査器と恒久的に食い違い、`triaged` と区別が付かない** |

**B を採ると `open` と `triaged` が同義のまま固定される** —— 実測がまさにその状態である。
**同義の 2 語は、片方が必ず意味を失う。**

| 値 | 意味 | 誰が遷移させるか |
| --- | --- | --- |
| `open` | 記録は作ったが**計画リポへまだ伝達していない**（`TEMPLATE.md` の既定値） | —— |
| `triaged` | **伝達済み**（issue 起票または `draft/feedback/` へのコピー）。**裁定待ち** | **実装側**（伝達した事実を書く） |
| `accepted` | 計画側が**受け入れた**（計画書・ADR へ反映される／された） | **計画側の裁定**を実装側が転記 |
| `rejected` | **採らないと決まった** | 同上 |

**`triaged` という語は「実装側が伝達した」ではなく「計画側がトリアージに載せた」と読めてしまう**が、
**#700 が値域を閉じた後なので改名は別の変更である。** 本決定は**語を変えず意味を固定する**に留める
（改名すると既存 38 件すべてと検査 2 本に波及し、本 issue の射程を超える）。

## ★★ 決定 2: **`open` の 3 件を `triaged` へ是正する —— IADR-0184 決定 2 に反しない**

**`20260809_document-write-machine-client.md` を含む 3 件を `triaged` へ直すと、
`check-feedback-dispatched.js` の警告は 1 → 0 件になる。**

**[IADR-0184](./IADR-0184_feedback-dispatch-checker-verbatim.md) 決定 2 は「偽陽性を消すために記録へ嘘を書かない」と定めた。本決定はこれに反しない。**

| | #710 の時点 | #712 の時点 |
| --- | --- | --- |
| 語彙の定義 | **無い** | **ある**（決定 1） |
| `open` のまま置いた理由 | **直す根拠が無かった**（`triaged` にする規約が無い） | —— |
| いま `triaged` にする根拠 | —— | **定義に照らして `open` が誤りだから**（伝達済みである） |

**#710 が退けたのは「`planning_issue:` へ PR 番号を書く」「検査器を満たすために別途 issue を立てる」
という、事実の側を作りにいく手であって、`status` の付け替えではない。**
**付け替えは、付け替える先の意味が決まって初めて可能になった。**

> **★ 偽陽性の正体は検査器ではなく、語彙の不在だった。**
> **ただし planning#319 の知見 1（検査器が記録ファイル経路を証拠と認めない）は依然として有効である** ——
> **本決定は `status` 側だけを正す。** 当該記録は**証拠を持たないまま `triaged`** であり、
> **経路の件が反映されるまでその状態が正しい。**

### 是正しないもの（遡及適用しない）

| 検査器が認める伝達の証拠を持たないもの | 件数 | 扱い |
| --- | ---: | --- |
| `accepted` | **16** | **是正しない**（起票状況を書く運用より前の記録） |
| `rejected` | **2** | **是正しない**（実装側の取り下げと読める） |
| `triaged` | **1** | **是正しない**（同上） |

**規約が無かった時期の記録へ後から規約を遡及適用しない**（#706 / #707 / #710 と同じ判断）。
**これらは `status` が `open` でないため検査器を鳴らさず、決定 2 の「0 件」を崩さない。**

### ★★ 決定 2 の補足: **既存記録への書き込みは「記録の改竄」に当たらない**（#715 レビュー 🟡）

[`.claude/rules/traceability.md`](../../.claude/rules/traceability.md) は
**「確定済み（過去 PR の）`docs/specs/`・`feedback/`・`docs/superpowers/` は書いた時点の記録であり、
後から注記を足すのは記録の改竄にあたるので書き換えない」**と定める。**`feedback/` が名指しされている。**
**決定 2 は既存 3 件を書き換えるので、この規約との関係を明示しておく。**

**結論: 抵触しない。** 理由は 3 つある。

| # | 理由 |
| --- | --- |
| 1 | **当該規約の射程は「この書式」＝ `Superseded by <後継 ID>` の**後付け注記**である**（節の見出しが「Superseded / Deprecated な ADR を引用するときの書式」であり、当該段落は**その書式を適用する母集合**を限定している）。**`status` の是正はこの書式の話ではない。** |
| 2 | **`status` は「書いた時点の事実」ではなく、遷移することが前提の状態欄である**（決定 1）。`open` → `triaged` → `accepted` / `rejected` と**後から動かすためにある**。凍結したら**この鍵は最初から意味を持てない** —— 現に `accepted` / `rejected` の 28 件は、すべて**起票後に計画側の裁定を転記して**その値になっている。 |
| 3 | **本文の主張は 1 文字も変えていない。** 変えたのは `status` と、**日付・issue 番号つきの追記ブロック**（`［2026-08-13 追記 / #712］`）だけである。これは同規約が「決定を変える追記」に対して**指定している形そのもの**であり、**いつ誰が何を根拠に足したかが記録から辿れる。** |

> **★ ただし規約の文言は「`feedback/` は書き換えない」と読める。** 射程が ADR 引用書式に限るのか一般原則なのかは
> **本文からは判然としない**（レビューの指摘のとおりである）。**本 IADR は上の読みを採ったが、規約側の
> 文言を直す権限は本 issue に無い** —— **射程を明示する形へ改めることを #717 として起票した。**

**なお #712 の受け入れ基準は「矛盾があれば**是正するか**、しない理由を記録する」と書いており、
是正は起票時点で想定されていた選択肢である。**

## ★ 決定 3: **欠落節はキット原文で取り込む。ただし CI ジョブ名だけ実態へ直す**

[IADR-0115](./IADR-0115_impl-handoff-kit-as-single-source.md) 決定 1 のとおりキット本文を土台にし、**追随漏れを埋める**（デルタを減らす方向）。

**取り込み元は pin `2cf0795` のキットである。** 計画リポの HEAD（`690b0c7`）は planning#319 の反映で
**さらに先へ進んでいる**（`dispatched:` 鍵・経路別の証拠表）が、**本リポの検査器はまだ pin 側と
バイト一致**である（[IADR-0184](./IADR-0184_feedback-dispatch-checker-verbatim.md) 決定 1）。
**HEAD 側の節を取り込むと、本リポに無い機能を説明する嘘になる** —— 節と検査器は**同じ pin で揃える**。

**ただし 1 点だけキット原文から外す。** キットは検出を **`doc-links` ジョブ**が行うと書くが、
**本リポは独立ジョブ `feedback-dispatched`**（[IADR-0184](./IADR-0184_feedback-dispatch-checker-verbatim.md) 決定 3）。**そのまま取り込むと嘘になる。**
**これは IADR-0115 決定 2 が許す固有デルタ（2. 技術スタックとその CI 配線）に当たる**ので環流は要らない。

## ★ 決定 4: **語彙の定義は暫定デルタとして置き、キットへ環流する**

**語彙の定義は IADR-0115 決定 2 の固有デルタ 4 種のどれにも当たらない。**
**同 決定 3 が「汎用的な改善はキットへ環流する」と定める** —— **どの実装リポでも同じ穴が空いている**
（キットが `TEMPLATE.md` で `status: open` を配りながら、意味をどこにも書いていないため）。

**IADR-0115 が第 12〜13 ラウンドで確立した「一時デルタ」の運用に従う** ——
**コメントで環流先の issue を必ず参照し、キット側へ反映されたら撤去してキット準拠へ戻す。**

**環流は `feedback/20260813_kit-feedback-status-vocabulary.md` に記録し、planning#323 として起票済み**
（[`docs/README.md`](../README.md) 運用ルール 5: **起票まで済んで初めて「環流した」と書ける**）。

## 結果

- 良い影響
  - **`open` / `triaged` の区別が付いた** —— 実務で同義に崩れていた 2 語が、それぞれ別の状態を指す
  - **#710 が残した既知の偽陽性 1 件が、記録に嘘を書かずに解消した**（警告 **1 → 0 件**）
  - **キットとの内容差分が 1 件減った**（欠落節 19 行の取り込み）
  - **語彙の定義と検査器の読みが一致**したので、以後 `status: open` の警告は**本物の滞留だけ**を指す
- 悪い影響・トレードオフ
  - **`triaged` の語は「計画側がトリアージした」とも読める**が、改名の波及が大きいので据え置く（決定 1）
  - **語彙の定義が暫定デルタとして残る** —— planning#323 が反映されるまで、キットとの差分 1 件を抱える
  - **遡及適用しない 19 件**（`accepted` 16 / `rejected` 2 / `triaged` 1）は、伝達の証拠を持たないまま残る。
    **検査器は鳴らない**ので、これらの到達確認は `/sync-impl` の突合に委ねる
- フォローアップ
  - **planning#323 が反映されたら暫定デルタを撤去し、キット準拠へ戻す**（IADR-0115 第 13 ラウンドと同じ往復）
  - **キット追随の全体棚卸し（内容差分の分類）は #713** —— 本件はその 1 例である
  - **`traceability.md` の「`feedback/` は書き換えない」の射程を一意にする** —— **#717**（決定 2 の補足）

## ★★ 追記（2026-08-13 / PR #715 のレビュー 🔴）: **条件分岐を、それが走る条件で動かしていなかった**

**回帰テストのキット本文比較が `planning` を populate した環境で必ずクラッシュする**という欠陥を、
AI レビューが実測で見つけた（`scripts.test.js` が **491 件中 107 件**で異常終了）。

| | |
| --- | --- |
| 原因 | 比較前に HTML コメントを落とす `strip()` が**行単位のフィルタ**で、`<!--` の行と `-->` の行にしか当たらず、**3 行コメントの中間行が素通り**していた |
| なぜ気づかなかったか | 比較は **`fs.existsSync(KIT_README)` の内側**にあり、**手元も CI も `planning` を populate していない** —— **一度も実行されていなかった** |
| 是正 | `strip()` を**コメントブロックごと落とす**形（`/<!--[\s\S]*?-->/g`）へ直し、**キットを populate して再実測**（**491 件全数 pass**）。**乖離を実際に捕まえるか**も変異試験で確認した（本文の書き換え・行削除を検出／コメントの増減では誤検出しない） |
| 併せて | **未 populate 時に notice を出す** —— **黙って飛ばすと「検査した」と読める**（[IADR-0183](./IADR-0183_false-green-warning-on-worktree-state.md) の「偽の緑」と同型） |

> **★ 教訓は [IADR-0183](./IADR-0183_false-green-warning-on-worktree-state.md) の再演である。** 変異試験を 10 件通していたが、**そのすべてが
> 未 populate 環境で走っており、問題の分岐に一度も入っていなかった。**
> **「変異試験を通した」は「変異試験が対象の分岐に入った」を意味しない。**
> **分岐を書いたら、その分岐が実際に走る条件を作って 1 度は動かすこと。**
