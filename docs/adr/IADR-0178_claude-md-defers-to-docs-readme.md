# IADR-0178: CLAUDE.md の減量と 50KB 到達（#697 / #623）

- 状態: Accepted
- 日付: 2026-08-11
- 決定者: claude（起案・実装）

## 起点・関連

- **NFR**（運用保守）。実装 issue: **#697**（**#623 の子**）
- 実行する対象: **[[IADR-0177]] 決定 3**（`CLAUDE.md` 減量の解禁）
- 拡張する対象: **[[IADR-0171]]**（`docs/README.md` を正本とする扱い）
- 作業仕様書: [20260811_issue-697](../specs/20260811_issue-697_claude-md-slimming.md)

> **★ 本 ADR も可変の数値を断定しない**（[[IADR-0175]] 決定 0）。**実測値は作業仕様書 §着地の実測**に置く。
>
> ```console
> $ node -e "const fs=require('fs');const f=['.claude/rules/traceability.md','CLAUDE.md'];\
> let t=0;for(const p of f){const n=fs.statSync(p).size;t+=n;console.log(p.padEnd(34),n)}\
> console.log('必読合計'.padEnd(30),t,' / 50,000 まで',t-50000)"
> ```

## ★★ 決定 1: **重複は「別紙化」ではなく「正本へ畳む」**

**段 1〜5 は入口にしか無い経緯を別紙へ移した。本件は違う** —— **同じ表が 2 箇所にあった。**

**仕様書の種別表（必須 10 / 任意 9）は `CLAUDE.md` と `docs/README.md` に重複しており、
19 種別が 1 つ残らず一致していた**（実測は作業仕様書 §軸 b）。

| | 扱い |
| --- | --- |
| 入口にしか無い経緯 | **別紙を作って移す**（段 1〜5） |
| **2 箇所に同じ記述** | **正本を残し、片方を導線に置き換える**（本決定） |

**別紙を作ると 3 箇所目になる** —— [[IADR-0141]]「参照点を 1 つに畳む」に反する。

> **★ [[IADR-0171]] の扱いを広げただけである。** 同 ADR は運用ルール 4 について
> **「正本は `docs/README.md`。`CLAUDE.md` は本項を指すだけ」**と既に定めていた。**同じ線を種別表へ適用する。**

## ★ 決定 2: **`CLAUDE.md` は「進捗」を持たない**

SPA 移行の段の消化状況（どの段まで済み・どの issue が残りを引き受けているか）は
**[[IADR-0121]] が正本**とし、`CLAUDE.md` からは落とす。

**進捗は最も速く腐る記述である** —— 引き受けた issue が着地した瞬間に `CLAUDE.md` が嘘になる。
**規範（React 19 / Vite 6 / Vitest 3 / Node 22 / TanStack Router）は残す。**

## ★★ 決定 3: **誤りは「削る」のではなく「直す」**

`CLAUDE.md` は「`.github/workflows/` は GitHub App 権限では編集不可」と書いていた。
**[[IADR-0169]] が `git log` の実測でこれを否定している**（同ディレクトリの変更は繰り返し着地している）。

**減量のついでに黙って消さない。** **誤りとして直し、根拠の IADR を指す。**

> **★ 消すだけだと「なぜ消えたか」が残らない。** 同じ記述が将来また書かれる。
> **必読ファイルに残る誤りは、減量とは独立に直す価値がある。**

## ★★ 決定 4: **50KB 目安へ到達した。以後は「予算内に保つ」が各 PR の責任**

**#623 の減量（段 1〜5 ＋ 本件）で必読合計は 50,000 を下回った**（実測は作業仕様書）。

**ただし余白はごく小さい。** **「到達した」で終わりにせず、必読ファイルを増やす変更は
そのつど現在値を測る。** 測り方は上記コマンドである。

> **★ 予算超過を機械で止める検査は置いていない。**
> 置くなら「必読 2 ファイルの合計バイト数」を CI で見るだけでよいが、
> **本 PR の射程外**とする（**同型の事故はまだ 0 回**であり、`CLAUDE.md`「検査器の追加は同型 2 回から」に従う）。

## ★ 決定 5: **「到達した」と書く行為そのものが余白を食う**

**本 PR は実際にこれを踏んだ。** `CLAUDE.md` の「50KB 予算（本リポは超過中。減量は #623）」を
**到達済みの記述へ書き換えたところ、書き換え後の文が元より長く、いったん 50,000 を再び超えた**
（実測は作業仕様書 §着地の実測）。**2 度縮めて収めた。**

**したがって: 予算に関する記述は、予算の内側で書く。** **到達の記録は短く。詳細は本 ADR と作業仕様書が持つ。**

> **★ [[IADR-0175]] 決定 0（ADR は可変の数値を断定しない）と同じ型の自己参照**である。
> あちらは**古くなる**問題、こちらは**膨らむ**問題である。

## ★★ 決定 6: **記録の単位は「出した塊」ではなく「変更の全数と実効」**

**本 PR の初版は「出す塊 4 件」とだけ記録し、実際に行った 6 件のうち 2 件が漏れた**
（冒頭注記の圧縮 ／ 認証の重複の削除。レビューが 1 件を検出し、**全数を引き直してもう 1 件が出た**）。

**漏れた理由は枠にある** —— **「塊を出す」は抽出の枠**であり、**圧縮も、後から足した削除も、そこに収まらない。**

| | |
| --- | --- |
| 従前 | **出した塊を列挙**（総バイト） |
| **本決定** | **変更を 1 件残らず列挙し、旧・新・実効を並べる。実効の合計がファイルの増減と一致することを検算する** |

> **★ 検算が閉じることが、漏れの無さの機械的な担保である。**
> **総バイトの列挙では検算のしようがなく、漏れても気づけない。**

## 結果

- **6 件の変更**（種別表・進捗・冒頭注記・認証の重複・`workflows` の是正・予算記述）を行い、**実効 −1,669B が検算で閉じることを確認した**（決定 1・2・6）
- SPA 移行の進捗を [[IADR-0121]] へ畳んだ（決定 2）
- `.github/workflows/` の誤りを [[IADR-0169]] の実測に合わせて是正した（決定 3）
- **50KB 目安へ到達した**（決定 4）。**予算記述の自己参照を記録した**（決定 5）
- 切り出しの残骸検査（[[IADR-0177]] 決定 5）の対象へ **`CLAUDE.md` を追加**した

## 検出しないこと（明示する）

- **予算の超過** —— **機械検査は無い**（決定 4）。**同型の事故が起きたら置く**
- **`docs/README.md` 側が正しいこと** —— 本 ADR は**重複の解消**だけを扱う。正本の内容は検証していない
- **`CLAUDE.md` にこれ以上の重複が無いこと** —— **保証しない。**
  実測したのは種別表・進捗・`workflows` の 3 件である
