# IADR-0143: 計画 ID 修飾の検査は追跡下の全ファイルを見て、生成物と記録だけを外し、自己参照はパス導出で解く

> 実装リポジトリ内の意思決定記録（Implementation ADR）。1 ファイル = 1 意思決定。

- 状態: Accepted
- 日付: 2026-08-08
- 決定者: Claude（実装）

## 起点・関連

- 関連する計画書 ID: NFR（保守性・追跡可能性）
- 関連 issue: [#576](https://github.com/endazon/microservices-platform/issues/576)（起点。親 [#454](https://github.com/endazon/microservices-platform/issues/454)）
- 関連する実装 ADR: [[IADR-0140]]（姉妹検査器。**対象が違う**）／[[IADR-0141]]（母集合の引き直し）／[[IADR-0115]]（キット同期）
- 規約: [`.claude/rules/traceability.md`](../../.claude/rules/traceability.md)「複数プロジェクトを跨ぐ場合の ID 修飾」

## 背景

`.claude/rules/traceability.md` は他プロジェクトの**計画 ID / ADR ID** を `<PROJ>/<ID>`（`AST/FR-17`）と
書くよう定めるが、**守る機械が無かった**。実測すると空白区切り（`AST FR-17`）が 28 occurrence あり、
**8 番号が本リポジトリの同番号 IADR と衝突**していた。

**[[IADR-0140]] は issue / PR 番号（`AST#24`）の検査器であり、本件とは対象が違う。** 同 ADR の
決定 4（`*.md` 限定）・決定 5（`CHANGELOG.md` を外さない）は、条文の根拠がいずれも
`check-cross-repo-refs.js` と型 1〜3 に縛られているため**本件の射程外**である。
ただし**本 ADR は 2 つの決定について逆向きの判断を採る**ので、記録を残す。

## 決定

### 決定 1: 走査対象は追跡下の**全ファイル**にする（`*.md` に限らない）

[[IADR-0140]] 決定 4 は `.md` 限定を選び、根拠を「母集合の大半が `.md`」とした。**本件では成立しない**
——実害の中心は `deploy/docker-compose.yml`・`deploy/helm/*/values.yaml`・
`deploy/keycloak/*.json`・`src/**/*.cs`・`src/**/*.ts` のコメントであり、`.md` 限定では
**誤帰属の主戦場を丸ごと見逃す**。拡張子で絞らない（[[IADR-0141]] 規則 3）。

### 決定 2: 外すのは「生成物」と「書いた時点の記録」だけにする

`CHANGELOG.md`（生成物）・`docs/specs/`・`feedback/`・`docs/superpowers/`（記録）と submodule を外す。
**[[IADR-0140]] 決定 5 は `CHANGELOG.md` を「検査から外さない」と決めており、本 ADR は逆向きである。**
理由: 同ファイルは `gen-changelog.js` が**過去コミット件名から機械生成**しており、
**手で直すと次の再生成で戻る**。是正するなら `changelog-overrides.json` の `remap` だが、
`AST SC-02` は**誤りではなく修飾書式が古いだけ**で件名の意味は正しく、`desc` を書き換えると
過去の件名と CHANGELOG が食い違って追跡可能性がむしろ落ちる。

### 決定 3: 「AST 文脈で裸の ID」（型 B）は**機械検査しない**

近傍規則になり**偽陽性が避けられない** —— `.claude/rules/traceability.md` 自身が
「AST の `FR-17`（当時 MSP は FR-15 まで）」と**誤帰属そのものを説明する地の文**を持つ。
偽陽性を 1 件でも出すと検査は外される（[[IADR-0140]] 決定 3 が裸 `#NNN` の一律検出を同じ理由で棄却）。
**#576 で全数（実測 32 occurrence）を是正したが、再混入は人と AI が防ぐ。**

### 決定 4: 検査器の自己参照は**除外リストではなくパス導出**で解く

検査器のヘッダと自己試験フィクスチャは「検出対象の文字列そのもの」を持つので、
全ファイル走査では必ず自分で落ちる（[[IADR-0140]] 決定 4 が `.js` へ広げない理由として挙げた型）。
**`__filename` から自分のパスを導出して外す** —— 除外リストは腐るが、導出は
ファイル名を変えても追随する。

> **★ この死角はローカルでは見えない。** 新設直後のファイルは untracked なので
> `git ls-files` に載らず、**コミットして追跡下に入った瞬間に初めて自分を走査する**。
> #576 は CI で初めて赤になった。**「ローカルで緑」は「CI で緑」を意味しない。**

自己除外が効いていることの自己試験は、**ファイル名をリテラルで書かない**
（リネームで vacuous truth になる）。導出したうえで「**自ファイルは追跡下に在る**」ことも
併せて主張し、「追跡下だが除外されている」を固定する。

### 決定 5: 型 A の区切りは空白に限らない

`AST [[IADR-0080]]`（wiki リンク）・TAB・バッククォート・全角括弧が挟まる形が実在した。
**wiki リンク形は本リポジトリの実在 IADR（Headlamp）へ実際に張り付いており、
表記ゆれではなく生きた誤帰属だった。** `check-doc-links.js` は `[[...]]` を見ないので誰も止めない。

**着手時の走査式は「空白 ＋ ID 直結」しか見ておらず、この形を母集合から丸ごと落とした**
（[[IADR-0141]] 規則 2「あり得る形をすべて列挙してから引く」・規則 5「軸を 1 本で終わらせない」の違反）。
**同一行で `AST IADR-0086` は直し `AST [[IADR-0084]]` は残った**のが引き漏らしの動かぬ証拠である。

## 検出しないこと（本検査は網羅ではない）

- **型 B**（決定 3）。
- **列挙の後続 ID**（`AST/SC-02/SC-03` の `SC-03`）。近傍規則になるため型 B と同じ判断。
  **この型は実在した** —— #576 の一括置換が 4 件作り、手で直した。
- **行またぎ**（`AST` で改行して次行が `FR-17`）・**小文字 `ast`**・`NFR`。
- **`.github/workflows/**` に型 A が入った場合**、CI は赤になるが **GitHub App 権限では直せない**
  （[[IADR-0140]] 決定 2 の前提制約）。ローカル認証での修正が要る。
- `.md` の**字下げコードブロック**・**HTML コメント**・**リンクタイトル**は `maskCode` が潰さないため
  偽陽性になり得る（現時点の実データは 0 件）。`maskCode` は借り物なので、直すなら
  `check-cross-repo-refs.js` 側と共有で直す。

## 影響

- `scripts/check-plan-id-qualification.js` を新設し、`scripts.repo.test.js` 経由で
  `ci.yml` の `scripts-tests` へ相乗りする（[[IADR-0140]] 決定 2 と同じ結線。新ワークフローは足さない）。
- `maskCode` は**再実装せず `check-cross-repo-refs.js` から借りる**（2 箇所に置くと片方だけ直したとき挙動が割れる）。
- **姉妹検査器が正反対の対象を持つ**ことになるので、規約側にも「対象が違う」ことを明記した。

## 棄却した案

| 案 | 棄却理由 |
| --- | --- |
| `check-cross-repo-refs.js` に相乗りして型を足す | あちらは「番号の表記」に閉じた道具で、ID 修飾を混ぜると責務が割れる。決定 4・5 の射程も読めなくなる |
| `.md` 限定にする（IADR-0140 決定 4 に揃える） | 誤帰属の主戦場（`deploy/` の設定コメント・`.cs` / `.ts`）を丸ごと見逃す |
| 型 B を近傍規則で検査する | 偽陽性が避けられず、規約自身の地の文で発火する |
| 自己参照を除外リストで潰す | 腐る（IADR-0140 決定 4 根拠 2 が同じ懸念を挙げている） |
