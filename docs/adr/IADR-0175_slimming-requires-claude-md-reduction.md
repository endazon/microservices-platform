# IADR-0175: 50KB は入口だけでは届かない（#691 / #623 段 3）

- 状態: Accepted
- 日付: 2026-08-11
- 決定者: claude（起案・実装）

## 起点・関連

- **NFR**（運用保守）。実装 issue: **#691**（**#623 の子**）
- 更新する対象: **[[IADR-0174]] 決定 2**（段 4 を必須とした。**さらに先が要ると分かった**）
- 方式: **[[IADR-0173]]**（見出しスタブ／規範は出さない）
- 作業仕様書: [20260811_issue-691](../specs/20260811_issue-691_id-qualification-annex.md)

## ★★ 決定 0: **本 ADR は可変の数値を断定しない**

**[[IADR-0174]] は入口ファイルのサイズを本文へ書いた。その ADR 自身を編集するとサイズが変わり、
自分の記述が古くなった** —— **自己参照的で構造的に不安定**であり、**レビュー 3 巡ぶんの是正を要した**
（#690。`51,558` の取り残し 3 箇所 → `1,628B` の算数 → `4,258` の導出値）。

**本 ADR では次の書き方を採る**（[[IADR-0141]]「参照点を 1 つに畳む」を数値へ適用）:

| | |
| --- | --- |
| **測り方を書く**（下記コマンド） | **誰でも「今の値」を出せる。ADR が古くならない** |
| 数値を書くときは | **基準コミットを明記する**（例: 「commit `8cd47a3` 時点の実測」） |

### 現在値の出し方

```console
$ node -e "const fs=require('fs');const f=['.claude/rules/traceability.md','CLAUDE.md'];\
let t=0;for(const p of f){const n=fs.statSync(p).size;t+=n;console.log(p.padEnd(34),n)}\
console.log('必読合計'.padEnd(30),t,' / 50,000 まで',t-50000)"
```

> **★ 作業仕様書の「§着地の実測」は時点の記録なので数値を書いてよい。**
> **問題は ADR 側が可変の値を断定すること**である。

## 文脈 —— **段 3 で「出せる量」が見込みの 32% しか無かった**

**[[IADR-0174]] は「節が丸ごと出る」前提で段 3 を約 9,117B と見込んでいた。**
**段 3 の対象節を構成要素ごとに測ると、出せるのは説明・経緯の 4 塊だけである**
（内訳は作業仕様書 §軸 a。**commit `8cd47a3` 時点で 2,898B ／ 節全体の 32%**）。

**残りは規範である** —— `<PROJ>` の値・AST の採番レンジ・短縮形の書式・列挙形の修飾・
空白を入れない・`endazon` owner・誤例の書き方。**[[IADR-0173]] 決定 2 により別紙へ出さない。**

## ★★ 決定 1: **`CLAUDE.md` の減量を「想定」から「確定事項」へ格上げする**

**[[IADR-0174]] 決定 2 は「段 4 でも届かない場合、`CLAUDE.md` が対象になる」と条件付きで書いた。**
**段 3 の実測により、条件は満たされることが分かった。**

**段 4（「残す箇所と書式」）が段 3 と同じ規範比率なら、入口をすべて処理しても 50,000 に届かない。**
**不足分は `CLAUDE.md` から出すほかない。**

> **★ 段 4 の規範比率は未実測である。** 上は**計算であって実測ではない**（[[IADR-0174]] 決定 3）。
> **段 4 の着手時に測る。** **本 ADR は「届かない」という向きを確定するだけで、不足量は断定しない。**

## ★ 決定 2: **段 4 の後に「入口の総括」を置く**

**段ごとに実測してきたが、各段の着地は次段の見込みを毎回変えている**
（段 1 −7,470 ／ 段 2 −721 ／ 段 3 は本 PR で実測）。

**段 4 が終わった時点で、入口から出せるものは尽きる。**
**そこで一度、上記コマンドで現在値を出し、`CLAUDE.md` から出すべき量を確定する。**
**それまで `CLAUDE.md` には手を付けない** —— **必要量が分からないまま削ると、削りすぎるか足りないかのどちらかになる。**

## 決定 3: **[[IADR-0173]] の 2 決定は変えない**

**規範を出さない・見出しはスタブとして残す** —— **どちらも 50KB 到達を遠ざける**が、**変えない。**

| 決定 | 変えない理由 |
| --- | --- |
| 規範は出さない | **別紙を読まなかっただけで CI に落ちる。** 止まってから読むのでは手戻り |
| 見出しはスタブとして残す | **確定済み記録が節名で引いている**（段 3 の対象節は**確定済み 5 件で最多**）。規約上、引用側を直せない |

> **★ 目標に届かないことを理由に、統制を弱める方向の判断をしない。**
> **50KB は手段の目安であって、規約を守らせる力より優先しない。**

## 結果

- 段 3 の対象節から**説明・経緯の 4 塊を別紙へ出し**、**規範と見出しは入口に残した**
- **`CLAUDE.md` の減量を確定事項とした**（決定 1）
- **段 4 の後に総括を置き、それまで `CLAUDE.md` に手を付けない**ことを決めた（決定 2）
- **本 ADR は可変の数値を断定せず、測り方を書いた**（決定 0）

## 検出しないこと（明示する）

- **段 4 の規範比率** —— 未実測。**着手時に測る**
- **`CLAUDE.md` から出せる量** —— 未実測。**段 4 の総括で確定する**（決定 2）
- **50,000 に到達できること自体** —— **本 ADR は保証しない。**
  **入口を尽くしても届かない**ことまでが実測で分かっている範囲である
