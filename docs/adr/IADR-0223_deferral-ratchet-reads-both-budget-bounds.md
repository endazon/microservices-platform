# IADR-0223: 保留の根拠ラチェットは予算の上限と下限の両方を読む

- 状態: Accepted
- 日付: 2026-08-17
- 決定者: 実装担当（AI）／#853 の自動 AI レビューが検出した自己矛盾への対処

## 起点・関連

- [[IADR-0204]] 決定 1 —— **保留（分類 X）の根拠そのものを機械が検査する**。本 ADR はその判定式を改める。
- [[IADR-0190]] —— 必読規約に**恒久的な余白（下限）**を確保する。`scripts.repo.test.js` の `#730`（`FLOOR = 1000`）。
- [[IADR-0200]] —— 予算値と母集合の**単一情報源**は `scripts/check-reading-budget.js`。
- [[IADR-0205]] 決定 3 —— 分類 A の側でも空振りしない形（対偶）で検査する。
- [[IADR-0058]] —— private な `planning` submodule は PR の CI では取得しない。

## 背景

`scripts.repo.test.js` の `#790 / #793: traceability.md の分類とキット原文の予算適合が一致している` は、
「分類 X（保留）に居るなら、**保留の根拠が実測で生きている**こと」をラチェットとして固定していた。
その判定式は **上限だけ**を見ていた。

```js
// 変更前
if (deferred) assert.ok(would > BUDGET_BYTES, '...保留の根拠が消えた...');
else          assert.ok(would <= BUDGET_BYTES, '...追随を維持できない...');
```

この式が書かれた時点では、取り込みを妨げる要因が上限（51,200B）しか無かったため正しかった。
その後 [[IADR-0190]] が**下限（確保した余白 1,000B）**を別に設け、**取り込み可否を決める条件が 2 本になった**。
**判定式は追随していなかった。**

## 実際に起きたこと

計画 pin を `f216783` → `b095b8f` へ進めたところ、キット版 `traceability.md` が
**25,963B → 25,207B（−756B）へ純減**し、次の状態が生まれた。

| 判定 | 値 |
| ---: | --- |
| 取り込み後の合計（`would`） | **50,747B** |
| 上限 51,200B | ✅ **満たす** |
| 余白 | **453B** |
| 下限 1,000B | ❌ **547B 不足** |

**取り込みは依然として不可能**（下限を割る）にもかかわらず、上限しか見ない `#790 / #793` は
**「保留の根拠が消えた。分類 A へ戻せ」と誤って赤くなった。**

```text
AssertionError: キット版を取り込んでも予算内（50747B <= 51200B）である。
  保留の根拠が消えたので .claude/rules/traceability.md をキット原文で上書きし、分類 A へ戻すこと（#793）
```

**根拠が消えていないのに消えたと言う**のは、[[IADR-0204]] 決定 1 の意図（保留の正当性を機械が検査する）を
外している。指示どおり分類 A へ戻せば、今度は `#730` が落ちる —— **2 つのラチェットが矛盾した指示を出す状態**であった。

## 決定

### 決定 1: 判定の軸を「取り込みが実際に可能か」へ揃える

上限・下限のどちらか一方でも満たせなければ「取り込めない」と判定する。

```js
const margin = BUDGET_BYTES - would;
const adoptable = would <= BUDGET_BYTES && margin >= MARGIN_FLOOR_BYTES;
if (deferred) assert.ok(!adoptable, '...保留の根拠が消えた...');
else          assert.ok(adoptable,  '...追随を維持できない...');
```

**保留の側と分類 A の側は対偶のまま保つ**（[[IADR-0205]] 決定 3）。失敗メッセージには
**どちらの境界で落ちたか**と、**あと何バイト減らせばよいか**を出す。

### 決定 2: 下限の値は `check-reading-budget.js` が単一情報源として持つ

下限を読む場所が `#730` と `#790 / #793` の **2 つになった**ため、リテラルを各所に置かない。
`MARGIN_FLOOR_BYTES`（既定 1,000・環境変数 `READING_BUDGET_FLOOR` で上書き可）を
`scripts/check-reading-budget.js` へ置き、両方がこれを読む。**予算値 `BUDGET_BYTES` を
同ファイルへ集めたのと同じ理由**である（[[IADR-0200]]）。

**下限を緩めると 2 つのラチェットが同時に黙る**ため、値そのものを 2 か所で固定する
（`check-reading-budget.js` の `--self-test` と `scripts.repo.test.js` の `#755`）。

### 決定 3: 保留の解除は「減量」と「移設先への転記」を同時に行う

キット版 `traceability.md` は、移設した内容を相対リンク（`../../docs/ai-workflow.md`）で
**参照するだけ**になった（planning#407）。**`traceability.md` だけを取り込むとリンク先に中身が無い。**
`#790 / #793` の失敗メッセージにこの条件を書き入れ、解除作業が片肺で行われないようにする。

解除に要るのは次の 3 点の**同時適用**である。

1. 必読集合から **547B 以上**の減量（規範でない部分の別紙化。[[IADR-0173]] / [[IADR-0190]] 決定 2）
2. キット原文で `.claude/rules/traceability.md` を上書き
3. キット版 `docs/ai-workflow.md` の差分を本リポの同ファイルへ転記（分類 B・種 2 のデルタは保つ）

## 却下した代替案

### 代替案 A: 分類 A へ戻す（ラチェットの指示どおりにする）

**却下。** `#730` が落ちる（余白 453B < 下限 1,000B）。**ラチェットの指示自体が誤っていた**のであり、
指示に従うと [[IADR-0190]] が確保した余白を食い潰す。

### 代替案 B: 保留の理由欄（分類表）だけを書き換え、ラチェットは触らない

**却下。** 分類表は人が読む記録であり、**機械はそれを読まない**。散文だけ整合させても
`#790 / #793` は赤いままで、**「文章では整合しているが CI が検査する条件には違反している」**状態が残る。

### 代替案 C: `#790 / #793` から保留側の検査を外す

**却下。** [[IADR-0204]] 決定 1 の「保留の根拠そのものを機械が検査する」装置ごと失われる。
既存コメントが明記するとおり、**この試験は消さない**。

### 代替案 D: 下限 `FLOOR` を引き下げて取り込みを通す

**却下。** [[IADR-0190]] が別紙化で作った余白を、**測り直さずに定義のほうを緩める**行為である。
下限を動かすなら改定 ADR で根拠を残す。

## 影響

- **この 2 つのラチェットは PR の CI では走らない。** [[IADR-0058]] により private な `planning` submodule を
  PR の CI で取得しないため、`fs.existsSync(KIT)` が false となり `#790 / #793` は notice を出して早期 return する。
  **「CI が green」は本検査が通ったことの裏付けにならない。** 本 ADR の変更は、`planning` を populate した
  環境で `REQUIRE_REPO_TESTS=1 node scripts/scripts.test.js` を実走して確認した（変異試験つき。後述）。
- **本 PR では CI の配線を変えない。** planning を PR の CI で取得するには token 付きの checkout が要り、
  fork からの PR で秘匿情報の扱いが変わる。**夜間ジョブ（`doc-links-planning.yml` / `planning-pin-freshness.yml`）
  側へ寄せるのが既存の型**であり、どちらへ寄せるかは別途決める（未解決）。
- `#730` の `FLOOR` はリテラルから `rbudget.MARGIN_FLOOR_BYTES` の参照へ変わる（値は変わらない）。

## 検証

`planning` を pin `b095b8f` で populate した状態で実測した。

```text
REQUIRE_REPO_TESTS=1 node scripts/scripts.test.js        ✓ 651 tests passed
node scripts/check-reading-budget.js --self-test         自己試験 16 件がすべて通った
```

**変異試験**（判定が空振りしていないことの確認）—— 下限を 0 へ落とすと取り込み可能になり、
保留側のラチェットが正しく鳴る。

```text
READING_BUDGET_FLOOR=0 REQUIRE_REPO_TESTS=1 node scripts/scripts.test.js
  AssertionError: キット版を取り込める（50747B <= 51200B かつ余白 453B >= 下限 0B）。
    保留の根拠が消えたので ... 分類 A へ戻すこと（#793）。
    **取り込みは docs/ai-workflow.md への転記と同時に行う** ...
```
