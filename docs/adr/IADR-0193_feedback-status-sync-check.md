# IADR-0193: 環流記録の `status` 追随と突合検査（#737）

- 状態: Accepted
- 日付: 2026-08-14
- 決定者: claude（実装）

## 起点・関連

- **NFR**（文書統制。**当たる番号が無い＝場合 ②** なので無採番・環流しない。[IADR-0179](./IADR-0179_unnumbered-nfr-for-meta-work.md) 決定 1）
- 実装 issue: **#737**
- 作業仕様書: [20260814_issue-737](../specs/20260814_issue-737_feedback-status-sync.md)

## 文脈 —— **語彙を差し替えたとき、確認の軸を差し替えていなかった**

**planning#323 の裁定により `status` は「計画側の裁定がどこまで進んだか」を表す**
（伝達したかは `dispatched:` が担う。[IADR-0187](./IADR-0187_status-vocabulary-follows-upstream-adjudication.md) 決定 1）。
**値の正は計画側にある。**

**[IADR-0187](./IADR-0187_status-vocabulary-follows-upstream-adjudication.md) 決定 2 は `triaged` 11 件を `open` ＋ `dispatched: true` へ移行し、
その前に「本当に伝達済みか」を全数で確かめた。** —— **確かめたのは `dispatched` の軸である。**

**裁定後の `status` が「計画側の裁定の進捗」なのだから、移行時に確かめるべきだったのは
「計画側が既に裁定していないか」であった。** **確かめなかったため、既に `accepted` だった記録へ一律に `open` を書いた。**

> **★ 語彙を差し替えるときは、値だけでなく「何を確かめるか」も差し替わる。**
> **移行前の値が `triaged`（＝伝達の意味）だったため、検証の軸が旧語彙へ引きずられた。**

## ★★ 決定 1: **11 件を計画側の裁定へ追随させる**

| 系統 | 件数 | 追随 |
| --- | ---: | --- |
| **#721 の移行が上書きした** | **10** | 9 件 → `accepted` ／ 1 件（`20260719_headlamp…`）→ `awaiting-decision` |
| **#504 の取り下げと計画側の裁定が別語になった** | **1** | `20260709_sc11-wireframe-drawio`: `rejected` → `accepted` |

**10 件すべて、計画側の裁定は #721 のマージより前に下りている**（実測。2026-08-09〜2026-08-14）。

### `20260709_sc11` は陳腐化ではない —— **結論は一致しており、食い違っているのは語だけである**

| | 実装側（#504・2026-08-05） | 計画側（planning#329 の棚卸し・2026-08-14） |
| --- | --- | --- |
| 語 | `rejected`（**取り下げ**） | `accepted` |
| 中身 | **drawio は作らない**。HTML モックアップが正 | **drawio は作らない**。「形式の違いであって不足ではない」 |

**`status` は計画側の裁定を表すのだから、語は計画側に合わせる。**
**陳腐化した `status_note`（「計画側原典は open（planning 未追随）」）は、当時は正しく、いま偽である。**

## ★★ 決定 2: **frontmatter だけを直す。本文へ追記しない**

**[IADR-0191](./IADR-0191_rewrite-boundary-is-body-vs-frontmatter.md) が引いた境界どおりにする** ——
**「書き換えない」の対象は本文への後付け注記であり、frontmatter の状態欄は対象外である。**

> **★ 本文へ「追随した」と書き足したくなるが、それは #733 が撤去を諮っている当のものである。**
> **利用者の裁定を待っている実務を、別 issue の作業で既成事実にしない。**

**追随の経緯は本 ADR と作業仕様書が持ち、記録側は `status` と `status_note` だけを動かす。**

## ★★ 決定 3: **突合を機械検査にする。同型 2 回目である**

| # | 同型の事故 |
| --- | --- |
| 1 | **AST#477 / `AST/IADR-0188`** —— 実装側 18 件が `open`、計画側は `accepted`（**同じ向き・同じ原因**） |
| 2 | **本件** —— 本リポで 10 件 |

**`CLAUDE.md`「検査器・規約の追加は同型の事故が 2 回起きたら」を満たす。**
**`feedback/README.md` が「この語彙を検査する機械は無い。値の誤りは沈黙する」と明記していた**ところの、その沈黙である。

**計画側も planning#329 の記録で「次に同じ形が出たら機械化を検討する」と述べており、本件がその「次」に当たる**
（planning#329 へ回答済み）。

## ★★ 決定 4: **写しを持たない記録を不一致にしない。ただし黙って捨てない**

**記録ファイル経路と GitHub Issue 経路は等価である**（`feedback/README.md` §経路ごとの証拠。planning#319）。
**計画側 `draft/feedback/` に写しが無いことは、伝達していないことを意味しない。**

**不一致に数えると恒久的な偽陽性が 5 件残る**（実測。別日付で収録された 2 件 ＋ 記録ファイル経路を採っていない 3 件）。

**したがって検査対象から外すが、件数を出力に出す。** **門（#664 の型）を 2 つ置く:**

- **記録が 0 件なら fail**（走査が空振りしている）
- **突合できた件数が 0 なら fail**（検査が実質何も見ていない）

## ★★ 決定 5: **変異試験は `--self-test` として恒久化する。手で確かめただけにしない**

**当初コミットしたテストは、実データに対して `main()` が 0 を返すことしか見ていなかった**（#738 レビュー 🟡）。
**全記録が同期している限り、`implStatus !== planStatus` を `===` に取り違えても緑のままである。**

> **★ 「変異試験で検出を確認した」と書けるのは、その変異を CI が拒むときだけである。**
> **セッション中に手で確かめたことは、次の変更を守らない。**

**`compare(implDir, planDir)` を経路引数の形へ分離し、`--self-test` が R1〜R5 を fixture で駆動する**
（本リポの既存イディオム。`check-plan-id-qualification.js` 等が同じ形）。

**さらに、自己試験そのものが利くことを回帰テストで固定した** ——
**`!==` → `===` を注入した変異体を書き出し、自己試験が非 0 で落ちることを確かめる。**

**副次的な利得**: **`--self-test` は fixture で駆動するため `planning` 未 populate でも実効する。**
**実データ走査が skip される CI でも、この 1 本だけは必ず何かを検査している**（決定 3 の弱点を部分的に埋める）。

## 決定 6: **pin を前進させる。前進に伴う追随の要否を先に実測する**

**`20260709_sc11` の裁定は planning `130a109` で入ったため、pin が `915981a` のままだと検査が観測できない。**

**#721 は pin だけ進めて追随を伴わなかった。** 同じ轍を踏まないよう、**前進の影響を先に引いた。**

| 確かめたこと | 結果 |
| --- | --- |
| `tools/impl-handoff-kit/` の差分 | **空** —— **キット追随は不要** |
| `projects/microservices-platform/` の差分 | **空** —— **ID レンジの引き直しは不要** |

## 結果

- 良い影響
  - **`status` の陳腐化が沈黙しなくなった**（`feedback/README.md` が認めていた穴が閉じる）
  - **計画側の裁定が実装側から読めるようになった** —— 11 件は「裁定待ち」に見えていた
  - **pin 前進の影響を先に引く型が、2 回目にして実行された**（#721 の反省）
- 悪い影響・トレードオフ
  - **`planning` 未 populate の CI では skip する**（`doc-links` と同じ既知の制約）
  - **写しを持たない記録は検査されない**（決定 4。両経路が等価である以上、避けられない）
  - **値そのものの妥当性は依然として沈黙する**（下記）
- フォローアップ
  - **本検査器のキットへの環流** —— **#736 に積む**（キットは本検査器を持たない）

## 検出しないこと（明示する）

- **`status` の値そのものの妥当性** —— **一致を見る検査であって、正しさを見る検査ではない。**
  **両側が同じ値なら、その値が語彙外でも意味を取り違えていても素通りする**
- **`status` 以外の内容差分** —— 実装側はトリアージ結果節を持たない等、**正当な差がある**
- **写しを持たない記録**（決定 4）
- **計画側にしか無い記録** —— 本リポから見えない。**逆向きの陳腐化は計画側が引く**（planning#329 が実際に引いた）
