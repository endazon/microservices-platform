# IADR-0180: blocked 判定の再検証（#701 / #623）

- 状態: Accepted
- 日付: 2026-08-11
- 決定者: claude（起案・実装）

## 起点・関連

- **NFR**（運用保守。**メタ作業なので無採番**。[[IADR-0179]] 決定 1）
- 実装 issue: **#701**（**#623 の子**・受け入れ基準 4）
- 正本: `planning/docs/ai-implementation-workflow-guide.md` §6
- 再発防止の対象: **#554 / #556 / #562 → #617**
- 作業仕様書: [20260811_issue-701](../specs/20260811_issue-701_blocked-reverification.md)

## ★★ 決定 1: **判定には賞味期限がある**

**「AI だけでは閉じられない」は環境に対する観測であり、環境は変わる。**
**したがって、一度書いた判定は棚卸しのたびに測り直す。**

**根拠は #617 の実測である** —— #554 / #556 / #562 の 3 件は
「AI だけでは完結しない」として保留され、**フェーズ B を打ち切る根拠にされた**が、
**3 件とも別の環境では実施でき、同日中に着地した。**

## ★ 決定 2: **判定に「最後に測った時点」を添える**

**時点の無い判定は、再検証すべきかどうかを判断できない。**
日付 ＋ 起票 ID を添え、**測り直して覆ったら分類を動かし、覆った事実を残す**（消さない）。

## ★ 決定 3: **規範は「手順書」の節に置き、「スナップショット」からは指す**

`docs/how-to/session-handoff.md` の **§2 は自ら「この節だけは必ず古くなる」と書いている。**
**規範の置き場所として不適**である。**§4.5（#617 が「実測の手順書」として書き直した節）へ置く。**

> **★ §2 が古くなること自体は直さない。** **古くなってよい**（生きた状態は GitHub が正）。
> **古いと分かる形にする**のが目的である。

## 決定 4: **機械検査は置かない**

**「環境固有の観測か恒久制約か」は意味の理解が要り、文字列一致では判定できない**
（本リポが `AST` の近傍規則で既に採っている言い方と同じ）。
**同型の事故はまだ 1 回**（#617）であり、`CLAUDE.md`「同型の事故が 2 回起きたら」にも満たない。

**回帰テストで固定するのは「規範が消えないこと」だけ**である。

## 結果

- **棚卸しのたびに行 H を測り直す**規範を §4.5 へ置いた（決定 1・3）
- **判定へ「最後に測った時点」を持たせた**（決定 2）
- **§5 型 8 との住み分けを明示した** —— 型 8 は**書くとき**、本決定は**書いた後**

## 検出しないこと（明示する）

- **判定が正しいかどうか** —— **機械検査は無い**（決定 4）
- **行 H の個々の issue の現在の可否** —— **本 ADR は観点を定めるだけ。**
  **#574 / #546 / #336 / #380 / #578 は現在も環境依存として据え置き**であり、各着手時に測る
- **棚卸しが実際に行われること** —— **本リポに棚卸しの自動化は無い**（planning 側の `stocktake.js` 相当が無い）
