# IADR-0155: 文書の `updated:` 据え置きは「base 以降の最初のコミット日」と比べて検出する

- 状態: Accepted
- 日付: 2026-08-10
- 決定者: claude（実装）

## 起点・関連

- **NFR**（文書の保守性・トレーサビリティ）。実装 issue: **#649** / PR **#652**
- `CLAUDE.md`「**検査器・規約の追加は同型の事故が 2 回起きたら**」
- 作業仕様書: [20260810_issue-649](../specs/20260810_issue-649_doc-updated-checker.md)

## コンテキストと課題

内容を変えた文書の `updated:` が据え置かれる事故が **2 回**起きた（PR #648 レビュー 2 巡目で 9 件、
4 巡目で `IADR-0030` が 1 件）。**原因は 2 回とも同じ**で、「本文を編集した」と
「frontmatter を更新した」が**別操作**であり、**前者だけでも既存の機械検査は全て通る**。

決めること: (1) 据え置きをどう判定するか。(2) 何を対象外にするか。(3) CI へどう載せるか。

## 決定

### 決定 1: 判定は **`updated:` < base 以降の最初のコミットの日付**（案 C）

**3 案を PR #648 の変更文書 12 件へ当てて選んだ。**

| 案 | 判定 | 挙げた件数 | 評価 |
| --- | --- | --- | --- |
| A | `updated:` が base から変わっていない | **2** | **誤検知あり**。develop 側が既に同日付なら、**同日中の再編集は据え置きが正しい** |
| B | `updated:` < その文書を最後に変えたコミットの日付 | **10** | **誤検知だらけ**。コミットが UTC の日付境界を跨ぐと全件落ちる |
| **C** | **`updated:` < base 以降の最初のコミット日** | **1** | **正確** |

**採るのは案 C。同日は通す。**

**この ADR が本当に記録したいのは「案 C を選んだ」ことではなく、選び方である**——
**検査器は思いついた式ではなく、手元の実例へ当てて誤検知を数えてから入れる。**
案 A・B を実測せずに入れていたら、誤検知で早々に無効化されていた。
案 A の誤検知は**回帰テストとして固定**してある。

### 決定 2: 本文が変わったかは **frontmatter を除いた本文の比較**で判定する

`git diff` のハンク解析は出力形式に依存し、frontmatter が壊れたファイルで誤判定する。
base 版と HEAD 版から frontmatter を除いた本文を取り出して比較すれば、形式に依存しない。

### 決定 3: **`docs/templates/` は対象外**

雛形の `updated:` は**穴**（`<YYYY-MM-DD>`）であり、**埋まっていないのが正しい状態**である。
本文（項目追加・誤字直し）を編集するたびに `invalid-date` で落ちると、
**検査器が邪魔者になって外される**。

> **これは入れる前に気づけなかった見落としである**（PR #652 レビュー 1 巡目が 17 件で実測した）。
> 決定 1 で「実例へ当てて誤検知を数えてから入れる」と書いておきながら、
> **当てた実例が PR #648 の 12 件だけで、テンプレートを含んでいなかった。**
> **誤検知の実測は「対象になり得る母集合」全体へ当てないと意味が薄い。**

除外は**パスに閉じる**（日付検査そのものは緩めない）。テンプレートが穴のままであるという
前提が崩れたら気づけるよう、実データを見る回帰テストを置いた。

### 決定 4: CI 配線は **`scripts-tests` への相乗り**（新ジョブを作らない）

`.github/workflows/` は GitHub App 権限で編集できない。[[IADR-0140]] 決定 2 が
`check-cross-repo-refs` / `check-plan-id-qualification` で確立した相乗り方式へ載せる。

**起票時は「配線は別途」と書いたが誤りだった。**「権限が無いからできない」と書く前に、
**同じ制約下で先に解いた例が無いかを見る**。

## 根拠 / 代替案

- **`updated:` を持たない文書を violation にしない**: `README.md` 等が該当し、
  「日付を持て」という規約は別の話である。notice に留める。
- **未来日を見ない**: 日付の妥当性は本検査器の射程ではない。**検出しないことは冒頭コメントに開示した。**

## 影響

- `scripts/check-doc-updated.js`（新設）と `scripts/scripts.repo.test.js` の自己試験。
- CI は `scripts-tests` ジョブから走る（`fetch-depth: 0` は既に満たされている）。
