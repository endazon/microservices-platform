# IADR-0189: planning#311 への追随と、追随漏れの検出経路（#728）

- 状態: Accepted
- 日付: 2026-08-14
- 決定者: claude（実装）

## 起点・関連

- **NFR**（文書統制。**該当する `NFR-xx` が無い作業＝場合 ②** なので無採番。
  **本 ADR が取り込む当の条文に従っている**）
- 実装 issue: **#728**（出所: PR #727 のマージ直後、利用者の指示で planning の更新を確認した際に検出）
- 作業仕様書: [20260814_issue-728](../specs/20260814_issue-728_follow-planning311-unnumbered-nfr-clause.md)

## ★★ 文脈 —— **上流は 3 日前に裁定していた**

**[IADR-0188](./IADR-0188_unnumbered-nfr-applies-to-all-work.md)（2026-08-14 マージ）は無採番 `NFR` の射程を一般化した。**
**planning#311 は 2026-08-11 に同じ結論を出し、キットへ反映していた。**

> **裁定 1: 「当たる番号が無ければ無採番」という読みで相違ないか → 相違ない。実装側の読み（`IADR-0179`）を追認する**

**結論が一致しているので実装上の誤りは無い。** **問題は 2 つある。**

| # | 問題 |
| --- | --- |
| 1 | **IADR-0188 が planning#311 を引用していない** —— 「本リポが決めた」形になっている |
| 2 | **キットが持つ規範 4 点が本リポに無い** —— とくに**「① は環流する / ② は環流しない」** |

**②「環流しない」の欠落が実害である。** **無採番を採るたびに環流の要否を判断できない** ——
[IADR-0179](./IADR-0179_unnumbered-nfr-for-meta-work.md) 決定 3 は実際に環流したが、**上流は「② では環流しない」と裁定している。**

## ★★ 決定 1: **キットの規範 4 点を入口へ取り込む。逐語コピーはしない**

**入口 `.claude/rules/traceability.md` は分類 B/C であり、バイト一致の対象ではない。**
**取り込むのは規範であって文章ではない。**

| 規範 | 取り込み |
| --- | --- |
| ① ID 列が無い → **環流する** | 入口へ |
| ② ID 列はあるが当たる番号が無い → **環流しない** | 入口へ |
| **「面倒だから無採番」は ② に当たらない** | 入口へ |
| **着手前に計画の ID 列を見て判断する** | 入口へ（**言い換え**。キットは「作業を始める前に」） |

**キット原文 1,525B に対し、入口の増分は 349B である。**
**差はキットが持つ理由と典型例の説明**であり、**本リポは別紙と ADR がそれを持つ。**

## ★ 決定 2: **#688 / #724 の記述と統合する。並置しない**

**場合 ② は #724 が一般化した内容そのものである。**
**並べれば同じ規範が 2 つになり、片方が古くなる**（[IADR-0141](./IADR-0141_audit-rounds-and-population-drawing.md)）。**1 つの箇条へ畳んだ。**

**#724 の回帰テストが固定する 4 文字列はすべて保持した** —— **統合はテストを緩めて行うものではない。**

## 決定 3: **ID 種別名は `NFR` のままとする（固有デルタ）**

**キットは `NFR-xx` と書き、「粒度なしの `NFR` だけを書かない」と定める。本リポは種別名を `NFR` のままにする。**

| | 理由 |
| --- | --- |
| 1 | **既存参照が一律 `NFR`** であり、**planning#295 が遡及書き換えを禁じている** |
| 2 | 種別名を `NFR-xx` にすると**「裸の `NFR` は種別として存在しない」と読める** —— 既存参照と矛盾する |
| 3 | **キットの意図（粒度なしを既定にしない）は箇条の側で満たしている** —— 採番の実在と 2 場合をそこに書いた |

**[IADR-0115](./IADR-0115_impl-handoff-kit-as-single-source.md) 決定 2 の固有デルタとして記録する。** **環流は不要**（本リポ固有の既存参照の事情である）。

## ★★ 決定 4: **IADR-0188 は覆さない。引用の欠落だけを日付つき追記で是正する**

**決定内容は上流と一致しており、正しい。**
**独立に同じ結論へ至ったことと、上流の裁定に従ったことは、記録として区別する価値がある** ——
**前者は「実装側の読みが妥当だった」ことの証拠**であり、**後者は「上流に従った」という別の事実**である。

> **★ 事後に「最初から上流に従っていた」と書き換えない。** **それは記録の改竄である。**

## ★★ 決定 5: **この型は「バイト一致テストでは捕まらない追随漏れ」である**

**#721 は分類 A のバイト一致テストが検出した。本件は検出できなかった。**

| | #721 | #728 |
| --- | --- | --- |
| 対象 | `check-feedback-dispatched.js` / `TEMPLATE.md` | **`.claude/rules/traceability.md`** |
| 分類 | **A**（バイト一致） | **B/C**（固有デルタ込み） |
| 検出 | **回帰テストが自動で落ちた** | **人が planning を見に行って気づいた** |

**分類 B/C の追随漏れを機械で捕まえる手段は無い。** **本 ADR も作らない** ——
**「規範が移ったか」を機械が知るには意味の理解が要り、文字列一致では偽陽性が避けられない**
（本リポが `AST` の近傍規則・規則 7 の機械検査で既に採っている言い方と同じ）。

**代わりに、取り込んだ 4 語を回帰テストで固定した** —— **「入った規範が後で消える」ことは捕まえられる。**
**「上流に新しい規範が入った」ことは捕まえられない。** **これは #713（キット追随の棚卸し）の領分である。**

## ★ 決定 6: **入口の予算捻出が 2 回連続した。「同型 2 回」として起票する**

**#724 と本 PR の 2 連続で、規範を足すために捻出を強いられた。**
`CLAUDE.md`「検査器・規約の追加は同型の事故が 2 回起きたら」の**2 回目**である。

**本 PR では恒久的な余白の確保を行わない** —— **節の別紙化は規範の射程に触れる作業**であり、別の判断が要る。
**別 issue として起票する。**

### 捻出したもの（**すべて重複または規範でない部分**）

| # | 対象 | 種別 | 削減 |
| --- | --- | --- | ---: |
| 1 | 「このレンジが効くのは、ローカル実行と…AI だけ」 | **別紙と重複**（行単位の機械検出） | **−125B** |
| 2 | 「★ 5 種目が生まれた。」 | 経緯（別紙 §4 が持つ） | **−30B** |
| 3 | 「（レンジは…突合基準であり…誤検出する）」 | **規範の理由**（規範は直前行） | **−151B** |
| 4 | ID レンジ行の「内訳と…は別紙」 | **直後の別紙導線と重複** | **−70B** |

**削る前に、4 語すべてが回帰テスト・NORMS 一覧に固定されていないことを確認した。**

## 結果

- 良い影響
  - **無採番を採るときに環流の要否が判断できる**（従前は書かれていなかった）
  - **IADR-0188 から planning#311 が辿れる**
  - **入口の余白が 13B → 26B へ増えた**（規範を 4 点足しながら）
- 悪い影響・トレードオフ
  - **余白 26B は依然として薄い。** 決定 6 の起票が実効するまで、次の加筆も捻出を伴う
  - **分類 B/C の追随漏れは、次も人が見つけるしかない**（決定 5）
- フォローアップ
  - **恒久的な余白の確保**（決定 6 で起票）
  - **planning#315 / planning#316 の取り込み** —— **キットに入っていることは確認済み**。対象ファイルが違うので **#713** で拾う

## 検出しないこと（明示する）

- **上流に新しい規範が入ったこと** —— **決定 5。** 機械検査は置かない
- **無採番が ① と ② のどちらに当たるか** —— **書き手が判断する。** 機械には決められない
- **入口に「規範でない部分」が残っているか** —— **測る手段は無い。** 予算テストは合計しか見ない
