# IADR-0144: 採番検査は着地後の不整合だけを止め、並行 PR の衝突は未然に防げないことを明記する

- 状態: Accepted
- 日付: 2026-08-08
- 決定者: Claude（実装）

## 起点・関連

- 関連する計画書 ID: NFR（保守性・追跡可能性）
- 関連 issue: [#581](https://github.com/endazon/microservices-platform/issues/581)（起点。親 [#454](https://github.com/endazon/microservices-platform/issues/454)）
- 関連する実装 ADR: [[IADR-0140]]（CI 結線方式）／[[IADR-0141]]（母集合）／[[IADR-0143]]（姉妹検査器の作法）
- 規約: [`.claude/rules/traceability.md`](../../.claude/rules/traceability.md)「採番衝突時の改番手順」

## 背景

規約は「**先着尊重・後発は次の空き番号へ・欠番を作らない**」と定めるが、**守る機械が無かった**。
**衝突は既に 2 回起きて 2 回とも人手で事後修復している**（#530 の `IADR-0132` 重複、
#533/#538 の重複で `IADR-0136` → `IADR-0137` へ改番・追随先 24 箇所）。

`scripts/` に採番検査は無く、唯一 IADR に触れる `check-commit-messages.js` は
**コミット件名スコープの `IADR-xxxx` が実在するか**しか見ない。
**番号の重複・欠番・索引との過不足・自称番号の一致は、どれも誰も見ていなかった。**

## 決定

### 決定 1: 6 判定を機械化する

重複なし／欠番なし（**`0000` 起点で**最大番号まで連続）／ファイル名の番号 = 本文の自称番号／
索引 `docs/adr/README.md` ⇔ 実ファイルが**双方向**で過不足なし／索引が昇順／
**索引行の「形」**（ID セルがリンク形式か・リンク先ファイル名が当該 ID で始まるか・行末の閉じ `|`）。

**欠番の下端は 0 に固定する**（#606 レビュー）。当初は実在する最小番号を起点にしていたが、
それでは**先頭がまるごと欠けている型**（`IADR-0000` から数本が消える）が「連続」として緑になる。
採番が `0000` から始まるのは規約であり、下端は実データから導かない。

**判定 6 は #580 から統合したものである**（決定 6）。

### 決定 2: **件数を判定にも baseline にも書かない**

判定は「連続」「重複なし」「双方向一致」という**関係**であり、総数は関係から導かれる。
**数を持つと IADR を足すたびに更新が要り、必ず古くなる**（#590 が「3 型」で踏んだ型）。
実際 **#581 の本文が挙げる「139 件」は着手時点で既に古く、実測は 144 件**だった。

### 決定 3: **この検査は並行 PR の衝突を未然に防げない**（#581 が明記を求めた）

**衝突の本体は「並行 PR が互いの採番を見ない」ことであり、本検査は develop に着地した後しか
見られない。** 2 本の PR が同じ番号を持ったまま並行しても、**先にマージされた側は通り、
後発の CI が初めて落ちる**。

**それでも価値はある** —— 現状は**後発も素通りし、人が気づくまで develop が壊れたまま**である。
規約の後半（欠番を作らない・重複を残さない）だけを機械化するものであり、**先着の調停はできない**。

### 決定 4: 検査不能は **fail-closed**

ディレクトリが読めない・`IADR-xxxx_*.md` が 1 件も無い場合は**違反として上げる**。
「見つからないから素通り」で検査が静かに失効するのを防ぐ（`check-i18n-catalogs.js` と同じ作法）。

### 決定 5: 索引行の抽出は `scripts.repo.test.js` と**同じ形**に揃える

2 箇所に別々の正規表現を書くと、片方だけ直したとき挙動が黙って割れる
（[[IADR-0143]] が `maskCode` を借りたのと同じ理由）。

### 決定 6: #580 の索引行「形」検査を本検査へ統合し、`scripts.repo.test.js` から削除する

#580 は同じ検査を `scripts/scripts.repo.test.js` の `inspectAdrIndex` ブロックに置き、
作業仕様書（[`20260807_issue-580_adr-records-drift.md`](../specs/20260807_issue-580_adr-records-drift.md)）で
「#581 が索引行をパースする時点で統合し、そちらからは削除する。**同じ不変条件の検査を 2 本残さない**」
と申し送っていた。本検査は判定 4・5 のために索引行をパースするので、ここが統合先である。

**#580 が置いていた fail-open 下限（索引行数 >= ADR 本体数）は引き継がない** ——
判定 4 の `index-missing` と `no-adr-files` が**同じことをより直接に**見るためであり、
下限値という手作業の更新点も同時に消える。

**実行経路は変わらない**（どちらも `ci.yml` の `scripts-tests` ジョブ）。

## 検出しないこと（本検査は網羅ではない）

- **並行 PR の衝突の未然防止**（決定 3）。
- **索引の状態列と本体 `status:` の突合** —— **#580 はこれも #581 へ委ねたが、本 PR では実装しない**
  （#606 レビューが「委譲されたのに未実装かつ未開示」と指摘したもの）。索引の状態セルは
  `Superseded by IADR-XXXX` のように**後継 ID を含む自由文**であり、本体 `status:` の語
  （`Accepted` / `Superseded` 等）と 1 対 1 に対応しない。突合するには先に状態列の語彙を規約化して
  既存行を揃える必要があり、それは索引タイトル列の要約化（`adr-index-title-baseline.json` の
  ラチェット）と同じ「**先に是正、後から検査**」の順序になる。**今検査を掛けると、是正の目標形では
  なく現状の大半を一斉に赤にするだけで方向が合わない**（[[IADR-0141]] が #580 のタイトル列で
  確立した判断と同型）。後続の起票で扱う。
- **リンク先ファイルの実在** —— `check-doc-links.js` の担当。二重に持たない（判定 6 は「形」だけを見る）。
- **索引タイトル列** —— `scripts.repo.test.js` のラチェットの担当。字義一致は方向が合わない。
- **計画 ADR（`ADR-xxxx`）の採番** —— 計画リポの所有物であり、本リポは pin を進めるだけ。
- **`docs/superpowers/` の旧 IADR** —— 保管された旧計画であり live な採番空間ではない。
- **改番時の追随先**（コード内コメント・テスト名・**PR タイトル**）。規約は追随を求めるが、
  本検査が見るのはファイル名・自称番号・索引の 3 つだけである。**PR タイトルは人手の追随に
  依存する最も漏れやすい箇所**（規約が明記）だが、ここでは守れない。

## 影響

- `scripts/check-adr-numbering.js` を新設し、`scripts.repo.test.js` 経由で `ci.yml` の
  `scripts-tests` へ相乗りする（[[IADR-0140]] 決定 2 と同じ結線。新ワークフローは足さない）。
- **実データは全判定 clean なので、検出力は変異でしか示せない。** 自己試験に M1〜M10 を対で常設し、
  実バイナリ経路（CLI が exit 1 を返すか）も別に固定した。
- `scripts/scripts.repo.test.js` の `inspectAdrIndex` ブロック（と fail-open 下限）を**削除**した
  （決定 6）。テスト総数はその分減るが、**同じ不変条件は判定 6 が引き継いでいる**。

## 棄却した案

| 案 | 棄却理由 |
| --- | --- |
| 総数を baseline に焼く | IADR を足すたびに更新が要り必ず古くなる（決定 2） |
| `check-doc-links.js` へ相乗り | 相対リンクの実在を見る道具であり責務が割れる |
| 並行 PR の衝突を止める仕組みを作る | develop 着地前に他 PR の採番を知る経路が無い。**できないことを明記する方を選んだ** |
