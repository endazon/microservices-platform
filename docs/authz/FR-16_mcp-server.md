# 権限・認可仕様書: MCP サーバー

## ロール定義

| ロール | 説明 | 対象 |
| --- | --- | --- |
| 管理者 | クライアント登録・無効化・属性割当・公開ツール一覧の確認 | システム管理者 |
| 有人エージェント | 利用者の代理としてツールを実行する MCP クライアント | 登録済みの対話型クライアント |
| 無人エージェント（サービスアカウント） | バッチ等、自然人の主体を持たない MCP クライアント | 登録済みのサービスアカウント |

## 認可マトリクス

| 機能 / リソース | 操作 | 管理者 | 有人エージェント | 無人エージェント |
| --- | --- | --- | --- | --- |
| クライアント登録管理 | 参照 | ○ | × | × |
| クライアント登録管理 | 更新 | ○ | × | × |
| 実効ツール一覧 | 参照 | ○ | ○（自分に公開されたもの） | ○（同左） |
| ツール実行 | 実行 | — | ○（利用者の権限スコープ内） | ○（サービスアカウントの権限スコープ内） |
| **個人資料** | 参照 | — | ○（所有者・共有先の判定に従う） | 🔴 **一律で対象外** |

## 認可ルール

### 1. 主体の解決

- 主体種別（有人 / 無人）は**登録簿から採る。トークンのクレームからは採らない。**
  クライアント側の申告で除外の適用対象から外れられないようにするためである。
- 登録簿は**呼び出しのたびに引く。キャッシュを挟まない。** 無効化を即時に効かせるためである。
- 未登録クライアントと無効化済みクライアントは**同じ文言**で拒否する（登録の有無を漏らさない）。

### 2. 🔴 サービスアカウント実行時の個人資料の一律除外

計画の決定は次のとおりである。

> サービスアカウント（無人エージェント）による実行では、個人資料を一律で探索・応答の対象外とする。
> **所有者の個人資料であっても含めない。**

適用の要点:

- **経路で分けない。** 検索・文書取得・グラフ探索のいずれにも同じ規則が及ぶ。
  経路によって扱いが変わると除外の意味が失われる。
- **2 層で強制する。** 下流サービスへ渡す実行スコープに除外制約を立て（要求側）、
  応答からも個人資料を落とす（応答側）。応答側は下流が制約を無視した場合の防壁である。
- **件数からも外す。** 「権限が無い」と「存在しない」を区別させない原則に従い、
  除外した文書は全体件数にも含めない。件数自体がサイドチャネルになる。
- **判定は集合帰属で書く。** 「文書スコープ属性が個人資料の値を持つ」で判定し、
  「組織文書でない」では判定しない。属性は新設で既存文書へ遡及付与しないため、
  否定で書くと組織文書が一斉に落ちる。

理由（計画側の論拠）: 動的束縛（所有者が現在の利用者であること）は**自然人の主体を前提とした
記法**であり、サービスアカウントを束縛先に据えると「誰の個人資料か」を問わない判定になりかねない。
無人経路では**除外という単純な規則**で原則を担保する。

### 3. サービスアカウントへの属性割当の制約

**個人資料を読ませる属性割当を構成上禁止する。** 公開構成のスキーマ検証と管理 API の両方で拒否し、
検証は 1 つの関数を共用する（2 箇所に書くと片方だけが緩むため）。

### 4. 公開範囲の統制（存在秘匿）

- 既定は非公開である。宣言的公開構成に明記されたツールだけが公開される。
- 構成に無いツールの呼び出しは **「不明なツール」** として拒否する。
  「権限がありません」と返すと、そのツールの存在が漏れる。
- 未登録・無効化されたクライアントには、ツール一覧そのものを空で返す。

### 5. データ越境（認可とは別の軸）

越境統制は「見えてよい文書の本文を外へ出してよいか」を決める。**存在秘匿とは別の軸**であり、
送信不可の文書を応答から消しはせず、本文を落として参照リンクのみへ縮退させる。
