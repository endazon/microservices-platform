# 権限・認可仕様書: 個人資料の共有先

## ロール定義

| ロール / 主体 | 説明 | 対象 |
| --- | --- | --- |
| 所有者 | 個人資料の作成者。共有先の付与・取り消しができる唯一の主体 | 認証済みの利用者本人 |
| 共有先（個人） | 利用者名で名指しされた利用者。読めるだけで再共有・書き込みはできない | 認証済みの利用者 |
| 共有先（グループ） | Keycloak グループの所属者。読めるだけ | 所属している認証済みの利用者 |
| 管理者 | 平時は非公開の個人資料を一切閲覧できない（共有されていれば共有先として読める） | `platform-admin` |
| サービスアカウント | 名簿の読み口（利用者・グループの検索）へ到達できない。共有先ベースの読み取りは自然人の主体を持たないため対象外 | `service-account-*` |

## 認可マトリクス

| 機能 / リソース | 操作 | 所有者 | 共有先 | 管理者 | サービスアカウント |
| --- | --- | --- | --- | --- | --- |
| 共有台帳（指定先の一覧・付与・取り消し） | 参照 / 更新 | 可 | 不可（404） | 不可（404） | 不可（404） |
| 共有された個人資料 | 参照（検索・詳細・本文・グラフ） | 可 | 可 | 共有されていれば可 | 不可 |
| 共有された個人資料 | 更新 / 再共有 | 可 | 不可 | 不可 | 不可 |
| 利用者の名簿（検索・表示名の解決） | 参照 | 可 | 可 | 可 | 不可（403） |
| グループの名簿（検索・表示名の解決） | 参照 | 可 | 可 | 可 | 不可（403） |
| グループ木の作成・所属の変更 | 更新 | — | — | Keycloak の管理コンソールで行う | — |

## 認可ルール

### 共有先ベースの分岐（選言の第 3 節）

読み取りの選言 `doc.scope ≠ private-note ∨ doc.owner = ${current_user} ∨ doc.shared_with ∩ ({${current_user}} ∪ ${current_groups}) ≠ ∅` の第 3 節は、**ポリシー 1 本**として表す。

```json
{
  "name": "共有された個人資料を読める",
  "action": "read",
  "documentConditions": { "shared_with": ["${current_user}", "${current_groups}"] }
}
```

- 評価器は `${current_user}` を利用者名（1 値）、`${current_groups}` を所属グループ ID の集合（0..N 値）へ展開し、1 ポリシー＝1 分岐として出す。展開後に許可集合が空になるフィルタを持つ分岐は落とす。
- 🔴 **配備環境では本ポリシーの投入が統制の実現手段である。** 投入前は共有が誰にも効かない（安全側だが「共有したのに見えない」）。開発環境の seed は `deploy/local/abac-seed/policies.json` にある。投入の有無はポリシー一覧の API で確かめる。
- `${current_groups}` の値は Keycloak のグループ ID であり、評価のたびに身元プロバイダの所属照会から引く（トークンのクレームは用いない）。キャッシュは無い。所属の変更は次の判定から反映される。所属照会に失敗した場合は「引けなかった」（503）であり、権限が無いとは記録しない。

### 共有先の値と突合

- 共有台帳の `subjectId` は、個人なら利用者名、グループなら Keycloak のグループ ID。`subjectType` は突合に使わず、1 つの集合として交差で判定する。
- 文書側の集合値属性（`shared_with` / `tags`）の突合は契約側の 1 つの述語で行い、検索・BFF・グラフ・Wiki の 4 面が同じ答えを出す。単一値属性の判定は変えない。
- 共有先は DocumentService が応答（`sharedWith`）とイベントに写しを載せる。消費側は共有台帳へ到達しない。

### 名簿の読み口

- 利用者・グループの検索と表示名の解決は、認証済みの**人の主体**だけが到達できる（ロールは問わない）。サービスアカウントは 403。判定は主体の種別（利用者名の接頭辞・クライアント資格情報の有無）で行い、ロールでは行わない。
- 面は利用者が「利用者名・表示名・有効状態」、グループが「識別子・表示名・パス」の各 3 項目に閉じる。総件数は返さない。1 回の上限は検索 50 件・解決 100 件。

### 運用（グループ木）

- グループの作成・改名・所属の付け替えは管理者が Keycloak の管理コンソールで行う。本システムの画面にグループ管理の面は無い。部門・プロジェクト単位で共有したい要求は、その単位のグループを作ることで満たす。
- グループを削除しても共有台帳の行は残るが、誰にも効かない。画面は「見つからないグループ」として取り消しだけを許す。
