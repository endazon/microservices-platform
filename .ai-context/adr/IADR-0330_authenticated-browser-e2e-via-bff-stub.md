# IADR-0330: 認証済み画面のブラウザ E2E は BFF 応答のネットワーク層スタブで踏む

- 状態: Accepted
- 日付: 2026-08-31
- 決定者: implementation-agent（#1099）

## 文脈

#1099 は「SPA ルートを持つ 17 画面のうち 4 画面（SC-12 / SC-17 / SC-19 / SC-20）にブラウザ E2E が
無く、**UC-11 が E2E で 1 度も踏まれていない**」を突いた。#452 §退行防止 は UC-11 を名指ししている。

**ところが issue の受け入れ基準は 2 つが互いに矛盾していた。**

- 基準②「既存 15 本と**同じ形**である（未認証リダイレクト。認証後の画面を踏もうとしていない）」
- 基準④「**ルート定義を意図的に壊すと、その spec が落ちる**ことを変異試験で確かめる」

②を満たすと④は原理的に満たせない。未知パスの受け皿（`catchAllRoute`）は `RequireAuth` 配下に
居るため、**ルートを消しても未認証なら同じく `/login` へ行く**（#918 が改名の変異を当てて
「落ちたテスト 0 件」を実測し、`check-route-manifest.js` 判定 2 がその主張の再混入を禁じている）。

そして既存 spec と `docs/tests/` は、②の根拠として**「セッションは BFF（Keycloak）との往復で成立し、
プレビューにはどちらも無いため認証済みの画面を実走できない」**と書いていた。

## 実測（決定の根拠。推定ではない）

- SPA から出る HTTP は `foundation/api/apiClient` の 1 箇所に収束し（IADR-0121 決定 3）、宛先は
  **同一オリジンの相対パス `/bff/*`** である（`bffBaseUrl`。絶対 URL は `assertSameOriginBffBaseUrl`
  が起動時に禁じる）。
- 認証状態の一次情報は **`GET /bff/auth/me` の応答だけ**である（`AuthProvider`）。資格情報は
  HttpOnly Cookie でブラウザ側からは読めないが、**画面はそれを読んでいない。**
- したがって Playwright の `page.route('**/bff/**')` で応答を与えるだけで**認証済み画面が描画される**。
  Keycloak も BFF も後段サービスも 1 つも起動しない。4 画面すべてで、共通シェル・左ナビ・パンくず・
  **ルート単位の遅延チャンク**（`assets/PrivateNotesPage-*.js` 等）まで実際に読み込まれた。

**「実走できない」は誤りだった。** 反証は 1 本のスパイクで得られ、以後 4 本の spec が恒常的に踏んでいる。

## 決定

1. **画面ごとのブラウザ E2E は「未認証リダイレクト 1 本」＋「セッションを与えた本体」で構成する。**
   セッションは `src/platform/frontend/e2e/support/bffSession.ts` の `installBffSession` が与える。
2. **陽性対照と陰性対照を対で置く。** 「起きるべきことが起きる」だけの spec は、何も描かない実装と
   区別できない。ロール限定画面（SC-12 / SC-17）は「管理者では出る」と「管理者でなければ同じ
   『見つかりませんでした』が出て、管理端点を呼びにも行かない」を対にする。
3. **スタブは生成型（`bff.schemas.ts`）で組む。** 状態コードも契約の値であり、既定の 200 で
   済ませない（`reply(201, …)`。端末登録は 201 でなければ画面が平文トークンを描かない）。
4. **応答を用意していない `/bff/*` は 500 を返して `unhandled` へ積み、`expectBffTrafficIsComplete`
   が落とす。** あわせて「1 件も観測していない」も落とす —— どちらも「何も見ずに緑」の経路である
   （IADR-0130 の 0 件走査 fail と同じ規律）。
5. 🔴 **この層で「後段まで固定した」とは書かない。** スタブは**契約の写しであって後段ではない。**
   実応答との一致は **#466**（実 BFF ＋ Keycloak ＋ Istio）と後段のテストが持つ。
6. **画面 ↔ e2e spec の対応を機械検査する**（`check-route-manifest.js` 判定 3）。除外は理由つきで
   しか宣言できない（`SCREENS_WITHOUT_E2E_SMOKE`。現時点で 0 件）。
7. 🔴 **`e2e/` を型検査の対象に入れる**（`platform/frontend/tsconfig.node.json` の `include`）。
   従前 e2e は `tsc -b` の射程外で、**生成型を import しても何も検査されていなかった** ——
   決定 3 が飾りになる。入れた直後に**実在しない値**（`egressTier: 'internal'`。契約の値域は
   `self-hosted` / `protected-external` / `standard-external`）を検出しており、投資は 1 回で回収された。

## 棄却した案

| 案 | 棄却理由 |
| --- | --- |
| **issue の基準②どおり「未認証リダイレクトだけ」の spec を 4 本足す** | 基準④を原理的に満たせない（#918 の実測）。**UC-11 も 1 度も踏まれないままになる** —— issue が正そうとした事象そのものが残る |
| 実 BFF ＋ Keycloak を起動して踏む | **#466 の射程**。基盤の配備が要り、#1099 の宣言ファイル領域を大きく超える |
| セッション Cookie を `page.context().addCookies` で偽装する | **成立しない。** Cookie の中身を検証するのは BFF であり、プレビューに BFF は無い。加えて SPA は Cookie を読まない（読ませない設計である）ため、偽装しても `/bff/auth/me` が答えを返さなければ未認証のままになる |
| 単体テスト（jsdom）で足りるとして E2E を置かない | jsdom は Vite の解決に依存し、**成果物側の配線**（遅延チャンクの相対 URL・`modulepreload`・base の解決）を見ない。分割の壊れ方は「テストは緑・実機は白画面」であり、それが起きるのはこの層である |
| `msw` をブラウザへ載せる | 成果物へ検査用のコードを混ぜることになる（`check-static-egress.js` が守る「配る物に余計なものを入れない」と逆行）。`page.route` は**成果物を 1 バイトも変えない** |

## 影響

- **UC-11 の基本フロー 1・2・4 と例外フロー（容量 100% の非対称・論理削除の告知）が E2E で踏まれる。**
- 変異試験（ルートの path を改名）で **SC-19 は 3 件・SC-20 は 2 件・SC-12 と SC-17 は各 1 件**が
  落ちることを実測した。**未認証の 1 本は落ちない**（それが基準②の限界そのものである）。
- Playwright は 15 本 19 テスト → **19 本 28 テスト**。実行時間は 5.5 秒 → 5.6 秒（4 並列）。
- 「認証済みの画面を実走できない」と書いた**残り 6 箇所**（`docs/tests/` 2 件・`docs/how-to/` 2 件・
  knowledge ユニットの導線テスト 2 件）は **#1139** で是正する。`.ai-context/` の 14 件は凍結記録で
  あり書き換えない（IADR-0166 決定 2）。

## 限界（次に触る人へ）

- **スタブと `docs/api/openapi.yaml` の食い違いは、この層では検出できない。** 防いでいるのは生成型で
  組むことだけである。契約が変われば型検査が落ちるが、**実装の応答が契約から外れても落ちない。**
- **`/bff/notifications` は既定で空配列を返す**（共通シェルが全画面で読むため）。通知そのものを
  見たい spec は `handlers` で上書きすること。
- 判定 3 は**「spec がある」ことしか見ない。** 中身が意味のあることを見ているかは各 spec の
  変異試験が受け持つ。**行の有無の検査に検出力を期待しない。**
