# IADR-0254 trace 追随の記録単位ルール

## 状況

`docs/` の文書を**ある記録（IADR / 作業仕様書）の決定に沿って書き換えたのに、
trace ブロックへその ID を足していない**追随漏れがある。

`#885` は機械検査を設計し、**精度 1/38 ≒ 2.6% で棄却した**（[IADR-0235](./IADR-0235_trace-block-completeness-checker-rejected.md)）。
`#906` で数え直したところ**数字が桁で違い**、`#975` で精度と再現率の両方を測って裁定した。

## 🔴 母集合は後ろへ広げられない

trace ブロックは **`#872`（2026-08-21 02:26 UTC）で導入された**。それ以前に規約は存在しない。
実測で確認した（`git log -S '<!-- trace:' -- docs/` の最古が `#872`）。

**広げられるのは前だけである。** `#885` も本決定も、**若く小さい母集合の上で判断している。**

## 実測

- **pair-rule**（`#885` 候補 A）: 変更された**各文書**について、新規記録がその trace ブロックに在るか
- **record-rule**: **各記録**について、変更されたいずれかの文書の trace ブロックに在るか

| | pair-rule | record-rule |
| --- | ---: | ---: |
| flag 総数 | **167** | **21** |
| うち `#872`（規約導入・116 docs）由来 | 115 | 0 |
| 本物 | 17 | 16 |
| **精度** | **10.2%** | **76.2%** |
| **再現率** | **100%** | **94.1%** |

### 再現率の損失は 17 件中 1 件

pair-rule が挙げ record-rule が黙る対は 117 件だが、**115 件は `#872` 1 本**である。
残る 2 件を個別に判定し、**`#893` の 1 件が本物、`#881` の 1 件は偽陽性**だった。

### 🔴 偽陽性は 1 本の束ね PR に集中している

record-rule の偽陽性 5 件は**すべて `#878`**（`IADR-0230_meta-work-bundled-prs` を足した束ね PR）である。

| 母集合 | flag | 本物 | 精度 |
| --- | ---: | ---: | ---: |
| **`#878` を除く 12 PR** | **13** | **13** | **100%** |
| `#878`（束ね PR）のみ | 8 | 3 | 37.5% |

**通常の PR（`IADR-0116` の「1 issue = 1 PR」）では精度 100%、
偽陽性は束ね PR という宣言された例外にだけ現れる。**

### 発生頻度

**25 コミット（2 日）に対し本物の追随漏れは 17 件。**
`#885` / `IADR-0235` は「同型の事故が 2 回」を前提に設計されたが、**実際の発生率は桁違いに高い。**
`#906` の実測では **AI レビューの当該クラスの検出率は約 6%**（16 件中 1 件）だった。

## 決定

### 決定 1: 🔴 `#885` の裁定は覆さない。**測られた形が違った**

`#885` が退けたのは **pair-rule** であり、本決定の実測でも **10.2%** である。
**その形については `#885` の判断が正しい。** 数値が `1/38` と違うのは母集合と窓が違うためで、**桁は一致している。**

**新しいのは「record-rule は測られていなかった」という事実**である。

### 決定 2: 足す。**ただしゲートではなく warn**

🔴 **ゲートにしない決定的な理由は、偽陽性のときに人が取る行動である。**
「記録 X がどの文書の trace ブロックにも無い」と赤くしたとき、
**無関係な記録に対して人ができるのは「無関係な ID を trace ブロックへ足す」ことだけ**である。
それは**この検査器が守ろうとしているメタデータそのものを汚す。**
**自分の目的を壊す失敗様式**なので、**除外の手段を設計するまで赤にしない。**

`#885` が挙げた「**赤の常態化**」の懸念も、warn なら当たらない。

### 決定 3: warn が無視される危険を設計で減らす

🔴 **warn は無視される。今日それを実測した** ——
`k8s-local-up.sh` の `ABACSEED` は best-effort（WARN で通す）で、
**投入器が壊れていたことが見えなかった**（`#984`）。したがって warn は次を満たす。

1. **記録名と文書名を名指しする**
2. **件数を出す**
3. **範囲を決められなければ EXIT=1**（0 件走査で静かに緑にしない。`#664` の門）
4. **束ね PR で件数が増えることを warn 本文で予告する**
5. 🔴 **赤くならないので、このステップが CI から消されても誰も気づかない。**
   `scripts/README.md` の検査器表と CI ジョブ表の**両方**に載せ、対で残す

### 決定 4: 判定は同一範囲の同居だけを見る。遡及しない

### 決定 5: ゲート化は 1 サイクル測ってから別途判断する

**warn を足した後の実測（無視されたか・偽陽性の分布が変わったか）を経てから決める。**
🔴 **本決定は「ゲートにすべきでない」ではなく「まだゲートにしない」と述べている。**

## 検出しないこと

- **記録と文書が意味的に関係あるか**は判定しない。機械にはできない
- **1 つでも載っていれば黙る。** 「A には載せたが B にも要る」形は**見逃す**（実測 17 件中 1 件）。
  **設計上の取引であり、欠陥ではない**
- **束ね PR では偽陽性が出る**（実測 37.5%）。**warn である理由がこれである**
- **`#872` のような規約導入コミット**では 0 件になる（pair-rule なら 115 件）。**黙るのが仕様どおり**

## 🔴 実装中に自分で踏んだ 2 件（どちらも試験が無かったので気づかなかった）

1. **範囲の終端を取り違えていた。** `/^(.*?)\.\.\.?(.*)$/` と書いたつもりが、
   エスケープが落ちて `/^(.*?)...?(.*)$/`（**任意の 3 文字**）になり、
   **SHA の先頭 3 文字を区切りと誤認**していた。正規表現をやめ、最後の `..` で切る形にした
2. **適用条件が報告側にしか無かった。** `docs` を 1 つも変更していない範囲に対して
   「どの文書にも無い」が真になり、**全記録を挙げていた**。`main()` の早期 return で隠れていたが、
   `inspectRange` を直接使うと嘘をつく状態だった。**判定の一部なので計算側へ移した**

**どちらも「検査器が自分の実測を再現するか」を確かめて初めて出た。**
自己試験に回帰として固定した。
