# IADR-0250 記録と文書の追随を AI レビューの観点へ置く

## 状況

`docs/` 配下の文書を**ある記録（IADR / 作業仕様書）の決定に沿って書き換えたのに、
trace ブロックへその ID を足していない**追随漏れがある。

`#885` はこれを機械検査で塞ぐ設計を検討し、**実測のうえ棄却した**（[IADR-0235](./IADR-0235_trace-block-completeness-checker-rejected.md)）。
候補 A の精度は **1/38 ≒ 2.6%**、偽陽性の主因は**束ね PR の直積**という構造だった。

`IADR-0235` 決定 2 は、代わりに **AI レビューの責務として宣言する**ことを定めた。
その根拠は「**同型の追随漏れ 2 件はどちらも AI レビューが捕捉し、CI は 2 件とも素通りした**」である。

## 🔴 その根拠は、母集合を引くと成り立たない

`origin/develop` へ **2026-08-20 以降にマージされた PR 全 63 件**を母集合として測った
（日付で引いており、恣意的な抽出はしていない）。

### AI レビューの精度は高い

| 項目 | 実測 |
| --- | ---: |
| AI レビュー本文があった PR | 61 / 63 |
| 指摘の総数 | **103**（🔴 10 / 🟡 43 / 🟢 50） |
| PR あたり | 1.69 件 |

**`🔴` 10 件を 1 件ずつ追跡し、9 件が確認済みの真、1 件が追跡不能**（断定していない指摘・後続レビュー無し）。
**偽陽性は 1 件も見つからなかった。**

### 🔴 だが検出率は低い

| 項目 | 実測 |
| --- | ---: |
| 新観点が発火する露出（新規記録 ＋ `docs` 変更） | **24 / 63（38%）** |
| マージ後も残っている本物の追随漏れ | **16** |
| **うち AI レビューが指摘したもの** | **1** |
| **検出率** | **約 6%** |

さらに `#923` では、**AI レビューが積極的に誤った** ——
「周辺文書の追随は網羅されており**抜けは見当たらなかった**」と書いた同じ PR で、
`20260822_issue-882_xunit1051-staged-adoption-harness` が `specs:` へ足されていない。
**沈黙ではなく、安全宣言の形で漏れた。**

🔴 **`IADR-0235` 決定 2 が引く「2 件とも捕まえた」は、
「捕まえたから記録に残っている 2 件」を数えたものである（生存者バイアス）。**
母集合を引くと、**同じ 3 日間だけで 16 件が捕まらずにマージされている。**

## 決定

### 決定 1: 観点を足す。ただし「格上げ」ではなく「機能させにいく」ものである

レビュー観点へ 1 項足す。
**`IADR-0235` 決定 2 の「暗黙の挙動を宣言された責務へ格上げする」という言い方は、実測に合わない。**
格上げの前提は「挙動が既に在る」ことだが、**検出率 6% は防護と呼べる水準ではない。**

**足す判断は費用側からも支持される。**

| 項目 | 実測 |
| --- | ---: |
| `prompt:` ブロック（毎 PR 送信される実体） | 20,208 バイト |
| 追加 | **665 バイト（+3.29%）** |

`#885` が検査器を退けた理由（**偽陽性が CI を赤くし、赤の常態化を招く**）は**ここには当たらない**。
🔴 **レビューは判断であって門ではない。** 指摘が外れても CI は赤くならず、人が読んで捨てられる。

### 🔴 決定 2: 効果は主張しない。再測定の手順を残す

**観点を足せば検出率が上がる、という根拠は無い。** 測ったのは「今が約 6% であること」までである。

したがって**本決定は効果を主張しない**。次に判断する者のため、**母集合の引き方を残す**。

1. `gh pr list --state merged --base develop` を `mergedAt >= <日付>` で絞る（**日付で引く**）
2. 各 PR の `issues/<n>/comments` から `github-actions[bot]` の本文を全取得する
3. **初回レビュー本文**の `🔴` / `🟡` / `🟢` 節の**先頭列の箇条書き**だけを数える
   （継続行・`[Fix this →]` 行・「（指摘なし）」で始まる行を除く）
4. 露出は `git show --name-status <squash>` で
   「`.ai-context/{specs,adr}/*.md` の新規追加」と「`docs/**/*.md` の変更」の同居として数える
5. **追随漏れはマージ後の状態で数える**

🔴 **3 の「初回レビューのみ」は意図的である。** 再レビューは同じ指摘の追跡であり、
数えると 1 件が最大 9 回計上される（`#878` は再レビュー 9 回）。
🔴 **5 も意図的である。** PR 中に直ったものを漏れに数えると、**防護の効果を過小評価する。**

### 🔴 決定 3: `#885` の裁定はここで覆さない

実測は、**`#885` が退けたのは「記録 × 文書の直積」という形**であることを示す。
同じ窓で直積は **191 対**（うち `#872` 1 本で **116 対**）だが、
**記録単位**（その記録が変更されたどの文書の trace ブロックにも無い）に絞ると
**21 件中 16 件が本物 ＝ 約 76%** である。

**それでもここでは検査器に触れない。**

1. **射程が違う。** `#906` は観点表への 1 項追加である
2. **記録単位の規則は再現率を落とす。** 「どれか 1 つの文書に載っていれば良し」とするので、
   **5 文書中 3 文書へ足すべきところを 1 文書だけ足すと素通りする**
3. **`#885` の裁定を、その issue の外で静かに覆さない**

**別 issue として起票した —— `#975`**（実測値と母集合の引き方を渡してある）。

### 決定 4: 文面に経緯を書かない

`prompt:` は毎 PR 送信されて課金される。**実測値・経緯・issue 番号を書かない。**
**機械的な直積で全対を要求しないことだけは明記する** —— それが `#885` の失敗形だからである。

## 検出しないこと

- **記録と文書が意味的に無関係な場合**の判断は、読み手（AI）に委ねる。機械的な規則を置かない
- **既存文書への遡及**は求めない。同一 PR 内の同居だけを見る
- 🔴 **本観点は「漏れがある」ことを保証しない。** 検出率は本決定の時点で約 6% であり、
  **足したあとの値は測っていない**

## 影響

- `.github/workflows/claude-code-review.yml` の `prompt:` に 1 項
- **起動条件・ジョブ名・必須チェック名は変えない**（`IADR-0230` の M-A から外れるため単独 PR）
- **必読予算（`CLAUDE.md` ＋ `.claude/rules/*.md`）には影響しない** —— 母集合が違う
