# IADR-0337: 画面スモークは全画面でセッション付きにし、変異試験の的をパスからロール条件へ移す

- 状態: Accepted
- 日付: 2026-09-02
- 決定者: implementation-agent（#1139）

## 文脈

IADR-0330（#1099）は 4 画面（SC-12 / SC-17 / SC-19 / SC-20）で「未認証リダイレクト 1 本 ＋
セッションを与えた本体」を確立し、決定 1 として**画面ごとにこの形を採る**ことを定めた。
しかし同 PR の宣言ファイル領域の都合で、**残る 13 画面は未認証リダイレクト 1 本のままだった。**

#1139 はこの 13 画面へ広げるかを判断する issue である。あわせて「認証済みの画面は実走できない」と
書いた live な記述の是正を持つ。

**広げない理由になり得るのは「原理的に踏めない」だけであり、それは実測で否定されている**
（IADR-0330 §実測）。**4 画面だけが決定に従い 13 画面が従わないのは、設計ではなく不徹底である。**

## 実測（決定の根拠。推定ではない）

### 1. 広げられる

13 画面すべてで `installBffSession` によりセッションが成立し、見出し・左ナビ・固定文言が
**実ブラウザ・実ビルド成果物の上で**描かれた。Playwright は **28 件 → 47 件**、実行時間は
5.8 秒 → 9.4 秒（4 並列）。**spec ファイルは 19 本のまま**（既存ファイルへ test を足した）。

### 2. 🔴 変異試験の的が誤っていた

**「画面のルートのパスを改名する」は、ブラウザ E2E の検出力を測れない変異である。**

- パスは**型付きルータの union に入る**（IADR-0124 決定 4）。改名すると `tsc -b` が落ち、
  `vite build` まで到達しない。**E2E を走らせる前に止まる。**
- #918 がこの変異で「落ちたテスト 0 件」を実測し、`docs/tests/SC-21` と
  `check-route-manifest.js` 判定 2 がその主張を土台にしていたが、**測っていたのは
  「古い成果物に対する E2E」だった**（成果物は変異前のままである）。
- ルート合成の**順序**を変える変異も効かない —— ルータは宣言順ではなく**特異度**で解決する。

**効いた変異は「ロール条件を緩める」**（管理者限定の画面へ運用者を通す 1 語の変更）である。
型検査は通り、**新設した陰性対照が 1 件落ち、未認証の 1 本は落ちなかった。**

### 3. 🔴 「変異が効かなかった」は、成果物に届いたことを確かめてからしか言えない

上の②を突き止める直前、私は「47 件すべて緑＝変異が検出されなかった」と読みかけた。
実際には**ビルドが失敗しており、E2E は変異前の `dist` に対して走っていた**。
`grep -rl "<変異文字列>" dist/` という**陽性対照**を置いて初めて分かった。

## 決定

1. **SPA ルートを持つ全 17 画面で「未認証リダイレクト 1 本 ＋ セッションを与えた本体」を採る。**
   既存の未認証 spec は**残す**（認証ガードそのものの固定であり、本体とは別の観点である）。
2. **ロール限定画面の陽性対照は、許可ロールのうち最も緩い側で当てる。**
   管理者と運用者の両方に開く画面を管理者だけで測ると、**許可の列挙から運用者が落ちても
   気づけない。** 運用者で測れば、その脱落は陽性対照が落として教える。
3. 🔴 **ロール限定画面の陰性対照は「隣のロール」で当てる。**
   管理者限定の画面（SC-09 / SC-12 / SC-17）は**運用者**を当てる —— 「ロール無し」で当てると、
   **許可の列挙に運用者が紛れ込む変異を検出できない**（②で実測した唯一の効く変異がそれである）。
   運用者にも開く画面は隣のロールが存在しないため「ロール無し」で当てる。
4. **陰性対照は「描かれないこと」だけでなく「呼びに行かないこと」も見る。**
   `handlers` を空にしたうえで `expectBffTrafficIsComplete` を通すと、
   **権限が無いのに管理端点を取りに行った**場合に `unhandled` として落ちる。
5. 🔴 **画面スモークの変異試験は、パスの改名ではなく「型検査を通る振る舞いの変更」を的にする。**
   具体的にはロール条件・ガードの有無・存在秘匿の分岐である。**パスの取り違えは
   `tsc -b` が受け持つ**と明記し、E2E に二重で期待しない。
6. **変異が成果物へ届いたことを、テストの結果とは別の手段で確かめてから合否を読む**
   （ビルド成功の確認と成果物の文字列走査）。**「落ちなかった」は、届いていなければ無意味である。**
7. 🔴 **この層で「後段まで固定した」とは書かない**（IADR-0330 決定 5 を継承）。
   スタブは契約の写しであって後段ではない。実応答との一致は #466 が持つ。

## 棄却した案

| 案 | 棄却理由 |
| --- | --- |
| 13 画面は未認証のままにする | **「できないから」は理由にならない**（実測で否定済み）。ルートの実在が E2E で守られない状態が 13 画面ぶん残り、IADR-0330 決定 1 が 4 画面だけの例外規定に堕する |
| 一部（描画ライブラリを使う SC-18 等）だけ除外する | 除外の理由が「重い」しかない。実測は 9.4 秒（全 47 件・4 並列）であり、**SC-18 こそ遅延チャンクの実配線を見る価値が最も高い**（jsdom では読み込まれない） |
| 陰性対照を「ロール無し」で統一する | 実装は単純になるが、**唯一効く変異（許可ロールの緩め）を検出できなくなる**。検出力を捨てて統一を買うことになる |
| パスの改名を変異として使い続ける | ビルドが通らないため**測定になっていない**。「0 件落ちた」を検出力の記録として残すと、後任が誤った限界を引き継ぐ |
| 画面ごとに新しい spec ファイルを起こす | ファイルが 19 → 32 本に増え、**未認証 spec と本体が別ファイルへ散る**。同じ画面の 2 つの観点は 1 ファイルで対にして読ませたい |

## 影響

- ブラウザ E2E は **28 件 → 47 件**、セッションを与えた画面は **4 → 17**。
- `check-route-manifest.js` 判定 3 の除外は引き続き **0 件**。
- `docs/tests/` の SC-01 / SC-03 / SC-04 / SC-09 / SC-10 / SC-11 / SC-18 / SC-21 に
  陽性・陰性の行を足した。とくに **SC-21 の「E2E で固定する」未充足は解消した**
  （#918 の起票時の要求を満たした）。
- **SC-09 / SC-10 / SC-11 の「ルートの実在は測っていない」は誤りになったため是正した**
  —— 是正のたびに「この変更で新たに誤りになる自分の記述」を引き直す規則の適用例である。

## 限界（次に触る人へ）

- **スタブと `docs/api/openapi.yaml` の食い違いは、この層では検出できない**（IADR-0330 の限界を継承）。
  防いでいるのは生成型で組むことだけである。
- **陰性対照は「今ある禁止事項」しか写せない。** 計画が新しい禁止を足したとき、
  spec は黙って古いままになる。**機械検査は無い**（`check-route-manifest.js` は spec の
  有無しか見ない）。
- 🔴 **本 ADR の決定 5 は「パスの取り違えは型検査が受け持つ」に依存している。**
  型付きルータをやめる・`AnyRoute` を混ぜる等で union が失われると、**この前提ごと崩れる**
  （IADR-0124 §実測が警告している経路である）。そのときは変異試験の的を引き直すこと。
