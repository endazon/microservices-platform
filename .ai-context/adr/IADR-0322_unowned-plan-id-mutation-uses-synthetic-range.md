# IADR-0322: 「無主の計画 ID」の変異試験は実状態の残余に相乗りせず、合成レンジで作る（#1106）

- 状態: Accepted
- 日付: 2026-08-31
- 決定者: claude（実装）

## コンテキストと課題

`scripts/check-test-traceability.js` は「どの open issue も起点 ID として宣言していない計画 ID」を
**無主**として fail させる（#748）。その検出力を担保する変異試験が `scripts/scripts.repo.test.js` に
あり、擬似 `owners.json` を渡して **exit 1 になること**を spawn で実測していた。

この変異試験は、**その時点でテスト仕様書を持たない ID に相乗り**していた。無主の母集合は
`missingSpec`（`docs/tests/` に仕様書が無い計画 ID）に限られるためである。相乗り先は残余が減るたびに
付け替えられてきた —— `SC-20` → `SC-12` → `UC-01`。テスト本文にもその作法が書かれていた。

> **固定に使う ID はテスト仕様書を持たない ID へ追随させる。**
> いま残っているのは UC-01〜UC-07 である

**#1106 で UC-01〜UC-07 の 7 件に仕様書を起こした結果、計画レンジ 54 件の全件が仕様書を持った。**
付け替え先が尽き、`missingSpec` は空になった。すると `unownedPlanIds(missingSpec, ...)` は
**何を仕込んでも常に空**を返す。実測:

```console
$ REQUIRE_REPO_TESTS=1 node scripts/scripts.test.js
AssertionError [ERR_ASSERTION]: 無主があるのに fail しない:
[check-test-traceability] OK: 仕様書のある起点 ID 55 件中 52 件が写像済み（未写像 3 件はすべて allowlist 済み）。
  計画レンジ 54 件中 54 件にテスト仕様書あり
0 !== 1
```

**これは仕様書を書いた側の落ち度ではない。** 変異試験が「リポジトリにたまたま残っている穴」を
装置として使っていたことの帰結である。穴が塞がるほど装置が壊れるのだから、装置の設計が逆立ちしている。

🔴 **もし赤にならず素通りしていたら、無主検査は検出力ゼロのまま恒久的に緑だった。**
今回は assert が落ちたので気付けたが、それは偶然に近い（変異試験が exit code を見ていたおかげである）。

## 決定

1. **変異試験は合成した計画レンジで無主を作る。** `check-test-traceability.js` の `readPlanIds()` の
   既定パスを環境変数 `PLAN_ID_RULES` で差し替えられるようにし、変異試験は一時ファイルへ
   `` `FR-01..22` / `UC-01..12` / `SC-01..21` / `ADR-0001..0068` `` を書いて読ませる。
   `UC-12` は `docs/tests/` にも擬似 `owners.json` にも無いので、**実状態に依存せず**無主になる。
2. **逃げ道は `PLAN_ID_OWNERS` と同じ形にそろえる。** 同ファイルには既に「変異試験のために
   材料ファイルを差し替える」env override の前例がある。新しい仕組みを増やさない。
   **本番実行では未設定であり、挙動は変わらない。**
3. **陽性対照を同じテストへ組み込む。** 合成レンジを外した実状態の実行が **exit 0** に戻ることを
   同じ 1 回のテストで確かめる。これが無いと「常に fail する検査」でも変異試験は緑になる。
4. **相乗り先の付け替えという作法は撤回する。** テスト本文からその指示を削り、理由を残す。

## 検討した代替案

- **`missingSpec` ではなく計画レンジ全件を母集合にする**: 採らない。#748 が明示的に否定した形で、
  突合材料が open issue だけを載せる以上、**完了して issue が閉じた ID が軒並み無主になる**。
  同ファイルの別テストがこの退行を固定している。
- **リポジトリ全体を一時ディレクトリへ複製し、仕様書を 1 件消して実行する**: 採らない。
  検査器は `src/` 全体を走査するため複製が重く、テスト 1 件のために数百 MB を写す。
- **変異試験を消す**: 採らない。消せば無主検査の検出力を誰も測らなくなる。**#748 が塞いだ穴が
  開き直る。**
- **テスト仕様書を 1 件わざと書かないでおく**: 採らない。**装置のために成果物を歪める**のは本末転倒で、
  かつ allowlist の ratchet（`specMissing` を空にする）と正面から衝突する。

## 結果

- 無主検査の変異試験は、**リポジトリに穴が 1 つも無くても検出力を保つ**。
- 検査器に env override が 1 つ増えた（`PLAN_ID_RULES`）。**本番経路では未設定**なので実行時の
  挙動は変わらないが、**「テストのための穴」が production コードに 2 つある**状態にはなった。
  3 つ目を足すときは、この形自体を見直すこと。
- `REQUIRE_REPO_TESTS=1 node scripts/scripts.test.js` は 668 件緑（実測）。

## 検出しないこと

- **本決定は「無主として名指しされる ID が正しいか」を測らない。** 測るのは
  「無主があれば fail する」「無ければ fail しない」の 2 点だけである。突合材料
  （`scripts/plan-id-issue-owners.json`）の生成側の正しさは別の話であり、材料が無い間は
  検査自体が skip される（`notice` が「無主 0 件ではなく見ていない」と述べる）。
