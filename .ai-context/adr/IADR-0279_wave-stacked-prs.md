# IADR-0279: セッション横断の波単位の積み上げ PR — IADR-0116 規約 1 の第 3 の限定例外

## コンテキストと課題

**規約の側に無い運用が、既に 1 度行われている。**

[IADR-0116](IADR-0116_reimplementation-branching-and-pr-policy.md) 規約 1 は「1 issue = 1 branch = 1 PR」を
定め、束ねてよい場合は 2 つの限定例外だけである。

| | 第 1 の例外 | 第 2 の例外 |
| --- | --- | --- |
| 正本 | [IADR-0139](IADR-0139_domain-bundled-contract-prs.md) | [IADR-0230](IADR-0230_meta-work-bundled-prs.md) |
| 対象 | 裁定済みの**同型な契約追加** | 変更ファイルが**検査器領域**に閉じるメタ作業 |
| 判定 | 資源単位（条件 A〜F） | ファイル領域（条件 M-A〜M-E） |
| 上限 | 4 件 | 4 件 |

**PR #1009 はこのどちらにも当たらない。** 同 PR が束ねたのは製品コード・検査器・文書にまたがる
複数 issue であり、判定単位（資源／ファイル領域）も上限（4 件）も満たしていない。
にもかかわらず、**当たらないことを記録した文書が本リポジトリに 1 つも無い**。

これは「規約に反した」よりも悪い状態である。**規約と実運用が食い違ったまま、食い違いが可視化されていない**
——`CLAUDE.md`「**『統制を定めた』と『統制が働いている』が同じ文書内で読み分けられない書き方をしない**」
（計画側の裁定 2026-08-08 / planning#286）の裏返しがここで起きている。

2026-08-27、リポジトリオーナーは **open issue 72 件の一括対応**と、その過程で
**複数 issue を 1 PR に束ねること**を明示的に指示した。この指示のもとで作業を進めるなら、
決めるべきは 1 点である ——**この束ね方を、どの条件で認めるか。**

## 検討した選択肢

| | 案A: 第 3 の限定例外として条件つきで認める（採用） | 案B: 既存 2 例外の上限・判定単位を緩める | 案C: 認めない（1 issue = 1 PR を貫く） | 案D: 記録せず運用だけ続ける |
| --- | --- | --- | --- | --- |
| 既存 2 例外への影響 | **無い**（対象が交わらない。決定 2） | **大**（資源単位・ファイル領域という判定の芯を壊す） | 無い | 無い |
| 歯止め | オーナーの明示許可 ＋ W-B〜W-D | 上限が実質消える | — | **無い** |
| 規約と実運用の一致 | **一致する** | 一致するが芯を失う | **一致しない**（指示と規約が正面衝突） | **一致しない**（食い違いが不可視のまま） |
| 巻き戻しの単位 | 波（コミットは 1 論理変更に保つ） | 不定 | issue | 不定 |

**案B を退けたのは、既存 2 例外の価値が「判定が主観に落ちないこと」にあるからである**
（[IADR-0230](IADR-0230_meta-work-bundled-prs.md) 決定 1 の M-A が「メタ作業かどうか」を判定していないのと
同じ理由）。上限 4 件を 72 件へ広げれば、**同型性という条件は残っていても意味を失う。**

**案C は指示と正面衝突する。** かつ [IADR-0115](IADR-0115_impl-handoff-kit-as-single-source.md) が実測した型
（**逃げ道の無い規約は無視される**）に真っすぐ当たる —— 72 件を 72 PR に分けることは、
1 PR あたりの固定費（作業仕様書・rebase・CI 一巡・クロス監査）から現実的でない。

**案D が最悪である。** PR #1009 の状態がそれであり、**次に同じことをする者は先例を根拠にできず、
差し戻す者は規約を根拠にできる**。どちらに転んでも判断が人に依存する。

## 決定

### 決定 1: 次の **4 条件（W-A〜W-D）をすべて満たすとき**に限り、波単位の積み上げ PR を認める

| 条件 | 内容 | 判定の仕方 |
| --- | --- | --- |
| **W-A. オーナーの明示許可がセッション単位で存在する** | リポジトリオーナーが、当該セッションについて「複数 issue を 1 PR へ束ねてよい」と明示的に指示していること。**過去のセッションの許可は引き継がない** | 統括の作業仕様書へ、許可の日付と文言を書き写す。**書けないなら許可は無い** |
| **W-B. 1 コミット = 1 論理変更を維持し、コミット件名に起点 ID を残す** | 束ねるのは PR であってコミットではない。件名は `種別(起点ID): 要約`（`CLAUDE.md`「Git 運用」） | `node scripts/check-commit-messages.js --range <base>..HEAD` |
| **W-C. PR 本文に issue ↔ 作業の対応表と「閉じない issue の理由」を明記する** | 束の中で**どの issue がどのコミットで消化されたか**、および**触れたが閉じない issue はなぜ閉じないか**を表で示す | PR 本文の表を読む。`Closes #NNN` は issue ごとに 1 行（[IADR-0139](IADR-0139_domain-bundled-contract-prs.md) 決定 3 を援用） |
| **W-D. 波ごとに push し、CI の緑を確認してから次の波へ進む** | 積み上げは無検証のまま伸ばさない。**波の単位が検証の単位である** | 各波の push 後に CI の結論を確認し、赤のまま次の波を積まない |

**W-A は本例外の芯である。** 既存 2 例外が「対象の同型性」で歯止めをかけるのに対し、本例外は
**同型性を要求しない**（波は製品コードも検査器も文書も含む）。したがって歯止めは**許可の存在**に置く。
**許可が無ければ、本例外は 1 件も適用できない。**

> **W-A は「オーナーが束ねてよいと言ったか」だけを判定する。** 「この作業は束ねるに値するか」という
> 主観は判定に入らない。**主観を判定から外すことは既存 2 例外と同じ作法である**
> （[IADR-0230](IADR-0230_meta-work-bundled-prs.md) 決定 1 の但し書き）。

### 決定 2: 件数の上限を置かない。代わりに **波が検証と巻き戻しの単位**である

- **[IADR-0139](IADR-0139_domain-bundled-contract-prs.md) / [IADR-0230](IADR-0230_meta-work-bundled-prs.md)
  の上限 4 件は本例外へ持ち込まない。** 両者の 4 件は**同型な作業が並ぶ**ことを前提にした数であり、
  同型性を要求しない本例外に当てても意味を成さない。**2 つの数を持たないための「4 件へ揃える」
  （IADR-0230 決定 2）も、揃える相手が居ないため働かない。**
- **代わりに W-D が単位を与える。** 波は「独立に着地でき、CI が緑になる塊」であり、
  巻き戻しも検証も波の単位で行う。**上限は件数ではなく、波が緑になることで課される。**
- **本例外は既存 2 例外を置き換えない。** 対象が交わったときは**厳しい側（既存例外の条件）を満たすこと**を
  求める ——同型な契約追加だけを束ねるなら [IADR-0139](IADR-0139_domain-bundled-contract-prs.md) の
  6 条件と上限 4 件が働く。W-A の許可は、**既存例外の条件を免除しない。**

### 決定 3: [IADR-0116](IADR-0116_reimplementation-branching-and-pr-policy.md) 規約 1 は存置する

- **本 IADR は `Superseded` を作らない。** 原則（1 issue = 1 branch = 1 PR）は残り、限定例外が
  もう 1 つ増えるだけである（第 1・第 2 の例外と同じ扱い）。
- **規約 4（PR ではなく issue を分割する）も変わらない。** 波が大きくなりすぎるなら**波を分ける**。
- IADR-0116 側には**日付つき追記だけ**を置き、条件・棄却案・機械検査を置かない理由は本 IADR が持つ
  （[IADR-0230](IADR-0230_meta-work-bundled-prs.md) と同じ分担）。

### 決定 4: 機械検査は置かない（**いまは**）

- W-B は既存の `check-commit-messages.js` が既に見ている。**W-A・W-C・W-D に検査器を新設しない。**
  `CLAUDE.md`「**検査器・規約の追加は『同型の事故が 2 回起きたら』**を条件とする（1 回目は記録に留める）」に従う。
  **記録の無い積み上げは PR #1009 の 1 度目である**（本 IADR がその記録である）。
- **「機械検査が無い」ことをここに開示しておく**（[IADR-0130](IADR-0130_test-spec-coverage-ratchet.md)
  の作法。検査していないことは黙らせない）。**2 度目が起きたら、そのときに検査器を足す。**

## 理由

- **オーナーの明示指示という事実は、記録しなければ 1 セッションで消える。** 本例外の実質は
  「指示を規約の言葉へ翻訳して残すこと」であり、翻訳しないかぎり次のセッションは
  **PR #1009 と同じ無記録状態**を再生産する。
- **束ねる代償（巻き戻しの単位が大きくなる）を、波が受け止める。** 本リポジトリはスカッシュのみで
  `develop` に着地した PR は 1 コミットである（[IADR-0139](IADR-0139_domain-bundled-contract-prs.md) 決定 2）。
  波ごとに push して CI を通す（W-D）ことで、**戻す単位を波に閉じる**。
- **レビュー可能性は W-B と W-C が担う。** 束ねられるのは PR であってコミットではないため、
  レビュアーはコミット境界で 1 論理変更ずつ読める。対応表（W-C）は
  [IADR-0116](IADR-0116_reimplementation-branching-and-pr-policy.md) 規約 4 が挙げた
  懸念（**issue のクローズ条件が PR から読めなくなる**）への直接の応答である。
- **「閉じない issue の理由」を必須にしたのは、一括対応の失敗が『触ったが閉じない』の沈黙で起きるからである。**
  72 件のうち環境依存・別リポ・裁定待ちで手を出せないものがあり、**それを黙って持ち帰ると、
  次の棚卸しで同じ判定を最初からやり直す。**

## 結果

- 良い影響:
  - オーナーの一括対応の指示を、**規約に反しない形で**実行できる。
  - 規約（IADR-0116 規約 1）と実運用の食い違いが解消し、**PR #1009 の型が先例として参照できる**ようになる。
  - 「閉じない issue の理由」が PR に残るため、**次の棚卸しが判定をやり直さずに済む**。
- 悪い影響・トレードオフ:
  - **巻き戻しの単位が波になる。** 波の中の 1 件だけを戻すには、マージ後は手作業になる
    （[IADR-0139](IADR-0139_domain-bundled-contract-prs.md) 決定 2 と同じ代償。件数が多いぶん重い）。
  - **束の中の 1 件が監査で保留になると、波全体のマージが待つ。** その 1 件を波から外してからマージする。
  - **W-A の判定は人の記憶に依存しうる。** 統括の作業仕様書へ許可の日付と文言を書き写すこと
    （書き写せないなら許可は無い、と決めたのはこのためである）。
  - **監査の対象数は減らない**（[IADR-0141](IADR-0141_audit-rounds-and-population-drawing.md)）。
    減るのは PR 単位の固定費だけである。
- フォローアップ:
  - **記録の無い積み上げが 2 度目に起きたら、検査器を足す**（決定 4）。1 度目は本 IADR が記録である。
  - 本例外を適用した波の実績（波数・件数・戻しの発生有無）は統括の作業仕様書に残す。
    **上限を置かない決定（決定 2）を見直す材料はそこから採る。**
