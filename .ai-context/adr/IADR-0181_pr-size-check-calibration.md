# IADR-0181: PR サイズ検査の較正（#703）

- 状態: Accepted
- 日付: 2026-08-11
- 決定者: claude（実装）

## 起点・関連

- **NFR**（運用保守。メタ作業なので無採番。[IADR-0179](./IADR-0179_unnumbered-nfr-for-meta-work.md) 決定 1）
- 実装 issue: **#703**（**#623 の子**・受け入れ基準 1・2）
- 作業仕様書: [20260811_issue-703](../specs/20260811_issue-703_kit-e0bc81c-followup.md)
- 正本: `planning/tools/impl-handoff-kit/repo-template/.github/workflows/pr-size.yml`（[IADR-0115](./IADR-0115_impl-handoff-kit-as-single-source.md)）

## 文脈 —— **「作る」課題だと思っていたものが「追随する」課題だった**

`#623` の受け入れ基準 1（PR サイズ検査）と 2（issue テンプレート）は、新規に設計する作業だと
読んでいた。**`repo-template` を全 107 ファイルで突き合わせた結果、どちらもキット側に既に存在した。**

キット `e0bc81c`（planning#296 / planning#303）は `repo-template` へ **5 ファイル**を加えている。
**そのうち 3 つは #622 で本リポへ着地し、2 つが置き去りにされていた** ——
**置き去りの 2 つが、そのまま `#623` の基準 1・2 である。**

> **★ 「上流の 1 コミットを部分的に取り込む」型の取り残しである。**
> **取り込み元をコミット単位で控えていれば、`git show --stat` 一発で全数を追えた。**
> 本リポは分類 A のバイト一致を「機械判定できる」と書いているが（IADR-0115 決定 1）、
> **実際に判定している検査器は無い。** 今回も人が `find` を回して見つけた。

### **本決定は [IADR-0169](./IADR-0169_cross-repo-ref-scan-beyond-markdown.md) 決定 1 に乗っている**

`pr-size.yml` は `.github/workflows/` に置く。**`CLAUDE.md` は同ディレクトリを「GitHub App 権限では
編集不可」と書いており、それが正なら本決定は成立しない。**
IADR-0169 決定 1 は**その前提を実測で覆している**（同ディレクトリは繰り返し変更・マージされている）。

> **★ 本 PR で、実際に push まで通ることを確かめた。**
> **`.github/workflows/pr-size.yml` を含む push が成功し、`pr-size` ジョブが起動して
> 追加行数 212 を出した。** —— IADR-0169 の主張に対する**新規実行での陽性確認**である。
> [IADR-0180](./IADR-0180_blocked-judgments-expire.md) 決定 2 に従い、**測った時点を残す: 2026-08-11 / #703。**

## ★ 決定 1: **分類 B とし、固有デルタは `EXCLUDES` に限る**

**しきい値・warn 方式・警告文・`permissions`・ステップ構成は 1 文字も変えない。**

[IADR-0115](./IADR-0115_impl-handoff-kit-as-single-source.md) 決定 2 は固有デルタを **4 種**に限る。
`EXCLUDES` の差し替えは**種別 2（技術スタック）・種別 3（本リポにしかない成果物）**に当たり、
**キット自身が「プロジェクトに応じて追加すること」と明示している** —— 逸脱ではなく、想定された調整点である。

## ★★ 決定 2: **しきい値 400 は動かさず、数える対象の側を正す**

**400 は `#623` と正本 §1 の両方が名指しした数値**である。**動かせば、動かした側が説明責任を負う。**
**数値ではなく、数える対象が本リポに合っていなかった。**

### 実測（`develop` 直近 30 PR。ワークフローが実行する式そのもの）

| 数え方 | **400 行超** | 中央値 | 最大 |
| --- | ---: | ---: | ---: |
| キット既定（`EXCLUDES` をそのまま） | **23 / 30 ＝ 76%** | 510 | 1,649 |
| **本決定の `EXCLUDES`** | **7 / 30 ＝ 23%** | 101 | 1,163 |

**76% に当たる警告は読まれない** —— それは統制ではなく雑音である。
キット自身が「しきい値を動かす場合も**まず実測してから**」と書いており、**実測がこれ**である。
窓を広げても壊れない（直近 **60 PR で 19 / 60 ＝ 31%**）。

### 差し替えた 2 種と、その根拠

| # | 変更 | 根拠（実測） |
| ---: | --- | --- |
| 1 | `**/orval/**` → 実パス（`foundation/api/generated/**` ＋ `foundation/i18n/locales/**`） | **`**/orval/**` は直近 60 PR で 0 ファイルしか当たらない。** 実パスへ直すと **18 PR・計 2,080 行**が動く（単一 PR 最大 **534 行**） |
| 2 | `docs/**` `feedback/**` `CHANGELOG.md` を追加 | **必須文書だけで中央値 393 行・p75 443 行**（最大 567）。**4 回に 1 回は文書だけで 400 を超える** |

### **文書行数は「束ね過ぎ」の指標にならない**

検査の目的は**複数 issue の混在を見つけること**である。
本リポでは `CLAUDE.md` が**1 PR ごとに作業仕様書と実装 ADR を必ず 1 組**要求する ——
**PR を細かく割るほど文書は増える。** **混在の兆候どころか、逆向きに動く量である。**

> **★ 隠していない。** 除外した対象は `EXCLUDES` に明示されており、
> **ジョブログには数え方が残る。** **サマリへ「除外前／除外後」を併記する改良はキットへ環流する** ——
> 本リポで先に足すと**分類 B の 5 種目**を作ってしまう（決定 1）。

## 決定 3: **`#623` の「警告コメント」に対し、キットの**ジョブサマリ**を採る**

`#623` 基準 1 は「警告**コメント**を付ける」と書くが、**キットの実装はジョブサマリ**である。**キットに合わせる。**

1. **分類 B の逸脱を 4 種に限る規約**（IADR-0115 決定 2）に、出力先の変更は含まれない
2. **本リポは全 PR に AI レビューのコメントが付く。** さらにボットコメントを足すと**警告が埋もれる**
3. **警告率 23%。** コメントにすると通知は増えるが、情報量はサマリと変わらない

> **★ キットは `pull-requests: write` を宣言しているが、コメントを投稿するステップが無い。**
> **宣言だけ残った未使用権限**である。**本リポでは削らない**（分類 B の 5 種目を作らないため）。
> **キット側の不整合として環流する。**

## ★ 決定 4: **正本の 2 つの規範が両立しないことを、実装側で黙って吸収しない**

| 正本 | 本リポ |
| --- | --- |
| ガイド §1: **1 issue の見込み diff は 400 行以内** | `CLAUDE.md`: **1 PR ごとに作業仕様書＋実装 ADR が必須** |

**必須文書だけで中央値 393 行**（実測）。**枠をほぼ使い切る。**
**どちらかが誤っているのではない。2 つの規範が同時には満たせない。**

**除外設定でこれを吸収することはできる**（決定 2 で実際にそうした）が、
**吸収して黙っていると「400 行以内を守っている」という誤った像が残る。**
**`feedback/` へ記録し、計画リポへ起票する。**

## 決定 5: **分類 A のバイト一致に、機械検査を置かない（今回は）**

`ai-implementation.yml` はキットで上書きし、**バイト一致を回帰テストで固定する**（1 ファイル）。
**`repo-template` 全体のバイト一致検査は置かない。**

- **分類 A / B / C の判定は意味の理解が要る**。ファイル名からは決まらない（IADR-0115 決定 1）
- **`planning` submodule が未 populate の環境では検査自体が走らない** ——
  **静かに緑を返す検査器**になる（本リポが **#664（PR #672）で 5 本**是正した型）
- **同型の事故は今回で 2 回目**（第 8 ラウンドの `.claude/settings.json`・今回）だが、
  **今回の取り残しは「分類 A の差分」ではなく「ファイルの不在」**であり、
  バイト一致検査では**そもそも検出できない**（比較対象が無い）

**代わりに、キットの取り込みはコミット単位で記録する** —— 本 IADR 冒頭の表がその記録である。

## 結果

- 良い影響
  - `#623` の基準 1・2 が満たされ、**起票時にファイル領域の宣言が必須**になる（並列判定の入力が揃う）
  - PR サイズの警告が **23%** で鳴る。**76% で鳴る設定を入れずに済んだ**
  - **正本の 2 規範の非両立**という、実装側だけでは決められない矛盾が計画側へ出る
- 悪い影響・トレードオフ
  - **文書だけが肥大した PR は警告されない。** 意図した割り切りであり、決定 2 に根拠を書いた
  - **`EXCLUDES` はキットと分岐した。** キットが同欄を更新したとき、手で再適用が要る
  - **`repo-template` の取り残しを機械検出する手立ては、依然として無い**（決定 5）
- フォローアップ
  - **環流 2 件**: (a) 正本 §1 の 400 行と必須文書の非両立、(b) 未使用の `pull-requests: write` と
    「除外前／除外後」の併記
  - **`scripts/check-feedback-dispatched.js`**（キット `06fa163` 由来）の未取り込みは別 issue
