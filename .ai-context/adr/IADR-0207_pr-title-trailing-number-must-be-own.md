# IADR-0207: PR タイトル末尾の `(#NNN)` は PR 自身の番号に限る

- 状態: Accepted
- 日付: 2026-08-16
- 決定者: 実装担当（AI）／起票 #799

## 起点・関連

- 関連する計画書 ID: `NFR`（無採番。検査基盤・規約統制のメタ作業であり、計画側の非機能要件表に
  当たる番号が無い。`.claude/rules/traceability.md`「起点 ID の種別」の 2 の場合）
- 関連する実装仕様書: [`docs/specs/20260816_issue-799_pr-title-number-match.md`](../specs/20260816_issue-799_pr-title-number-match.md)
- 関連 IADR: [IADR-0145](./IADR-0145_landed-subject-check-scope.md)（着地件名の検査範囲）／
  [IADR-0192](./IADR-0192_kit-sync-classification-and-check.md) 決定 2（分類 X には追跡 issue が必須）／
  [IADR-0139](./IADR-0139_domain-bundled-contract-prs.md) 決定 1・3

## コンテキストと課題

規約は PR タイトル末尾の `(#123)` を「**スカッシュマージ既定件名として**許容」と書いている。
これは **GitHub がスカッシュ時にその PR 自身の番号を自動付加する**挙動を前提にした規定だが、
`check-commit-messages.js` の単一件名モードは `\(#\d+\)$` の**形にマッチするかしか見ていなかった**。

**実測（2026-08-16・全 PR 443 件を GitHub API から取得）**:

| 量 | 値 |
| --- | --- |
| タイトル末尾に `(#NNN)` を持つ PR | 66 |
| **PR 自身の番号と一致するもの** | **0** |
| **一致しないもの（起点 issue の番号を書いたもの）** | **66** |

**正しく自番号を書いた例は 1 件も無い。** 当然で、GitHub が自動付加する以上、
タイトル側に自番号を書く動機がそもそも無い。

**実害は「誰がマージするか」で変わる。**

- スカッシュ件名を明示的に渡すマージ → 渡す側が差し替えれば正しくなる（**手作業に依存**）
- **GitHub の UI からマージ** → 既定件名に自動付加が重なり **`… (#796) (#798)` と二重**になる

**既に `develop` へ 58 件着地している**（`(#A) (#B)` の形）。force push 禁止のため事後修正できず、
直せるのは `changelog-overrides.json` による生成物の補正だけである。

`CLAUDE.md`「検査器・規約の追加は同型の事故が 2 回起きたら」の条件は満たしている（3 回以上）。

## 検討した選択肢

| 案 | 内容 | 評価 |
| --- | --- | --- |
| **A（採用）** | `pr-title.yml` が `PR_NUMBER` を渡し、`check-commit-messages.js` が末尾番号と突き合わせる | 予防が効く面（PR タイトル）で止まる。コミット件名モードは無改変 |
| B | 末尾の `(#NNN)` を PR タイトルで**一律禁止**する | 実測 66/66 が誤りなので実質同じ結果になるが、**規約（キット配布物）の書き換えを伴う**。規約は「許容」と定めており、本リポだけで狭めると配布先と割れる |
| C | 着地件名（`check-landed-subjects.js`）側で検出する | **検出できない。** 着地件名の**末尾**は自動付加で必ず自番号になる（実測 65/65 が正しい）。壊れているのは「末尾の 1 つ手前」であり、しかも事後検知になる |
| D | 検査を足さず、マージ手順書で注意する | 現状そのもの。3 回続けて混入した |

## 決定

1. **PR タイトル末尾の `(#NNN)` は、PR 自身の番号でなければ `pr-title` を fail させる。**
   `pr-title.yml` が `PR_NUMBER`（`github.event.pull_request.number`）を渡し、
   `check-commit-messages.js` の `validateTitlePrNumber()` が突き合わせる。
2. **PR 番号が読めないときは、従来どおり形状だけを見る。**
   `PR_NUMBER` 未設定・空文字は「番号一致を検査しない」を意味する。
   **コミット件名モード（`base..HEAD` の検査）へは PR 番号を一切渡さない** ——
   スカッシュ後の履歴コミット（`… (#794)`）が 425 件あり、一致を課すと全滅する。
3. **末尾の `(#NNN)` 自体は任意のまま**（無ければ pass）。禁止はしない（案 B を採らない）。
4. **`PR_NUMBER` が設定されているのに数値として読めない場合は `notice` で可視化してスキップする。**
   終了コードは変えない。配線ミスで**黙って検査が消える**状態（偽の緑）を作らない。
5. **失敗メッセージには直し方を書く** —— 「末尾の `(#NNN)` を外すか、PR 自身の番号にすること。
   起点 issue は本文の `Closes #NNN` で示す」。
6. **規約の一文はキットへ環流する。** `.claude/rules/traceability.md` はキット配布物であり
   直接編集しない。かつ必読規約は残余 1,118B しかないため、**本リポ側の記述は別紙
   （`docs/how-to/commit-message-rules-annex.md`）に置き、必読規約は 0 バイト増**とする。
7. **`scripts/check-commit-messages.js` の同期分類を B 種 5 → B〔X〕へ落とす**（IADR-0192 決定 2）。
   キットに無いロジックを持つ状態は環流債務であり、X の件数として測られるべきである。
   追跡は #799。**環流記録は本作業では `feedback/` へ置かない** —— 未送付の環流記録を 0 件で
   固定するラチェット（`check-feedback-dispatched.js`）があり、**記録の作成と伝達は同時でなければ
   ならない**が、伝達（起票／`planning/` へのコピー）は本作業の射程外である。
   **草案は作業仕様書の §付録**に置き、伝達と同じ変更で `feedback/` へ移す。
8. **`Closes #NNN` の担保（`IADR-0139` 決定 3 の 3 段目）は本決定の射程に入れない。**
   入力が違い（PR 本文 / スカッシュ本文であって件名ではない）、
   実測の母集合が桁違い（着地本文 425 件中 388 件・merged PR 本文 431 件中 267 件が `Closes` 無し）で、
   **検査器の追加ではなく規約の新設**に当たる。**裁定が要るため別 issue とする**（起票案は作業仕様書）。

## 理由

- **止められる面はここしか無い。** 着地件名では検出できず（案 C の実測）、着地後は直せない。
- **番号の一致は機械が確実に判定できる**（PR 番号は GitHub が与える一次情報である）。
  一方 `IADR-0145` が扱う「スコープの ID を落とした / 足した」は PR タイトルとの突合や
  実体との突合が要り、機械では捕まえられない。**同じ「件名の事故」でも、機械化できる部分と
  書き手が守る部分の境目がここにある。**
- **コミット件名モードを触らない**ことで、既存履歴 425 件を 1 件も落とさない。

## 結果

- 良い影響: 規約が守られるかがマージ操作者に依存しなくなる。二重付加の恒久履歴が増えない。
- 悪い影響・トレードオフ:
  - `check-commit-messages.js` の分類が **X へ戻る**（環流が着地するまで債務として残る）。
  - **PR タイトルへ自番号を書く運用を選ぶと、改番のたびに追随が要る**。実測どおり
    自番号を書く動機は無いので、実務上は「末尾に番号を書かない」へ寄る。
- フォローアップ:
  - **キットへの環流（未了）**。草案は作業仕様書 §付録。伝達と同じ変更で `feedback/` へ置く。
    着地したら分類を X → 種 5 へ戻す。
  - `Closes` の担保の裁定依頼（別 issue。起票案は作業仕様書 §`Closes` の穴）。
