# IADR-0266: AI 提案の LLM 境界を「候補列挙の段で絞る」型ゲートで表し、生成は要求時・利用者スコープで走らせる

- 状態: Accepted
- 日付: 2026-08-23
- 決定者: claude（#915 / 親 #450 子 8）

## 起点・関連

- 関連する計画書 ID: FR-18 / UC-10 / SC-03 / SC-21 / ADR-0051（決定 1〜4）/ ADR-0034（決定 2・5・6・9）/ ADR-0033（決定 7・10）
- 関連する実装仕様書: `.ai-context/specs/20260823_issue-915_ai-suggestion-generation.md`
- 前例として参照した既存実装: `AuthorizedNode` / `AuthorizedGraphView.Seal`（GraphService。[[IADR-0242]] 決定 2）、`LlmGatewayEmbeddingService`（RetrievalService）、`RagOrchestrator` の機密区分の最大値算出（AiAnalysisService）

## コンテキストと課題

ADR-0051 が #915 の 2 つのブロッカーを解いた。**類似度は全文書横断で算出してよい**（決定 1）が、**提示段階で
件数も存在も漏らさず完全に絞る**（決定 2）ことが条件で、**順序は「全文書横断で類似度 → スコープで絞る → LLM へ渡す」**
であり**絞りを LLM 呼び出しより後ろに置いてはならない**（決定 3）。実行タイミングは実装設計に委ねられ、
**不変条件は「1 実行 = 1 利用者のスコープ」ただ 1 つ**である（決定 4）。

決めるべきは 3 つある。

1. **「絞りが LLM の前にある」ことを、どう表現すれば後から壊れないか。** 散文のコメントでは守られない。
   ADR-0034 決定 5 は「**送信そのものが違反であり、後段のフィルタでは償えない**」と書いており、
   **違反が起きたときには既に取り返しがつかない**種類の規律である
2. **実行主体とタイミングをどちらに決めるか**（要求時／利用者単位の定期バッチ）
3. **類似度と LLM の供給元をどう持つか。** GraphService はベクトルを持たず、LLM を呼んだことも無い
   （実測: 当該サービス配下に `Llm` / `Completion` の語のヒットが 0 件）

## 検討した選択肢

### 論点 A: LLM 境界の表し方

| 案 | 内容 | 評価 |
| --- | --- | --- |
| A-1 | LLM クライアントの引数を `IReadOnlyList<GraphDocument>` にし、呼ぶ前に絞る規約をコメントで書く | **不採用。** 絞り忘れがコンパイルを通る。ADR-0034 決定 5 は「後段のフィルタでは償えない」規律であり、規約の遵守を人に委ねる形は釣り合わない |
| A-2 | LLM へ渡してから応答をスコープで濾す | **不採用（ADR-0051 決定 3 が明示的に禁止）** |
| **A-3** | **送信物を封（`SuggestionPrompt`）にし、構築経路を `AuthorizedNode` ＋ `AccessScopeResponse` を要求する `Seal` 1 本に閉じる。LLM ポートは封しか受け取らない** | **採用。** 本サービスが探索で既に採っている型ゲート（[[IADR-0242]] 決定 2）と同型で、**生の文書を LLM へ渡すコードがコンパイルできない** |

### 論点 B: 実行主体とタイミング

| 案 | 内容 | 評価 |
| --- | --- | --- |
| **B-1** | **利用者リクエスト時**にその利用者のスコープで生成する | **採用。** 要求の `HttpContext` から解決したスコープが**その実行の唯一のスコープ**になり、不変条件を構造で満たす。加えて ADR-0051 決定 4 後段が課す「生成結果の失効条件」を新設せずに済む —— 提示（一覧）が**その時点のスコープで再判定**するため |
| B-2 | 利用者単位の定期バッチ | 不採用。**誰のスコープで走っているかが実行時の変数**になり、取り違えがテストに現れにくい。失効条件も別に要る |

### 論点 C: 類似度と LLM の供給元

| 案 | 内容 | 評価 |
| --- | --- | --- |
| C-1 | GraphService がベクトルを持つ | 不採用。索引が二重になり、ADR-0009 / ADR-0013 の系統から外れる |
| **C-2** | **ポートで切り、実装は交換可能にする** | **採用。** LLM 側は LlmGateway `/complete`（共有契約 `CompletionApiRequest`）を叩く実装を置く。類似度側は**越境してよい口が RetrievalService に無い**ため、既定は空を返すアダプタとし、口ができた時点で差し替える |

## 決定

### 決定 1: 送信物を型で封じる（`SuggestionPrompt`）

`SuggestionPrompt` は private コンストラクタを持ち、構築経路は `Seal(AuthorizedNode origin,
IReadOnlyList<AuthorizedNode> candidates, IReadOnlyList<string> edgeTypeNames, AccessScopeResponse scope)`
**ただ 1 つ**である。`ISuggestionLlmClient.ProposeAsync` は `SuggestionPrompt` しか受け取らない。

**`Seal` は述語を再適用する**（多層防御。`AuthorizedGraphView.Seal` と同じ理由）。入口のゲートを通っていれば
恒等だが、迂回経路が生まれても**出口で必ず濾される**。

構築経路の単一性は `SuggestionPromptGateTests` がリフレクションで固定する。

### 決定 2: スコープ述語は候補列挙の段で適用する。SQL 述語ではないことを隠さない

`IGraphStore.EnumerateAuthorizedCandidatesAsync` は `AccessScopeResponse` を要求し、
**`IReadOnlyList<AuthorizedNode>` しか返さない。** この 1 メソッドの中で次を終わらせる。

1. **SQL で絞れるもの**（候補 ID 集合・自己・却下済みの組み合わせ・既存辺・既存提案）は `IQueryable` の
   `Where` に置き、DB から出さない
2. **ABAC 述語**は同じメソッドの中で、返す前に適用する

🔴 **ABAC 述語を SQL へ押し込めないことは、ごまかさずに記録する。** `graph_documents.attributes` は
値変換（`jsonb` ↔ `Dictionary<string,string>`）で持っており、`AbacNodeFilter` の意味論
（キー欠落は不一致・値集合内 OR・フィルタ間 AND）を EF が翻訳できない。**本番の Npgsql でもテストの
InMemory でも同じ制約である。**

**それでも「候補列挙の段で絞った」と言えるのは、非許可ノードを持つ値が LLM 呼び出しの引数として
存在し得ないからである。** ADR-0051 決定 3 が禁じたのは「絞りを LLM 呼び出しより後ろに置く」ことであって
「SQL で絞る」ことではない。

### 決定 3: 落とした件数を、応答にもログにも出さない

ADR-0051 決定 2 と ADR-0034 決定 1 の具体化（「不許可ノードは辺・ノード・件数・**ログ**のいずれにも
現れない」）に従う。生成 API の応答は**生成できた提案の配列のみ**で、「候補が N 件あった」「N 件落とした」を
持たない。起点文書が見えない場合は **404**（403 ではない）。

### 決定 4: 不足分を追加で引き直さない（側チャネルを 1 本閉じる）

ADR-0051 は応答時間の相関を**禁じていない**が、「範囲の外に置いた」と明記して実装側へ判断を残している。
**目標件数に満たないぶんを追加照会で埋める形を採らない**ことで、フィルタで落ちた件数と後段の処理量が
相関しなくなる。**費用ゼロで閉じられるので閉じる。**

### 決定 5: LLM の応答は許可済み候補集合と突き合わせてから取り込む

LLM が返した対象文書 ID が**その実行の許可済み候補集合に無ければ捨てる。** 幻覚・復唱によって
「渡していない ID」が提案として実体化する経路を塞ぐ。辺の型名が辞書に無ければ `related` へフォールバックする
（ADR-0033 決定 3）。

### 決定 6: 縮退した LLM 応答を根拠に使わない

`CompletionApiResponse.Sent=false`（機密区分による送信拒否）と `StopReason="refusal"` のいずれでも、
**提案を 1 件も作らない。** `LlmGatewayEmbeddingService` が `Embedded` を読んで降りるのと同じ作法である
（[[IADR-0256]] 決定 3 と同じ向き）。

### 決定 7: 機密区分は送信物に含まれる文書の最高区分を渡す

`CompletionApiRequest.Confidentiality` に、封に入っている文書（起点＋候補）の**最高機密区分**を渡す。
語彙と順位は `Knowledge.Contracts` の `ConfidentialityLevels` が単一情報源であり、**ここで再定義しない**
（`RagOrchestrator` と同じ規則から導く）。

## 理由

- **決定 1・2 は同じ 1 つの理由から来ている** —— ADR-0034 決定 5 の「送信そのものが違反であり、後段の
  フィルタでは償えない」は、**違反したことに後から気付いても直せない**種類の規律である。そういう規律は
  規約ではなく型で表す。本サービスは同じ判断を探索で既に下している（[[IADR-0242]] 決定 2）
- **決定 2 の注記を書くのは、実装が「SQL 述語である」と誤読されないためである。** 誤読されると、
  次の担当者が「既にクエリで絞れているはず」と考えて型ゲートを外しかねない
- **決定 4 は ADR-0051 が明示的に実装へ委ねた判断である。** 委ねられたものを「触れなかった」で済ませない

## 結果

- **良い影響**: スコープ外の文書を LLM へ渡すコードが書けない。生成の実行単位が要求と 1 対 1 になり、
  「誰のスコープか」が曖昧になる余地が無い
- **悪い影響 / トレードオフ**:
  - **類似度の実供給元が無いため、既定では提案が 0 件になる。** ADR-0051 決定 1 が認めた「全文書横断」の
    口が RetrievalService に無く、同サービスは別 issue の作業領域である。**ポートは切ってあるので差し替えで済む**
  - **本文を送っていない。** GraphService は表題と ABAC 属性の複製しか持たない（ADR-0033 決定 2）。
    提案の品質は本文を使う場合より劣る。本文を渡す設計へ進むときも、封（決定 1）を通すこと
  - **要求時生成のため、1 要求あたりの待ち時間に LLM 呼び出しが乗る。** バッチなら隠せるが、決定 4 の
    失効条件が別途要る
- **フォローアップ**:
  1. RetrievalService に**越境してよい類似度の口**ができたら `ISimilarityCandidateSource` を差し替える
  2. `docs/tests/FR-18_ai-suggestions.md` へ生成分のテストケースを追記する
  3. ADR-0051 §フォローアップ 4（応答時間の側チャネルの実測）は、決定 4 により相関源を 1 つ減らしたが
     **測っていない。** 実データが入った時点で測る
