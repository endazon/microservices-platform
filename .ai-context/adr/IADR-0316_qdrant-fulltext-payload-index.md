# IADR-0316: Qdrant 全文ペイロードインデックス

- 状態: Accepted
- 日付: 2026-08-31
- 決定者: claude（実装判断。#1116 の実測で確定）

## 起点・関連

- 起点: #1116「Qdrant の全文ペイロードインデックスを誰も作っておらず、ハイブリッド検索のキーワード側が全配備で死んでいる」
- 出所: [[IADR-0313]] §コンテキストが「本作業の射程外の欠陥」として記録したもの
- 先例（縮退の可観測化）: #972 / #992 / [[IADR-0252]]（「200 ＋ 空リスト」を PASS にしない）・
  [[IADR-0255]]（`200 ＋ 空` が 3 つの失敗と区別できない）・[[IADR-0256]]（縮退と故障の切り分け）
- 版の前提: [[IADR-0315]]（Qdrant サーバは 1.9.2 → 1.18.1）
- 関連する実装仕様書: [`20260831_issue-1116_qdrant-fulltext-payload-index.md`](../specs/20260831_issue-1116_qdrant-fulltext-payload-index.md)

## コンテキストと課題

`QdrantVectorStore.KeywordSearchAsync` はペイロード `text` への full-text `Match` で `ScrollAsync` する。
**その `text` に全文ペイロードインデックスを作るコードがリポジトリのどこにも無い**（実測。
`CreatePayloadIndex` / `TextIndexParams` の本文ヒットは記録の記述だけで、呼び出しは 0 件）。

### 🔴 起票の機構説明は、稼働中の版では成立しない（自分で実測して分かった）

#1116 は「`catch (RpcException)` が**常に**成立し、`KeywordSearchAsync` は**常に空配列を返す**」と書く。
稼働 k3s の `qdrant/qdrant:v1.18.1` へ **`KeywordSearchAsync` と同形の gRPC 呼び出し**を出したところ、
**例外は 1 度も出なかった**。

```
collection=knowledge_chunks_deterministic_v1 points=3
payload_schema: (empty)          ← 索引は 1 つも無い

   1  <- msp-searchseed-tanpopo
   1  <- anpop                   ← 🔴 語でない断片が当たる
   0  <- zzzznotexistword
   0  <- 検索 tanpopo             ← 🔴 語順に依存する
   1  <- tanpopo 検索
```

**索引が無いとき、v1.18.1 は `Match { Text }` を部分文字列の全走査へ黙って落とす。**
（起票の記述は v1.9.2 時代の観測である。[[IADR-0315]] で版を上げたときに挙動が変わっていた。）

**結論は変わらない —— FR-03 のキーワード側は成立していない。** ただし壊れ方が違う。
「常に 0 件」ではなく **「全文検索でないものが全文検索の顔をして動いている」** である。

| 索引なしの挙動 | なぜ悪いか |
| --- | --- |
| `anpop` が `msp-searchseed-tanpopo` に当たる | 語でない断片が当たる（偽陽性） |
| `検索 tanpopo` は 0 件・`tanpopo 検索` は 1 件 | 語順に依存する（トークン集合の一致ではない） |
| 全点走査 | NFR-08（数万〜数十万件）で p95 目標（NFR-01 / NFR-04）を保てない |
| 版で静かに変わる | v1.9.2 は例外・v1.18.1 は部分文字列。**FR-03 をこの挙動に預けられない** |

## 検討した選択肢

### トークナイザ（実測で選ぶ。使い捨てコレクションに既知 4 文書を入れ、同じ 27 クエリを 5 通りで引いた）

| クエリの種類 | 索引なし | `word` | `whitespace` | `prefix` | **`multilingual`** |
| --- | --- | --- | --- | --- | --- |
| 英数字識別子（`IngestionService` `ABAC`） | ○ | ○ | ○ | ○ | **○** |
| ハイフン内部の語（`tanpopo` `7800X3D`） | ○ | ○ | **×** | ○ | **○** |
| 日本語の語中（`索引` `チャンク` `埋め込み`） | ○ | **×** | **×** | **×**（語頭のみ） | **△**（当たる語がある） |
| 同じ文の中の別の語（`文書` `検索` `統合` `合言葉`） | ○ | × | × | × | **×**（§既知の限界） |
| 陰性対照（`zzzznotexistword`） | 0 件 | 0 件 | 0 件 | 0 件 | **0 件** |
| 語でない断片（`anpop` `estionServ`） | **🔴 誤爆** | 0 件 | 0 件 | 0 件 | **0 件** |
| 語順を替えた複数語（`検索 tanpopo`） | **🔴 ×** | ○ | ○ | ○ | **○** |
| 索引を使うか | **🔴 全走査** | ○ | ○ | ○（巨大） | **○** |

🔴 **`multilingual` が公式イメージで使えるかは、思い込まずに実機で確かめた** ——
`create-index tokenizer=Multilingual -> Completed` で受理され、サーバは
`"payload_schema":{"text":{"params":{"tokenizer":"multilingual",...}}}` を echo した。
**ビルドオプションの差し替えは要らない。**

### 縮退の可観測化（受け入れ基準 3）

| # | 案 | 評価 |
| --- | --- | --- |
| 1 | 応答（`SearchResponse`）へ縮退の別を載せる | **採らない。** 存在秘匿（[[IADR-0009]]）を崩す。[[IADR-0313]] 決定 1 が同じ案を既に退けている（`docs/api/openapi.yaml`・orval 生成物・フロントまで巻き込む） |
| 2 | `catch (RpcException)` のログを Error へ上げる | **足りない。** 🔴 本件の縮退は**例外を伴わない**。捕まえる先が無い |
| 3 | readiness を **Unhealthy** にする | **強すぎる。** ベクトル側は生きており、pod を Ready から外すのは計画 NFR-06（縮退運転: 検索は継続）に反する |
| 4 | **readiness を Degraded にし、メトリクスを 1 本置く**（採用） | `/health/ready` は 200 のまま（k8s の probe は落ちない）で、本文と Grafana からは見える。**「壊れているのに完全に正常に見える」状態だけを解消する** |

### 索引の後付け

| # | 案 | 評価 |
| --- | --- | --- |
| 1 | 新規作成の経路にだけ足す | **採らない。稼働中の配備は永久に索引を持たない。** 本件はまさにその形の欠陥である |
| 2 | 移行スクリプトを別に用意する | 呼び忘れが起きる。**実行されたかどうかを誰も見ていない**（本件と同型） |
| 3 | **起動時に無条件で 1 回張る**（採用） | 実測で `CreatePayloadIndex` は冪等であり、パラメータが違えば張り替える。**新規・既存・張り替えが 1 本で収束する** |

## 決定

### 決定 1: トークナイザは `multilingual`（`min_token_len=1` / `max_token_len=40` / `lowercase=true`）

上表のとおり、`multilingual` は他の 3 つを**すべての軸で上回る**。
索引なしと比べると日本語の一部で再現率を落とすが、**索引なしの「当たり」は全文検索ではない**
（部分文字列一致であり、偽陽性・語順依存・全走査を伴う）。版依存で静かに変わる挙動に FR-03 を預けない。

宣言値は `QdrantIngestionVectorStore.BuildFullTextIndexParams()` に純関数として置き、
実機なしで固定できるようにする（`BuildChunkPayload` と同じ位置づけ）。

### 決定 2: 索引はコレクション生成と同じ 1 点で、**存在の有無によらず**張る

`QdrantIngestionVectorStore.EnsureCollectionsAsync` から
`if (await CollectionExistsAsync(...)) continue;` を外し、
「無ければ作る」→「**その後、必ず `text` の全文索引を張る**」にする。

🔴 **`continue` を残してはならない。** 残すと既存コレクションにだけ索引が付かず、
本件と同じ欠陥をそのまま残すことになる。

### 決定 3: 縮退は**応答の外側**で観測する（契約は 1 バイトも変えない）

1. **readiness（Degraded）**: `QdrantFullTextIndexHealthCheck`（`qdrant-fulltext-index`）が、
   **検索が実際に見ているコレクション**の `payload_schema` に `text: Text` が在るかを見る。
   コレクション名の解決は `QdrantVectorStore.ResolveCollectionName` に畳んだ ——
   別々に解決すると「見ていないコレクションの索引を健全と報告する」という同型の食い違いが生まれる。
2. **メトリクス**: `search.keyword_degraded.total`（0 が正常。理由タグ `missing_index` / `backend_error`）。
   `EdgeTypeFallbackMetrics`（GraphService）と同型。クエリ文字列はタグにしない（基数が無界）。
3. **ログ**: `RpcException` の握り潰しは残す（検索全体は落とさない）が、**必ず数えてから返す**。

### 決定 4: 退行防止の門は `mode=keyword` ＋ **語順を替えた合言葉**で置く

🔴 **`#1113` の門（`SEARCH_HITS=1`）に「ベクトルでは当たらない語」を足すことはできない。**
ベクトル検索は閾値の無い kNN であり、索引に 3 点しか無い使い捨てスタックでは
**どんな語でも全点が返る**（[[IADR-0313]] §既知の限界）。**モードで系統を切り分けるしかない。**

さらに🔴 **合言葉をそのまま `mode=keyword` で引いても足りない** —— 索引が無くても
部分文字列として当たるからである。**語は同じまま順序だけ替える**と、索引の有無で結果が割れる。

| クエリ | 索引なし | 索引あり |
| --- | --- | --- |
| `msp-searchseed-tanpopo` | 1 | 1 | ← 現行の門。**欠陥を通す** |
| `tanpopo searchseed msp` | **0** | **1** | ← 新しい門 |
| `msp-absent-zzzznotexistword` | 0 | 0 | ← 陰性対照 |

**合言葉を 2 つに増やさない。** `documents.json` の `probeTerm` を区切りで割って順序を替える
（`seedKeywordOnlyQuery`）。1 語しか取れないときは **null を返して門を落とす** ——
合言葉そのものへ黙って落とすと、索引が無くても PASS してしまう。

正の対照だけでは「全部当たる」実装を見逃すので、**陰性対照を同じモードで対に置く**（#972 / [[IADR-0252]]）。

## 理由

- **静かな壊れ方を、静かでなくする**のが本 ADR の主眼である。索引の欠落は例外を伴わず、
  応答も 200 で、結果も返る。**索引の存在そのものを見る以外に検出手段が無い。**
- 契約を変えないのは、存在秘匿（[[IADR-0009]]）と、[[IADR-0313]] 決定 1 の裁定を覆さないためである。
- Degraded に留めるのは NFR-06（検索は継続・AI 回答のみ停止を許容）に沿うためである。

## 結果

- **良い影響**: FR-03 のキーワード側が実際に全文検索として機能する。
  固有名詞・型番・略語（`RX-7800X3D` / `ABAC` / `msp-searchseed-tanpopo`）が索引で引ける。
  既存コレクションへも起動のたびに収束する。
- **悪い影響 / トレードオフ**:
  - 🔴 **日本語の再現率は部分的であり、文書に依存する。隠さずに書く。**
    公式イメージ v1.18.1 の `multilingual` を実機で測った結果は次のとおりで、
    **「日本語で引ける」と言い切れない**。

    | 測った対象 | 結果 |
    | --- | --- |
    | 短い日本語の文（`オブジェクトストレージへ本文を格納し、チャンクに分けて索引へ登録する。`） | `索引` `チャンク` `埋め込み` `オブジェクトストレージ` は**当たる** |
    | 同じ文書群の別の語 | `文書` `検索` `統合` `横断検索` `合言葉` `型番` `略語` は**当たらない** |
    | 漢字＋ひらがなの混在（`この文書は統合スタックで動く。`） | `文書は` は当たるが **`文書` は当たらない**（助詞まで 1 トークンに入る） |
    | 漢字だけの語（`文書管理`） | `文書` / `管理` に分かれて**当たる** |
    | 🔴 **実配備の seed チャンク**（日本語＋識別子＋記号の長文） | **日本語の語で 12 語試して 1 件も当たらなかった**（同じ文書で識別子 `IngestionService` `MarkdownUri` `DocumentUpdatedConsumer` は当たる） |

    **索引なしの部分文字列一致では当たっていた日本語の語が、当たらなくなる場合がある。**
    それでも索引を張るのは、索引なしの挙動が全文検索ではない（偽陽性・語順依存・全走査・版依存）ためであり、
    **キーワード側の主目的（ベクトルが苦手な固有名詞・型番・略語）は索引で確実に引けるようになる**からである。
    日本語の再現率を上げるには形態素解析器を積んだ Qdrant の自前ビルドが要る。**射程外とし、別 issue に回す。**
  - **索引の分だけメモリ・書き込みコストが増える**（`on_disk` は既定のまま）。
  - **`tags` / `attributes.<key>` は依然として未索引である**（[[IADR-0151]] のフォローアップのまま）。
    本 ADR は `text` に限る。フィルタ経路全体の索引方針は別判断である。
  - **検索品質（nDCG）は測っていない。** 測ったのは「全文の系統が索引を使って動くか」までである。
- **フォローアップ**:
  - `multilingual` の日本語分割で取りこぼす語が実運用で問題になるなら、
    形態素解析器つきの Qdrant ビルド、または `Match::Phrase` / `TextAny`（v1.18 の新フィールド）の
    採否を裁定に掛ける。
  - 既存の稼働環境では、**索引を張っても既存の点は再索引される**（Qdrant が張り直す）ので
    `DocumentUpdated` の再発行は要らない（[[IADR-0313]] のコレクション切替とは事情が違う）。

## 検証

- **実機（稼働 k3s / Rancher Desktop `v1.35.4+k3s1`・`platform-infra` / `qdrant/qdrant:v1.18.1`）**:
  `scripts/verify-qdrant-fulltext-index.sh` が **PASS 7 / FAIL 0**。
  陽性対照（語順を替えた合言葉 → 1 件）・陰性対照（索引に無い語 → 0 件）・
  語でない断片（`anpop` → 0 件）・識別子/型番/略語（各 1 件）を対で測った。
  **索引を張る前は、同じ「語順を替えた合言葉」が 0 件だった**（同スクリプト段 1）。
  日本語は段 7 が**数字をそのまま出す**（`索引`=1 / `文書`=0 / `チャンクに分け`=1）——
  「揃って当たること」は期待しないと明記してある。
- **稼働クラスタ（同上）での通し**:
  1. 新しいイメージで取り込みサービスを再起動すると、**既に在る 2 コレクション**の
     `payload_schema` が `{}` → `{"text":{...,"tokenizer":"multilingual",...}}` になった（後付けの実測）。
  2. 検索サービスの `/health/ready` は **200 `Healthy`**。
  3. 🔴 **変異試験**: 索引を消すと `/health/ready` が **200 `Degraded`** になり、
     同じコレクション・同じデータで `mode=keyword` の
     「語順を替えた合言葉」が **1 件 → 0 件**へ落ちた。
     **一方、旧来の門が使う合言葉そのままは 1 件のまま**であり、
     **旧来の門がこの欠陥を通すことを実測で確認した。**
  4. 取り込みサービスを再起動すると索引が戻り、3 の値も戻った。
- **単体**: `QdrantFullTextIndexBootstrapTests`（既存コレクションにも張ること・field type・
  トークナイザの宣言値）／`QdrantFullTextIndexObservabilityTests`（Degraded の切り替え・
  Unhealthy にしないこと・縮退の計数）。実機 Qdrant なしで測るため
  `QdrantGrpcClient(CallInvoker)` に記録用の `CallInvoker` を挿している。
- **統合スタックの門**: `scripts/verify-oidc-edge-flow.sh` の段 S4・S5（`SEARCH_HITS=1`）。
