# IADR-0653: 間引きの次数は許可済みの辺で数える（#2145）

> 実装リポジトリ内の意思決定記録（Implementation ADR）。1 ファイル = 1 意思決定。

- 状態: Accepted
- 日付: 2026-10-30
- 決定者: claude（#2145。親 #2047 の指摘 L-15）

## 起点・関連

- 起点 issue: #2145。
- 関係する計画: ADR-0049 決定 4（間引きの 3 択）、ADR-0035 決定 2（ハブ文書を中継点にしない）、ADR-0034 決定 2（存在秘匿）。
- 作業仕様書: [20261030_2145_sc18-graph-details](../specs/20261030_2145_sc18-graph-details.md)。

## 背景

- `GraphTraversal` は、ハブ判定のために全辺（ABAC で絞らない）の次数を読む（`LoadDegreesAsync`）。
- 同じ値を、表示上限を超えたときの間引き（`by=degree`）の並びにも使っていた。次数そのものは応答に出ないが、**どの文書が残るか**は応答に出る。
- このため、権限外の辺を多く持つ文書が上位に来て残る ＝ 見えない関係の多寡が、並びから読める。

## 決定

1. 間引き（`by=degree`）の並びには、**候補集合の辺（探索の段で両端とも許可済みと判定した辺）だけで数えた次数**を使う（`GraphTraversal.Select` の `VisibleDegrees`）。
2. ハブ判定（`MaxHubDegree`）の次数は、従来どおり全辺で数える。ハブかどうかは構造上の性質で、利用者の権限の関数にしない（ポートの注記の判断を維持する）。

## 却下した案

- **ハブ判定も許可済みの辺で数える**: 同じ文書が利用者によってハブになったりならなかったりする（ポートの注記が却下済み）。ハブ判定の結果は「次のホップへ進むか」に効くだけで、本件の漏れ（並びの差）とは別の問いである。
- **`LoadDegreesAsync` を ABAC で絞る**: ハブ判定まで変わる（上の案と同じ）。加えて、ストア側に利用者のスコープを持ち込むことになる。

## 帰結・残余リスク

- 間引きの「次数が大きい順」は「表示し得る関係が多い順」になる。利用者が見られない関係は並びに効かない。
- 候補集合が算出上限（2,000 / 5,000）で打ち切られた場合、可視の次数も打ち切られた母集合で数える。これは厳密な上位ではない（ADR-0049 の既知の注記と同じ。帯の文言が示す）。
