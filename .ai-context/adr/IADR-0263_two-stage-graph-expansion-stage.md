# IADR-0263: 二段検索の段はデコレータとして足し、既定オフは「DI に登録しない」で表す。近接度は Score に混ぜない

- 状態: Accepted
- 日付: 2026-08-23
- 決定者: claude（実装）／起票 #970（親 #947）

## 起点・関連

- 関連する計画書 ID: FR-04 / FR-14 / FR-17 / UC-10 / ADR-0035（決定 1・2）/ ADR-0034 / ADR-0018
- 関連する実装仕様書: `.ai-context/specs/20260823_issue-970_two-stage-graph-expansion.md`
- 前提: #947a（辺の型の重み・ハブ次数上限）/ #969・IADR-0259（文書 ID 制約つき検索）/ #916a（権限伝播の方式 A）

## コンテキストと課題

ADR-0035 決定 1 は統合方式を「二段検索」と定め、決定 2 は探索パラメータと**既定オフ・opt-in**を定めた。
決めるべきは 6 点である。**段の置き場所**・**既定オフの表し方**・**既存検索との接続**・**再ランクの式**・
**権限伝播**・**辺の重みが取れないこと**。

## 決定

### 決定 1: 段は `IHybridSearchService` のデコレータとして足す

`GraphExpandingSearchService` が `HybridSearchService` を包む。ADR-0035 決定 1「**既存検索の実装は
変更せず、後段を足す**」に最も素直に対応する形である。

### 決定 2: 既定オフは「DI にその型を登録しない」で表す。`pipeline.json` の段としては宣言しない

- 構成 `GraphExpansion:Enabled`（**既定 false**）が false のとき、`IHybridSearchService` は素の
  `HybridSearchService` であり、**段のコードは実行経路に存在しない**。フラグを見て中で分岐する形は
  採らない —— 「着脱可能」（ADR-0018 / FR-14）が実行時条件に化けると、A/B の 2 群が同じ経路を通る。
- 🔴 **`pipeline.json` の段（`AddPlatformWolverineStep`）には載せない。** あの機構は
  **入力イベント型を持つ購読段**専用であり（`IPipelineStep<TIn>` を導出できないこと自体を起動失敗に
  する規則 5 がその前提）、**同期の検索経路には入力イベントが無い**。載せるには存在しないイベント型を
  捏造することになり、`input` 照合が「宣言 対 別の宣言」に退化する。
- **段の在否は自己申告（`/internal/introspection`）のポート `graph-expansion` で外から読める。**
  応答（`SearchResponse`）の形は同じなので、**結果だけを見ても A/B の別が判らない**。

### 決定 3: 既存検索には「中間値を返す内部口」を足す（アルゴリズムは変えない）

`HybridSearchService.SearchDetailedAsync`（internal）が `Fused` / `VectorSide` / `QueryVector` /
`Filters` / `Sort` / `TopK` / `CandidateK` を返し、`SearchAsync` はその薄いラッパになる。

- 段② の起点は**ベクトル側の順位**であり（ADR-0035 決定 2）、融合結果からは系統が読めない。
- 段③ は `queryVector` と**同じ ABAC フィルタ**を要求する（IADR-0259 決定 3）。
- デコレータが自前でやり直すと、**1 回の検索で埋め込みを 2 回呼ぶ**うえ `BuildFilters` の真実源が
  2 つに割れる。**「変更しない」を字面で守って二重実行を招くより、観測可能な振る舞いを不変に保つ方を採る**
  （試験で固定: 段オン時も埋め込みは 1 回）。

### 決定 4: 再ランクは重みつきの合成とし、**近接度を `Score` に混ぜない**

```text
Composite = w_search × RankScore(順位) + w_graph × Proximity(文書)
RankScore(rank) = (K+1)/(K+rank+1)   K = 60（RRF と同じ平滑化定数）
Proximity(d)    = 起点からの経路上の**辺の型の重みの積の最大値**（起点自身・未到達は 0）
```

- **`SearchResultDto` は 1 件も書き換えない。** ① 由来は融合スコア、③ 由来はベクトルストアが返した
  コサイン類似度のまま返す。合成値は並べ替えにしか使わない。混ぜると**出典に載る数字が何の値か
  誰も言えなくなる**（利用者は類似度として読む）。
- **重みの積を近接度とする**ことで、ADR-0035 決定 2 の 2 つの名指しがそのまま式の性質になる ——
  `supersedes`(1.0) は減衰せず「強く誘導」、`related`(0.3) は 2 ホップで 0.09 まで落ちて「弱く扱う」。
  **ホップ減衰の係数を別に持たない**（係数を 2 つ持つと、どちらで効かせるかが実装者の気分になる）。
- ③ 由来のチャンクの順位は `|①| + ③内順位` から始める。**後段で拾ったという事実を順位に残す**。
- ⚠️ **帰結: 1 つの応答の中で `Score` の尺度が 2 種類になる**（① は RRF の融合値、③ はコサイン類似度）。
  揃えるには ① 側を書き換えるしかなく、それは ADR-0035 決定 1 が禁じる「既存検索の変更」に当たる。
  **本 issue の 🔴 は「`Score` は類似度であって近接度ではない」であり、③ 側を類似度のまま返すことが
  その線に最も忠実である**（③ を順位由来の合成数値にすると、今度は類似度ですらなくなる）。
  尺度の統一が要るなら**別 issue**とする（出典表示の見せ方の問題であり、本段の判断ではない）。
- 既定 `w_search=1.0` / `w_graph=0.35`・起点 5 件は **実測値ではない**（実データが無い。#947a と同じ理由）。

### 決定 5: 権限伝播は `Authorization` ヘッダ（方式 A）。ヘッダが無ければ下流を呼ばない

- GraphService は自分で ABAC を解決する型である（#916a の規則「下流が自分で解決する型なら A」）。
  **解決済み scope を本文で渡す方式 B を採らない** —— 下流に権限昇格の口を開ける。
- 🔴 **資格情報が無いなら GraphService を呼ばない。** 呼ぶと全ホップが deny-closed の 404 になり、
  **「グラフには何も無い」と読める静かな故障**になる。呼ばずに警告を出す。
- 権限伝播が RetrievalService の側から効いていることを、**否定形＋陽性対照の対**で測る
  （#952 の教訓。「後段で効いているから効く」は測った証拠にならない）。

### 決定 6: 辺の型の重みは取得できないので暫定 0.5 とし、**要求ごとに警告する**

🔴 **#947a が `edge_types.Weight` を入れたが、GraphService はどの口からも公開していない**
（近傍探索の `GraphEdgeDto` にも型カタログの `EdgeTypeCatalogItemDto` にも重みの項目が無い。
2026-08-23 実測）。公開は GraphService 側の変更であり #970 の作業範囲外である。

- **アダプタは全辺を既定重み 0.5 で扱い、要求ごとに警告を出す**（型ごとの重み付けが効いていない
  ことを運用から読めるようにする）。**黙って無差別にしない。**
- **再ランク側は重みを一級の入力として完全に実装し、ポート経由の試験で固定する。**
  重みが公開されればアダプタの 1 行が変わるだけで効き始める。
- 「テストは緑・本番は無差別」という形を**承知のうえで**置いている（IADR-0014 が記録した型）。
  **承知していることを記録に残すのが本決定の目的である。**

## 検討した選択肢

| # | 論点 | 採らなかった案 | 理由 |
| --- | --- | --- | --- |
| A | 段の置き場所 | `HybridSearchService` の中に展開を書き、フラグで分岐 | 「既存検索の実装は変更しない」（ADR-0035 決定 1）に反し、着脱が実行時条件に化ける |
| B | 既定オフ | 段は常に登録し、`Enabled` を見て内部で早期復帰 | A/B の 2 群が同じ経路を通り、「段が無い構成」を測ったことにならない |
| C | 既存検索との接続 | デコレータが埋め込み・フィルタ組み立て・ベクトル検索をやり直す | 1 検索で埋め込み 2 回。`BuildFilters` の真実源が 2 つ |
| D | 再ランク | 近接度を `Score` へ加算（合成値をスコアとして返す） | 出典のスコアが類似度でなくなる。ADR-0035 の「案A を採らない」判断とも合わない |
| E | 重み | RetrievalService 側に型名 → 重みの表を持つ | 重みの真実源が 2 つに割れる（`edge_types` が正）。改名・編集に追随できない |

## 影響・残件

1. **辺の型の重みの公開（GraphService 側）が要る。** それまで再ランクは全辺 0.5 で動く（決定 6）。**追随 issue が要る。**
2. **呼び出し元（BFF `/bff/search`・AiAnalysisService `RagOrchestrator`）は RetrievalService へ
   `Authorization` を伝播していない**（実測）。したがって**段を有効化しても、呼び出し元を直すまで展開は
   0 件**である。**追随 issue が要る**（本 issue の territory 外）。
3. `scripts/check-bff-downstreams.js` の CALLERS に RetrievalService が入っていない
   （新たに service → service の呼び出し元になった）。
4. 実 GraphService / 実 Qdrant を要する結線検証は Docker 不在のため実行できず、CI に委ねる。
5. `w_graph` / 起点件数は A/B（既定オフの構成が可能にしたもの）で測って決め直す。
