# IADR-0230: メタ作業（検査器領域に閉じる変更）は 1 PR に束ねてよい — IADR-0116 規約 1 の第 2 の限定例外

> 実装リポジトリ内の意思決定記録（Implementation ADR）。1 ファイル = 1 意思決定。
> 計画リポジトリの ADR（`ADR-XXXX`）とは別系統（`IADR-XXXX`）とし、実装に閉じた決定を記録する。
> 計画に影響する決定は計画側へ環流する（`/plan-feedback`）。

- 状態: Accepted
- 日付: 2026-08-21
- 決定者: 利用者裁定（2026-08-21「メタ作業に限り PR の束ねを緩和してよい」）＋ 実装（claude）

## 起点・関連

- 関連する計画書 ID（FR/UC/SC/ADR）: **無採番 `NFR`**（保守性・進行方式）。メタ作業は稼働する製品の
  要件ではないため対応する採番 `NFR` が無いことがある（[IADR-0179](IADR-0179_unnumbered-nfr-for-meta-work.md)
  決定 2。**「番号が無い」は「実装側で作ってよい」ではない**）。
- 関連する実装 ADR:
  - [IADR-0116](IADR-0116_reimplementation-branching-and-pr-policy.md) 規約 1（**改定対象**。
    「子 issue 1 件 = ブランチ 1 本 = PR 1 本」へ**第 2 の限定例外**を足す。**`Superseded` にはしない**
    ——原則は残り、条件を満たす場合だけ例外が働く）
  - [IADR-0139](IADR-0139_domain-bundled-contract-prs.md)（**第 1 の限定例外**。裁定済みの同型な
    契約追加を資源単位で束ねる。**本 IADR とは対象が交わらない**——あちらは製品の契約、こちらは
    検査器領域。上限件数は本 IADR も 4 件に揃える。理由は決定 2）
  - [IADR-0141](IADR-0141_audit-rounds-and-population-drawing.md)（監査の巡数と母集合の引き方。
    束ねても**監査の対象数は減らない**——本 IADR も同じ）
  - [IADR-0130](IADR-0130_test-spec-coverage-ratchet.md)（**検査していないことは notice で出す**。
    条件 M-D が要求する「固定」の受け皿）
- 関連する実装仕様書:
  [20260821_meta-work-bundled-checker-fixes.md](../specs/20260821_meta-work-bundled-checker-fixes.md)
- 関連 issue: #877（検査器 2 本の食い違い）／#842（`lib/worktree-state.js` の結線が静かに死ぬ）／
  #826 の残骸（`scripts/setup.sh` の宙に浮いた参照）。**この 3 件が本決定の最初の適用例である**（決定 5）。

## コンテキストと課題

**1 issue = 1 PR（[IADR-0116](IADR-0116_reimplementation-branching-and-pr-policy.md) 規約 1）の固定費が、
メタ作業では作業そのものより大きい。**

メタ作業（検査器・規約・文書統制の是正）の 1 件は、しばしば **1 ファイル 10 行程度の変更 ＋ 回帰試験 1 本**である。
一方 1 PR あたりの固定費は、作業仕様書 1 本・IADR（必要なら）1 本・`develop` への rebase・CI 一巡・
クロス監査（[IADR-0141](IADR-0141_audit-rounds-and-population-drawing.md)）と、件の大小によらずほぼ一定である。
**同じ 3 件を 3 PR に分けると、固定費だけが 3 倍になり、レビューの読み筋は 3 回とも同じ**になる。

[IADR-0139](IADR-0139_domain-bundled-contract-prs.md) は同じ問題を**製品の契約追加**について解いたが、
その条件（同一資源・非破壊・契約の追加に閉じる）はメタ作業にそのまま当てられない。メタ作業には
「資源」に当たる概念が無く、条件 A を当てようとすると**どの 2 件も束ねられない**か、逆に
**何でも束ねられる**かのどちらかになる。

決めるべきは「**メタ作業のうち、どこまでを 1 PR に束ねてよいか**」であり、要点は 2 つある。

1. **束ねてよい単位を機械的に判定できること。** [IADR-0139](IADR-0139_domain-bundled-contract-prs.md)
   の 2026-08-16 追記が案 D（実測連動の可変上限）を退けた理由がそのまま効く——
   **判定が機械化しにくい規則は守られない。**
2. **束ねることの唯一の代償（巻き戻し単位が件数に比例する）を、メタ作業でも小さく保つこと。**
   本リポジトリはスカッシュのみであり、`develop` に着地した束は 1 コミットである
   （[IADR-0139](IADR-0139_domain-bundled-contract-prs.md) 決定 2）。

## 検討した選択肢

| | 案A: ファイル領域で判定（採用） | 案B: 「メタ作業ラベルが付いた issue」で判定 | 案C: 束ねを認めない（現状維持） |
| --- | --- | --- | --- |
| 判定の機械性 | **高**（変更ファイル一覧を glob に当てるだけ） | 低（ラベルは人が付ける。付け方が揺れる） | — |
| 誤って広がる余地 | 小（`src/**` を 1 件でも触れば束ねられない） | **大**（「これもメタ作業だ」と言えば何でも入る） | なし |
| 巻き戻しの代償 | 小（製品の振る舞いを変えないため、束ごと revert しても稼働に影響しない） | 不定 | なし |
| 固定費 | 件数ぶん下がる | 件数ぶん下がる | **下がらない** |
| 実測の裏付け | #877 / #842 / #826 の 3 件で当てて再現できる（決定 5） | — | — |

**案B を退けたのは、[IADR-0139](IADR-0139_domain-bundled-contract-prs.md) が案 C（ドメイン単位へ広げる）を
退けたのと同じ理由である**——**同型性を機械的に判定できなくなる**。「メタ作業かどうか」は主観だが、
「変更ファイルが検査器領域に閉じているか」は `git diff --name-only` で決まる。

**案C（現状維持）を退けた理由は固定費だけではない。** 小さな是正が「PR 1 本分の固定費に見合わない」と
判断されて**先送りされる**ことが実害である（[IADR-0115](IADR-0115_impl-handoff-kit-as-single-source.md)
「逃げ道の無い規約は無視される」の裏返し）。#826 の残骸（撤去済み機構への宙に浮いた参照）は、
まさに**単独では PR を立てるほどでない**という理由で残っていた。

## 決定

### 決定 1: 次の **5 条件（M-A〜M-E）をすべて満たすとき**に限り、メタ作業を 1 PR に束ねてよい

| 条件 | 内容 | 判定の仕方 |
| --- | --- | --- |
| **M-A. ファイル領域が検査器領域に閉じる** | 変更ファイルの**全件**が次のいずれかに一致する: `scripts/**`（検査器・`scripts/lib/**`・baseline JSON・`scripts/README.md`・`scripts/setup.sh` を含む）／`.ai-context/adr/**`／`.ai-context/specs/**`／`docs/how-to/**` | `git diff --name-only <base>...HEAD` を上の glob に当てる。**1 件でも外へ出たら束ねない** |
| **M-B. 件どうしが独立に revert できる** | 束の中の 2 件が**同じ関数・同じ行**を編集しない（同じファイルを触ること自体は妨げない） | 件ごとのコミットを `git revert` して衝突が出ないこと。着手前は変更予定の関数名で宣言して非重複を確かめる |
| **M-C. 1 コミット = 1 issue** | 束の中で issue とコミットが 1:1 に対応する | [IADR-0139](IADR-0139_domain-bundled-contract-prs.md) 決定 1 条件 D と同じ |
| **M-D. 振る舞いを変える件は固定を足す** | 検査器の**挙動**を変える件は `scripts/scripts.repo.test.js` または当該検査器の `--self-test` へ回帰試験を足す。**緩める変更（fail-open の追加・baseline の緩和）では、緩めすぎていないことを示す変異試験を対で置く** | 差分に試験の追加が在ること。**コメント・文書のみの是正はこの限りでない**（固定する挙動が無い） |
| **M-E. 裁定待ちを含まない** | 実装中に判断が要らない。issue 本文に未解決の質問が無い | [IADR-0139](IADR-0139_domain-bundled-contract-prs.md) 決定 1 条件 B と同じ |

**M-A の裏返しを明示する。次のものは 1 件でも含まれたら束ねられない**（それぞれ単独 PR にする）:

- `src/**` —— 製品コード。**本例外が「製品の振る舞いを変えない」ことを前提に代償を小さく見積もっている
  以上、ここが入った時点で前提が崩れる。**
- `.github/**` —— 起動条件・必須チェックが変わり得る（`CLAUDE.md`「変更したら、その変更で起動条件・
  必須チェックが変わらないかを確かめること」）。**レビューの読み筋が検査器の中身と違う。**
- `CLAUDE.md` / `.claude/rules/**` —— **毎セッション必読の規約であり総量 50KB 予算に効く**。
  レビューは差分そのものより予算と母集合の話になる。
- `deploy/**` / `templates/**` / `perf/**` / ルート直下の設定ファイル。

> **M-A は「メタ作業かどうか」を判定していない。** 判定しているのは**変更ファイル領域**だけである。
> メタ作業であっても `.claude/rules/` を触るなら束ねられないし、逆に M-A に収まる変更は
> （それがメタ作業と呼ばれようがなかろうが）束ねてよい。**主観を判定から外すことが本条件の要点である。**

### 決定 2: 束の上限は **4 件**

- **[IADR-0139](IADR-0139_domain-bundled-contract-prs.md) 決定 1 の上限（4 件）と同じ数を採る。**
  別の数を立てない理由は、**リポジトリに覚えるべき上限が 2 つあると、どちらを当てるかの判定が
  先に立ってしまう**ためである（同 ADR が案 D を退けた「規則が状態を持つと守られない」と同型）。
- **ファイル数・行数の目安は上限を決めない。** [IADR-0139](IADR-0139_domain-bundled-contract-prs.md)
  の 2026-08-16 追記と同じ扱いである。メタ作業の 1 件は数十行のことが多く、目安に当てても
  4 件を下回る根拠にならない。
- **上限を超える場合は分ける。** [IADR-0116](IADR-0116_reimplementation-branching-and-pr-policy.md)
  規約 4（PR ではなく issue を分割する）は変わらない——**束ねる方向にも同じ歯止めを当てる。**

### 決定 3: 束の PR は `Closes #NNN` を issue ごとに 1 行書く

[IADR-0139](IADR-0139_domain-bundled-contract-prs.md) 決定 3 をそのまま援用する（キーワードは番号ごとに
前置する／PR タイトルに束の全 ID をカンマ併記する／スカッシュ本文に issue ごとの内訳を書く）。
**本 IADR は同決定を写さない**——写すと片方が腐る。

### 決定 4: 機械検査は置かない（**いまは**）

- M-A は `git diff --name-only` ＋ glob で機械化できるが、**検査器を新設しない。**
  `CLAUDE.md`「**検査器・規約の追加は『同型の事故が 2 回起きたら』**を条件とする（1 回目は記録に留める）」に従う。
  **本 IADR の時点で事故は 0 回である**（規則を作ったばかりで、破られた実例が無い）。
- したがって判定は **PR を作る側が M-A〜M-E を当てて作業仕様書に書く**（決定 5 が最初の実例）。
- **「機械検査が無い」ことをここに開示しておく**（[IADR-0130](IADR-0130_test-spec-coverage-ratchet.md)
  の作法。検査していないことは黙らせない）。破られた実例が 2 度出たら、そのときに検査器を足す。

### 決定 5: **本 IADR 自身が、本規則の最初の適用例である**

本 IADR を含む PR は次の 3 件を 1 本に束ねている。**条件の当て方の見本としてここに残す。**

| 件 | 変更ファイル | M-A | M-B | M-D |
| --- | --- | --- | --- | --- |
| **#877**（検査器 2 本が凍結記録の扱いで食い違う） | `scripts/check-doc-links.js` | 収まる | `collectBroken` ＋ 新規ヘルパ | 自己試験に正例 1・負例 4 を追加 ＋ 実データの変異試験 |
| **#842**（`lib/worktree-state.js` の結線が静かに死ぬ） | `scripts/scripts.repo.test.js` | 収まる | `#836` ブロックの末尾 | **本件そのものが固定である**（回帰試験の追加） |
| **#826 の残骸**（撤去済み pin 検査への宙に浮いた参照） | `scripts/setup.sh` | 収まる | コメント 1 箇所 | **不要**（コメントのみの是正。固定する挙動が無い） |

- **M-A**: 上記 3 本に加え、束に付随する `.ai-context/adr/IADR-0230_*.md`・`.ai-context/adr/README.md`
  （索引 1 行）・`.ai-context/specs/20260821_*.md`・`.ai-context/adr/IADR-0116_*.md`・
  `.ai-context/adr/IADR-0139_*.md`（いずれも日付つき追記）。**除外領域（`src/` 配下・`.github/` 配下・
  `CLAUDE.md`・`.claude/rules/` 配下）は 1 件も含まない。**
- **M-B**: 3 件は**別々のファイル**を触る。`.ai-context/adr/README.md` だけが共有点だが、追加行は 1 行で
  他の件と行が重ならない。
- **M-C**: 3 件を 3 コミットに分ける（本 IADR ＋ 作業仕様書は束の記録としてどちらかに含める）。
- **M-E**: 3 件とも裁定は済んでいる（#877 は利用者裁定 2026-08-21、#842 は #836 の申し送り、
  #826 は事実の是正）。
- **件数 3 ≤ 上限 4。**

## 理由

- **束ねることの代償（巻き戻し単位が件数に比例する）が、メタ作業では小さい。**
  M-A が `src/**` を排除するので、束ごと `git revert` しても**稼働中の製品は 1 バイトも変わらない**。
  戻るのは検査器の網の目だけであり、その間に何かが素通りする危険は「その検査器が無かった頃」と同じである。
  [IADR-0139](IADR-0139_domain-bundled-contract-prs.md) が「マージ後の部分差し戻しは手作業になる」ことを
  **唯一かつ本質的な代償**と呼んだのに対し、本例外ではその代償が構造的に軽い。
- **レビューの読み筋が件をまたいで変わらない。** 検査器の変更のレビューは「何を検査し、何を検査しないか」
  「緩めるなら notice を出しているか」「変異試験で検出力を示しているか」の反復であり、
  [IADR-0139](IADR-0139_domain-bundled-contract-prs.md) の 2026-08-16 追記が 4 件を許した根拠
  （**同型性が保たれる限り件数が増えてもレビューは同じ観点の反復になる**）がそのまま当たる。
- **判定を主観から外した。** 「メタ作業か」ではなく「変更ファイルが領域に収まるか」で決める。
  条件 M-A は着手前（変更予定ファイルの宣言）にも、マージ前（`git diff --name-only`）にも同じ形で当たる。
- **`.claude/rules/**` と `.github/**` を外したのは、レビューの読み筋が違うからである。**
  必読規約は総量予算（50KB）と母集合の話になり、ワークフローは起動条件と必須チェックの話になる。
  どちらも検査器の中身とは別の観点であり、**束ねると片方が薄く読まれる。**

## 結果

- 良い影響:
  - 小さな是正が「PR 1 本分の固定費に見合わない」という理由で先送りされなくなる（#826 の残骸が実例）。
  - 検査器どうしの食い違い（#877）のように、**関連はするが同一 issue ではない**是正を、
    同じ文脈のまま 1 度のレビューで見られる。
  - 判定が `git diff --name-only` で済むため、着手前の並列可否判定
    （宣言済みファイル領域の非重複）と**同じ材料**で回る。
- 悪い影響・トレードオフ:
  - **マージ後の部分差し戻しは束単位になる**（スカッシュのみ。
    [IADR-0139](IADR-0139_domain-bundled-contract-prs.md) 決定 2 と同じ）。M-A により影響は検査器に限られるが、
    **代償が無いわけではない。**
  - **束の中の 1 件が監査で保留になると、束全体のマージが待つ。** その 1 件を外してからマージする
    （[IADR-0139](IADR-0139_domain-bundled-contract-prs.md) 決定 2 と同じ運用）。
  - **`Closes` の書き忘れが件数分まとめて起きうる**（同 決定 3 が実測した型）。レビュー時に
    「`Closes` の行数 = 束の件数」を数える。
- フォローアップ:
  - **M-A に反する束ねが 2 度目に起きたら、`git diff --name-only` を当てる検査器を足す**（決定 4）。
    1 度目は記録に留める。
  - 上限 4 件は [IADR-0139](IADR-0139_domain-bundled-contract-prs.md) に追随させる。
    **同 ADR の上限が動いたら本 IADR も同じ数へ動かす**（2 つの数を持たない。決定 2）。

決定 5 は本 IADR が載る PR（#878）を「最初の適用例」として として記述し し、次の 2 点を主張していた。
**どちらも実測と食い違う。**

### なぜそうなったか

**PR #878 は本 IADR の束ね規則を適用した結果ではない。** セッションのブランチ指定が
`claude/msp-all-issues-moclv4` の単一ブランチであり、**1 issue = 1 PR を物理的に取れない**ため、
7 件の issue が 1 PR に同居している。これは [IADR-0116](./IADR-0116_reimplementation-branching-and-pr-policy.md)
規約 1 からの**環境由来の逸脱**であって、本 IADR が定めた**選択としての束ね**とは別物である。

**決定 5 はその 2 つを混同して書かれた。** 検査器領域 3 件（#877 / #842 / #826）を 1 コミットへ
束ねた判断そのものは M-A を満たす（`git show --pretty=format: --name-only dd6c867 | grep -c '^src/'` = **0**）が、
**M-A の判定コマンドは決定 1 が `git diff --name-only <base>...HEAD`（＝ PR 単位）と明記している**以上、
「PR が適用例である」という言い方は成立しない。

### 訂正

- **本 IADR の最初の適用例は「PR #878」ではなく「コミット `dd6c867`」である。**
- **M-C は満たしていない**（3 件が 1 コミット）。**次の束ねでは issue とコミットを 1:1 にすること。**
- **決定 4「破られた実例が 2 度出たら検査器を足す」の 1 度目として、本追記を記録に残す。**
  2 度目が出たら、`git diff --name-only <base>...HEAD` に除外領域が含まれないことを
  機械で突合する検査を足す。

### 単一ブランチ制約が続く限りの運用

**PR 単位で M-A を満たせない環境では、本 IADR の束ね規則を「適用した」と称してはならない。**
代わりに「1 コミット = 1 issue を守り、コミット単位で M-A を満たす」ことを PR 本文へ明示する
（#878 はそうしている）。**これは規則の緩和ではなく、規則が適用できない状況の開示である。**
