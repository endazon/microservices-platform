# IADR-0686: 調停の差分にサービスアカウントの権限の余剰を数える

> 実装リポジトリ内の意思決定記録（Implementation ADR）。1 ファイル = 1 意思決定。

- 状態: Accepted
- 日付: 2026-11-06
- 決定者: コーディネーターの指示（2026-11-05）・claude（段の分け方）

## 起点・関連

- 要求 **NFR-18**。前提: IADR-0369（サービスアカウント利用者のロールは宣言が正）。

## コンテキストと課題

- 調停はサービスアカウントのロールの欠落だけを見ていた。稼働で足されたロールがあっても `drift=0` になり、G9 が緑のままだった。

## 検討した選択肢

1. **apply で既定で外す**: 稼働のロールに依っている処理があると、起動器の再実行で止まる。段階の作法に反する。
2. **check で数え、apply は段 1 では報告だけ（採用）**
3. **人の seed 利用者の余剰も見る**: 人の利用者のロールは実行時（SC-17）が所有する。採らない。

## 決定

- `collectLive` はサービスアカウント利用者の全割当を読む。読めない形なら余剰を見ない。
- 余剰は `plan` の出力先 `surplus` に積む（`ops` に混ぜない）。数えないもの: `default-roles-<realm>`、自分の client の `uma_protection`。
- `--check` は余剰を drift に数える。apply は段 1（既定）では外さずに `surplus` の行で報告し、収束の判定に入れない。`RECONCILE_REMOVE_SURPLUS=1`（Job の env。起動器の `reconcile-realm.sh` が 0 / 1 だけを受ける）で外す。
- `plan` の出力先は IADR-0685 の `kept`（稼働側の無効化・削除を戻さない）と並べて持つ。Job の差し替えは、余剰の `"0"` の行を作り直しの名前の `""` の行より先に当てる（名前が `0` でも互いの env へ当たらない）。

## 結果

- 良い影響: 宣言より多い権限が G9 で見える（偽の安心が消える）。
- 悪い影響: 稼働に余剰が在るクラスタでは、G9 が赤になる（外すか宣言へ足すかを決めるまで）。

## 残余

1. 段 2（apply で既定で外す）は、PoC で余剰が 0 になってから別の PR。
2. 人の seed 利用者の余剰は見ない。
