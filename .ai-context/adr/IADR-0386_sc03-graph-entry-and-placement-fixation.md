# IADR-0386: SC-03 の SC-18 導線と、配置規約の固定のしかた

- 状態: Proposed
- 日付: 2026-09-05
- 決定者: claude（実装判断）／起点 issue #1240（#454 の子トラッカー棚卸し）

## 起点・関連

- 関連する計画書 ID: `FR-17`（文書間リンク）/ `SC-03` / `SC-18` / `SC-04` / `UC-10` /
  `ADR-0033`・`ADR-0034`・`ADR-0035`（2026-08-07 に Accepted）
- 計画の確定事項（`05_screens` §SC-03「知識グラフ」・2026-08-02 の利用者裁定）:
  「**SC-03 に置くのは次の 2 つのみである**: ①`SC-18` への導線、②AI 提案の承認欄」／
  「バックリンク欄・ローカルグラフは **Wiki.js 側（`SC-04`）のみ**に置き、`SC-03` には併置しない」
- 関連する実装仕様書: `.ai-context/specs/20260905_issue-1240_sc03-graph-entry-and-placement-e2e.md`
- 前提 IADR（覆さない）: `IADR-0119`（着手保留。`FR-17` / `FR-18` について 2026-08-07 に解除済み）/
  `IADR-0300`（承認欄）/ `IADR-0124`（ルート）/ `IADR-0009`（存在秘匿）

## コンテキストと課題

計画が `SC-03` へ置くと定めた 2 つのうち、②は 2026-08-29（#450）に着地したが**①だけが残っていた**。

繰り延べの条件は 2 つとも満たされていた。

| 条件 | 充足 |
| --- | --- |
| 前提 ADR が `Accepted` になる（`IADR-0119` 決定 2） | **2026-08-07**（#586） |
| `SC-18` の画面が着地する（同 決定 6 の「同じ段で足す」） | **#917** |

にもかかわらず導線が無かった。**理由は「忘れた」ではない。**
コードのコメントは「本区画を足すかどうかは #504 / #452 の作業仕様書で判断する」と
**判断先を名指ししていたが、その issue が判断を残さずに閉じた**。
条件と相手は書かれていたが、**解除を実行する主体が書かれていなかった。**

同時に、`DocumentDetailPage.test.tsx` に
`does not render the knowledge-graph link (SC-18 belongs to another screen)` が立っており、
**導線を足すと CI が赤くなる**状態だった。

決めるべきは 4 つである。

1. 導線に何を渡すか（起点・深さ・間引き基準）
2. ラベルをモックの「知識グラフ」にするか、画面名の「ナレッジグラフ」にするか
3. 不在を固定していたテストをどうするか
4. 「`SC-03` に併置しない」を E2E でどう固定するか（`SC-04` 側は対で固定するのか）

## 検討した選択肢

### 論点 1: 導線が渡す検索パラメータ

| 案 | 内容 | 評価 |
| --- | --- | --- |
| A | `root` だけ渡す | **型が通らない。** `SC-18` の `GraphSearch` は `root` / `hops` / `by` の 3 つとも必須で、既定は `validateSearch` の内側にある |
| B | 3 つとも明示して渡す | 通る。「既定値の複写」に見えるが、**既定を feature をまたいで引くことは `ADR-0066` 決定 1（feature どうしを import しない）が禁じている** |
| C | 既定を `knowledge/frontend/src/lib/` へ出して両方から引く | 単一情報源にはなるが、**2 つの feature でしか使わない値のために共有層を増やす**（計画外の抽象化） |
| D | 何も渡さない（`/graph` へ送るだけ） | **押しても何も見えない。** `SC-18` は `root` が無いと照会せず案内文を出す |

### 論点 2: ラベル

| 案 | 内容 | 評価 |
| --- | --- | --- |
| A | モックどおり「知識グラフで見る（SC-18）」 | **押した先の画面名（左ナビ・パンくずとも「ナレッジグラフ」）と一致しない。** 括弧内は画面 ID の露出でもある |
| B | 「ナレッジグラフで見る」 | 画面名・左ナビ・パンくずと揃う |

### 論点 3: 不在テスト

| 案 | 内容 | 評価 |
| --- | --- | --- |
| A | 削除する | 赤は消えるが、**次に導線が失われても緑のまま**になる |
| B | 存在の固定へ反転する | 失われれば落ちる。**同じ場所で「無い」→「在る」の履歴が読める** |

### 論点 4: 併置の禁止の固定範囲

| 案 | 内容 | 評価 |
| --- | --- | --- |
| A | `SC-03` の不在だけ E2E で固定する | 計画の確定事項（置かないと決めた）だけを固定する |
| B | A ＋ `SC-04` に在ることも固定する | **`SC-04` 側は実現方式が計画で未確定**。固定すると計画より先にテストが決めたことになる |
| C | A ＋ `SC-04` に無いことも固定する | **計画が決めて実装した瞬間に、正しい実装がテストを落とす** |

## 決定

### 決定 1: 導線は `root` / `hops` / `by` を明示して渡し、常に出す（論点 1 = 案 B）

`/graph?root=<id>&hops=2&by=distance`。**これは既定値の複写ではなく明示の要求である** ——
渡した値は `SC-18` 側の `validateSearch` が値域で丸めるので、こちらが古くなっても
壊れ方は「別の深さで開く」に留まる。計画の §ルートパス 自身が `/graph?root=…&hops=2` を例示している。

「Wiki で閲覧」と違い**辿り着ける先の有無を前もって引かない**（`SC-18` は起点があれば必ず描ける）。
ただし**文書が見えないとき（404）は画面ごと中立表示になるので導線も出ない** ——
導線だけが残ると `ADR-0034` 決定 2 の存在秘匿がそこで破れる。**陰性対照で固定した。**

### 決定 2: ラベルは「ナレッジグラフで見る」（論点 2 = 案 B）

**新しい判断ではなく、`sc18GraphRoute.ts` が既に下していた判断への追随である**
（同ファイルは「計画は §用語 で同じものに 2 つの名前があることを名指しで避けている」と記して
左ナビ・パンくずを「ナレッジグラフ」に統一している）。モックの `（SC-18）` は出さない。
表記ゆれそのものは計画側へ環流する。

### 決定 3: 保留を書くときは「解除の条件」「解除の相手」に加えて**解除を実行する主体**を書く

本件の機序は**主体の不在**である。条件も相手も書かれていたが、
名指し先が判断を残さずに閉じた時点で「誰の手番でもない」状態になった。
コード・画面仕様書の両方へ書いた（コードだけを直して仕様書を残さない非対称を作らない）。

### 決定 4: 不在テストは消さずに反転する（論点 3 = 案 B）

`does not render the knowledge-graph link …` を
`links to SC-18 with this document as the graph root` へ置き換え、**`href` の起点まで見る**
（`to` だけを見ると「押しても何も見えない導線」が緑になる）。
テストのコメントに**何が反転したか・なぜ反転してよいか**を残す。

### 決定 5: 併置の禁止は `SC-03` 側だけ E2E で固定する（論点 4 = 案 A）

`sc03-document.smoke.spec.ts` に (a) 導線の実在（**陽性対照** —— 不在アサーションが
「画面がまだ描けていないだけ」で緑になっていないことの担保）(b) バックリンク欄・ローカルグラフの
不在（語と `canvas` の両方で見る）を置く。

**`sc04-wiki.smoke.spec.ts` には何も固定しない。** 在ることも無いことも書かない。
非対称の理由（`SC-03` は「置かないと決めた」、`SC-04` は「まだ決まっていない」）を
spec・テスト・画面仕様書の 3 箇所へ書く。

## 理由

- **決定 1**: 案 A は型が通らず、案 C は 2 つの feature でしか使わない値のために共有層を増やす
  （`CLAUDE.md` の「計画外の過剰な抽象化を行わない」）。案 D は導線として機能しない。
- **決定 4**: 「赤を消すために消す」と、**同じ穴が音もなく開く**。反転なら、
  導線を落とす変更がそのまま落ちる。
- **決定 5**: 未確定のものを固定すると、テストが計画の代わりに決めてしまう。
  `C` の危険は非対称でとくに見えにくい —— 「両方とも不在を固定する」は一見整合的だが、
  **片方は確定事項、片方は未確定**であり、根拠の違いが形に出ない。

## 結果

- 良い影響:
  - 計画が `SC-03` へ置くと定めた 2 つが揃った。`SC-18` へ**起点つきで**到達できる。
  - `SC-03` の配置規約が、単体テストに加えて**実ブラウザ・実ビルド成果物の上でも**固定された。
  - 存在秘匿が導線の側で破れないことを陰性対照が固定した。
- 悪い影響・トレードオフ:
  - `hops` / `by` の値が `SC-03` 側にも現れる。**単一情報源ではない**が、
    値域の正規化は `SC-18` 側が持つので壊れ方は限定される。
  - `SC-18` の面のコードは変わらないのに、その画面仕様書は追随が要る（入口が増えたため）。
- フォローアップ:
  - モックの「知識グラフ」と計画の「ナレッジグラフ」の表記ゆれを計画側へ環流する。
  - `SC-04` のバックリンク欄・ローカルグラフの実現方式が確定したら、その issue が
    `sc04-wiki.smoke.spec.ts` へ陽性の固定を足す（本 IADR は場所だけ空けている）。
