# IADR-0259: 文書 ID 制約つき検索は別メソッドで足し、空集合は「該当なし」・ABAC とは AND とする

- 状態: Accepted
- 日付: 2026-08-23
- 決定者: claude（実装）／起票 #969

> **［番号は仮である］** 本 IADR の番号は統括側が最終的に付け替える（並行採番のため）。

## 起点・関連

- 関連する計画書 ID: FR-04 / FR-17 / FR-05 / UC-01 / UC-10 / ADR-0035（決定 1「既存検索の実装は
  変更せず、後段を足す」）/ ADR-0009
- 関連する実装仕様書: `.ai-context/specs/20260823_issue-969_vectorstore-document-id-filter.md`
- 起票: #969（親 #947。後続 #970 が本口を使ってグラフ近傍展開と結線する）

## コンテキストと課題

二段検索は、グラフが返す**文書単位**の候補を**チャンク単位の出典**へ変換する必要がある
（`CitationDto` は `ChunkId` / `Score` / `Snippet` を要求するが、グラフのノードはどれも持たない）。
そのため「文書 ID 集合に絞ったベクトル検索」を後段として走らせるが、`IVectorStore` には
その口が無い（`filters` は ABAC の多値 allow-list であって文書 ID の集合ではない）。

決めるべきは 3 点である。**口の足し方**・**空集合の意味**・**ABAC との関係**。

## 検討した選択肢

| # | 案 | 評価 |
| --- | --- | --- |
| A | 既存 `SearchAsync` に省略可能引数 `documentIds` を足す | 呼び出し面は 1 つで済む。しかし**全実装のシグネチャが変わる**うえ、**既定値（省略＝絞りなし）と本口の意味（空＝該当なし）が逆**になり、渡し忘れが静かな全件検索になる |
| B | **別メソッド `SearchWithinDocumentsAsync` を足す**（採用） | 既存の口の意味論に触れない（ADR-0035 決定 1「既存検索の実装は変更せず、後段を足す」に沿う）。実装は Qdrant 側でフィルタ組み立てを共有でき、重複は条件 1 本ぶんに留まる |
| C | 汎用の「述語つき検索」を導入する | 二段検索が要るのは文書 ID 制約だけであり、過剰な抽象化になる |

空集合の扱いは **「該当なし」**（issue #969 の指定）と **「全件」** の二択だが、後者は
**グラフが 0 件を返した瞬間に検索が全文書へ広がる**（二段検索が事実上ただの全体検索に化ける）。

## 決定

1. **`IVectorStore.SearchWithinDocumentsAsync(queryVector, topK, documentIds, filters, ct)` を足す**
   （既存 `SearchAsync` は変更しない）。
2. **`documentIds` が空なら「該当なし」**（空リスト）。**両実装ともストアを呼ぶ前に返す** ——
   空の `Match.Keywords` を投げて Qdrant 側の解釈に委ねない。
3. **ABAC フィルタとは AND。** 文書 ID の制約は ABAC を置き換えず、追加の条件として重なる。
4. Qdrant 実装は `DeleteByDocumentAsync` と**同じ機構**（`document_id` の `Match`）に乗せる。
   単一 ID は `Match.Keyword`、集合は `Match.Keywords`（ABAC の多値 allow-list と同じ書き方）。
   キーは `QdrantVectorStore.DocumentIdKey` に集約し、書き込み・復元・削除・絞り込みで 1 つの値を使う。
5. **InMemory 実装の本口はコサイン類似度で実際に採点する。** 既存の `InMemoryVectorStore.SearchAsync`
   は `queryVector` を参照せずスコア `0.9f` を返す作りであり、**ベクトル側の欠陥がテストで緑のまま
   通り抜ける**（#995 で実際に起きた）。二段検索の後段はチャンクの `Score` を出典へ載せるため、
   ここで「見ているふり」をすると後続（#970）の順位検証が空振りする。

## 理由

- 決定 1: 既存の口の意味論を触らないことが ADR-0035 決定 1 の「後段を足す」に最も素直に対応する。
  省略可能引数は「渡し忘れ＝絞りなし」という**逆向きの既定**を作る。
- 決定 2: 「空＝全件」は権限や候補の縮退が**拡大方向へ**化ける唯一のパターンであり、
  静かに壊れる（0 件返るはずが全件返っても例外は出ない）。
- 決定 5: 縮退（#995 の空ベクトル）が渡り得るので、ノルム 0・次元不一致は例外ではなくスコア 0 とする。

## 影響・残件

- 既存 `InMemoryVectorStore.SearchAsync` の「`queryVector` を見ない」問題は**本 IADR では直さない**
  （#969 の射程外）。本口だけが実際に採点するため、**同一クラス内で 2 つの流儀が並ぶ**。
  是正するなら別 issue とする。
- 実機 Qdrant でのフィルタ解決は Docker が使えない環境では検証できず、CI に委ねる。
  純関数へ切り出した `BuildDocumentScopedFilter` は実機なしで固定してある。
