# IADR-0164: LLM 費用の月次手動確認をどう置くか（#546）

- 状態: Accepted
- 日付: 2026-08-10
- 決定者: claude（実装）

## 起点・関連

- **NFR**（運用・可観測性）／**SC-10**／**FR-11**。実装 issue: **#546**
- 計画の裁定: planning#286 → planning `b8002cc` **決定 39〜41**（決定 42 は #665 へ）
- 作業仕様書: [20260810_issue-546](../specs/20260810_issue-546_llm-cost-monthly-review.md)

## コンテキストと課題

計画は**暫定期間の統制を「月次の手動確認」と定め、手順・担当・記録の実体を実装側へ委ねた**。
計画の文言は次のとおりである。

> 運用者が**毎月 1 回** Grafana の LLM コストダッシュボードを確認する。
> **SC-10 の Grafana 導線カードは残っているため、導線は既にある。**

### ★ 実測すると**導線の行き先が無かった**

| 確かめたこと | 実測 |
| --- | --- |
| Grafana のダッシュボード | **`microservices-platform-overview.json` の 1 枚だけ** |
| **LLM コストのダッシュボード** | **存在しない** |
| LLM ゲートウェイのメトリクス | **`llm.completion.total` の 1 本だけ**（＝補完の**呼び出し回数**） |
| トークン消費量・金額換算・単価表 | **いずれも未実装**（[IADR-0110](./IADR-0110_llm-completion-stop-reason-metrics.md) §結果 フォローアップ 2） |

**リンク（SC-10 の導線カード）はある。その先に見るものが無い。**
**費用の金額は現状 1 円も出せない。**

## 決定 1: **観測できる範囲でダッシュボードを実際に作る**（手順書の行き先を実在させる）

`llm_completion_total` から **LLM 利用実績**のダッシュボードを新設した
（`deploy/grafana/provisioning/dashboards/llm-usage.json`、uid `llm-usage`）。

**採らなかった 2 案:**

| 案 | なぜ採らないか |
| --- | --- |
| 手順書だけ書き、行き先は #443 の完了を待つ | **行き先の無い手順は実行されない。** しかも「毎月 Grafana を見る」とだけ書くと、**決定 40 が名指しした型**（統制を定めたと統制が働いているが読み分けられない）を**自分の新しい文書で作る** |
| 費用が出せるまで統制を置かない | 計画の裁定に反する。**呼び出し回数の前月比は費用の急変を捉える代理として実用に足りる** —— 決定 41 が「絶対額のしきい値を持たず前月比で見る」と定めているため、**代理指標でも決定の趣旨は満たせる** |

## 決定 2: **「これは費用ではない」をダッシュボードとタイトルの両方に書く**

ダッシュボード名を `LLM Usage (proxy for cost — NOT cost)` とし、
**1 枚目のパネルをテキストパネルにして限界を先に読ませる**。

**理由**: 「LLM コスト」という名で回数を出すと、**次に見る人は費用を見たと思う**。
本 issue が起きた原因（SC-10 からカードを外した結果の空白）と同型の誤解を、**こちらから作らない**。

**呼び出し回数は費用ではない** —— 1 回あたりのトークン数はプロンプトと応答の長さで大きく変わるため、
**回数が横ばいでも費用は増えうる**。上位モデルの比率が上がった場合も同じであり、**だからモデル別のパネルを置く**。

## 決定 3: **手順書は独立した Runbook にする**

`docs/operations/operations.md` は既に 600 行超であり、`CLAUDE.md` の分類でも
**Runbook は「運用仕様書の下位の手順書。複数可」**である（先例: `local-sso-recovery-runbook.md`）。
`operations.md` からは**導線だけ**を張る。

## 決定 4: **絶対額のしきい値を 1 つも書かない**（決定 41）

比較の基準は**前月比の増減**と**月内累計の推移**に限る。
**金額を書くと「実測を待って確定する」という裁定と食い違う。**
目安として置いたのは「前月比 1.5 倍」という**比**だけで、これは金額ではない。

## 決定 5: **記録簿（ログ）は本 PR で作らない**

`llm-cost-monthly-review-log.md` は**1 回目の確認時に作る**。
**空のログファイルを置くと「運用している」ように見える** —— 本 ADR が決定 2 で避けたのと同じ誤解である。
Runbook には置き場所と記録項目だけを定めた。

## 決定 6: **決定 42（SLO の暫定通知先）は本 PR に含めない**

**資源が違う**（LLM 費用の統制 ではなく **SLO の通知経路**）。[IADR-0139](./IADR-0139_domain-bundled-contract-prs.md) 決定 1
「判定の単位は資源」に従い束ねない。**#665 として起票した。**

**加えて、本セッションでは Grafana を起動して検証できない。**
検証できない配線を「配備した」と記録すると、**本 issue が問題にしている
「統制を定めたが働いていない」を自分で作る**ことになる。

> **ただし決定 40 の是正は SLO 表にも及ぶ。** 配線は #665 だが、
> **`operations.md` の SLO 表が「通知先: Alertmanager」と平叙で書いていた**のは本 PR で直した
> —— 誤読される記述を残す理由は無い。

## 結果

### 是正した「統制が働いているように読める」記述（**自分で全数走査した**）

#546 のコメントは `:523` / `:534-538` / `:553` / `:620` を名指ししていたが、**転記しなかった**。
自分で引くと**行番号はすべてずれていた**（`:532` / `:543-547` / `:562` / `:629`）。

| 箇所 | 直した内容 |
| --- | --- |
| SLO 表の見出しと 5 行 | 「通知先」→「**通知先（配備後。現状は未配線）**」。表の前に**通知が誰にも届いていないこと**と暫定の一次検知（Prometheus UI / Grafana の目視）を置いた |
| エスカレーション/通知 | 「Alertmanager の受信先…定める」→「**配備後に**…定める。**配備までは自動通知が無い**」 |
| ダッシュボード | 新設した `llm-usage.json` と、**LLM 費用の統制が月次手動確認であること**への導線を追加 |
| 未決事項 | **空なのが 2 か所**であること・追跡先（#546 / #665）・**LLM 費用の自動検知が無いこと**を追記 |

### 検証

| 対象 | 結果 |
| --- | --- |
| ダッシュボード JSON の妥当性・`uid` 重複 | OK（`llm-usage` は既存と重複しない） |
| **式のメトリクス名・属性名・属性値が実装と一致すること** | **突合して OK**（`LlmCompletionMetrics.cs` ＋ `CompletionDto.cs`） |

> **★ 突合は 1 ファイルでは足りなかった。** 初回は `LlmCompletionMetrics.cs` だけを見て
> `max_tokens` / `refusal` を「実装に無い」と判定した —— 実体は `CompletionStopReasons`（`CompletionDto.cs`）に
> あり、メトリクス側は定数を参照していただけである。**母集合を 1 ファイルに絞ると誤判定する。**

### 検出しないこと（正直に書く）

- **費用の金額は出せない。** 本 Runbook が与えるのは**気づく機会**であって保証ではない。
- **回数が横ばいでも費用は増えうる**（決定 2）。
- **検知の遅れは最大 1 か月**（計画が受け入れた帰結。実装側で埋めない）。
- **ダッシュボードの式が Grafana で意図どおり描画されるかは未検証**（起動できないため）。
  **突合したのは名前の一致までである。**

## 申し送り

- **#443 / [IADR-0110](./IADR-0110_llm-completion-stop-reason-metrics.md) §結果 フォローアップ 2** が着地したら、**ダッシュボードを費用へ差し替える**。
  そのとき決定 2 の「NOT cost」表記も外す。
- **Alertmanager 配備後は Runbook を終了する**（`status: superseded` へ。併存させない）。**#546 で追跡中。**
- **月次予算の金額**は実測後に確定する（決定 41）。記録簿がその入力になる。
