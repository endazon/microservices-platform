# IADR-0274: SC-18 のグラフ描画は既存依存 ECharts の GraphChart を専用遅延チャンクで用いる

- 状態: Accepted
- 日付: 2026-08-23
- 決定者: claude（#917 / 親 #450）

## 起点・関連

- 関連する計画書 ID: FR-17 / FR-05 / UC-10 / SC-18 / ADR-0039（決定 2・4・§導入の条件）/
  ADR-0034（決定 1〜4）/ ADR-0049 / ADR-0054（決定 3・5）/ ADR-0033 決定 7・9 / ADR-0031
- 関連する実装仕様書: `.ai-context/specs/20260823_issue-917_sc18-graph-view.md`
- 前提となる既存決定: [[IADR-0036]]（SC-11 は描画ライブラリ非導入。**射程は SC-11 に限る** —— ADR-0039 決定 1
  で計画側と合意済みであり、本 IADR は SC-18 についての別判断である。覆さない）、
  [[IADR-0242]]（ホップごと ABAC の型ゲート）、[[IADR-0134]]（ルート単位のコード分割と初期ロード予算）、
  [[IADR-0122]] 決定 2（既定値の無い契約メンバー追加は破壊的変更）

## コンテキストと課題

ADR-0039（`Accepted`・原文で確認）は SC-18 でのグラフ描画ライブラリ導入を認めたが、
**決定 4 で「具体的なライブラリの選定は本 ADR では行わない。実装リポジトリの IADR で決める」**と
実装側へ委ねた。あわせて §導入の条件が 4 件の確認を課し、**条件 1 は「見込みではなく実測」**、
条件 3 は「導入前後の差分を数値で残す」ことまで指定している。本 IADR がその記録である。

また ADR-0054 が新設した `doc_scope`（個人資料と組織文書の判定軸）は**実データ 0 件・既存文書へ
遡及付与しない**ため、画面は「値の無い文書」に長期間出会う。この扱いを決める必要がある。

## 検討した選択肢

1. **ECharts（`echarts@6.1.0`・既存依存）の `GraphChart`**（採用）
2. **Cytoscape.js / sigma.js（新規依存）**（不採用 —— **測っていない**。planning `14_knowledge-graph-graphrag.md`
   §7 が「既存採用の ECharts で足りるかを**最初に**検証し、**足りない場合にのみ**専用ライブラリを
   検討する順序が費用対効果に優る」と定めており、下の実測で ECharts が 4 条件をすべて満たしたため、
   次候補を測る条件が発生しなかった。**選んでから測ったのではない** —— 実測（§条件 1）は
   実装着手前にハーネスで行い、その結果で選んだ）
3. 自前 SVG 描画（不採用 —— ADR-0039 選択肢 2 が計画側で却下済み。再検討しない）

## 決定

### 決定 1: ECharts `GraphChart`（力学レイアウト・SVG レンダラ）を採用する

- 供給源は既存依存 `echarts@6.1.0`（ADR-0031 §採用技術一覧「チャート = Apache ECharts（自己ホスト）」）。
  **新規依存は 1 つも足さない**（`src/pnpm-lock.yaml` は不変）。
- レンダラは **SVG**（SC-08 / SC-10 の既存判断と同じ。jsdom に canvas が無くテストが描画で落ちない・
  成果物へ canvas 依存を持ち込まない）。§条件 1 の実測では canvas がやや速いが、SVG でも
  対話操作は約 50 fps で足りており、揃える利得が上回る。
- 登録層は `echartsGraphBundle.ts`（`GraphChart` / `TooltipComponent` / `SVGRenderer` だけを静的
  import して `use()`）に閉じ、`echartsGraphLoader.ts` の動的 import で遅延させる（バレルの動的
  import は tree-shaking が効かない —— #788 の実測 1,092.40 kB と同じ罠）。
- **既存の `vendor-echarts` チャンクに同居させない。** 同居させると 603,300 bytes（実測）で
  1 チャンク上限（600,000）を超えるため、`echarts/lib/chart/graph/` 配下を専用チャンク
  `vendor-echarts-graph` へ分けた（`vite.config.ts` の manualChunks ＋ `chunk-budget-baseline.json`）。
  SC-08 / SC-10 しか開かない利用者に graph の面は届かない。

### 決定 2: `GraphNodeItemDto` / `GraphNodeDto` へ `IsPrivateNote`（bool・既定 false）を足す

SC-18 の描き分け（組織文書＝円＋📄 / 個人資料＝角丸四角＋👤・破線輪郭）は**全ノードに要る 1 bit**
であり、選択時に 1 件ずつ文書詳細を引く形では 200 ノードの描画に間に合わない。Seal
（`AuthorizedGraphView`）が属性複製から導出して載せる。

**欄の追加が権限外の情報を漏らさないかの検討**（#962 で使用件数を出さないと判断したときと同じ観点）:

| 観点 | 判断 |
| --- | --- |
| 値が付く母集合 | **ABAC 判定（AuthorizedNode）を通過し、既に応答へ載っているノードだけ**。Seal の後段で導出するため、権限外ノードにこの値が生成される経路はコンパイル時に存在しない（[[IADR-0242]] 決定 2 の型ゲートの内側） |
| 値の情報量 | 個人資料は ABAC で**所有者本人にしか見えない**（ADR-0036 / ADR-0046 の系）。したがって `IsPrivateNote=true` を受け取るのは常に所有者自身であり、**本人が既に知っている事実**しか運ばない |
| 集計値か | 否。#962 が拒んだのは「ABAC で絞られていない集計値（使用件数）」であり、本欄は**可視ノード 1 件ごとの属性**である。絞られていない母集合に触れない |
| 契約互換 | 既定値つきで足す（既定値の無いメンバー追加は破壊的変更。[[IADR-0122]] 決定 2） |

### 決定 3: `doc_scope` の**値が無い文書は組織文書として描く** —— 暫定ではなく決定である

- 導出は**集合帰属**で書く: `attributes["doc_scope"] == "private-note"`（大文字小文字不問）のときだけ
  個人資料。**「organization でない」という否定形で書いてはならない** —— `doc_scope` は実データ 0 件・
  遡及付与しない方針（ADR-0054 §結果）であり、否定形だと既存文書が全部「個人資料」に化ける。
- 根拠は **ADR-0054 決定 5**:「システム投入経路で作られる文書の既定は `organization`。
  **取り込み経路が個人資料を作ることはない**」——値の無い文書は取り込み経路（`doc_scope` 新設前を
  含む）が作ったものであり、個人資料ではない。`owner` / `department` と違い `doc_scope` は
  「解決できないときの予約値」を持たず既定が終端であるため、**「未判定」という第 3 の状態を
  作らない**（凡例に載らない状態を画面に出せない —— SC-18 は凡例を必須要素に挙げている）。
- `doc_scope` の強制（属性辞書照合）にはコードが要り（IADR-0047 が動的照合を見送っている）、
  値を持たない文書が入り続ける期間は長い。**この扱いは事実上の仕様になる**ため、暫定の
  埋め合わせではなく本 IADR の決定として残す。判定は `GraphDocumentScope.cs`（GraphService 内。
  platform ユニットの `DocumentScope.cs` と同形だが、可変ユニットから参照できないため共有化しない
  —— ユニット外参照の追加は IADR-0117 の改定事項であり bool 1 個の導出に見合わない）。

### 決定 4: 辺の型フィルタは `neighbors` の `types` 引数として**サーバ側・探索の入口**で適用する

- 05_screens §SC-18「辺の種別フィルタはサーバ側で適用する」（環流 planning#446 の裁定）の実装である。
  絞りは `GraphTraversal.ExploreAsync` の**候補へ入れる前**に置く —— 打ち切り後にクライアントで
  絞ると「フィルタ後の上位 200 件」ではなく「上位 200 件のうち一致したもの」になる。
  **総数（TotalNodes / TotalEdges）もフィルタ後の母集合で数え直す**（帯の「全 N 件」は
  「いま選んでいる型での全数」の意味）。
- 検証は **hops と同じく認可より前**（形式不正は文書の存在と無関係に 400）。後ろへ置くと
  400/404 の打ち分けから存在が漏れる（ADR-0034 決定 2 の存在秘匿と同じ線）。
- **実在しない型 ID はエラーにしない**（1 本も一致しないだけ）。型辞書は認証のみで全利用者へ
  公開済みの語彙（#962）であり実在の有無は秘匿対象ではない。辞書の改廃と共有済み URL が
  競合しても画面が壊れない。

## ADR-0039 §導入の条件 — 4 条件の確認結果（実測・2026-08-23）

### 条件 1: ノード 200 / 辺 500 を対話操作込みで扱えること — **実測で満たす**

ハーネス `perf/graph-render/measure.mjs`（SPA と同じ供給源の echarts を esbuild で束ね、外部 CDN を
一切引かない self-contained HTML を headless Chromium 1280×800 で駆動。ノード 200 / 辺 500・
力学レイアウト・線種 5 種・各 3 回の中央値）:

| 操作 | SVG レンダラ（採用） | Canvas レンダラ（参考） |
| --- | ---: | ---: |
| 初期化＋力学レイアウト収束＋初回描画 | 368.8 ms | 312.6 ms |
| パン（ドラッグ 30 ステップの平均フレーム間隔） | 19.8 ms（≈ 50 fps） | 17.2 ms |
| ズーム（ホイール 20 回の平均フレーム間隔） | 19.1 ms（≈ 52 fps） | 16.6 ms |
| ノード選択（select 反映まで） | 16.5 ms | 19.5 ms |
| 種別フィルタ切替相当（辺 500 → 250 の setOption・再レイアウト込み） | 304.5 ms | 264.3 ms |

判断: 初期表示 0.4 秒・対話中は概ね描画リフレッシュ間隔どおり・フィルタ切替 0.3 秒であり、
**SC-18 の対話要件（ズーム・パン・ノード選択・種別フィルタ切替）を SVG レンダラで満たす**。
次候補（Cytoscape.js / sigma.js）を測る条件（ECharts で足りない）は発生しなかった。

### 条件 2: 個人資料と組織文書をアイコンと形の併用で区別し、凡例を画面内に置けること — **満たす**

組織文書＝円＋📄 / 個人資料＝角丸四角＋👤・破線輪郭（`symbol: 'roundRect'` ＋ `borderType: 'dashed'`）、
ホバーでタイトルと種別ラベルを表示、凡例（`GraphLegend`）はグラフ領域の直下に常時表示
（`<details open>`）。**色だけで意味を持たせない** —— 形・アイコン・線種・太さ・矢印が担う。
写像は `graphOption.test.ts` が固定する。

### 条件 3: バンドルサイズへの影響 — **実測（minified bytes・Vite 6 ビルド）**

| チャンク | 導入前 | 導入後 | 差分 |
| --- | ---: | ---: | ---: |
| vendor-echarts（共有部。**遅延**） | 557,207 | 586,044 | +28,837 |
| vendor-echarts-graph（graph 固有。**遅延**・新設） | — | 18,164 | +18,164 |
| echartsGraphBundle（登録層。**遅延**・新設） | — | 162 | +162 |
| **ECharts 面の増分合計** | | | **+47,163（≈ 47.2 kB。すべて遅延チャンク）** |
| GraphViewPage（画面本体。**遅延**・新設） | — | 12,958 | +12,958 |
| 初期ロード合計（check-chunk-budget の定義） | 575,856 | 582,842 | +6,986（ルート登録＋Lingui カタログ 47 メッセージ × 2 ロケール。カタログは foundation/i18n が静的 import するため初期ロードから外せない） |

ECharts の増分は**すべて遅延チャンク**であり、SC-18 を開かない利用者には配信されない
（ADR-0039 §結果が求めた「遅延読み込みの要否の判断」への答え）。

### 条件 4: 外部 CDN 非依存・セルフホスト配信 — **満たす（機械検査つき）**

npm からの自己ホストのみ。`node scripts/check-static-egress.js --require src/platform/frontend/dist`
が成果物走査で OK（外部オリジンからの取得 0 件）。アイコンは絵文字（📄 / 👤）でありフォント・
画像の外部取得も無い。

## 結果

- **良い影響**: 依存 0 追加で SC-18 が成立する。ECharts の面（折れ線・棒 / グラフ）が画面別の
  遅延チャンクに分かれ、`IADR-0036` の SC-11 非導入判断とも両立する（射程は SC-11 に限る）。
- **悪い影響 / トレードオフ**: ECharts の力学レイアウトは Cytoscape.js ほどレイアウトの選択肢が
  無い（階層レイアウトは任意要素であり本 IADR では実装していない —— 系列辿りで必要になった時点で
  再評価する）。`vendor-echarts` の分割規則が 1 本増え、manualChunks と baseline の突合対象が増えた。
- **フォローアップ**:
  1. 計画側への反映（ADR-0039 §結果 フォローアップ 3: `13_frontend-stack` §採用技術一覧と
     `14_knowledge-graph-graphrag` §7 へ選定結果と実測値を反映）は planning への環流で行う。
  2. 実データ到来後（属性複製の配線 #911 / #912）、`doc_scope` を持つ実ノードで描き分けを確認する。
  3. ADR-0049 の算出用上限（2,000 / 5,000）は実測で覆り得る値である。応答時間の実測は
     `GraphTraversal` 側の作業（#980 の残件）に属し、本 IADR は関与しない。
