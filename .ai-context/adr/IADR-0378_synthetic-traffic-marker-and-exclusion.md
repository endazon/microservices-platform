# IADR-0378: 合成トラフィックの標識と、費用・利用状況からの除外（#1203）

- 状態: Accepted
- 日付: 2026-09-05
- 決定者: claude（実装）

## 起点・関連

- 計画 ADR **ADR-0076** 決定 4（合成監視を計画へ位置づける。**合成トラフィックは識別できる標識を持ち、
  `ADR-0044` の LLM 費用計測と `SC-10` の利用状況・検索傾向の集計から除外する。
  **除外できない構成では合成監視を配備しない**。標識と除外は同時に入れる）
- 同 決定 3（常時トラフィックがある経路にだけ `absent` を併設する。`/analysis/ask` 系は
  **決定 4 の合成監視で常時トラフィックを作ってから**対象へ入れる）
- 実装 issue **#1203**。直前段は **#1202**（`absent` の併設・**IADR-0370**）と
  **#1204**（初回トークン計器・**IADR-0354**）
- 先行: **IADR-0343**（利用イベントの発火）／**IADR-0367**（利用イベントの主体撤去）／
  **IADR-0299**（内部 API の無認証化と、その残余リスクの受容）／**IADR-0110**（属性の値域を閉じる規律）

## コンテキストと課題

`/analysis/ask` 系は無風が 5 分を超え得るため、`IADR-0370` は `absent` の対象から外した。
その穴を塞ぐのが合成監視である。**ところが合成監視は、置いた瞬間に別の壊し方をする。**

合成リクエストが BFF を通れば利用イベントが発火し、`SC-10` の利用状況が合成分だけ嵩上げされ、
`ADR-0071` のしきい値（出現件数 3 件）を**合成の語が通過する**。LLM を呼べば `ADR-0044` の費用にも入る。
**指標が「人が使った量」を表さなくなる。**

したがって決定 4 は配備条件を先に置いた —— **除外できない構成では配備しない。**
本 IADR が答えるのは「**何をもって合成と判定するか**」と「**どこで外し、外したことをどう見せるか**」である。

## 決定

### 決定 1: 標識は「外周＝検証済み JWT の主体」「内周＝外周が付けたヘッダ」の 2 段にする

🔴 **同じ 1 つの材料で両方の面は賄えない。**

| 面 | 到達性 | 判定材料 | 偽装可能性 |
| --- | --- | --- | --- |
| **外周**（`Platform.Bff` の `/bff/*`、`DashboardService` の `/dashboard/events`） | 外部から到達し得る | **検証済み JWT の主体**（`azp` / `client_id` / `preferred_username` / `sub` が `SyntheticMonitoring:Subjects` に一致） | **無い**。他人の `azp` を名乗るトークンの発行にはクライアント資格情報が要る |
| **内周**（`AiAnalysisService` → `LlmGateway`） | ClusterIP ＋ NetworkPolicy 既定拒否 ＋ STRICT mTLS の内側 | ヘッダ `X-Synthetic-Traffic`（**外周が付ける**） | 同一ネットワーク内からのみ。**`IADR-0299` が `/internal/*` について受容した残余リスクと同型・同じ境界** |

🔴 **外周は受信ヘッダを一切見ない。** 見れば「外から印を付けて実利用を費用集計から隠す」経路が開く。
これは**攻撃者に費用計上の免除権を配ることに等しい**。否定形の試験（外からヘッダを付けても除外されない）を
陽性・陰性と対で置いた。

**ヘッダだけで済ませなかった理由**: 合成監視は `.RequireAuthorization()` の端点を叩くため、
**どのみち主体を用意しなければならない**（#443 / #1103 が踏んだ罠）。主体が要るなら、
**その主体そのものを標識にするのが最も偽装しにくい。** ヘッダは内周への運び手に徹する。

**シークレット付きヘッダ（共有秘密）にしなかった理由**: 資格情報が 2 系統になり、
片方（JWT）を厳しくしても片方（ヘッダ秘密）の漏洩で除外が効いてしまう。**判定の権威を 1 つに保つ。**

### 決定 2: fail-closed —— 許可集合が空なら何も合成と見なさない

`SyntheticMonitoring:Subjects` が空なら `IsSyntheticPrincipal` は常に `false` を返す。

🔴 **逆向き（空＝全部が合成）に倒すと、設定漏れで実利用がまるごと費用計上から消える。**
片方向にしか倒せない選択であり、倒す先は「除外が効かない」側である
（**指標が汚れることは検知できるが、指標が消えることは検知できない**）。

### 決定 3: 除外は「発火の唯一の口」で行い、検索傾向の側に独立した除外を置かない

`IUsageEventReporter.Report` は利用状況イベントの**唯一の発火点**である（走査で確認。作業仕様書 §母集合 ②）。
ここを通さなければ `UsageEvents` に行は入らず、**行が入らなければ `ADR-0071` のしきい値を通る語も生じない。**

**しきい値の側へ別の除外を置かない。** 置くと同じ規則が 2 か所に分かれ、
片方だけが古くなる（`IADR-0141` の規律）。**上流で断つ方が、経路が増えても壊れない。**

**ただし受け口（`POST /dashboard/events`）にも同じ判定を置く**（多層防御）。
除外を「1 つの呼び出し元の作法」ではなく**行を作る側の性質**にするためである
（`IADR-0044` の多層防御・`IADR-0039` 決定 2 と同じ向き）。応答は **202 Accepted** ——
これは誤りではなく設計どおりの除外なので 400 にしない。

### 決定 4: 外した件数を数える。`dropped` と混ぜない

🔴 **黙って落とさない。** 落とした件数がどこにも無いと、
**「合成だけが通っていて実利用は 0」でも計器が緑に見える** ——
#1103 が直した「0 件が正常に見える」形をそのまま作り直すことになる。

| 計器 | 意味 |
| --- | --- |
| `usage.event.dispatch.total{usage.event.outcome="excluded_synthetic"}` | 合成のため利用イベントを発火しなかった件数 |
| `llm.usage.synthetic_excluded.total` | 合成のため費用へ計上しなかった補完の件数 |

**`excluded_synthetic` を既存の `dropped` に混ぜない。** あちらは受け口の不調による取りこぼしであり、
こちらは設計どおりの除外である。混ぜると**「除外が効いている」と「受け口が壊れている」が同じ数**になる。

**除外の計器にトークン数を属性として載せない**（非有界。`IADR-0110` の規律）。
属性は用途・モデル・プロバイダ・機密区分で、**`RecordUsage` と同じ軸に揃える** ——
軸が違うと「外したぶん」と「計上したぶん」を並べて読めない。

### 決定 5: 費用計測からは外すが、呼び出し回数（`llm.completion.total`）からは外さない

決定 4 が挙げるのは **`ADR-0044` の費用計測**である。`llm.completion.total` は「呼んだ事実」の計器であり、
**拒否率の分母**である。合成を抜くと分母が欠けて拒否率が過大に見える（`IADR-0110` が未送信も計上する理由と同型）。
**合成の補完は実際に起きた補完であり、回数としては真である。**

### 決定 6: SLO の分子分母からは外さない

🔴 **決定 4 の列挙に SLO は無い。** そもそも合成監視を置く目的は
**「SLO の評価対象を作ること」**（決定 3）であり、SLO から外せば器の意味が消える。
**「観測が指標を汚す」のは費用と利用実績についてであって、レイテンシではない。**

### 決定 7: 合成は既定で LLM を呼ばない（`AllowLlmEgress` の既定は `false`）

🔴 **これは費用の上限が未定であることへの実装側の応答である。**
`ADR-0076` §残るもの は「**合成監視の頻度・費用の上限は定めていない。LLM を呼ぶ経路を含めるなら
費用が発生する。除外規則は指標を守るものであり、費用そのものを減らさない**」と自認している。

**上限が無いまま恒常的に費用を出す構成を既定にすることは、実装裁量の外である**（#78 の向き）。
したがって `AiAnalysisService` は、合成でありかつ `AllowLlmEgress` が立っていないとき
**`LlmGateway` を呼ばずに縮退する**。**検索までは実際に走る**ので、
`/analysis/ask` の HTTP 系列は立ち、決定 3 の評価対象は生まれる。

🔴 **その代償を明示する。** `rag.answer.first_token.duration`（`IADR-0354`）は
**`token` イベントが 1 件も出なければ記録されない**設計である。したがって
**`RagFirstTokenP95High`（`NFR-02` の SLO 判定）の評価対象は本 PR では生まれない。**
これは実装の手抜きではなく、**費用上限が未定であることの帰結**であり、計画へ裁定を依頼した（**planning#538**）。

### 決定 8: プローブは CronJob ではなく Deployment のループにする

- **CronJob の刻みは 1 分が下限**であり、pod 起動の揺らぎが乗ると**要求間隔が 5 分境界の近くで不安定**になる。
  決定 3 の判定基準は「無風でいられる時間が 5 分より短いこと」であり、**間隔の決定性そのものが要件**である。
- **メッシュ内の Job はサイドカーのせいで完了しない**（realm reconcile Job を `platform-infra` へ置いたのと同じ罠）。
  プローブは BFF（`microservices-platform`）へ到達する必要があるため、この namespace に常駐させる。
- **外部 SaaS は使わない**（計画 `08_data-egress-policy`）。実装は Node 標準の `fetch` だけで、依存パッケージを持たない。
- 🔴 **`PROBE_INTERVAL_SECONDS` に既定値を置かない**（未設定なら起動しない）。
  **未定の数字を実装が埋めると、それが既成事実として計画へ逆流する。**

### 決定 9: 既定の起動器には入れない（opt-in オーバーレイ）

realm クライアントと Secret が揃っていない環境で回すと 401 を打ち続ける。
さらに **除外を含むイメージが配備されていない環境で回すと、決定 4 が禁じた「除外できない構成での配備」になる。**
`deploy/local/observability` と同じ opt-in の形にし、前提を README の手順に置いた。

## 理由

- **決定 1 の 2 段構えは「到達性の違い」に対応している。** 外周は誰でも叩けるので**偽造できない材料**が要り、
  内周は到達性そのものが統制なのでヘッダで足りる。**一段で揃えると、厳しすぎて内周が実装できないか、
  緩すぎて外周が破れるかのどちらかになる。**
- **決定 2 が fail-closed なのは、誤りの検知可能性が非対称だからである。** 汚れた指標は
  「増えすぎている」と気づけるが、**消えた指標は「使われていない」と区別が付かない。**
- **決定 4 が別軸の計器なのは、除外そのものが観測対象だからである。** 除外は**正しく効いていても、
  効きすぎていても、静かである**。数えていなければどちらも見えない。
- **決定 7 が既定 `false` なのは、可逆性が非対称だからである。** 呼ばない設定は後から開けられるが、
  出てしまった費用は戻らない。

## 影響・残るもの

- 🔴 **`NFR-02` の SLO（初回応答）の評価対象は依然として無い**（決定 7）。**裁定待ちである**（planning#538）。
- 🔴 **`absent` の対象拡大（`/analysis/ask` 系を決定 3 の対象へ入れる）は本 PR では行わない。**
  #1203 本文が「#1202 の対象拡大」を後段と明示しており、**頻度の裁定が下りてからである。**
- 🔴 **意図的に 5xx を出す合成経路は置いていない。** 製品の振る舞いを変える判断であり、
  `ADR-0076` §残るもの も「本番相当の 5xx を発生させる経路が無い」と残している。**裁定待ちである**（planning#538）。
- **稼働クラスタでの端から端までの実測は取れていない。** 除外はコード側にあり、稼働イメージには入っていない。
  そして **除外の入っていないイメージへ向けてプローブを回すことは決定 4 が禁じている**ため、
  「イメージを焼き直さずに実測する」という道は原理的に無い。**測れなかったものは測れなかったと記録する**
  （実測の内訳は #1203 の PR 本文）。
- **`Platform.Shared.Infrastructure` に `Foundation/Observability/` を新設した。** 標識の定義は
  platform / knowledge の両ユニットから参照されるため、`Shared` の 3 プロジェクト以外に置き場所が無い
  （`IADR-0117`）。
