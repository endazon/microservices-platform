# IADR-0467: 分離したコレクションを 1 回の検索で束ねる —— 定数・候補幅・重みと、コレクションごとのクエリ埋め込み

> 実装リポジトリ内の意思決定記録（Implementation ADR）。1 ファイル = 1 意思決定。

- 状態: Accepted
- 日付: 2026-09-26
- 決定者: claude（#336。計画 ADR-0092 フォローアップ 1〜3 の実装）

## 起点・関連

- 関連する計画書 ID: FR-03（横断検索）・FR-02（埋め込み）・FR-05（ABAC）・UC-01
- 関連する計画 ADR: **ADR-0092**（決定 1: 束ね RRF で合成／決定 2: クエリ埋め込みは取り込みと別・ティア A のコレクションはティア A で埋める／決定 3: ABAC は束ね方と独立）、ADR-0016（モデル別コレクション分離）、ADR-0017（ティア A は Ruri v3）、ADR-0035（二段検索）、ADR-0043（権限内属性値）、ADR-0057（削除の伝播）
- 関連する実装 ADR: [IADR-0422](./IADR-0422_ndcg-harness-and-query-embedding-profile.md)（クエリ埋め込みプロファイルと照合。**決定 2 を内部契約について部分改定する**）・IADR-0012（deny-by-default）・IADR-0151（属性値は検索と同じ制約で引く）・IADR-0256（輸送の失敗は潰さない）・IADR-0085（TEI の opt-in 配備）
- 関連する実装仕様書: `.ai-context/specs/20260926_issue-336_multi-collection-rrf-fusion.md`（母集合の全列挙はそちら）

## 状況

ADR-0092 フォローアップ 1 は「**ティア A（`embedding.enabled: true`）を有効化する前に入れること**」と書く。
実装の現状（`origin/develop` `b54b719c`）:

- 検索サービスは `Qdrant:CollectionName` の **1 本しか読まない**（ベクトル・全文・属性値・削除のすべて）
- ゲートウェイは検索クエリを `Public` へ倒し、優先度順に **1 つ**選ぶ。**ティア A のコレクション用に埋めてくれと頼む口が無い**
- `git grep "ADR-0092" -- src` は 0 件

## 決定

### 決定 1: 検索が読むコレクションは「主」＋「束ねる追加」。**追加の既定は空**

- 主は従来どおり `Qdrant:CollectionName`（意味も値も変えない）。追加は新設 `Qdrant:FusedCollections`（配列）。
- 空・空白・主と同名・重複は捨て、構成の順を保つ（`QdrantVectorStore.ResolveFusedCollectionNames`）。
- 1 コレクション = **「そのコレクションを読むストア」と「そのコレクションのモデルでクエリを埋める客体」の組**（`FusedCollection`）。
  ストアだけを増やすと、ティア A（768 次元）のコレクションへティア B（1024 次元）で埋めたクエリを投げることになる
  （ADR-0092 実測 4「(a) を実行するには (b) が要る」）。
- 🔴 **既定（空）では、検索・属性値・削除は従来と同一**である（戻り値・`Score`・呼び出し回数を試験で固定）。
- 配線: Helm は `embedding.enabled=true` のときだけ retrieval に `Qdrant__FusedCollections__0=<embedding.collection>` を描画する
  （llmgateway のセルフホスト有効化と**同じ条件**。片方だけだと「索引されるが検索されない」か「検索するが埋め込めない」になる）。
  compose は `SEARCH_FUSED_COLLECTION`（既定空）。

### 決定 2: 束ね方の定数 —— **k = 60・候補幅は既存と同じ・重みは全系統 1・同点は初出順**

| 項目 | 値 | 理由 |
| --- | --- | --- |
| RRF の k | **60**（既存 `HybridSearchService.RrfK` を共用） | ADR-0092 決定 1「同じ問題に同じ道具を当てる」。系統ごとに k を変える根拠（測定）が無い |
| 融合の形 | **平ら**（全コレクションの全系統を 1 回の RRF へ。並びは 主ベクトル → 主全文 → 追加 1 ベクトル → 追加 1 全文 → …） | 追加が空のとき `RRF(主ベクトル, 主全文)` となり**従来と同じ式**になる。入れ子（コレクション内で融合→コレクション間で融合）だと主だけでも `Score` が変わる |
| 候補幅 | hybrid は各系統 **`max(TopK*4, TopK)`**、keyword / semantic は従来の `singleModeK`（relevance なら `TopK`、updated なら hybrid と同じ幅） | 既存の幅をそのまま全コレクションへ当てる。互いに素な並びの RRF では、合成後の上位 `TopK` は各並びの上位 `TopK` の和に含まれるので、単一モードで幅を広げる必要が無い |
| 重み | **全系統 1** | 重みを入れる根拠（nDCG の実測）がまだ無い。入れるなら測ってから本 IADR を改める |
| 同点 | **先に現れた方が先**（上の並び → 各並びの中の順位）。二次キーとして**明示**した | 従来は `Dictionary` の列挙順に暗黙依存していた。明示しても従来の並びは同一（試験で固定） |
| スコア | 🔴 **入力の生スコアは読まない**。結果の `Score` は RRF の合算値 | モデルが違えばスコアは同じ意味を持たない（ADR-0092 決定 1・ADR-0016 の分離理由） |

モードごとの振る舞い:

| モード | 追加あり | 埋め込めないとき |
| --- | --- | --- |
| hybrid | 各コレクションのベクトル（埋め込めたものだけ）＋全文を 1 回の RRF | そのコレクションのベクトル系統だけを落とし、全文は引く（#995 と同じ縮退の向き。コレクション名つきの警告ログ） |
| keyword | 🔴 **全文も束ねる**（ADR-0092 実測 6: 全文も同じコレクションを読むので、束ねないとティア A の文書はキーワードでも見つからない） | 埋め込みを呼ばない |
| semantic | 埋め込めたコレクションだけを RRF | **全コレクションが埋め込めなければ 0 件**（従来の semantic と同じ意味。全文へ振り替えない） |

**nDCG@10 で測れるようにする**（ADR-0092 決定 1・フォローアップ 3）: 束ね方は構成 1 つ（`Qdrant:FusedCollections`）で入れ外しできる。
「voyage のみ」（空）と「束ねた」（ティア A を足す）を同じ qrels で 2 回収集し、既存ハーネス
（`scripts/measure-search-ndcg.js`）の A/B 比較に掛ける。手順は `perf/ndcg/README.md`。ハーネスのコードは変えない
（束ねるかどうかは検索 API の外からは同じ形であり、収集の名札で区別すれば足りる）。

### 決定 3: 追加コレクションのクエリは**要求にコレクション名を名乗って**、そのモデルで埋める

- 内部契約 `EmbedApiRequest` に任意項目 **`TargetCollection`**（既定 null）、proto に `target_collection = 4`（空文字＝未指定）を足す。
- ゲートウェイの `EmbeddingRouter` は **`Purpose=Query` のときだけ**、越境判定（`EmbeddingEgress.AllowedTiers`）と `Enabled` の篩を
  **通った後で**候補を `Collection == TargetCollection` に絞る（`QueryProfile` と同じ位置。**両方が指定されれば積**で効く）。
  候補が消えたら既定へ落とさず拒否（fail-closed）し、理由に読み先を書く。
- 🔴 **Index では無視する**（文書の送信先は機密区分が決める。呼び出し側がコレクションを選べてはならない）。
- **主コレクション用の要求は名乗らない**（`TargetCollection = null`。gRPC は空文字で線に載らない）。名乗るのは追加コレクション用だけ。
  既定構成（追加が空）では、名乗る要求は 1 本も出ない。
- 検索側の照合（IADR-0422 決定 3 の `QueryEmbeddingCollection.Matches`）は**コレクションごとに**そのまま効く ——
  名乗ってもゲートウェイが別のコレクションを答えたら、その系統を捨てる。
- 要求の形は REST・gRPC とも 1 つの関数（`QueryEmbeddingRequest.For`）で作る（輸送ごとに分けない）。
- ティア A は社外送信の無い側であり、クエリをそちらへ送ることは露出を増やさない（ADR-0092 決定 2）。**主のクエリの既定はティア B のまま。**

#### IADR-0422 決定 2 との関係（部分改定）

IADR-0422 決定 2 は「切替口は構成 1 つ。**契約は 1 バイトも変えない**」とし、代替案で
「切替口を RetrievalService 側に置く ——『どのエンドポイントで埋め込むか』を指示する形にすると越境判定の外側に第 2 の決定点ができる」を退けた。

- **改めるのは内部契約 `EmbedApiRequest` / proto `EmbedRequest` に任意項目を 1 つ足すことだけ**である。公開契約 `SearchRequest`（BFF → SPA）は変えない。
  IADR-0422 が退けた「要求ごとにティアを混ぜる」のは利用者の検索要求の話であり、本決定でも利用者はティアを選べない。
- 名乗るのは**エンドポイントではなくコレクション**、すなわち「検索が読むもの」という検索側の事実である。選ぶのは篩の後のゲートウェイであり、
  **決定点は越境判定の内側に 1 つのまま**（前へ移す変異は試験で赤になる）。
- IADR-0422 の A/B は「系全体を切り替えて 2 回測る」ものであり、1 回の検索で 2 つのモデルが要る ADR-0092 決定 1 は構成 1 つでは表せない
  （**1 回の検索の中でコレクションごとに違う埋め込みが要る**）。これが要求に項目を足す理由である。

### 決定 4: ABAC は全コレクションの全系統に**常に**掛ける。**問い合わせの省略は入れない**

- `BuildFilters(request)` の 1 本を、主と追加の**ベクトル・全文・属性値**のすべての問い合わせへ渡す。
- deny-by-default（`Scope is not { GrantsAccess: true }`）の早期 0 件は、**全コレクションと全埋め込みの手前**で効く。
- ADR-0092 決定 3 は「利用者のスコープが高機密を許さないとき、ティア A への問い合わせを省いてよい（費用の判断）」とする。
  🔴 **本実装は省略を入れない。** 入れる根拠（計測された費用）がまだ無く、入れれば「省略の判定を 1 つ間違えた瞬間に穴が開く」経路が増える。
  入れるときも**フィルタは外さない**（統制はフィルタが担う。試験は高機密を許さないスコープで追加コレクションが引かれ、フィルタが渡ることを固定する）。

### 決定 5: 束ねないもの（対象外）と理由

| 箇所 | 扱い | 理由 |
| --- | --- | --- |
| 二段検索の段②③（`VectorSide` / `QueryVector` / `SearchWithinDocumentsAsync`） | **主コレクションのまま** | 段は既定オフの opt-in。段③は起点と同じベクトル空間でしか採点できず、コレクションごとに段を持たせるのは ADR-0035 の設計の改定になる。段①の融合結果（`Fused`）には追加のヒットが入るので、段を有効にしても束ねた結果は消えない |
| 全文索引の readiness（`qdrant-fulltext-index` / `qdrant-cjk-ngram-index`） | **主コレクションのまま** | 索引は取り込み側が `Embedding:Collections` の全コレクションへ同じコードで張る。追加コレクションの索引欠落は検出されない —— ティア A 有効化時の確認項目として残す |
| `scripts/check-stack-ready.js` G13 | **主のまま** | 稼働クラスタ用。目的は #1215（主の読み先の食い違い）の検出 |
| `UpsertAsync` | **主のまま** | 本番の呼び出し元が 0 件 |

束ねるもの（決定 1 の帰結）: **権限内属性値は全コレクションの和集合**（束ねないと「検索には出るが候補に無い値」＝ IADR-0151 決定 1 の禁止形）、
**削除は全コレクションから**（ADR-0057 決定 1「ベクトルストアに残っていない」）。

## 影響・トレードオフ

- **後方互換**: 既定（追加が空・`embedding.enabled: false`）では、検索・属性値・削除・埋め込み要求の意味・Helm の描画が現状と同一。
  REST の埋め込み要求本文には `"targetCollection":null` が現れる（取り込みを含む）が、受け側は未指定として扱う。
- **遅延と費用**: 追加 1 本につき、1 検索あたり埋め込み 1 回（ティア A・クラスタ内）と Qdrant 問い合わせ 2 回が増える。埋め込みは主と並行に呼ぶ。
- **スコアの意味**: 追加を入れると keyword / semantic の `Score` も RRF 値になる（生スコアではなくなる）。追加が空なら従来どおり生スコア。
- **展開順序**: 新しい検索サービスが古いゲートウェイへ `TargetCollection` を送ると、古いゲートウェイは項目を無視して優先度順に選ぶ。
  その場合は検索側の照合（コレクションの食い違い）がその系統を捨てるので、壊れた順位が混ざることは無い。ゲートウェイを先に上げること。

## 代替案（不採用）

- **ゲートウェイが有効な全エンドポイントで一度に埋めて返す**: 応答の形が変わり、使わない埋め込み（有料の外部を含む）まで作る。
- **入れ子の RRF**: 追加が空でも主の `Score` が変わり、既定の不変が崩れる。
- **スコアの正規化（min-max 等）で束ねる**: モデル間でスコアの意味が違うという前提そのものに反する（ADR-0092 決定 1）。
- **検索側がエンドポイント名を指示する**: IADR-0422 の代替案が退けた形（越境判定の外側に第 2 の決定点）。
- **高機密を許さないスコープでティア A の問い合わせを省く**: 決定 4。
