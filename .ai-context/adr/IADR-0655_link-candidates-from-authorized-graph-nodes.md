# IADR-0655: リンク作成の補完候補の供給元（#2343）

> 実装リポジトリ内の意思決定記録（Implementation ADR）。1 ファイル = 1 意思決定。

- 状態: Accepted
- 日付: 2026-10-30
- 決定者: claude（#2343。親 #2107 の分割 B）。候補の範囲の水準は計画 ADR-0034 決定 8 が決めている。

## 起点・関連

- 起点 issue: #2343（#2107 の分割 B。祖 #2047 の指摘 M-10）。
- 計画:
  - `05_screens` §SC-19「リンク作成 UI」
  - ADR-0034 決定 2（見えない文書は完全に隠す。件数も出さない）
  - ADR-0034 決定 8（補完候補は作成者の ABAC スコープ内。失敗は「見つかりません」）
  - ADR-0034 決定 9（機械の主体は個人資料を扱わない）
  - ADR-0059 決定 1（起点に write、終点に read）
  - ADR-0061 決定 4（グラフの露出 OFF の個人資料はノードを撤収する）
- 前提:
  - [IADR-0242](./IADR-0242_graph-hop-abac-and-typed-edge-schema.md)（`AuthorizedNode` の型ゲート）
  - [IADR-0272](./IADR-0272_graph-write-action-authorization.md)（辺の作成の read / write）

## 文脈

計画は「補完候補を作成者の ABAC スコープ内に限る」と定めるが、**候補をどこから引くか**は定めていない。一般利用者が表題で文書を引ける口は無かった。

- `/bff/documents` の一覧は管理者・運用者だけである（SC-05）。
- `/bff/search` は本文の検索である。

## 決定

1. **候補の供給元はグラフのノードにする。** GraphService に `GET /graph/link-candidates?q=&limit=` を置き、BFF に `GET /bff/graph/link-candidates` を置く（認証のみ。ロールの門は置かない）。
   - 絞り込みは、辺の作成（`CreateGraphEdgeEndpoint`）と**同じ read のスコープ・同じ述語**（`AuthorizedNode.Authorize`）で行う。
   - 候補の集合は「終点として受け付けられる文書」と一致する。候補に出たのに作れない（ノードが無い・読めない）ことは、write を除いて起きない。
2. **個人資料は、呼び出し主体が所有者のものだけを候補にする**（`owner` の属性が主体名と一致。比較は本文の書き込みの所有者判定〔`DocumentBodyIntake.IsOwnedBy`〕と同じく大小も区別する）。
   - 共有されて読める他人の個人資料も出さない。リンク作成は「自分の個人資料から張る」操作であり、他人の個人資料の題名を補完に流す理由が無いためである。
   - 機械の主体には個人資料を一切出さない（ADR-0034 決定 9）。
   - 判定は ABAC の述語の**後**に重ねる。狭める向きにしか働かない。
3. **返すのは、文書 ID・表題・個人資料かどうかだけ**とする。
   - **件数・総数・打ち切りの印は返さない**（ADR-0034 決定 2。ADR-0100 の利用者検索が総件数を返さないのと同じ形）。
   - 表題の部分一致（大小を区別しない）。`q` は 2〜200 文字（範囲外は 400）。`limit` は既定 20・上限 50。
   - 並びは更新の新しい順。走査は 2,000 ノードで打ち切る。打ち切ったことも返さない。
4. **SC-19 は、グラフの露出が OFF の資料からはリンクを張らせない。**
   - ノードが無いので、後段が必ず 404 を返す（ADR-0061 決定 4）。
   - ボタンを押せなくし、「ナレッジグラフに表示する」をオンにすると張れることを文言で示す。自分の資料の露出の状態は自分に見えているので、存在秘匿とは関係しない。
5. 失敗の文言は、計画どおり 404 を「見つかりません。」にする。409 `edge_exists` と 400 `unknown_edge_type` は文言で区別する。

## 計画に無い口を足す根拠（コーディネータの拘束 3）

- 計画は補完候補の**範囲**を定め、供給の手段を実装に委ねている。新しい口は、その範囲を実装するためだけにある。
- 範囲は計画より広げない。辺の作成と同じスコープ・同じ述語で絞り、さらに他人の個人資料を落とす。件数は返さない。
- 計画の判断を要する論点（新しい閲覧面・件数の開示・管理者への開放）は持ち込んでいない。よって planning へは起票しない。

## 却下した案

- **`/bff/search`（索引の検索）を流用する**: 採らない。
  - 本文の検索であり、表題の補完としての精度が低い。
  - 索引に載る条件（横断検索の露出）とグラフに載る条件（グラフの露出）が違う。候補に出たのに作れない（またはその逆の）文書ができる。
- **文書台帳（DocumentService）から表題で引く口を BFF に置く**（`/bff/documents/lookup`）: 採らない。
  - 台帳の可視性（内容の ABAC の門が閉じている間は、組織文書を認証済みの全員に返す）と、グラフの read の述語が違う。候補に出たのに作れない文書ができる。
  - ノードの無い文書（露出 OFF・アーカイブ・未同期）も候補に出る。
  - 全台帳をページで辿るので、要求ごとの費用が文書数に比例する。
- **共有された他人の個人資料も候補に含める**: 採らない。拘束 2 の経路を作る必要が無い。共有の可視性の変化（取り消し）が補完の結果に現れる面を増やすだけである。

## 帰結・残余リスク

- 候補は**グラフに同期済みのノードだけ**である。作ったばかりの文書は、同期のイベントが届くまで候補に出ない。
- 走査は表題の部分一致で絞った後、2,000 ノードで打ち切る。表題が一致する読めないノードが大量にあると、読める候補が出ないことがある。件数を返さないので、存在は漏れない。
- **write ポリシーが 1 件も無い間は、辺の作成が全件 404 になる**（既知。#2107）。候補は出るが作れない。画面は「見つかりません。」を出す。配備で write ポリシーを登録するまでの状態である。
- 流量の制限は置いていない（利用者検索と同じ）。画面は 2 文字以上・300ms のデバウンスで問い合わせる。
