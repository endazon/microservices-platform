# IADR-0685: 調停は稼働側の無効化・削除を戻さない（#2431）

> 実装リポジトリ内の意思決定記録（Implementation ADR）。1 ファイル = 1 意思決定。

- 状態: Accepted
- 日付: 2026-11-06
- 決定者: コーディネーターの指示（2026-11-05）・claude（記録の形）

## 起点・関連

- 起点 issue: #2431。要求 **NFR-18**。前提: IADR-0369（宣言と実行時の境界）・IADR-0570（試験アカウント）。

## コンテキストと課題

- 運用者が稼働側でクライアントを無効にしても、次の起動の調停が宣言の `enabled: true` へ戻した。
- 運用者が seed 利用者を消しても、次の起動の調停が作り直した。宣言へ新しく足した利用者と、消された利用者を区別する手掛かりが無かった。

## 検討した選択肢

1. **`enabled` を比べない（`CLIENT_SKIP_KEYS` へ足す）**: 宣言が無効・稼働が有効（投入器の client を使った後に戻し忘れた）という危険な向きも直さなくなる。採らない。
2. **向きで分ける（採用）**: 宣言が有効・稼働が無効だけを戻さない。
3. **消された利用者を一切作らない**: 宣言へ新しく足した利用者が作られなくなる。採らない。
4. **調停が見た利用者を記録する（採用）**: 記録に在るのに無い利用者だけを、消されたものとして扱う。

## 決定

- client: 宣言 `enabled: true`・稼働 `false` は比べず、本文は稼働の無効を運ぶ。逆向きは宣言へ合わせる。
- 人の seed 利用者: 在ると確かめた利用者を realm の属性 `reconcile.seeded-users`（カンマ区切り・昇順）に記録する。realm の設定の差分と同じ PUT に載せる（2 本に分けると後の本文が前の本文を古い値で上書きする）。記録に在るのに稼働に無い利用者は作らない。
- 作り直しは `RECONCILE_RECREATE_USERS`（利用者名のカンマ区切り。英小文字・数字・`.` `_` `@` `-` だけ）で許す。起動器の `reconcile-realm.sh` がクラスタに触る前に形を検め、Job の env へ渡す。
- 戻さなかったものは `kept` の行で報告し、drift には数えない（稼働側が所有する）。
- 属性は realm の宣言へ書かない（門の属性と同じく実行時にだけ在る。宣言が `attributes` を持たないことは既存の試験が固定する）。

## 結果

- 良い影響: 運用者の無効化・削除が、起動のたびに戻されない。
- 悪い影響: 試験アカウントの回し直しは、作り直す名前を明示する手順になる（手順書を改めた）。本件より前に消された利用者は、最初の調停で一度作り直される。

## 残余

1. 消した client は従来どおり作り直す（無効化を推奨する）。
