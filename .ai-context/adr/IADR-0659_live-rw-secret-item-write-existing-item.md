# IADR-0659: live-rw の SC-22 の試験キー（#2240 / E-54b）

> 実装リポジトリ内の意思決定記録（Implementation ADR）。1 ファイル = 1 意思決定。

- 状態: Accepted
- 日付: 2026-10-30
- 決定者: claude（#2240）。項目を足さない・空に戻さない方針はオーケストレーターの裁定（2026-10-25）による。

## 起点・関連

- 起点 issue: #2240（#2034 から切り出した M-114）。前提は #2230（IADR-0658。e2e-live に Vault と BFF の書き込みの役）。
- 前提: IADR-0630（live-rw は使い捨てのスタックの中だけ・発行値の走査）、IADR-0624（秘密の値は `fill` で入れない）。

## コンテキストと課題

- SC-22 の項目は BFF のイメージへ焼き込まれ、環境ごとの重ね合わせが無い。e2e 専用の項目を宣言すると、本番の画面にも出る。
- SC-22 は書き込み専用で、BFF は空の値を受けない（400 `invalid-value`）。網羅表の後始末「値を空に戻す」はできない。計画 SC-22・ADR-0095 も空へ戻す操作を定めていない。
- 監査は BFF の構造化ログ 1 行で、画面にも API にも出ない。

## 決定

1. **既存の項目 `ast-app-secrets` の `fred-api-key` へ書く**（項目を足さない）。使い捨てのスタックには ESO が無く、Vault へ書いた値は Secret へ同期されないので、同じ実行の他の試験も、どのアプリケーションの挙動も変えない。
2. **後始末で空に戻さない**。値はスタックごと消える。live-rw は使い捨てのスタックの外では流れない（IADR-0630 の門）。網羅表の「空に戻す」は #2013 で訂正する。
3. **監査は BFF の Pod のログで確かめる**（`kubectl logs -l app=bff-service --all-containers --tail=-1`。context は `k3d-<E2E_STACK>` に固定）。
   - 返すのは「`action=secret.item.update` の行」と「書いた値がログに在るかの真偽」だけで、ログの本文は試験の外へ出さない。
   - granted の行が項目・プロパティ・版で 1 行あり、その主体が画面の「最終更新者」に出ることを見る。
4. **値を記録しない**。
   - 値は書く前に発行値として記録する（成果物の走査が探す）。
   - trace・スクリーンショット・動画は切る。
   - 入力は `fill` ではなく、ページの中で `value` の setter を呼んで `input` を起こす（`fill` は値を step の題に載せる。React の制御された入力欄は代入では変化に気づかない）。
   - 値に触れる比較は真偽で行う（`not.toContain(secret)` は失敗の文言に値を載せる）。
5. **`E2E_SECRETS_LISTED=1`**（Vault が居る）でなければ理由つきで skip する。

## 却下した案

- **e2e 専用の項目を宣言する**: 本番の一覧に載る（裁定で退けた）。
- **群（データソースの資格情報）へ書く**: 群の成員は作るたびにパスが増え、項目一覧ではなく群の宣言の側の試験になる。「既存の項目の 1 つ」の裁定にも合わない。
- **監査を画面の「最終更新者」だけで確かめる**: 最終更新者は書き込みの記録で、監査ログそのものではない。監査の記録を直接見る。

## 結果

- 良い影響: 実 Vault（-dev）への書き込みと、値が画面・応答・ログ・成果物のどこにも出ないことを CI で確かめる。
- 残余リスク:
  - ログの書式（コンソールの既定）が変わると、監査の行を拾えず赤になる（黙って緑にはならない）。
  - ESO の同期・消費側への反映は確かめない（IADR-0658 と同じ）。
- PoC 配備への影響: 無い（使い捨てのスタックの試験だけ。`sc22-secret-items.json` に差分は無い）。
