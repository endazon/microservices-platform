# IADR-0354: 本文なしの文書のメタデータ索引

- 状態: Accepted
- 日付: 2026-09-03
- 決定者: 実装（#1193）

## 起点・関連

- 関連する計画書 ID: FR-02 / FR-03 / FR-04 / FR-05 / UC-01 / UC-04 / SC-02 / ADR-0009 / ADR-0012 / ADR-0016 / ADR-0070
- 関連する実装仕様書: `.ai-context/specs/20260903_issue-1193_bodyless-document-metadata-index.md`
- 先行: `IADR-0002`（取り込みと Qdrant）／`IADR-0012`（fail-closed な検索スコープ）／
  `IADR-0014`（ペイロード表現と「テストは緑・本番は空」）／`IADR-0122`（契約の非破壊追加）／
  `IADR-0149`（`updated_at` の索引表現と null の意味）／`IADR-0283`（AI 入力の露出判定）／
  `IADR-0339`（CJK 2-gram 索引）
- 併走: #1192（PDF のテキスト層抽出と「本文なしで完了」）。**本記録は #1192 の状態名に依存しない。**

## コンテキストと課題

ADR-0070 決定 4 は「本文由来のチャンク・埋め込みは作れないが、**メタデータで FR-03 の検索に載せる**」
「**SC-02 には『本文なし（原本を参照）』を示し、結果から除外しない**」と定める。

**現状、本文が空の文書は検索結果に 1 件も出ない。** 実測（`develop` `45853885`。
`git rev-parse --is-shallow-repository` = `false`）:

- `MarkdownChunkingService.cs:13` が空本文で `[]` を返す。
- `DocumentUpdatedConsumer` はチャンクを回して点を作るので、**チャンク 0 件 → 点 0 件**。
- 検索結果は点（チャンク）単位（`QdrantVectorStore.MapPayload`）。
  **したがって現れる経路そのものが無い。**

決めることは 4 つある —— **何を索引の単位にするか**、**何を索引テキストにするか**、
**ベクトルをどう作るか**、**「本文なし」をどこまで運ぶか**。

## 検討した選択肢

### 単位 —— 案 A: 文書単位の別索引を持つ／案 B: メタデータ専用の点を 1 つ置く

**案 B を採る。** 案 A は Qdrant のコレクションか別ストアをもう 1 つ持つことになり、
**ABAC のフィルタ・スコープ解決・削除・再索引の経路が二重になる**。ADR-0070 決定 4 が
求めるのは「同じ検索に載る」ことであり、**同じコレクションの点として置けば、
`BuildAttributeConditions`（ABAC）・`DeleteByDocumentFromAllAsync`（削除）・
RRF（融合）・並び順（`updated_at`）が 1 行も変わらずそのまま効く。**

🔴 案 A は **`IADR-0012` の fail-closed を 2 か所で守る**ことになる。ABAC の判定経路を増やすのは、
本 issue が明示的に禁じた「本文が無いことを理由に権限判定を緩める」への最短経路である。

### 索引テキスト —— 案 C: `text` へメタデータを書く／案 D: `metadata_text` を新設する

**案 C を採る。** 全文検索は `text`（`multilingual`）と `text_ngram`（CJK 2-gram）の索引で成り立って
おり（`IADR-0339`）、案 D はこの 2 つを**もう 1 対**増やし、クエリ条件を `Should` で束ね直し、
readiness（`QdrantFullTextIndexHealthCheck` / `QdrantCjkNgramIndexHealthCheck`）も二重にする。
**本文なしの文書のためだけに検索経路の形を変える割に合わない。**

案 C の代償は「`text` ペイロードが必ずしも本文ではなくなる」ことである。**これは
`has_body` を同じ点に持たせ、復元時に必ず参照することで閉じる**（下記「決定 3」）。

### ベクトル —— 案 E: 零ベクトル／案 F: 索引テキストの埋め込み

**案 F を採る。** 案 E はコサイン距離のコレクションで**ノルム 0 の点**を作ることになり、
版によって拒否・NaN・0 のいずれにも転ぶ（`IADR-0014` が記録した「版で静かに変わる挙動へ
FR-03 を預けない」と同じ理由）。案 F は**本文由来ではない**ため ADR-0070 決定 4 の
「本文由来の埋め込みは作らない」に反しない。

### 「本文なし」の運び方 —— 案 G: 索引テキストをそのまま `Text` で返す／案 H: 空にして別欄で示す

**案 H を採る。** 案 G は**メタデータが本文の抜粋として画面と LLM へ出る**。
SC-02 の利用者には「本文がある」と読め、RAG では根拠のない文脈になる。

## 決定

### 決定 1 — 本文なしの文書には「メタデータ点」を 1 つだけ置く

**チャンクが 0 件になったときが「本文なし」である。** 判定は**本文（の分割結果）そのもの**で行い、
**上流の状態名（#1192 の「本文なしで完了」）に依存しない** —— 依存すると、状態名の改名や別経路
（直接投入・再正規化）で静かに漏れる。

- 点 ID は `ChunkId.DeriveMetadata(documentId)` = `Derive(documentId, -1)`。
  **`-1` は本文チャンクの索引が決して取らない値**であり、衝突しない。決定的なので再取り込みは冪等。
- **本文チャンクとメタデータ点が同時に存在することはない。** 取り込みは先に
  `DeleteByDocumentFromAllAsync` で全消しするため、本文が生えた／消えた文書は次の取り込みで入れ替わる。

### 決定 2 — 索引テキストは題名とタグから作る。パスとデータソース名は**載せられない**

`MetadataIndexText.Build(title, tags)` が唯一の生成点である。

🔴 **ADR-0070 決定 4 は「タイトル・パス・データソース・更新日時など」と書くが、
取り込みの口に届いているのは題名・タグ・更新日時・属性だけである**（実測）。
取り込み元のパス（`RawDocumentFetched.OriginalPath`）は ConversionService が
**拡張子なしファイル名 = 題名**へ畳んだ時点で終わっており、`DocumentNormalized` も
`DocumentUpdated` もパスを運ばない。**題名は原本のファイル名なので決定 4 の「タイトル」は満たす**が、
パスとデータソース名を索引に載せるには**イベント契約の変更**が要る（フォローアップ 1）。

**更新日時は既に点のペイロードに載る**（`updated_at`。`IADR-0149`）ので、メタデータ点でも同じく載せる
——並び順（`SearchSorts.Updated`）が本文なしの文書にもそのまま効く。

**ABAC 属性の値は索引テキストへ入れない。** 入れると「`confidential` で検索すると機密文書が並ぶ」
という、絞り込み（`AttributeFilters`）とは別経路の当て方が生まれる。

### 決定 3 — 点は `has_body` を持ち、検索側は復元時に必ずこれを見る

- ペイロードキーと射影は **`Knowledge.Contracts.Indexing.DocumentBodyPresence` に 1 つだけ置く**。
  キー文字列（`document_id` / `text`）は両サービスへ複写してきたが（`IADR-0014`）、
  **`text` から `SearchResultDto.Text` を導く射影は関数であり、複写すると必ず割れる**
  ——`CjkBigramPayload`（`IADR-0339` 決定 1）と同じ理由で共有契約へ置く。
- `DocumentBodyPresence.Excerpt(indexedText, hasBody)` は `hasBody` が偽なら**空文字列**を返す。
  **Qdrant 実装と `InMemoryVectorStore` の双方がこれを通す** —— 片方だけが通すと
  `IADR-0014` の「テストは緑・本番は空」（今回は逆向きに「テストは緑・本番はメタデータが漏れる」）が再発する。
- **既存の点に `has_body` を後付けしない。** 現存する点はすべて本文チャンクであり、
  **キーが無いこと＝本文あり**が正しい。`IADR-0339` が `text_ngram` で backfill を要したのは
  **無いと検索が 0 件へ落ちる**値だったからで、事情が違う。

### 決定 4 — `SearchResultDto` へ `HasBody`（既定 `true`）を末尾追加する

`IADR-0122` 決定 2 の非破壊追加。**既定は `true`** ——本項目を持たない旧発行者の応答は
「本文あり」として従来どおり抜粋が描かれる（縮退は現状維持へ倒す）。

### 決定 5 — 本文なしの結果は**検索結果に出し、RAG の文脈からは外す**

`RagContextPolicy.Select` が既に持つ「検索結果の集合 ≠ 文脈の集合」（FR-21 ⑨ / `IADR-0283`）を使う。
**根拠に使える本文が無い以上、文脈にも出典にも入れない** —— 入れると
`[n] タイトル` だけの空の根拠が LLM へ渡り、**中身を知らない文書について答える**ことになる。
除外は**静かに行わず**、件数とチャンク ID をログへ残す（既存の除外と同じ作法）。

### 決定 6 — SC-02 は抜粋の位置に「本文なし（原本を参照）」を出し、SC-03 へ導線を張る

アイコン＋テキストで示す（色だけで意味を持たせない）。**原本の所在は SC-03 が既に `sourceUri` で
持っている**ため、SC-02 は**そこへの導線**を示す —— `markdownUri`（正規化 Markdown の置き場）は
原本ではないので出さない。

### 決定 7 — 埋め込みが得られないときの扱いは本文チャンクと同一にする

一時障害は例外（ブローカの再試行へ）、恒久的な拒否（fail-closed・次元不整合）はスキップ。
**本文が無いことを理由に ADR-0016 の送信制御を緩めない。** 題名も文書の内容である。

## 理由

- **「同じ検索に載せる」を、経路を増やさずに満たす**のが骨格である。ABAC・削除・並び順・融合は
  すべて「点のペイロード」に対して書かれており、点を 1 つ置けば**規則を 1 つも書き足さずに**効く。
  規則を書き足す案（別索引・別ペイロード）は、`IADR-0012` の fail-closed を守る場所を増やす。
- **`text` に本文以外を入れる代償を、1 つのキーと 1 つの関数に閉じ込めた。** 復元が
  `DocumentBodyPresence.Excerpt` を通る限り、メタデータが本文として外へ出ることはない。
  変異試験（`Excerpt` を恒等関数へ変異させる）でこの性質を殺せることを確かめてある。
- **`has_body` の既定を「本文あり」にしたのは、既存の点が全部そうだからである。** 逆に倒すと、
  再索引が済むまで**全文書が「本文なし」と表示される**（`IADR-0149` が
  `DateTimeOffset.MinValue` で踏みかけた「知らないを別の意味へ化けさせる」と同型）。

## 結果

- **良い影響**
  - テキスト層の無い PDF が**存在として見つかる**。P-01（横断検索できない）がその文書について解消する。
  - **失敗として溜まらない**（決定 3・#1192）文書が、**検索からも消えない**。
  - 変更が点のペイロードと復元の 1 関数に閉じるため、**ABAC・並び順・融合・削除は無改修**である。
- **悪い影響 / トレードオフ**
  - **`text` ペイロードの意味が「本文」から「索引テキスト」へ広がった。** 復元を経ずに
    Qdrant を直接読む道具（運用の scroll など）は、`has_body` を見ないと本文と誤読する。
  - **メタデータ点は 1 文書 1 点であり、本文チャンクと同じ土俵で RRF の順位に混ざる。**
    題名一致は強く当たるので、本文なしの文書が上位に来ることがある。
  - **埋め込みを 1 回消費する**（題名の分）。本文が無い文書ほど安いが、0 ではない。
- **フォローアップ**
  1. **パスとデータソース名を索引へ載せる**なら `DocumentNormalized` / `DocumentUpdated` が
     原本のパスとデータソース名を運ぶ必要がある（契約変更。別 issue）。
  2. **SC-02 の並びで本文なしの文書をどう扱うか**（沈めるか・そのままか）は実データで見てから。
     計画は何も定めていないので、**今回は何もしない**（勝手に沈めない）。
