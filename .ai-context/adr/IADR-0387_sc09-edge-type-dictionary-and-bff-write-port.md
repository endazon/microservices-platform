# IADR-0387: 辺の型辞書の口の分け方と、「同じ規則」の射程

- 状態: Proposed
- 日付: 2026-09-05
- 決定者: claude（実装判断）／起点 issue #1241（#454 の子トラッカー棚卸し）

## 起点・関連

- 計画書 ID: `FR-17` / `SC-09`（管理者設定）/ `SC-10`（型ごとの使用件数）/
  `SC-03`・`SC-18`・`SC-21`（描画用カタログの消費者）/ `UC-05` / `ADR-0033`・`ADR-0034`・`ADR-0043`
- 計画 INDEX 決定 18: 「辺の型は**参照が 1 件でもあれば削除を拒否**し、**改名は許す**（既存の辺は
  新しい名前へ追随）。**同じ規則をタグ辞書にも適用**する。**`SC-10` に型ごとの使用件数を表示**する」
- 実装仕様書: `.ai-context/specs/20260905_issue-1241_sc09-edge-type-dictionary.md`
- 前提 IADR（覆さない）: `IADR-0129`（`SC-09` の未実装区画の理由）/ `IADR-0152`・`IADR-0153`（タグ辞書）/
  `IADR-0242`（ホップごと ABAC）/ `IADR-0281`（`related` フォールバック）/ `IADR-0387`（#1240。同型の機序）

## コンテキストと課題

計画 §`SC-09` は 4 区画を定める。属性体系・ポリシー定義・タグ辞書は揃っており、
**辺の型辞書だけが無かった**。後段（`GraphService`）は削除拒否も改名追随も**完成しており**、
欠けていたのは画面と BFF の書き込み口だけである。

繰り延べの機序は #1240 と**同型**である —— `IADR-0129` 決定 1 の理由 A（前提 `ADR-0033` が `Proposed`）は
**2026-08-07（#586）に失効**したのに、コードが判断先として名指しした **#504 が判断を残さずに閉じた**。

決めるべきは 5 つである。

1. 画面の読み取り口を、既存の `/bff/graph/edge-types` にするか新設するか
2. 認可の切り方
3. 後段の 409 と使用件数をどう運ぶか
4. INDEX 決定 18 の「同じ規則をタグ辞書にも適用する」の**射程**
5. hi-fi モックが描く「逆向きの表示語」の列を作るか

## 検討した選択肢

### 論点 1: 画面の読み取り口

| 案 | 内容 | 評価 |
| --- | --- | --- |
| A | 既存の `/bff/graph/edge-types` を後段 `/graph/edge-types`（辞書）へ向け替える | 🔴 **壊れる。** 実測: 同エンドポイントの消費者は `sc18-graph` / `sc03-document` / `sc21-ai-suggestions` の 3 feature で、**いずれも一般利用者の画面**である。後段は admin ＋ operator 限定なので**全員 403** になる。さらに、使用件数は ABAC で絞られていない集計値であり（`ADR-0043` / `IADR-0242`）**総量が漏れる** |
| B | `/bff/graph/edge-types` に使用件数を足す | 同じ漏洩が起きる。`EdgeTypeCatalogItemDto` が `UsageCount` を持たないのは**省略ではなく意図した除外**であると自ら書いている |
| C | **`/bff/edge-types` を新設する** | タグ辞書が `/bff/tags` であるのと同じ形。**prefix ごと分かれるので取り違えようがない** |

### 論点 2: 認可

| 案 | 内容 | 評価 |
| --- | --- | --- |
| A | 読み書きとも admin ＋ operator | issue の字面には近いが、**後段の `write` 群は `AdminOnly`** であり BFF だけ緩めても後段で 403 になる（画面だけが壊れる） |
| B | **読み = admin ＋ operator / 書き = admin** | 後段およびタグ辞書と一致する。`SC-10` が型ごとの使用件数を出すため読みは運用者にも要る |

### 論点 3: 409 と使用件数の運び方

| 案 | 内容 | 評価 |
| --- | --- | --- |
| A | `ProxyAsync<T>`（既存の GET 用ヘルパ）を使う | **本文が落ちる。** `Results.StatusCode` で status だけ返すため `usageCount` が消え、`SC-09` の「削除前に使用件数を示す」が満たせない |
| B | BFF で件数を数え直す | **数え方が 2 つになる。** 一覧と削除拒否で件数が割れると管理者は辞書を信用できない |
| C | **`RelayAsync` で本文ごと素通しにする** | タグ辞書と同じ。後段が唯一の数え手である |

### 論点 4: 「同じ規則をタグ辞書にも適用する」の射程

| 案 | 内容 | 評価 |
| --- | --- | --- |
| A | 削除拒否・改名追随だけを指す | 決定 18 の**直前に列挙された 2 つ**がそれである。タグ側は既に満たす（`IADR-0153` 決定 1・6） |
| B | `related` フォールバック（未定義値の丸め）も含める | 🔴 **計画の確定を壊す。** タグは「**辞書に無い名前は 400 で拒否する**」と確定している（`IADR-0153` 決定 5・2026-08-09 の裁定。画面からの手入力を自動登録しない） |

### 論点 5: 「逆向きの表示語」の列

| 案 | 内容 | 評価 |
| --- | --- | --- |
| A | モックどおり列を作る | **契約もドメインも持たない。** `EdgeType` にも `EdgeTypeDto` にもその欄が無く、作るなら後段の変更（マイグレーション込み）が要る |
| B | **作らない** | `ADR-0033` が逆向きの語を定めているのは「**バックリンク欄での表示**」であって辞書の管理項目ではない |

## 決定

### 決定 1: 画面の口は `/bff/edge-types` として新設し、`/bff/graph/edge-types` は据え置く（論点 1 = 案 C）

**2 つの口は用途ごと別物である。**

| 口 | 後段 | 認可 | 使用件数 | 使う画面 |
| --- | --- | --- | --- | --- |
| `/bff/graph/edge-types` | `/graph/edge-types/catalog` | 認証のみ | **持たない** | `SC-03` / `SC-18` / `SC-21`（描画・型フィルタ） |
| `/bff/edge-types`（新設） | `/graph/edge-types` | admin ＋ operator | **持つ** | `SC-09`（辞書管理） |

**issue の受け入れ基準 1 は自分の中で割れていた** —— 「読み取りも `/graph/edge-types` を叩くよう改める」と
「画面の口と、公開カタログの口を取り違えないこと」を同時に言っている。**後者を採る**：
向け替えは前者を字義どおり満たすが、**取り違えそのもの**だからである。
既存コードのコメントと OpenAPI の記述が、まさにその取り違えを警告していた。

**取り違えを落とすテストを両側に 1 本ずつ置く**（`It_calls_the_admin_listing_not_the_catalog_path` と、
既存の `It_calls_the_catalog_path_not_the_admin_listing`）。**片側だけだと、向け替えたときに
もう片方が道連れで直ってしまい、緑になる。**

### 決定 2: 読み = admin ＋ operator / 書き = admin（論点 2 = 案 B）

多層防御（`IADR-0044`）として BFF と後段の両方に置く。
**運用者で引く検査を書く** —— 読み取り群が admin ＋ operator なので、`AdminOnly` を 1 つも積まなくても
`viewer` は 403 になる（#629 で同じ穴を実測している）。**運用者で引くことがこの作業の検査である。**

### 決定 3: 409 と使用件数は `RelayAsync` で素通しにする（論点 3 = 案 C）

**後段が唯一の数え手である。** BFF は数えないし、詰め替えない。

### 決定 4: 保留を書くときは「解除を実行する主体」まで書く（`IADR-0387` 決定 3 の再確認）

本件は #1240 と**同じ機序**で取り残された —— 条件（`ADR-0033` の `Accepted` 化）も相手も書かれていたが、
**名指し先の #504 が判断を残さずに閉じ、誰の手番でもない状態**が残った。
**2 度目である以上、これは偶然ではない。** 検査器は置かない（同型の事故が 2 回起きた段階であり、
規約の側で受け止める）が、**画面仕様書とコードの両方へ主体を書く作法**を本 IADR で再確認する。

### 決定 5: 「同じ規則」は削除拒否と改名追随に限る。`related` フォールバックはタグへ持ち込まない（論点 4 = 案 A）

**辺の型**: 未定義値は `related` へ丸め、**警告として記録**する（拒否も破棄もしない。`ADR-0033` 決定 3）。
**タグ**: 辞書に無い名前は **400 で拒否**する（`IADR-0153` 決定 5）。

**この 2 つは意図的に逆である。** 辺は自動抽出の産物で、拒否すると取り込み全体が落ち、破棄すると
辺が失われる。タグは人が画面から入れるもので、黙って落とすと「保存できたのにタグが付いていない」に
なる。**「同じ規則」を広く読むと、この確定済みの非対称を壊す。**

`related` フォールバック自体は `IADR-0281`（#912）で実装済みであり、**本作業では再実装しない**。
画面は**帰結を告げるに留める** —— 管理者は「型を消すと以後の抽出が `related` に寄る」ことを
知って削除を判断する必要がある。

### 決定 6: 「逆向きの表示語」の列は作らない（論点 5 = 案 B）

`ADR-0033` が逆向きの語を置いているのは**バックリンク欄の表示**であり、**そのバックリンク欄自体、
`SC-04` 側で実現方式が未確定である**（#1240 / `IADR-0387` 決定 5 で確認済み）。
**消費者の無い管理項目を先に作ると、計画が決めたときに実装ではなく画面が先に決めたことになる。**
不在を**陰性対照として固定**し、契約が来たときに足せる形にしておく。

## 理由

- **決定 1**: 案 A / B はどちらも「一般利用者が 403」か「ABAC 未適用の集計値の漏洩」に落ちる。
  **prefix を分けるのが最も安い**（ルートも意味も衝突しない）。
- **決定 5**: 語が同じでも根拠が違うものを 1 つの規則に畳むと、**片方の確定が黙って消える**。
  #1240 で「置かないと決めた」と「まだ決まっていない」を分けたのと同じ形の誤りである。
- **決定 6**: モックは計画の**一表現**であって計画そのものではない。契約もドメインも消費者も無い列を
  画面だけが持つと、**画面が仕様の起点になってしまう**。

## 結果

- 良い影響:
  - 計画 §`SC-09` の **4 区画が揃った**。
  - 辞書の管理が実行時に閉じた（`ADR-0033` 決定 3 の「値の追加・改名は `SC-09` から行い、
    コードは触らない」が、はじめて本当になった）。
  - **口の取り違えが、両側のテストで落ちるようになった。**
- 悪い影響・トレードオフ:
  - `/bff/*` のルート群が 1 つ増えた（合成登録簿 20 → 21）。
  - 辺の型の口が 2 つある状態は、知らずに読むと重複に見える。**表を 3 箇所（BFF・フック・OpenAPI）へ
    置いて説明している**が、説明が要ること自体がコストである。
  - 「逆向きの表示語」はモックと画面が食い違ったままになる。
- フォローアップ:
  - 「逆向きの表示語」を辞書の管理項目にするかは、**バックリンク欄（`SC-04`）の実現方式が
    確定してから**判断する。確定するまで列は作らない。
  - `SC-10` の型ごとの使用件数（INDEX 決定 18 の後半）は本作業の射程外であり、別 issue が引き受ける。
