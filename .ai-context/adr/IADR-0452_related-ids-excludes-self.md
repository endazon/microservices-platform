# IADR-0452: `related_ids` に自分自身の ID を含めない

> 実装リポジトリ内の意思決定記録（Implementation ADR）。1 ファイル = 1 意思決定。

- 状態: Accepted
- 日付: 2026-09-13
- 決定者: Claude（実装）

## 起点・関連

- 関連する計画書 ID: なし（**メタ作業** ＝ 文書統制。`NFR` は無採番。planning#311 の裁定）
- 関連 issue: #1460（起票）、#1458（レビューで 1 件の自己参照が指摘された）
- 関連 IADR: IADR-0141（母集合の引き方）・IADR-0144（索引に関する検査の作法）。是正対象は IADR-0385 / 0387 / 0445 / 0446 / 0447 / 0448 / 0449 / 0450 / 0451
- 作業仕様書: `../specs/20260913_1460_related-ids-self-reference.md`

## コンテキストと課題

実装ADR の frontmatter `related_ids` は「この決定が関係する ID」を並べる欄である。**自分自身の ID を書いた記録が 9 件**あり、**そのうち 7 件は直近の連番**（`IADR-0445`〜`0451`）であった。つまり**少数派の形が直近で定着しかけていた**。

値域を決めていなかったため、書き手ごとに判断が割れる。機械検査も無く、どちらの形でも通る。

🔴 **母集合は 1 度取りこぼしている。** `related_ids` の YAML には**フロー形式 `[A, B]`（131 件）と
ブロック形式 `- A` の並び（322 件）**があり、起票時の走査はフロー形式しか読まない正規表現だった。
**多数派のブロック形式を丸ごと見ないまま「8 件」と数え**、検査を書いて全件を読ませた時点で
`IADR-0385` が 1 件出てきた。**規則 2（あり得る形をすべて列挙してから引く）の破れ**であり、
本 ADR の決定 3 が検査を要求する理由そのものでもある —— **人の走査は書き方の揺れで穴が空く。**

## 決定

### 決定 1: `related_ids` には「関係する**他の** ID」だけを並べ、自分自身の ID を含めない

理由は 2 つである。

1. **自己参照は辺として無意味である。** `gen-knowledge-graph.js` はこの欄からノード間の辺を作る。自己参照は自己ループを 1 本増やすだけで、**参照の網から読み取れることを何も足さない**。
2. **集合の意味が揺れる。** 「関係する ID」に自分を入れるかどうかが定まらないと、引く側（人・検査器）が毎回「自分を含むのか」を判断することになる。**含めない**と決めれば、`related_ids` は常に「外向きの参照」だけを意味する。

自 ID は**ファイル名と `title:` が既に持っている**（`IADR-XXXX_*.md` / `title: IADR-XXXX …`）。`related_ids` へ重ねて書く必要が無い。

### 決定 2: 既存の 9 件は frontmatter だけを直し、本文へ後付けの注記をしない

`.ai-context/adr/` は凍結記録であり、本文プロズを後から書き換えない。**ただし frontmatter の状態欄・ID リストは凍結の射程外である**（`.claude/rules/traceability.repo.md`「凍結の射程」。#717 / IADR-0191 決定 2 と同じ扱い）。よって **`related_ids` から自 ID の項目を落とすだけ**とし、他の ID の並びと順序は変えない。

### 決定 3: 機械検査を置き、baseline を持たない

**同型の混入が 9 回**起きており、「同型の事故が 2 回起きたら検査器を足す」条件を満たす。是正後の違反は 0 件なので、**ラチェット（baseline）ではなく 0 件を維持する検査**にする（IADR-0447 の索引と同じ判断。#1459）。置き場は `scripts/scripts.repo.test.js`（索引の検査の隣）であり、**新しい検査器ファイルを作らない**。**検査のパーサは YAML の 2 形式を両方読む**（片方しか読まない実装は実データでも静かに緑になる。上記の取りこぼしと同じ穴である）。

### 決定 4: 射程は実装ADR の frontmatter に限る

`.ai-context/specs/` は自分の ID を持たない（ファイル名で識別する）ため自己参照の概念が無く、`docs/` の trace ブロックは参照する側と参照される側が別文書であるため起こり得ない。**他の記録種へ広げるときは母集合を引き直す。**

## 影響

- 9 件の frontmatter が 1 行ずつ短くなる。**知識グラフの自己ループは 1 → 0 になる**——**辺は 1 本しか減らない**。
  9 件のうち 8 件（フロー形式）は**そもそもエッジになっていなかった**ためである:
  `gen-knowledge-graph.js` の `yamlListField()` もブロック形式しか読まない（実測で
  **フロー形式の欄 323・載っていない参照 3,567 件**）。**生成器の是正は #1462 へ切り出した**
  ——参照切れが大量に出る可能性があり、本 ADR の射程（値域の決定）を超える。
- 書き手は `related_ids` に自 ID を書かなくなる。忘れても検査が落とす。
- **既存の参照は壊れない** —— 自 ID 以外の項目に触れないためである。

## 代替案

- **自己参照を許容し、規約でも検査でも触れない**: 採らない。直近 7 件のうち 6 件が自己参照つきであり、**放置すると多数派と逆の形が定着する**。「どちらでもよい」は、書き手が毎回迷う状態を固定することでもある。
- **自己参照を正とし、444 件へ足す**: 採らない。情報を足さない項目を 444 件へ書き足す作業であり、辺も 444 本増える。
- **検査を置かず規約だけ書く**: 採らない。同型の混入が 8 回起きた後であり、**規約として書くだけでは守られない**ことが実証されている（`.claude/rules/traceability.md` 末尾の注記と同じ経験則）。
