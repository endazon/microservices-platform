# IADR-0321: `.gitkeep` による枠置きを規範として廃し、雛形も空枠を生成しない

- 状態: Accepted
- 日付: 2026-08-31
- 決定者: implementation-agent（計画 `ADR-0065` 決定 4 の実装側への写像として）

## 文脈

計画 `ADR-0065` 決定 4（Accepted・2026-08-30）は **「実体が無いものは空フォルダ＋`.gitkeep` を置く」
規範を撤回した**（planning#180 裁定の部分改定）。撤回の理由は **`.gitkeep` が「適合の見え方」を
作った**ことである —— 枠だけの状態が機械にも目視にも「構成要素が揃っている」と見え、
2026-08-22 の適合判定が**「標準の枠を認識した」ことの確認を「標準を満たした」と読み替えた。**

**撤回された形が、実装リポジトリに 2 通りで残っていた。**

1. **`knowledge/frontend` の feature 内部に 30 件**（13 feature の `api/` `hooks/` `stores/` `types/`）。
   `IADR-0309` 決定 3 が名指しで記録したうえで、並列作業との衝突を理由に繰り延べたものである。
2. 🔴 **`src/plopfile.js` が `stores/.gitkeep` を生成し続けていた**（`IADR-0309` 決定 4）。
   **撤回された形を、雛形が再生産していた。**

母集合を引き直した実測（2026-08-31・基点 `develop` `dfec09f1`。`--is-shallow-repository` = false）:
追跡下の `.gitkeep` は **70 件**。名前を変えた同型（`.keep` / `.placeholder`）は 0 件。
**0 バイトファイルで引くと `src/plop-templates/feature/gitkeep.hbs` が出た** —— ファイル名で引く軸
だけでは落ちる位置に、再発防止の本体があった。

## 決定

### 決定 1 — feature 内部の空枠 30 件を撤去する。区分の不在それ自体を情報とする

`IADR-0309` 決定 2 と同じ形を 13 feature へ広げる。**区分が無いことが「この画面はその関心を持たない」
を伝える**（`ADR-0065` 決定 4 が単一プロジェクト構成について書いた「フォルダが無ければそのサービスに
その関心が無い」と同じ）。feature ごとの根拠は作業仕様書 §3 と PR 本文が持つ（ここへ複写しない）。

共通する 2 つの根拠だけを記す。

- **`stores/`（13 件）**: クライアント状態の単一情報源は URL である（`IADR-0124` 決定 3）。
  Zustand は #788 で導入済みだが、**feature の `stores/` に実体を持つものは 1 件も無い**
  （唯一の利用は `platform/frontend/src/components/ai-chat/aiChatStore.ts`。共通シェルであり feature ではない）。
  **「ライブラリが無いから空」ではなく「持たないのが既定」である。**
- **`hooks/`（13 件）**: 13 画面のクライアント状態はいずれも **1 コンポーネントに閉じている**。
  抽出しても呼び出し元が 1 つしかない間接層が増えるだけで、`hooks/` が意味するもの
  （複数コンポーネントが共有する feature 固有の状態）にならない。

**実体のあるコードは 1 行も移していない。** 切り出す価値のあるフォーム状態（`sc09` / `sc12` / `sc17`）は
#1123 へ分けた ——「消した」と「直した」を同じ diff に混ぜない（#1100 の制約）。

### 決定 2 — plop の feature 生成器は `stores/` を作らない。空枠も実体も生成しない

`src/plopfile.js` の生成物一覧から `add('stores/.gitkeep', …)` を外し、
`src/plop-templates/feature/gitkeep.hbs`（0 バイト）を削除する。
`templates/unit-template/frontend/src/features/sample/stores/.gitkeep` も撤去し、**2 つの雛形が生む形を
一致させる**（`IADR-0309` 決定 4 が残した最後の食い違い）。

**採らなかった案と理由。**

| 案 | なぜ採らないか |
| --- | --- |
| **実体のストアを生成する** | `stores/` を持つのが既定であるかのように読める。実測で feature の `stores/` 実体は 0 件であり、既定は URL である。**逆向きの誤りを新しく作る** |
| **対話プロンプトで選ばせる** | `plopfile.js` に既に理由が書かれている —— 条件付きプロンプトを足すと `plop feature <値> …` の非対話実行が「You can not bypass conditional prompts」で止まる。**CI・スクリプトから叩けない生成器は使われなくなる** |

かわりに**生成後の案内文**へ、`stores/` を作る判断基準（複数ルート・複数コンポーネントを跨いで
生き残るクライアント状態が要ると分かった時点で作る）を出す。

### 決定 3 — `IADR-0218` / `IADR-0219` を `Superseded` とする。ID は付け替えない

計画 `ADR-0065` §結果 フォローアップ 5（「`IADR-0218` の改定または後継」）への応答である。

- **`IADR-0218`**（`.gitkeep` を 4 要素 × 11 サービスへ適用する）と、それを部分改定した
  **`IADR-0219`**（8 要素・55 件）は、**依拠していた計画条文を `ADR-0065` 決定 4・5・6 が
  すべて改めたため、適用対象そのものが消えた。**
- **実体は既に無い** —— `IADR-0282` 決定 3 が枠を全廃し、`ADR-0065` は 2026-08-30 実測で
  「`.gitkeep` のみの層ディレクトリは 0 件」としている。**残っていたのは状態欄だけが `Accepted` の
  ままという記録の食い違いである。**
- **書式は `.claude/rules/traceability.repo.md` §Superseded に従う** —— 旧 ID を残し後継を併記し、
  注記そのものへ起票 ID（#1100）を書き、`updated:` を前進させた。**ID を後継へ付け替えていない。**
  frontmatter の状態欄は凍結の対象外である（#717 / `IADR-0191` 決定 2）。

### 決定 4 — 機械検査は追加しない

`CLAUDE.md`「検査器・規約の追加は『同型の事故が 2 回起きたら』」に従う。

**#1078（lingui の `files` 列挙）・#1066（feature 分割の作り忘れ）・#1100（撤回された枠の残置）は
「伸ばし忘れ」という抽象では同型だが、機械検査の対象としては同型ではない** ——
検査すべき不変条件がそれぞれ違う（i18n カタログの網羅／feature 区分の実体／撤回済み規範の残置）。
**本件の再発経路は「雛形が空枠を生むこと」であり、決定 2 がその生成そのものを止めた。**

`IADR-0218` 決定 4（機械検査は置かない）の結論は、対象を変えてここへ引き継ぐ。

## 影響

- **バンドルは 1 バイトも動かない**（削除したのは 0 バイトのファイルだけで、import グラフに触れていない）。
  `scripts/chunk-budget-baseline.json` の更新は不要である。
- `templates/unit-template/README.md` の注記が引いていた根拠 —— 「計画
  `12_backend-application-stack` §規範性・粒度・置き場 がバックエンドについて同じ作法を定めており、
  フロントにも同じ理由が当てはまる」 —— は **`ADR-0065` 決定 4 で撤回済みであり、既に偽であった。**
  書き換えた。
- `src/plopfile.js` の案内文が指示していた「`eslint.config.js` の lingui 適用範囲（`files`）へ
  本 feature のパスを足す」は、**#1105 が許可リストを撤去して両ユニット全体を検査範囲にしたため
  既に偽であった。** 触る以上、偽の指示を残さない。
- **ユニット直下（`src/` 最上位）の枠 24 件は本 IADR の射程外である**（#1122 へ分けた）。
  `app/` と `locales/` は「可変ユニットでは通常空（アプリホストの platform 側が持つ）」という
  **意図的な不在**であり、feature 内部と同じ理屈でそのまま消してよいとは限らない。
- **`docs/<種別>/.gitkeep`（14 件）と `.ai-context/specs/.gitkeep` は残す。** あれは
  `docs/README.md` が定める種別の**出力先**であって「標準構成要素の枠」ではない。
  `ADR-0065` 決定 4 が撤回したのは「構成要素が揃って見える」枠である。

  > 🔴 **［2026-08-31 追記 / #1122］上の 1 行は粗すぎた。15 件のうち 11 件は撤去した。**
  >
  > 本 IADR は `.gitkeep` の**有無**しか見ておらず、**「その `.gitkeep` が何かを keep しているか」を
  > 測っていなかった。** #1122 でディレクトリごとの実体件数を数えたところ、
  > **11 件は追跡下のファイルが既にあるディレクトリに置かれていた**
  > （`.ai-context/specs` は **549 件**、`docs/tests` は 53 件、`docs/screens` は 21 件…）。
  > **ディレクトリは実体で存在しており、`.gitkeep` は何も keep していない死んだ残骸である。**
  > → **11 件を撤去した。**
  >
  > **残したのは実体が 0 件の 4 件だけ**である（`docs/batch` / `docs/errors` / `docs/infra` /
  > `docs/integration`）。上の理由（種別の出力先であり、消すとフォルダごと消える）が当たるのは
  > **この 4 件に限られる。**
  >
  > **教訓**: 「`.gitkeep` があるか」と「`.gitkeep` が要るか」は別の測定である。
  > 詳細は [IADR-0322](./IADR-0322_unit-level-scaffolding-frames-await-arbitration.md)。

## 残余リスク

- 🔴 **計画側の明文はまだ無い。** `ADR-0065` 決定 4 はバックエンド 8 要素標準の部分改定であり、
  **フロントエンドの feature 6 分割へ及ぼす明文は計画に存在しない。** 一方
  `13_frontend-stack` §ディレクトリ構成 は 6 分割を必須とし、planning#445 は
  「必須とするのはツリー全体への適合である」と裁定している。**文面上は衝突している。**
  `IADR-0309` 決定 3 が求めた裁定を **planning#510 として起票した**（同 決定 3 は環流すると書いたまま
  起票されていなかった）。**計画が「6 つとも置け（空でも）」と裁定すれば本 IADR 決定 1 は覆る。**
- **生成器を通さず手で作る経路が残る**（`IADR-0309` 残余リスクと同じ）。決定 4 により機械は止めない。
  **2 回目が起きたら検査を足す。**
