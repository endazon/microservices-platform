# IADR-0422: 測る道具を先に置き、測れるように経路を開ける

## 状況

計画 `ADR-0016` / `ADR-0017` は、埋め込みモデルの確定を **「PoC（検索精度 nDCG@10・スループット）」** に
委ねている。#336 はその実測を稼働環境依存として分離した（[IADR-0085](./IADR-0085_selfhosted-embedding-optin-deploy.md) 決定 5）が、
**分離した先で 3 度の棚卸し（2026-08-16 / 09-03 / 09-05）を跨いだ。**

棚卸しは毎回、**同じ 2 項目が環境非依存で着手できる**と書いている。

| # | 障害 | 実測（`develop` `7c9d184`） |
| --- | --- | --- |
| 1 | **測る道具が無い** | `ndcg` の全ヒットは散文。実行コードは 0。`perf/k6/` はレイテンシとスループットだけを測り、**返却結果の順位も ID も見ていない** |
| 2 | **クエリの埋め込みが常にティア B へ固定される** | `EmbeddingRouter` が `Purpose=Query` を `SensitivityClass.Public` へ倒す。Ruri は `Enabled: false` / 768 次元 / 別コレクション |

**②は `ADR-0016`「クエリは検索対象コレクションと整合させる」の実装であって、壊してはならない。**
壊れているのは「切り替える手段が 1 つも無い」ことだけである。

### 着手して初めて測れた 3 つ目の事実

索引側と検索側で、**コレクションの決め方が違う。**

| 側 | コレクションを誰が決めるか |
| --- | --- |
| 取り込み（Ingestion） | **ゲートウェイの応答**（`EmbedApiResponse.Collection`）。`DocumentUpdatedConsumer` がその名前へ upsert する |
| 検索（Retrieval） | **自分の構成**（`Qdrant:CollectionName`）。応答の `Collection` を読んでいなかった |

この非対称が #1215 の事故そのものである（点は `knowledge_chunks_deterministic_v1` に在るのに検索側は
`knowledge_chunks_voyage_3_5` を読み、**両サービスとも Ready のまま全件 0 件**になった）。
`check-stack-ready.js` の G13 が外から捕まえるが、**プロセスの中には照合が 1 つも無い。**

## 決定

### 決定 1: ハーネスは**収集と集計を分ける**（`scripts/measure-search-ndcg.js`）

`measure-abac-combinations.js` と同じ型に乗せる —— 読み取り専用・乱数/時刻非依存・Node 標準のみ・
集計は純関数・`--json` / `--dump` / `--input`。

**稼働環境が無い今、収集部は実走できない。** だから `--dump` した順位を `--input` で集計し直せる形にし、
**集計だけを TDD で書き切って CI で緑にする**（`scripts.repo.test.js`）。
これは「環境が来るまで何も置かない」と「環境が無いのに実測したと言う」の間の唯一の正直な位置である。

指標の定義は 1 つに決める。**利得は線形（gain = 関連度）、割引は log2(順位+1)**（Järvelin & Kekäläinen の原形）。
指数利得（2^rel − 1）は採らない —— どちらも「graded relevance ＋ log2 割引」だが値が違い、
**混ぜて比較すると意味を失う**。

採点の作法を 3 つ固定する（いずれも試験が守る）。

1. 🔴 **同一文書の重複（チャンク由来）は先頭だけを採る。** 検索が返すのはチャンクで qrels は文書単位なので、
   落とさないと同じ文書で二度加点され **nDCG が 1.0 を超え得る**（正規化が壊れる）。
2. 🔴 **正解ラベルが 1 件も無いクエリは平均から除外し、件数と ID を報告する。** 0.0 として混ぜると
   **「ラベルを付けていない」が「精度が低い」に化ける**。
3. 🔴 **qrels の指紋が違う結果は比較させない。** 別のラベルで採った数字を並べると、
   **モデルの差に見えるものが実はラベルの差**になる。

### 決定 2: 切替口は**構成 1 つ**（`Embedding:Routing:QueryProfile`）。契約は 1 バイトも変えない

`SearchRequest` に項目を足す案は採らない。

- `SearchRequest` は **BFF の公開契約**であり、openapi → orval 生成物 → SPA まで波及する
- **要求ごとにティアを混ぜられる形**になり、統制の説明が要求のたびに要る
- A/B 測定は**運用者が系全体を切り替えて 2 回測る**もので、要求ごとに混ぜる必要が無い

置き場は**ルーティングを所有する LlmGateway** である。`Purpose=Query` のときだけ、候補を
その名前のエンドポイント 1 つに絞る。

🔴 **絞り込みは越境判定の「後」に効く。** 候補は `EmbeddingEgress.AllowedTiers` と `Enabled` の篩を
既に通っているので、プロファイルは候補を**狭めることしかできない**。

🔴 **取り込み（Index）には効かない。** 文書側の送信先は機密区分が決めるものであり、
測定用の切替口で動かしてよいものではない。

**この 2 つは別の守りである**（変異試験で切り分けた）。`Query` は `SensitivityClass.Public`
（許容ティア A・B）へ倒れるので、**適用点を篩の前後どちらへ置いてもティアの集合は変わらない** ——
順序が実際に守っているのは **`Enabled` の篩**（無効なエンドポイントを名指しで選べてしまう形）である。
**ティアの越境を守っているのは「`Index` に効かない」という設計のほう**である。

🔴 **不在・無効なエンドポイント名は起動時に落とす**（`ValidateOnStart`）。黙って既定へ落ちると
**Ruri を測ったつもりで voyage を測る**という最悪の測定事故になる。ルーター側も、候補が消えたときは
既定へ落ちずに fail-closed で拒否する。

### 決定 3: Retrieval は**答えたコレクション**と**読むコレクション**を照合し、食い違えば降りる

決定 2 は「クエリの埋め込みモデル」を動かす。**検索対象コレクションは別の構成が決めている。**
2 つが食い違ったまま測ると、次元の等しい 2 つのコレクション（voyage 1024 / deterministic 1024）では
**別モデルの空間へ問い合わせて順位が返る** —— 0 件にすらならず、**壊れた測定が数字として成立する。**

そこで `IEmbeddingService` の 2 実装が、応答の `Collection` を自分の `Qdrant:CollectionName` と
突き合わせ、食い違えば**空ベクトルへ降りる**（＝`Embedded=false` と同じ既存の縮退。全文検索の系統は生きる）。

- **判定は 1 つ**（`QueryEmbeddingCollection.Matches`）。REST と gRPC の**両方が同じ関数を呼ぶ** ——
  `EmbedUseCase` が越境判定について採ったのと同じ姿勢である（輸送ごとに分けない）
- 応答の `Collection` が**空のときは照合しない**（情報が無い。拒否時の応答は既に `Embedded=false` で降りている）
- 照合先の値は**ベクトルストアと同じ関数**（`QdrantVectorStore.ResolveCollectionName`）から引き、
  合成点（`Program.cs`）が渡す。別の規則で読み直すと、照合しているつもりで別のものを比べることになる

**既定構成では一致する**（`voyage-managed` → `knowledge_chunks_voyage_3_5` ＝ Retrieval の既定。
Helm の決定的ローカル経路も両方を同時に書き換える）。**変わるのは、既に壊れている構成の見え方だけである。**

### 決定 4: 計画の裁定は要らない。ただし残る問いは記録する

`ADR-0016` は (a) モデル別コレクション分離、(b) クエリは検索対象と整合、(c) 高機密文書はティア A 固定を決めた。
本決定は **(a)(b)(c) をいずれも動かさない** —— (b) の「整合」を構成で選べるようにし、**かつ機械で照合する**だけである。
そのうえで `ADR-0016` 自身が nDCG@10 の PoC をフォローアップに挙げており、**測る手段の用意は同 ADR の宿題**である。

**残る問い（本 ADR では決めない。#336 の報告に添える）**:

> 高機密（ティア A / 768 次元 / `knowledge_chunks_ruri_v3`）の文書は、既定構成では**索引されるが検索されない**
> （検索側は単一コレクションしか読まない）。`ADR-0016` はコレクション分離を決めたが、**分離した複数の
> コレクションを 1 回の検索でどう束ねるか**を決めていない。実装側のコメントは 2026-07 から
> 「高機密コレクションの横断検索は FR-03 の後続課題」と書いたままである。

## 影響・トレードオフ

- **後方互換**: `QueryProfile` 未設定（既定）では、ルーティングの決定・応答・deploy の描画がすべて現状不変。
  照合も既定構成では常に一致する。
- **契約不変**: DTO・proto・openapi・orval 生成物のいずれも変えていない。応答の `Collection` は
  **元から在る項目**であり、**読むようになった**だけである。
- **新しい失敗モード**: 構成を片方だけ動かすと、意味検索の系統が落ちて全文検索だけの結果になる。
  これは**沈黙ではない**（起動時 fail-fast ＋ 実行時の error ログ）。壊れた数字を出すより良い、という判断である。
- **測れないものは測れないまま**: 実測（TEI 実配備・実モデル load・正解ラベル付け・Voyage のゼロ保持契約認定）は
  依然として稼働環境と組織の手にある。#336 は OPEN のままである。

## 代替案（不採用）

- **`SearchRequest` に埋め込みプロファイルを足す（案 a）**: 公開契約が波及し、要求ごとにティアを混ぜる形になる。
  A/B は系全体の切り替えで足りる（決定 2）。
- **切替口を RetrievalService 側に置く**: ルーティングの所有者は LlmGateway である。Retrieval が
  「どのエンドポイントで埋め込むか」を指示する形にすると、**越境判定の外側に第 2 の決定点**ができる。
- **照合を置かない（決定 3 を採らない）**: 切替口だけを開けると、**壊れた測定が数字として成立する**経路を
  新設したことになる。#1215 が「静かに 0 件」で済んだのは次元が違ったからにすぎない。
- **照合の不一致を例外にする**: ゲートウェイの故障ではなく**構成の食い違い**であり、既存の縮退
  （`Embedded=false` → 空ベクトル）と同じ意味に倒すのが一貫している（[IADR-0256](./IADR-0256_embedding-degradation-vs-backend-failure.md) は
  「輸送の失敗を握り潰すな」であって「構成の縮退を例外にせよ」ではない）。
