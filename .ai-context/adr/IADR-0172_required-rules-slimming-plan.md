# IADR-0172: 必読規約の減量計画（#684 / #623 基準 5）

- 状態: Accepted
- 日付: 2026-08-11
- 決定者: claude（起案・実装）

## 起点・関連

- **NFR**（運用保守）。実装 issue: **#684**（**#623 の子**。基準 5 のみ）
- 作業仕様書: [20260811_issue-684](../specs/20260811_issue-684_required-rules-slimming-plan.md)
- 計画リポの正本: `planning/docs/ai-implementation-workflow-guide.md`

> **★ 値の基準時点は develop `36bc4ea`（2026-08-11 実測）である。**

## 文脈

毎セッション必読の規約は **69,614B（68 KiB）** で、**50KB 目安の 1.39 倍**である。

| ファイル | バイト | 適用 |
| --- | ---: | --- |
| `.claude/rules/traceability.md` | **46,090** | `paths: - "**/*"` → **常時適用** |
| `CLAUDE.md` | 23,524 | 毎セッション自動読み込み |

**`traceability.md` が `.claude/` 全体（97,976B）の 47% を占める。** ここが主戦場である。

## ★ 決定 1: 「毎セッション必読」は**狭義**（自動で読み込まれる分）とする

**集合の取り方で 2 倍違うため、先に定義を固定する。**

| 定義 | 内訳 | 現在 |
| --- | --- | ---: |
| **狭義（採用）** | `CLAUDE.md` ＋ `.claude/rules/traceability.md` | **69,614B** |
| 中間 | ＋ `AGENTS.md`（他 AI 向け） | 74,157B |
| 広義 | ＋ `docs/README.md` / `DEFINITION_OF_DONE.md` / `ai-workflow.md` / `src/README.md` / `AI_SETUP.md` / `README.md` | 132,685B |

**根拠は #623 基準 5 の文面そのものである** ——
「**毎セッション必読部**を 50KB 目安まで削る計画を立てる（`.claude/rules/traceability.md` の
**「参照時にだけ読む別紙」化**を含む）」。
**「参照時にだけ読む」を対置している以上、「毎セッション必読部」＝自動で読み込まれる分**と読むほかない。

> **★ 定義を決めないと受け入れ基準が二値にならない。**
> 「50KB を達成した」を機械的に判定できる状態にすることが、この決定の目的である。

## ★★ 決定 2: **`.claude/rules/traceability.md` のパスは変えない**

**改名・移動・分割による置き換えを行わない。** **やらない方がよいのではなく、規約上やれない。**

**実測**: 同ファイルを参照するのは **114 ファイル**、うち Markdown リンク形は **32 件**。

| 区分 | 参照 114 | リンク 32 | 書き換え |
| --- | ---: | ---: | --- |
| `docs/specs/` | 62 | 22 | **不可**（確定済みの記録） |
| `docs/adr/` の **IADR 本体** | 18 | 6 | **不可**（Accepted 後は書き換えない） |
| **`docs/adr/README.md`（索引）** | 1 | 1 | **可**（都度更新する。後述） |
| live（`CLAUDE.md` / `scripts/` / `.claude/` / `.github/` 等） | 33 | 3 | 可 |

**書き換えられないリンクは 22 ＋ 6 ＝ 28 件**である。

> **★ 「`docs/adr/` だから不可」ではない。** **索引（`README.md`）と決定の本体（`IADR-xxxx`）は性質が違う。**
> 索引は**都度更新するのが正しい**（本 ADR の追加でも更新している）。
> **区分を粗く取ると、後段で「`docs/adr/` は触らない」と読んで索引更新まで避けてしまう。**

`.claude/rules/traceability.md` 自身と [IADR-0166](./IADR-0166_status-vocabulary-and-record-rewrite-boundary.md) が**確定済みの記録の書き換えを禁じている**ため、
**パスを変えるとリンクを追随させる手段が規約上存在しない。**
`check-doc-links.js`（548 件を検査）は**確定済み記録 28 件で赤くなり、直せない。**

**したがって減量は次の形でしか実現できない:**

> **当該ファイルを「入口」として残し、中身を別紙へ出して入口から指す。**

**この形なら 114 件の参照はすべて生き残る。**

## ★ 決定 3: 段階的に進める（**各段が子 issue の単位**）

**大きい順ではなく、「機械が代替している度合いが高い順」に出す。**
**説明を消しても統制が残る節から動かす**のが、事故の起きにくい順序である。

| 段 | 出すもの | バイト | 理由 |
| ---: | --- | ---: | --- |
| **1** | **コミットメッセージの機械チェック**（採番衝突の手順を除く） | 約 11,000 | **ほぼ全部が機械の説明**（決定 4 の表）。効果最大・危険最小 |
| **2** | CHANGELOG 生成時の誤記補正・除外規定 | 2,179 | 生成物の話。**編集時に読む必要がない** |
| **3** | 複数プロジェクトを跨ぐ場合の ID 修飾 | 9,117 | `check-plan-id-qualification.js` が型 A を強制。**ただし型 B は非検出**なので導線が要る |
| **4** | 残す箇所と書式（の詳細部） | 6,768 の一部 | **`paths` で絞れる**（決定 5）。**節ごと消さない** |

**残すもの（入口に置き続ける）**: 起点 ID の種別（9,716）／ 是正・追随の母集合の取り方（4,039）／
守ること（437）／ **採番衝突時の改番手順**（決定 4）。

> **★ 各段は `docs/adr/README.md`（索引）を必ず更新する。**
> 決定 2 の表のとおり**索引は可変**であり、「`docs/adr/` は確定済みだから触らない」は**索引には当たらない。**
> **確定済みなのは `IADR-xxxx` の本体だけである。**

**段 1 だけで 46,090 → 約 35,000B**、必読合計は **69,614 → 約 58,600B** の見込みである。
**段 2・3 まで進めて約 47,300B** となり **50KB 目安を下回る**見込み。

> **★ 「見込み」であって実測ではない。** 移動時に入口へ残す導線の分だけ増える。
> **到達の確認は最終段の子 issue が実測で行う**（本 ADR では確認できない）。

## ★★ 決定 4: **機械が強制していない規範は動かさない。動かすなら導線を残す**

**削る前に、節の規範が機械側にあるかを 1 つずつ突合した。**

| 規範 | 機械 | |
| --- | --- | --- |
| 許可する種別 / 起点 ID の書式 / 末尾 PR 番号 | `check-commit-messages.js` | 機械が強制 |
| FR / UC / SC の実在性（#579）、ADR / IADR の実在性 | 同上 | 機械が強制 |
| 検査対象から除外する自動コミット | 同上 | 機械が強制 |
| PR タイトル（スカッシュ後件名）の検査 | `pr-title.yml` | 機械が強制 |
| クロスリポジトリの issue / PR 番号の修飾 | `check-cross-repo-refs.js`（型 A のみ） | 機械が強制 |
| **採番衝突時の改番手順（4 項目の追随）** | **無し** | **★ 人の手順** |

**`check-adr-numbering.js` は欠番・重複は見るが、「改番時に何を追随させるか」は見ない**（実測）。

**よって「採番衝突時の改番手順」は入口に残す。**
段 3 の「ID 修飾」も**型 B（AST 文脈で裸の ID）が意図的に非検出**であるため、
**別紙へ出す場合は入口へ「いつ読むか」の 1 行を必ず残す。**

> **★ 導線なしの別紙化は、統制そのものを消す。**
> 「機械が止めるから読まなくてよい」は、**機械が止める範囲でしか成り立たない。**

## 決定 5: **`paths` の絞り込みは補助手段にとどめる**

`paths` による絞り込みは実在する（計画リポの `.claude/rules/adr.md` が
`paths: - "**/07_adr/**/*.md"` を使う。実測）。**しかし万能ではない。**

**`paths` は「どのファイルを編集するか」でしか条件を書けない。**
**「コミットするとき」「ID を採番するとき」はファイルパスで表現できない。**

| 節 | `paths` で絞れるか |
| --- | --- |
| 残す箇所と書式（コード内コメント） | **絞れる** |
| **コミットメッセージの機械チェック（最大節 29%）** | **絞れない** |
| 起点 ID の種別 / ID 修飾 | 絞れない（あらゆる編集で要る） |

**最大節に `paths` は効かない。** よって主手段は別紙化であり、`paths` は段 4 の補助にとどめる。

## ★ 限界（明示する）

- **別紙化しても総量は減らない。減るのは「毎セッション読む量」だけである。**
  **本 ADR および後続の PR で「総量削減」と書かない。** 事実と違う。
- **50KB 目安への到達は本 ADR では検証していない。** 1 行も移動していないため。
  **決定 3 の見込み値は計算であって実測ではない。**
- **狭義（決定 1）を前提にした計画である。** 広義を採るなら **83KB 削ることになり、計画ごと作り直し**になる。
- **#622 の仕様書が書く「約 131KB」の内訳は復元できなかった。**
  広義の集合で当時 120 KiB まで再現したが**一致していない**。**再現したとは書かない。**

## 結果

- **入口（`.claude/rules/traceability.md`）のパスを変えないことを確定**（決定 2）
- 段階的な減量計画を 4 段で確定し、**各段を子 issue の単位**とする（決定 3）
- **機械が強制していない規範（採番衝突時の改番手順）を特定**し、**入口へ残すことを確定**（決定 4）
- 回帰テスト: **決定 2・4 と「総量は減らない」の明記**が本 ADR から落ちないことを固定する

## 検出しないこと（明示する）

- **実際の移動が正しく行われたか** —— 本 ADR は計画のみ。**段ごとの子 issue が持つ**
- **`CLAUDE.md` 自身の減量** —— 23,524B。`traceability.md` の方が効果が大きいため後段
- **`CLAUDE.md` の「`.github/workflows/` は編集不可」の誤記** —— [IADR-0169](./IADR-0169_cross-repo-ref-scan-beyond-markdown.md) が実測で FALSE と記録済み。
  **減量とは別の論理変更**であり、別 issue で扱う
