# IADR-0480: 所有者の読み取りのポリシーを dev seed に必須として入れ、本番の配備の手順に投入を書く（#1664）

> 実装リポジトリ内の意思決定記録（Implementation ADR）。1 ファイル = 1 意思決定。

- 状態: Accepted
- 日付: 2026-09-27
- 決定者: claude（#1664。計画 ADR-0121 決定 1・4 の 1 番目の実装側の形）

## 起点・関連

- 関連する計画書 ID: FR-05 / FR-19 / NFR-09 / UC-05 / UC-11 / SC-09
- 関連する計画 ADR: **ADR-0121**（決定 1: 所有者の read はポリシー 1 本・dev seed と本番の両方で必須・本番は配備の手順で投入。
  決定 4: 配備の順序の 1 番目。フォローアップ 6: dev seed で所有者が自分の個人資料を BFF で開けるかを確かめる）、
  ADR-0036 D-01・D-02・D-05・D-08、ADR-0098 決定 1（共有先の分岐をポリシー 1 本で表した前例）、ADR-0062 実測 9（MSP#1242 の契機）
- 関連する実装 ADR: [[IADR-0133]]（dev seed）、[[IADR-0253]]（1 ポリシー = 1 分岐・束縛は評価器の中だけ）、[[IADR-0447]]（共有先の分岐の前例）、
  [[IADR-0384]]（区分のフィルタの不在を「無制限」と読まない）、[[IADR-0450]]（共有先の写しは所有者にだけ返す）、[[IADR-0476]]（DocumentService の判定）

## コンテキストと課題

評価器（`AbacEvaluator.ResolveScope`）はポリシー 1 件ごとに分岐を 1 本作り、組み込みの「所有者は読める」分岐を持たない。
dev seed には所有者の write しか無かったので、dev では所有者が共有していない自分の個人資料を BFF で開くと 404 になっていた
（ADR-0121 実測 4 は推論とされていた。本件の試験で、seed の応答を入れた BFF が 200 を返すことを確かめた）。

決める必要があったのは次の 4 点である。

1. seed に入れるポリシーの形
2. 「seed を入れた構成」を試験でどう作るか（計画のフォローアップ 6・issue のやること 3・4）
3. 本番の投入の手順（SC-09 の画面からは作れない。ADR-0121 実測 7）
4. 利用者の条件が空のポリシーを全利用者へ足すことの副作用（許可が広がる向き）

## 検討した選択肢

| 論点 | 採用 | 退けた選択肢と理由 |
| --- | --- | --- |
| 1 | **`read`・`userConditions: {}`・`documentConditions: {owner: ["${current_user}"]}` の 1 本**（名前 `dev: 所有者は自分の文書を読める`） | `userConditions` を省く —— 階段の回帰試験が read ポリシーの `userConditions.clearance` を無条件に読む（共有先の分岐と同じ理由で `{}` と明示）。評価器に組み込む —— ADR-0121 論点 1 で退けられた |
| 2 | **seed の実ファイルを読み込んだ認可サービスの `/authz/scope` の応答を期待値のファイル（`AuthorizationService/Tests/Fixtures/owner-read-seed-scopes.json`）と突き合わせ、BFF・MCP・検索・DocumentService の試験は同じファイルを入力にする** | 各試験で分岐を手で組む —— seed が変わっても消費側の試験は緑のまま残る（既存の手組みの試験はすでにそうなっている）。消費側の試験プロジェクトから認可サービスを参照して評価器を直接呼ぶ —— BFF・MCP の試験プロジェクトへ別サービスのホストを持ち込むことになり、knowledge 側はユニット外参照の例外（統合試験）に頼ることになる。期待値を各試験へ書き写す —— 同上 |
| 3 | **ポリシーの API（`POST /authz/policies`・SC-09 と同じ口）へシステム管理者が直接投入する手順を運用仕様書に書く。投入済みは名前ではなく形で確かめる** | 本番の seed スクリプトを作る —— ADR-0121 決定 1 は投入者をシステム管理者とし、計画は本番へポリシーを入れる仕組み（helm・マイグレーション）を持たない（実測 6）。名前で確かめる —— 名前は管理者が変えられる |
| 4 | **コードでの防御は足さない。予約値（`system`・`anonymous`）と同名の利用者を IdP に作らないことを手順書に書き、dev realm に居ないことを回帰試験で固定する** | 評価器で予約値への束縛を拒む —— 起こり得るのは IdP の管理操作だけで、判定の点を増やすと束縛の規則が 2 か所に散る（IADR-0253 決定 3） |

## 決定

1. `deploy/local/abac-seed/policies.json` に上の 1 本を足す。評価器・検証器・契約・消費側のコードは変えない
   （形は共有先の分岐と同じ単一キーの束縛で、全消費面が既に扱う）。
2. 試験は **seed → 認可サービスの応答 → 期待値のファイル → 各消費面** の鎖で置く。期待値のファイルの正は認可サービスの試験の突き合わせであり、
   seed を変えて応答が変わればそこが先に赤になる。
3. 本番の手順は `docs/operations/operations.md` §所有者の読み取りのポリシーの投入 に置く（API と本文・検証・投入済みの確かめ方・
   消したときの影響・配備の順番・予約値の注意・切り戻し）。
4. 内容の ABAC（#1615）は有効にしない。検知と通知（ADR-0121 決定 2）・古い写しの削除（決定 3）・判定の寄せ（決定 5）は後段である。

## 許可が広がる方向の評価

seed の追加で、IdP に居る**全利用者**に分岐 `owner ∈ {本人}` が 1 本足される。`granted` は変わらない（共有先の分岐も利用者の条件が空で、
既に全員 `true`）。据え置きの `AllowedFilters` には束縛前のリテラル `owner: ["${current_user}"]` が加わるが、これはどの文書にも一致しない
**狭まる向き**である（IADR-0253 決定 2）。

| 面 | 評価 |
| --- | --- |
| BFF の詳細・本文・版 | 所有者は自分の個人資料と、取扱区分の外にある自分の組織文書を読める（read 規則の所有者の分岐。計画の意図どおり）。他人の文書へは届かない |
| BFF の共有先の写し | 所有者に返るようになる（IADR-0450 の意図どおり）。共有された相手には返らない |
| BFF の SC-05 一覧 | 自分の組織文書が出る。個人資料は一律除外のまま |
| 検索（絞り込み・索引） | 自分の文書が出る。利用者が `owner` を他人へ絞っても、交差が空で所有者の分岐ごと落ちる |
| グラフ・Wiki | 同じ述語で、自分のノード・ページだけが加わる（本 PR では試験を置かない。GraphService は並行の作業が触っている） |
| DocumentService | 変化なし（所有者はコードで判定済み。分岐はグループ共有の段でしか見ず、所有者の分岐は本人の資料にしか一致しない） |
| MCP の登録者 | 変化なし。所有者の分岐は区分の軸の許可として数えない（IADR-0384）。ADR-0062 実測 9 の再顕在化が無いことを seed の応答で試験した |
| 束縛の失敗 | 名簿に居ない名前（`anonymous`・`system`・空文字）は `NotFound` で `granted=false`。許可へは倒れない |
| 予約値の owner | **残余リスク**: 予約値と同名の利用者が IdP に作られると、その利用者が予約値の文書を読める（write では既に書けた）。realm は自己登録と利用者名の変更を禁じ、SC-17 に作成の口は無いので、作れるのは Keycloak の管理者だけ。手順書で禁じ、dev realm は試験で固定した |

計画の意図の外へ許可が広がる副作用は見つからなかった。

## 結果

- dev で、所有者が共有していない自分の個人資料を BFF で開ける（ADR-0121 フォローアップ 6）。他人は開けない。
- seed が作る応答そのものが試験の入力になった。seed を変えると期待値のファイルの突き合わせが赤になり、消費側の試験が作り物のまま残らない。
- 🔴 **残るもの**:
  - 本番への投入は手作業である。消されたときの検知と通知は無い（ADR-0121 決定 2。内容の ABAC を有効にする前に入れる）。
  - SC-09 の画面からこのポリシーを作れない（ADR-0036 フォローアップ 5。手順書は API への直接投入を書く）。
  - 予約値と同名の利用者を IdP に作らないことは、本番では運用の約束である（機械の検査は dev realm だけ）。
  - グラフ・Wiki の面は述語が同じことで評価し、seed の応答での試験は置いていない。

> ［2026-09-27 追記 / #1665］上の「残るもの」の「消されたときの検知と通知は無い」と、決定 4 の「検知と通知（ADR-0121 決定 2）…は後段」のうち
> **検知と通知は入った**（[[IADR-0481]]。認可サービスの定期の検査と警報 `OwnerReadPolicyMissing` / `OwnerReadPolicyCheckSeriesAbsent`）。
> あわせて内容の ABAC の有効化の門（文書サービス。所有者の読み取りのポリシーを確かめるまで開かない）も入った。古い写しの削除・判定の寄せ・内容の ABAC の本体は後段のままである。
