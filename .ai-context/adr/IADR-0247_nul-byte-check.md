# IADR-0247 生の NUL バイトの検査

## 状況

生の NUL（`0x00`）が追跡下のファイルへ混入する事故が **4 回**起きた。

| 回 | 場所 | 経緯 |
| --- | --- | --- |
| 1 | `#900` `scripts/check-coverage-floor.js` | 重複排除キーの区切りに使うつもりが実バイトになった |
| 2 | `#919` `scripts/check-backend-libraries.js` | 「UTF-16 を utf8 で読むと NUL 混じりに化ける」を**説明する**コメントに 3 個 |
| 3 | `#919` の作業仕様書 | 回 2 を**記録する**文に 1 個 |
| 4 | **本検査器そのもの** | 回 1〜3 を**背景として書く**コメントに 1 個。**本検査器が自分で捕まえた** |

いずれも「エスケープ表記（バックスラッシュ と u0000）と書いたつもりが実バイトになる」という同じ機序で、
**エスケープ表記を含む文を書くたびに再発している**。

### なぜ検査するか

生の NUL が入ると **`git` と `grep` がファイルをバイナリ扱いする**。

- `git diff` が中身を出さない（`Binary files differ`）→ **レビューできない**
- `grep` が行番号を出さない（`Binary file … matches`）→ **走査・母集合の引き直しが機能しない**

🔴 **4 回とも実行時挙動は正常で、テストも他の検査器も緑だった。** 気付いたのは `grep` が
`Binary file … matches` を返したときで、**偶然に近い**。**混入したまま気付かずマージされ得る。**

CLAUDE.md「検査器・規約の追加は**同型の事故が 2 回起きたら**を条件とする（1 回目は記録に留める）」に対し
**4 回目**であり、条件を満たす。

## 決定 1: 検査範囲は「追跡下すべて」。拡張子の許可リストにしない

**着手前の実測**（`#919` で「偽陽性が構造的に増えない」を測ったのと同じ形）:

| 項目 | 実測 |
| --- | ---: |
| 追跡下のファイル | **1995 件** |
| **NUL を含むもの** | **0 件** |
| バイナリ拡張子（`png`/`jpg`/`pdf`/`zip`/`dll`/`exe`/`woff`/`ttf` ほか） | **0 件** |

**このリポジトリは追跡下が全部テキストである。** どちらの範囲でも今日の偽陽性は 0 件だが、
**壊れ方が違う**。

- **許可リスト方式**（テキスト拡張子だけ検査）は、**新しいテキスト拡張子が黙って対象から外れる**。
  実測でも `.gitkeep` / `Dockerfile` / `.hcl` / `.po` / `.template` など **126 件**が
  「テキスト系候補」から漏れていた。**この失敗は無音である。**
- **追跡下すべて**なら、将来バイナリを追加したときに落ちるが、**その失敗は目に見える**。

**無音の見逃しより、目に見える誤検出を選ぶ**（`IADR-0138` が「サフィックスは規約にすぎず、
壊れたときに無音になる」としてディレクトリ（構造）を選んだのと同じ判断）。

`BINARY_EXTENSIONS` は**空で始める**。🔴 **空であること自体が正解の状態である**（未整備ではない）。
足した拡張子は**そのぶん検査されなくなる**ため、足す判断は人が行い、自己試験が空であることを固定する。

## 決定 2: 検査器はバイトで読む。復号しない

🔴 **自分が検出したいもので自分が壊れないようにする。** NUL を含むファイルを `utf8` で読むと
内容が化け、実装によっては例外にもなる。`fs.readFileSync(abs)`（Buffer）で読み、
バイト列を走査するだけにする。自己試験で「バイナリ同然のファイルを渡しても例外を投げない」を固定した。

### 検査器自身が壊れた場合

**NUL がコメント内なら構文は壊れず、本検査器は自分を検出できる**（実測: 回 4 をそう捕まえた）。
**NUL がトークンの外（末尾など）なら Node が `SyntaxError` で読み込みに失敗する** ——
このとき落ちるのは検査ではなく起動である。**どちらでも CI は赤くなる**が、
**「検出した」と「起動に失敗した」を取り違えないこと**（変異試験で構文が壊れていないことを先に確認した）。

## 決定 3: 走査母集合は `git ls-files`。未追跡は対象外

未追跡ファイルは定義上の対象外とし、**`warnIfResultMayDifferFromCi(..., MODE.TRACKED)` で
「作業ツリーに未コミットの変更があると CI と一致しない」ことを毎回警告する**（`IADR-0183` のクラス B）。
0 件走査で静かに緑にしないため、走査件数の下限（`MIN_SCANNED`）を置く。
🔴 **下限の判定は純粋関数へ切り出した** —— `REPO_ROOT` が `__dirname` 基準のため、
**cwd を変えても門を試験できない**（実測: 空リポジトリで実行しても本リポジトリを走査して緑になった）。

## 検出しないこと

- **未追跡ファイル**（決定 3。定義上の対象外。警告は出す）
- **BOM 無し UTF-16 など、NUL を含むが正当なテキスト符号化**。本検査は「生の NUL があるか」しか見ない
  （`IADR-0245` の `readSource` が BOM 付き UTF-16 を復号するのとは別の関心事）
- **`BINARY_EXTENSIONS` へ足した拡張子**。足したぶんは検査されない
- **NUL 以外の制御文字**（`0x01`〜`0x08` 等）。git はこれらをバイナリ判定に使わないため射程外

## ［2026-08-23 追記 / #1008］ 除外した射程の判断根拠

`#956` の作業中に測った、射程に**足さない**と判断した根拠が worktree に untracked のまま
残っていて develop に着地していなかった（issue #1008）。上の「検出しないこと」節を補い、
何を測って外し、何が原理的に射程外かを記録する。

### 「編集操作が不可視に壊す」4 class 全体の切り分け

本 IADR が塞いだのは 1 だけである。**2 は測って外した。3 と 4 は原理的に射程外**である。

| # | class | 痕跡 | content scan で捕まるか | 判断 |
| --- | --- | --- | --- | --- |
| 1 | 生の NUL バイト | ファイルに残る | 捕まる | **塞いだ**（本 IADR） |
| 2 | BOM の混入 | ファイルに残る | 捕まる | 🔴 **測って外した**（次項） |
| 3 | コマンド置換による欠落 | **残らない**（内容が消える） | 捕まらない | 射程外 |
| 4 | コマンド置換による意図しない実行 | ファイルに何も残らない | 対象ですらない | 射程外 |

**「考えていない」で外したものはない。**

### 2. BOM の混入 —— 測って外した

実測（追跡下 1998 件）:

| 項目 | 実測 |
| --- | ---: |
| UTF-8 BOM | **15 件** |
| UTF-16 BOM | **0 件** |

15 件は全部 `.cs`、しかもすべて EF Core の生成コード（`Migrations/` 配下の
`*.Designer.cs` / `*ModelSnapshot.cs`）。`dotnet ef` が BOM 付きで書き出す。
**足さない理由は 3 点。**

1. 🔴 **害の class が違う。** 本 IADR が塞いだのは「`git` と `grep` がバイナリ扱いして
   diff もレビューも走査もできなくなる」ことである。**UTF-8 BOM ではこれが起きない**
   ——BOM 付きファイルも git・grep とも テキストとして扱い、diff も行番号も正常に出る。
   「不可視に内容が変わる」点は同じでも、**塞ごうとしている害が別**である。
2. 🔴 **検査器がツールチェーンと戦う形になる。** 15 件は `dotnet ef` の出力であり、
   **再生成のたびに BOM が戻る**。`IADR-0138` が「マイグレーションを 1 本足しただけで
   床が動く」を問題にしたのと同じ形で、**人の操作と無関係に赤くなる検査**になる。
3. **UTF-16 BOM は 0 件**で、必要な箇所（走査器がソースを読む経路）は `IADR-0245` の
   `readSource` が既に復号している。**残っている穴がない。**

**足すとしたら**生成コードの除外が要り、その判定は `Migrations/` 配下という**規約**になる。
`IADR-0138` はこれを構造的な根拠として採っている一方、本 IADR 決定 1 は**規約ベースの
許可リストを避ける**判断をしたため、**同じ検査器の中で両方の作法を混ぜることになる**。
**足すなら別の検査器として設計する。**

### 3. コマンド置換による欠落 —— 原理的に捕まらない

`WebApplicationFactory` が空文字に消えた形（`#439`）。**壊れた内容が残るのではなく
内容が消える**ため、バイト走査では検出できない。残ったテキストは妥当で、構文も壊れない。
**何かが無いことは、無いものを知らない限り分からない。**

検出するなら**検査器ではなく作法の側**——書き込み後に**想定文字列の存在を assert する**
（「書いたはずのものが書けているか」を書き手側で確かめる）——が要り、これは静的検査ではなく
手順の問題である。本検査器の射程外であることを明記する（「検出しないこと」と同じ扱い）。

### 4. コマンド置換による意図しない実行 —— 検査器の対象ですらない

`#783` のセッションが、クォート無しの heredoc 内にバッククォートで囲んだ git コマンドを書き、
**それがコマンド置換として実行された**形。しかも **Bash ツールが cwd を主 worktree へ
リセットする**ため、実行先は隔離 worktree ではなく**共有ツリー**だった（`git stash` →
`git stash pop` が走った。往復したので無傷だったが、**pop が競合していたら他セッションの
作業ツリーを壊していた**）。

🔴 **ファイルには何の痕跡も残らない。** これは**ファイルの中身の問題ではなく、生成手段の
問題**である。**3 と 4 は同じ原因（クォート無し heredoc でのコマンド置換）で、被害の形が
違うだけ**である。

対処は検査器ではなく作法:

1. **文章ファイルの生成に heredoc を使わない**（Write ツールを使う）
2. heredoc を使うなら**必ずクォート付き**
3. 🔴 **Bash の cwd リセットを忘れない** —— `cd` を先頭に置かないコマンドは**共有ツリーに
   当たる**

## 影響

- `scripts/check-nul-bytes.js` を新設（自己試験 19 件）。検査器の母集合は 39 → **40** 本。
- `scripts.repo.test.js` から自己試験・実データ走査・**変異（NUL を 1 バイト入れて名指しさせる）**を回す。
- クラス B（`TRACKED_CHECKERS`）へ登録。

## 代替案

- **テキスト拡張子の許可リスト** —— 新しい拡張子が無音で漏れる（決定 1 で棄却）。
- **git の binary 判定に委ねる**（`git grep -I` 等）—— NUL を含むファイルは git にとって
  binary なので、**検出したい対象がそのまま除外される**。循環する。
- **pre-commit hook だけで防ぐ** —— hook は環境依存で、CI の門にならない。
