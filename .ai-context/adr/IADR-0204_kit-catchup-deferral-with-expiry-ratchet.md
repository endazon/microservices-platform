# IADR-0204: 追随保留のラチェットと、分類 X 再判定の判定基準（#790）

- 状態: Accepted
- 日付: 2026-08-16
- 決定者: claude（実装）

## 起点・関連

- **NFR**（キット追随・文書統制＝メタ作業。計画の非機能要件表 `NFR-01`〜`NFR-27` は 27 件とも
  **稼働する製品の要件**であり、当たる番号が無い。`.claude/rules/traceability.md`「無採番 `NFR` を許す
  2 つの場合」の**場合 2** に当たるため無採番とし、**環流しない**。[IADR-0179](./IADR-0179_unnumbered-nfr-for-meta-work.md) 決定 2）
- 実装 issue: **#790**（計画 pin `4d6a7d6` → `8cae89d`。裁定 planning#369〜planning#374 の取り込み）
- 作業仕様書: [20260816_issue-790](../specs/20260816_issue-790_planning-pin-8cae89d-and-kit-rejudgement.md)
- 起票した追跡先: **planning#379**（`check-cross-repo-refs.js` の 0 件走査の門）／
  **planning#380**（`scripts.test.js` の試験がキット既定を断定している）／**#793**（必読規約の減量）

## 文脈 —— **キットが「自分の配った拡張点を埋めた側で落ちる」ようになった**

pin `8cae89d` は、本リポが出した環流 2 件（planning#373 `check-commit-messages.js` の実在性検査と
3 面クロスリポ参照／planning#374 `check-cross-repo-refs.js` の型 4・`〔〕`・`.md` 外走査）を
キットが受理した結果である。**受理は歓迎すべきことだが、副作用が 2 つ出た。**

| # | 副作用 | 実測 |
| --- | --- | --- |
| 1 | キット `.claude/rules/traceability.md` が **21,590B → 24,592B（+3,002B）** へ育った | 取り込むと必読規約が**予算 51,200B を超え** `check-reading-budget.js` が fail（★ 具体値は下記のとおり**書かない**。時点つきの実測は「超過の実測」節） |
| 2 | キット `scripts/scripts.test.js` の新試験が **「拡張点を持たない構成」を断定** | 拡張点を埋めた本リポでは `loadExistingPlanIds()` が `Set(54)` を返し `assert.strictEqual(…, null)` が必ず落ちる |

いずれも**分類 A（キットとバイト一致）を成立させない**。従来の選択肢は「バイト一致を捨てて分類 B へ落とす」
か「テストを赤のまま放置する」の二択だったが、**前者は「暫定」と書くだけで期限が誰にも確かめられない**。

### 超過の実測（**時点つき。値は転記しない**）

**［2026-08-16 追記 / #790］当初この ADR は副作用 1 の欄へ「50,193B → 53,195B」と具体値を書いていた。
その値は 3 回動いた。**

| 時点 | 合計 | would-be | 何が動かしたか |
| --- | ---: | ---: | --- |
| 作業途中 | 50,193B | 53,195B | （最初の測定） |
| 本 PR 完了時 | 50,182B | 53,184B | **自分が** companion を 11B 縮めた |
| develop `0e906f7` 取り込み後 | 50,061B | 53,063B | **別 PR（#794）が** `CLAUDE.md` を 121B 縮めた |

**いずれも規則 10 の破れとして事後に検出された**（2 回目は PR #795 の AI レビュー、3 回目は #794 のマージ時に自分で）。
**3 度同じ型を踏んだので、値を書くのをやめる。** 超過しているかどうかは**決定 1 のラチェットが実ファイルから
ライブ計算して判定する**のであり、散文の数値は判定に一切使われない。**書けば必ず腐り、腐っても誰も落ちない**
—— これが「導出値は走査ではなく計算し直す」（規則 10）の最も純粋な形である。

## ★★ 決定 1: **追随を保留するときは、保留の根拠そのものを機械が検査する（期限のラチェット）**

分類 B の X は「環流するか**期限つきの暫定**とする」と定義されている（[IADR-0192](./IADR-0192_kit-sync-classification-and-check.md) 決定 2）。
**しかし「期限」は理由欄の散文でしか表現されておらず、期限が来たことを誰も検出しない。**

**決定**: 保留の根拠が**計算できる量**であるとき、その量を `scripts/scripts.repo.test.js` の試験で
固定し、**根拠が消えたら試験を fail させる**。

```
#790 のラチェット（.claude/rules/traceability.md）:
  CLAUDE.md + キット版 traceability.md + companion > BUDGET_BYTES を assert する。
  減量が着地して予算内に収まった瞬間に、この assert が落ちて追随を促す。
```

- **「分類 B に置いた」ことを試験するのではない**（それは現状の追認にしかならない）。
  **試験するのは「置いた理由がまだ生きているか」である。**
- 根拠が計算できない保留（キット側の是正待ち等）は**追跡先の issue 番号だけ**を持つ
  （`scripts.test.js` / planning#380 がこれに当たる。ラチェットは置けない）。
- ラチェットが落ちたときのメッセージには**次にすべき操作**を書く（「キット原文で上書きし分類 A へ戻す」）。

### 棄却した案

| 案 | 棄却理由 |
| --- | --- |
| 予算値 51,200 を引き上げる | 正本は計画リポの運用ガイド §8（planning#364）であり、実装側が動かしてよい値ではない |
| companion を約 2KB 減量して今すぐ取り込む | **`.claude/rules/` の減量は #684 系の別作業**であり、`scripts.repo.test.js` が companion の文言リテラルを 10 箇所以上で固定している。pin 追随の PR で巻き込むと、減量の判断が「予算を空けるため」に歪む |
| `CLAUDE.md` を削る | 別 issue の領域（本 PR では触らない）。かつ同じ歪みが起きる |
| 赤のまま放置し「暫定」と書く | **期限を誰も確かめない。** 本決定はこれを機械化するためにある |

## ★★ 決定 2: **分類 X の再判定は「検出力が同値」だけでは A へ戻さない。fail の向き（門）まで突合する**

#756 は HOWTO §B-5 の手順どおり**検出結果**を突合した。#790 でその 2 本を再判定したところ、
**検出力は 2 本とも同値**になっていた。**しかし片方はキット版へ戻せなかった。**

| 検査器 | 検出力（同一入力） | 結論 |
| --- | --- | --- |
| `check-commit-messages.js` | 6 件名で exit と検出行数が**完全一致**（`SC-99` / `ADR-0099` / `NFR` 本文の 3 面 / `FR-012` の桁ゆれ） | **X → B（種 5）**。差は置換点 `PLAN_PROJECT` のみ |
| `check-cross-repo-refs.js` | 同一 fixture で **6 件 / 6 件**、実データ 1,626 件で **0 件 / 0 件**、owner 誤りの提案文字列まで一致 | **X のまま**（理由を書き直し） |

後者が戻せなかったのは、**キット版が 0 件走査の門（#664 / [IADR-0130](./IADR-0130_test-spec-coverage-ratchet.md) の作法）を持たないから**である。
空リポジトリで走らせるとキット版は `OK: 0 件に…違反はありません` と出して **exit 0** を返す。
**これは「違反が無い」ではなく「何も見ていない」であり、検出力の突合では絶対に現れない差である**
（違反を入れた入力でしか比べていないため）。実際に見つけたのは**変異試験**（`scripts.repo.test.js` が
4 本の検査器へ空リポジトリを食わせる）であり、**優劣の突合を「違反入力に対する出力」だけで
終わらせていたら、静かに門を失っていた。**

**決定**: 分類 X の再判定では、次の 3 つを**必ず**突合する。

1. **違反入力に対する検出結果**（従来どおり。HOWTO §B-5）
2. **入力が空・読めない・設定が未充填のときの終了コード**（fail-closed / fail-open の向き）
3. **本リポにしか無いモジュールへの結線**（`lib/worktree-state.js` 等。[IADR-0183](./IADR-0183_false-green-warning-on-worktree-state.md)）

2 が違えば、検出力が同値でも**キット版へ戻さない**。

## ★★ 決定 3: **キット土台を採りつつ、失う門は差し替え後に再付与する（「戻さない」＝「取り込まない」ではない）**

`check-cross-repo-refs.js` は**キット版を土台に採った**（キット版が優る点＝`createChecker` の設定
妥当性検査・NUL 読み飛ばし・型 4 の notice・置換点の環境変数注入を取り込むため）うえで、
**失う 2 点を明示的なコメントつきで再付与した**。

| 再付与したもの | 種別 | 行数 |
| --- | --- | --- |
| 0 件走査の門（#664 / IADR-0130） | **X**（キットに無い。環流待ち planning#379） | 5 |
| worktree 状態の警告（[IADR-0183](./IADR-0183_false-green-warning-on-worktree-state.md)） | 3（本リポにしか無いモジュールへの結線） | 4 |

**「本リポ版が優るから差し替えない」は、キット側の改善まで捨てる判断になりやすい。**
土台を入れ替えて差分を最小の固有デルタへ畳むほうが、次の追随が軽い。
**再付与した箇所には必ず `★ 固有デルタ（分類 B 種 N・#790）` の目印と理由を書く**
（次に同期する人が「消してよい残骸」と読み違えないため）。

## ★★ 決定 4: **配布物のテストが「キット既定の構成」を断定していたら、両方向を固定する形へ直す（skip にしない）**

planning#380 の是正が着地するまでの暫定として、`scripts.test.js` の当該 1 か所を
**拡張点の有無で期待値を選ぶ形**へ変えた。

**early return による skip にはしない。** 実効している側（拡張点を埋めた構成）が一度も試験されなくなり、
`readPlanIds()` の結線が切れても緑になる —— **「検査していない」を「違反 0 件」と読み分けられない**
という、本リポが繰り返し踏んできた事故そのものである。

## 影響・トレードオフ

- **X は 1 件増える**（`check-commit-messages.js` が抜け、`traceability.md` と `scripts.test.js` が入る）。
  X の件数は環流債務の測定値なので、**増えたこと自体を隠さない**。ただし**性質が変わった**:
  3 件とも**追跡先つき**で、うち 1 件は**期限のラチェットつき**である。
- **`.claude/rules/traceability.md` がキットより 1 世代古い状態が続く。** 規範の空白は生じていない
  （キット版が新たに書いた 3 点は companion が本リポ固有の形で既に持つ）が、**次の pin 更新で
  差分がさらに広がる**リスクがある。#793 を早く畳むこと。
- **`docs/how-to/session-handoff.md` の「`scripts.test.js` は変更禁止（分類 A）」は古くなった。**
  本 PR では触れない（並行 PR #789 と交差するため）。**#793 か次の追随で直す。**
