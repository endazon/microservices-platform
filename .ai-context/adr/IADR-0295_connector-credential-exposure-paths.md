# IADR-0295: コネクタ資格情報の露出経路を塞ぐ（#458）

- 状態: Accepted
- 日付: 2026-08-28
- 決定者: claude（実装）

## 起点・関連

- **FR-01 / FR-05 / UC-04 / SC-06 / NFR**（セキュリティ）。計画 **ADR-0005**。
  計画 `06_technical/09_datasource-connectors.md` の §認証・秘匿情報（「コミット・ログへ出力しない」）と
  §初期対応の優先順位の表（SaaS の認証は「OAuth／APIキー」）が直接の根拠である。
- 実装 issue: **#458**（セキュリティ暫定運用の解消。横断トラッカ・`blocked`）
- 作業仕様書: [20260828_issue-458](../specs/20260828_issue-458_connector-credential-exposure.md)
- 先行: [IADR-0053](./IADR-0053_wiki-connector-generic-rest-contract.md)（応答の Config マスク）／
  [IADR-0148](./IADR-0148_datasource-sync-health-persistence.md)（決定 6: 読んで書き戻す往復の保護）

## コンテキストと課題

外部コネクタの資格情報は `DataSourceService` の **1 テーブル 2 列**に平文で保存されている ——
`DataSources.Config`（jsonb）と `DataSources.ConnectionUri`（varchar(2048)）。
**同型の平文保存はリポジトリの他のどこにも無い**（走査 3 軸で確認済み）。

マスクは 2 層あった（応答の `SecretConfigMask.Redact`、保存時の `SyncErrorRedactor`）が、
**4 経路が素通しだった。** 4 本とも「マスクの規則が悪い」のではなく
**「マスクを通っていない出口が在る」**という同じ形をしている。

## 検討した選択肢

| 案 | 内容 | 評価 |
| --- | --- | --- |
| **A** | 保存を暗号化する（列暗号化・封筒暗号化） | **採らない**（決定 5）。前例ゼロ・完了定義に届かない・計画の go-live 条件に含まれない |
| **B** | **出る経路を塞ぐ**（応答・ログ）。マーカーは 1 本へ統合する | **採用。** 保存の平文は残るが、それは #458 が持つ既知の暫定状態である |
| C | 何もせず Vault 移行を待つ | **採らない。** #458 は `blocked`（実クラスタが要る）であり、待つ間ずっと露出が続く |

## 決定 1: **「何が秘密か」を 1 箇所に持つ**（`SecretMask`）

同じ知識が 2 箇所にあり、**実際に食い違っていた。**

| | 従前の集合 | 捕まらなかったもの |
| --- | --- | --- |
| `SecretConfigMask`（応答の Config マスク） | token / password / secret / credential | **`apiKey` / `pwd` / `privateKey` / `authorization`** |
| `SyncErrorRedactor`（保存時のエラーマスク） | password / pwd / token / secret / api key / credential / authorization | **`privateKey`** |

🔴 **計画が名指しする形式が捕まらなかった** —— 計画は SaaS の認証を「OAuth／APIキー」と定めており、
`Config["apiKey"] = "…"` は**応答で平文のまま返っていた。**

新設 `Domain/SecretMask.cs` の **`KeyMarkers` ただ 1 本**が唯一の情報源である:

```
password|pwd|token|secret|api[-_]?key|private[-_]?key|credential|authorization
```

`SecretConfigMask.IsSecretKey` も `SyncErrorRedactor` の正規表現も、**ともにこれを読む**。
`[GeneratedRegex]` は定数式を要求するので**定数補間文字列**で組み立てた（コンパイル時定数になる）。

**`key` 単独はマーカーにしない。** `spaceKey` を誤マスクする ——
**過剰マスクもまた欠陥である**（原因の切り分けを潰す）。回帰は否定形テストで固定した。

> **`SecretConfigMask` のコメント自身が、この事故の型を警告していた。** 警告を書いても
> **同じファイルの中に知識を残したままでは防げない。** 防ぐのは注意ではなく構造である。

## 決定 2: **応答も保存と同じマスクを通す**（経路 a）

`DataSourceSyncService` の discover 失敗は、`AlertOnFailure` 経由では**マスクして保存される**のに、
`SyncResult.Message` には `ex.Message` が**素で載っていた**（`DataSourceEndpoints` →
`DataSourceBffEndpoints` がそのまま中継する）。

**`DatabaseConnector` は `builder["Password"]` で接続文字列を合成して `OpenAsync` する**ため、
接続失敗例外にパスワードが載る経路は**仮定ではなく実在する**。

**文字列を組み立ててから `SyncErrorRedactor.Redact` へ通す。** そうすれば
保存される `LastSyncError` と応答が同じ規則（マスク ＋ 500 文字上限）で揃う。

**`fetch` 側に同型は無い**（実測）—— `RunAsync` は fetch 失敗時に `Message: null` を返し、
`AlertOnFailure` へ `ex` を渡さない。**素通しだったのはログだけ**であり、それは決定 4 が扱う。

## 決定 3: **`ConnectionUri` は応答で伏せ、書き込みでは資格情報を弾く**（経路 b）

`SecretConfigMask` は `Config` にしか掛からず、`ConnectionUri` は素で返っていた。
一方 `SyncErrorRedactor` は `scheme://user:pass@host` を**明示的に想定して伏せている** ——
**そこへ資格情報が入り得ることをコード自身が認めていた。**
`DatabaseConnector` のコメントは「`ConnectionUri`（パスワードを含めない）」と書くが、
**それを強制する検証がどこにも無かった。**

- **読み**: `ToResponse` で `SecretMask.RedactText` を通す。1 つの規則で両形式を伏せられる
  （`scheme://u:p@h` は URI 規則、`Host=..;Password=..` はキー=値 規則）。
- **書き**: **400 で弾く**（警告ではない）。

**「弾く」を選んだ理由**（影響を実測してから決めた）:

1. **壊れる既存データが無い。** リポジトリ内の `connectionUri` の値 14 種すべてが資格情報を持たない
   （テスト・フロントの faker・統合テストを横断して実測）。
2. **契約は既にそう定めていた。** 欠けていたのは強制だけである。
3. **警告は平文が DB に入るのを止めない。** しかも警告の出口はログであり、
   **それは決定 4 で塞ごうとしている経路そのものである。**
4. **`filesystem` の逃げ道を塞ぐ件も筋が通る。** 共有のマウント資格情報は PVC 側の関心事であって、
   アプリの列に置くものではない。

**判定規則は 1 本**である —— 「**マスクを掛けて値が変わるなら、それは資格情報を運んでいる**」。
第 2 のマーカー集合を作れば、決定 1 が解消した defect の再発になる。

🔴 **応答をマスクするなら、書き戻しの保護が必ず要る**（IADR-0148 決定 6 が `Config` について
確立した形を `ConnectionUri` へ広げた）。2 段で守る:

| 送られてきた形 | 扱い | 無いとどうなるか |
| --- | --- | --- |
| 既存値をマスクしたものと**一致** | 受理し、**既存の実値を保つ** | 資格情報つきの既存行は**名前 1 つ直すことすらできなくなる** |
| マスク値を**編集**した形（`***` を含む） | **400 で弾く** | どのマスク規則にも掛からない（`***` に `:` が無い）ので**そのまま保存され、資格情報が黙って消える** |

## 決定 4: **例外オブジェクトをログへ渡さない**（経路 d）

`logger.LogWarning(ex, …)` は `Exception.ToString()`（**メッセージ ＋ 内部例外のメッセージ ＋ スタック**）を
LogRecord へ載せる。**共通ログ基盤にスクラビングは無い**（`Foundation/` を
`redact|scrub|sanitiz|mask` で走査して **0 件**）。コネクタのコメントは「ログ出力しない」と主張していたが、
**例外経由の間接出力が塞がれていなかった。**

**例外の型名 ＋ マスク済みメッセージ**を渡す形へ変えた。

- **スタックは落とす。** 安全に残す方法が無い —— スタックの枠自体は秘密を運ばないが、
  `ToString()` は**内部例外のメッセージ**を一緒に運び、Npgsql のような実装ではそこから漏れる。
- **型名は残す。** 資格情報を運ばず、切り分けの主要な手掛かりである。
- **トレードオフを引き受けた**: fetch 失敗のスタックが読めなくなる。
  `ex.ToString()` を丸ごとマスクに通す案は、**上限の無い文字列を可観測性基盤へ流す**ことになるため
  別の判断が要る。**本 ADR では採らない**（作業仕様書 §未決事項）。

## 決定 5: **保存の暗号化は今やらない**

**3 つの理由で、いずれも本作業の外側にある。**

1. **前例がゼロである。** 可逆暗号の利用はリポジトリ全体で 0 件。`AddDataProtection` の前例は
   BFF セッション Cookie の 1 件だけで、**永続データの列暗号化の前例は無い。**
   前例の無い暗号を 1 サービスだけに入れると、鍵の配布・ローテーション・災害復旧が
   **そのサービス固有の運用**になる。
2. **完了定義に届かない。** close 済み #310 の完了定義は「`Config` は**参照キー**のみ保持」であり、
   **封筒暗号化はこれを満たさない**（暗号化しても値そのものは DB に在る）。
   暗号化は「参照キーへ移す」への**中間地点ですらない** —— 移行時に捨てる作業になる。
3. **計画の go-live 条件に含まれない。** 計画は Vault 化の go-live 条件を
   **2 種（外部 LLM API キー・Keycloak クライアントシークレット）に限定**しており、
   コネクタ資格情報は含まれない。横断は **#458** が持つ。

### やるときの設計（先に決めておく）

やる判断が下りたときに設計から始めなくてよいよう、**形だけ確定させておく。**

- **鍵は構成から注入し、既定値を持たない。** 形は `Program.cs` の DB 接続文字列と**同じ**である ——
  「既定値を持たず、未設定なら**起動時に落ちる**」。
  既定値を置くと、注入漏れが「起動失敗」ではなく**「既定鍵で暗号化成功」**へ倒れ、
  **暗号化したつもりで誰でも復号できる状態が健全に見える。**
- **供給経路は差し替え可能にする**: `k8s Secret` → **ESO** → **Vault**。
  これは基盤 secret で既に一巡している経路であり（ESO PR-1〜4）、新しい配管を作らない。
- **鍵 ID を暗号文へ添える**（ローテーションのため）。添えないと、鍵を替えた瞬間に
  既存行が**どの鍵で暗号化されたか分からなくなる。**
- **それでも「参照キーのみ保持」への移行は別作業である**（上の理由 2）。
  暗号化は**その日までの緩和**であって、到達点ではない。

## 結果

- **良い影響**: 保存された平文が**応答・ログのどちらからも出なくなった**。
  秘密キーの知識が 1 箇所になり、片方だけ古くなる事故が構造的に起きなくなった。
  `ConnectionUri` に新たな資格情報が入らなくなった（既存行は応答で伏せられる）。
- **悪い影響・トレードオフ**:
  - **fetch / discover 失敗のスタックトレースが読めなくなった**（決定 4）。
  - **`ConnectionUri` に資格情報を書く運用は 400 になる。** 実測では壊れる既存データは無いが、
    リポジトリ外の実環境に該当行があれば、更新時に `config` への移設を求められる。
  - **保存の平文は残る**（決定 5）。**これは緩和であって解決ではない。**
- **フォローアップ**:
  - 保存の暗号化 / Vault 移行（**#458**。`blocked`。実クラスタが要る）。
  - **サービス自身の DB 接続文字列**を運ぶ例外ログ（`PostgresAdvisoryLockLeaseCoordinator` /
    `DataSourceSyncHostedService`）。**同型だが対象が違う**ため本 PR の射程外。別 issue に委ねる。
  - `ex.ToString()` を丸ごとマスクに通してスタックを残す案（上限の置き方が未決）。
