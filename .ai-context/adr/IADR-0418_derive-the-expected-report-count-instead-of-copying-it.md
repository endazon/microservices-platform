# IADR-0418: 検知手段は写しではなく導出で持つ

## 状況

`#900`（[[IADR-0236]]）でカバレッジ集計がレポートを跨いで行を重複排除するようになった。
その結果、**同じテストプロジェクトを 2 回実行しても分母が倍にならず、床は割れない** ——
二重実行という測定基盤の事故が **fail ではなく無音**になった。

代わりの検知手段として置かれたのが「**レポート件数の期待値**」であり、
`integration.yml` と `src/coverage-floor.json` の**コメントに固定値**で書かれていた。

### 🔴 その固定値は 2 か所とも実物とずれていた（#1346）

| 置き場 | 書かれていた値 | 実物 |
| --- | --- | --- |
| `.github/workflows/integration.yml` | **16 件** | **19 件** |
| `src/coverage-floor.json` | **17 件** | **19 件** |

**2 つの写しが互いにも実物にも一致していない。**
つまり**検知手段そのものが陳腐化しており**、この 1 年で二重実行が起きていても
誰も気付けない状態だった（床は割れないので緑のまま通る）。

同じ PR で見つかった床値のコメント（`line 88 / branch 68`）も、`#901` の引き上げ（`90 / 75`）に
追随せず 3 か所に残っていた。**値を写した箇所は、写した瞬間から腐り始める。**

## 決定

### 決定 1: 🔴 **期待値は数えて導く。コメントに書かない**

`check-coverage-floor.js` が集計対象の**テストプロジェクト**（`src/` 配下の `*Tests.csproj`。
除外ユニットは**レポート側と同じ `isExcludedPath` で落とす**）を数え、
Cobertura レポートの件数と突き合わせる。

**除外の判定をレポート側と共有する**のが要点である ——
別々に持つと、除外ユニットを増やしたときに片方だけが追随し、**常時ミスマッチ**になって
（＝狼少年になって）検知が無効化する。探索起点も共有するので `templates/` の雛形は初めから範囲外である。

### 決定 2: 🔴 **多い側だけを error にする**

| 差 | 意味 | 扱い |
| --- | --- | --- |
| レポート > プロジェクト | **二重実行の疑い**。床では検知できない（重複排除で畳まれる） | **error** |
| レポート < プロジェクト | どれかがレポートを出していない。**床が下がる向き**なので床自身が捕まえる。部分実行という正当な形もある | **warn** |

**同じ扱いにしない。** 少ない側を error にすると、ユニット単体の実行やローカルでの部分実行が
落ちるようになり、**この門を外す圧力**が生まれる（門は外されたら 0 になる）。

### 決定 3: **`--report-only` では落とさない**

PR 側（`ci.yml`）は床と同じく報告に留める。**門は回収先 `integration.yml` に 1 つだけ置く**
（[[IADR-0232]] 改定 3）—— PR 側に門を増やすと、床が 1 つで二重実行の門が 2 つ、という
非対称な統制になる。

> **［注記］** 「回収先にしか門が無い」という構造そのものへの是非は #1345 が扱う（利用者の政策判断）。
> **本 ADR はその構造に合わせるだけであり、変えない。**

### 決定 4: **床の値もコメントへ写さない**

`integration.yml` / `ci.yml` の床コメントから数値を落とし、正本（`src/coverage-floor.json`）を指す
形にした。**当時の実測**は記録として残すが、「期待値」としては使わない。

## 帰結

- 二重実行は **fail する**ようになった（`integration.yml` の実行時）。実測で確認済み ——
  擬似レポートを 20 件置くと exit 1、19 件（＝実プロジェクト数）なら「一致している」と出る。
- **コメントに書かれた期待値が 1 つも残っていない**ので、腐る対象が無い。
- テストプロジェクトを増やしても**何も更新しなくてよい**（[[IADR-0236]] が分母の問題を解いた後に
  残っていた最後の手作業が消えた）。

## 一般化（この判断をどこまで広げるか）

**「機械が数えられる値をコメントへ写している」箇所には同じ判断を当てる。**
ただし**広げるのは検知手段として使われている値だけ**である ——
経緯・当時の実測・根拠として書かれた数値は**記録**であり、腐っても検知は壊れない
（`src/coverage-floor.json` の根拠欄をそのまま残したのはこのためである）。

🔴 **区別の仕方**: 「この値が実物とずれたとき、何が検知できなくなるか」を問う。
答えが「何も」なら記録であり、答えが在るならそれは**導出すべき期待値**である。
