# IADR-0508: 計画 ID レンジ・NFR 採番の宣言のずれを週次棚卸しで検知する（#1775）

- 状態: Accepted
- 日付: 2026-10-08
- 決定者: claude（#1775。#1769 受け入れ基準 3 の後続。作業仕様書 20261008_1775）

## 起点・関連

- 起点 issue: #1775（#1769 / #1774 の後続）。対の issue は AST#1208（同じ形を ai-stock-trading 側へ入れる）
- 計画: ADR-0093 決定 3（実装リポの突合は読み取り専用の HTTP に限り、落とし方は警告に限り、ビルドやテストの前提にしない）、決定 2（NFR は公開レンジ表へ足さない。足すかはフォローアップ 3 の裁定）、フォローアップ 4（「宣言と実物の差が 0 でない日数」を数える）。ADR-0048 決定 2（planning 非依存）
- 前提: IADR-0423（突合の新設・出典は公開 `kg-ranges.json`・`scanned` の併記。決定 3 の一部を本 IADR が改める）、IADR-0506（週次棚卸しは列挙のみで状態を書き換えない）

## コンテキストと課題

- `scripts/check-planning-adr-range.js` は PR CI で毎回走っていたが、**ずれても警告が出るだけ**で、ADR-0129（2026-10-06 マージ）の遅れは第 4 回全体監査 B-1（2026-10-07）まで残った（#1769 → #1774 が手で引き直した）。
- **NFR 採番の宣言（`NFR-01`〜`NFR-29`）は、どこからも突き合わされていない。** 公開レンジ表に NFR は無い（ADR-0093 決定 2）。#1774 は ADR-0129 が NFR-29 を足したことを人が読んで追随した。
- 週次棚卸し（`backlog-audit.js`）は本件を見ていない。
- 同型の遅れは AST でも 3 回目（AST#1208）。AST では週次監査が `behind` を正しく報告したのに、報告の 1 行で終わって誰も引き直さなかった。**報告するだけでは作業にならない**ことが実測されている。

## 検討した選択肢

| # | 案 | 評価 |
| --- | --- | --- |
| A | **週次棚卸しの前段で 5 種（NFR を含む）を突き合わせ、ずれたら専用 issue を upsert し、棚卸し報告に節を足す** | **採用**。#1775 の案 1。報告に加えて、AST で「報告だけでは動かない」と実測された段（作業化）を埋める |
| B | `check-planning-adr-range.js` を隣接クローンがあるときだけ警告にする（#1775 の案 2） | 採らない。CI に隣接クローンは無く、手元でしか効かない。既に PR CI で警告は出ており、足りないのは警告ではない |
| C | 現状維持（全体監査で拾う。#1775 の案 3） | 採らない。窓が監査の間隔になる |
| D | NFR も PR CI で突き合わせる | 採らない。ADR-0093 決定 2 が NFR の扱いを裁定待ちとしており、射程を PR 経路まで黙って広げない。週次の報告に限る |
| E | 計画側の NFR を公開レンジ表へ足すよう環流してから突き合わせる | 本 PR では採らない。フォローアップ 3 は既に計画側の残件である。裁定が出たら取得元を置き換える（決定 2） |

## 決定

### 決定 1: 週次棚卸しの前段が突き合わせ、ずれたら専用 issue を upsert する

- `backlog-audit.yml` に前段 `Resolve planning ID range`（`check-planning-adr-range.js --with-nfr --upsert-issue --out …`）を置く。
- `behind` / `ahead` のとき、ラベル `plan-range-lag`・マーカー `<!-- plan-range-lag -->` の open issue を探し、在れば本文を上書きし、無ければ作る（`GITHUB_TOKEN`。ジョブは元から `issues: write`）。本文は種別ごとの表・`reason`・引き直しの手順（転記元は計画リポの `gen-plan-ranges.js --check`・別紙への追記・`Closes #N`）。**自動でクローズしない**（IADR-0506 と同じく、状態を書き換えるのは人）。
- 結果は JSON（`lagIssue` を含む）に書き、棚卸しが節 8「計画 ID レンジ宣言の鮮度」に載せる。PR CI の配線は変えない（4 種・起票しない）。

### 決定 2: NFR は計画側の要求一覧から、計画リポの導出器と同じ規則で導く（週次に限る）

- `projects/microservices-platform/02_requirements/*.md` を `gh api …/contents` で取り（一覧 1 回 ＋ `.md` を raw で）、**定義表の行頭セル** `| NFR-NN |` の最大番号を取る。計画リポの `gen-plan-ranges.js` が参考行に出すのと同じ規則で、自由なトークン走査はしない（ADR-0093 実測 3）。
- 宣言側は同じ節の `` `NFR-01`〜`NFR-29` `` を読む。書式が崩れていれば例外（fail-loud）。
- 🔴 ADR-0093 決定 3 の範囲（ID レンジの突合ただ 1 つ・読み取り専用の HTTP）に収まるが、**読む対象が公開レンジ表から要求一覧へ広がる**。そのため週次の報告に限り、PR CI には入れない。フォローアップ 3 で NFR が公開表に入ったら取得をそちらへ置き換える。

### 決定 3: 計画側に届かないときは exit 0 のまま、棚卸しが「未確認」として数える。宣言の不読は exit 1

- 届かない（`unverified`・`scanned: 0`）、または一部の種別だけ届かない（`unverifiedKinds`）は exit 0（ADR-0093 決定 3）。**棚卸し報告の節 8 は「指摘なし」と書かず、🔴 未確認として指摘に数える。** 前段が結果を書かなかったときも同じ。
- 宣言が読めない（節が無い・書式が崩れた・ADR の宣言が無い）は `unverified` ではなく `error`・exit 1。計画側の到達性ではなく本リポジトリの欠陥であり、`readPlanIds()` が例外で落とすのと揃える。従前は `planAdrRange()` の null を黙って 3 種の突合へ縮めていた。**IADR-0423 決定 3 の「宣言不読も exit 0」を改める。** この 1 点は PR CI にも及ぶが、宣言が崩れていれば `check-trace-blocks` / `check-commit-messages` も既に落ちる。
- ずれを検知したのに起票できない（token 不在・API 失敗）も exit 1。ジョブが赤になれば `report-failure` が ci-failure issue を立てる。棚卸し本体は `!cancelled()`（自己試験が通っていること）で前段の失敗に巻き込まれずに出る。

## 理由

- PR CI の警告は既に出ていた。欠けていたのは「作業になること」と「NFR を見ること」であり、決定 1・2 はちょうどその 2 点を埋める。
- 計画 ADR-0048 決定 2 を崩さない。計画側の取得は読み取り専用の HTTP で、必須チェック・ビルドの前提にしない。新たに足す書き込みは本リポジトリの issue だけである。
- 「黙って緑にしない」を報告の数え方で担保する。届かない週は指摘として残るので、棚卸し issue の「指摘 0 件」は「計画側と突き合わせて一致した」ときだけになる。

## 結果

- 良い影響: ずれは週のうちに単独の issue になり、窓の開始（起票）と終了（`Closes`）が記録に残る（ADR-0093 フォローアップ 4 の数え方の材料）。NFR 採番の宣言が初めて突き合わされる。
- 悪い影響・トレードオフ:
  - 窓は最大 7 日（週次）。PR CI の警告は従来どおり出るので、実際にはそれより早く目に入ることもある。
  - NFR の取得は要求一覧のファイル数 ＋ 1 回の API 呼び出しになる（現状 2 回）。
  - AST 版とは NFR の有無が違う（AST の宣言は「NFR はレンジを持たない」）。乖離は受容する（ADR-0048 決定 6）。

### 実測した変異

自己試験（`check-planning-adr-range.js` 34 件・`backlog-audit.js` 13 件）と `scripts.repo.test.js` の新設 3 件に対し、次の変異はすべて落ちた。

| 変異 | 落ちた試験 |
| --- | --- |
| `exitCodeFor` を常に 0 | 自己試験・実バイナリ |
| 宣言不読を `unverified` へ戻す | 自己試験・実バイナリ |
| ADR の宣言の null を黙って許す（従前） | 自己試験 |
| NFR の行頭セル固定を外す（自由走査） | 自己試験 |
| `unverifiedKinds` を常に空にする | 自己試験・実バイナリ（節 8） |
| 既存 issue をマーカーで絞らない | 自己試験 |
| 節 8: 未確認を指摘に数えない | 棚卸しの自己試験・実バイナリ |
| 節 8: 読めない結果ファイルを指摘なし扱い | 棚卸しの自己試験 |
| ワークフローから `--with-nfr` を外す | `scripts.repo.test.js` |
| `behind` 判定を `>=` へ | 自己試験 |
