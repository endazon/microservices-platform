# IADR-0665: llm 層の呼び出しの上限（#2035 / E-70）

> 実装リポジトリ内の意思決定記録（Implementation ADR）。1 ファイル = 1 意思決定。

- 状態: Accepted
- 日付: 2026-10-31
- 決定者: claude（#2035）

## 起点・関連

- 起点 issue: #2035（#2013 の分割表 E-70）。網羅表の M-031（SC-01 の質問 1 件）と M-052（SC-08 の分析 1 件）。
- 受け入れ基準: 1 実行の LLM 呼び出しが 2 以下（`page.route` で `POST /search` `POST /analysis*` の回数を数え、超過で fail）。索引なしは skip。
- 前提: IADR-0569（層と opt-in）、IADR-0624（live の config）、IADR-0625（使い捨てのスタック）、IADR-0627（`E2E_SEARCH_HITS`）。

## コンテキストと課題

- MSP の LLM の費用には、自動の上限統制が無い（Alertmanager の配備までは月次の手動確認）。基準書 §6.2 は、e2e の上限を「週 1 回・1 実行 2 呼び出し」と置いた。
- 層 `llm` の project（workers 1・retries 0）は既に在るが、spec が 0 件だった。
- e2e-live の使い捨てのスタックは `LLM_KEYLESS=1`（鍵なし）である。後段は LLM の不調として縮退し、出典つきの縮退の文を返す。

## 決定

1. **上限は 1 試験 1 回 × 2 件 × retries 0 = 1 実行 2 回。** 定数と数え方は `e2e/live/support/llmBudget.ts` だけに置き、spec と L1 が同じ定数を読む。
2. **数えるだけでなく止める。** `page.route` で `POST /bff/search` と `POST /bff/analysis/*` を受ける。上限の内は `continue` し、超えた要求は `abort` して後段へ届けない。止めた要求は記録し、試験の終わりに fail させる。
   - 数えてから fail するだけだと、超過の要求はすでに費用を出した後になる。
   - 一致は完全一致（`/bff/search`）と区切りつきの前方一致（`/bff/analysis/`）である。名前が前方一致するだけの別の口は数えない。
3. **索引の待ちに LLM の口を使わない。** 対象範囲の候補（`POST /bff/attribute-values`）は索引から引き、LLM を呼ばない。ここに seed 文書の部門が出るまで、画面を開き直して待つ。
4. **本文の中身は見ない。** 判定は次の 4 つに揃え、実の回答と縮退の文のどちらでも通す。
   - 1 回だけ送った。
   - 応答が 200。
   - 出典に seed 文書が在る。
   - 失敗・空の表示が無い。

   鍵なしのスタックでも、試験が意味を持つ（出典・画面の完了・上限）。
5. **L1 の門**（`live-opt-in.smoke.spec.ts`。稼働の環境に触れない）。
   - 定数が基準書の値であること。
   - 数える口と数えない口の判定。
   - 数え手が超過を止めること。
   - `E2E_LAYER=llm` の `--list` が project `llm` にちょうど `1 実行の上限 ÷ 1 試験の上限` 件であること。
   - project `llm` の retries が 0 であること。
   - 既定の層に llm の試験が載らないこと。

   試験を足す・上限を変える・retries を足す・一致を緩める変更は、ここで赤になる（変異で確かめた）。
6. **`e2e-live.yml` は dispatch の `layer` の説明に上限を書くだけにする。** 週次の cron は置かない（流す判断はオーナー）。

## 却下した案

- **数えて終わりに fail するだけ**: 受け入れ基準の字面は満たすが、超過の要求は後段へ届いて費用を出す。
- **`POST /bff/search` で索引を待つ**: 待つたびに上限を使う（後段の再順位付けが LLM を呼び得る）。
- **鍵なしでは llm 層を止める（または skip する）**: 全 skip になり、`check-e2e-skips` が赤にする。縮退の形でも、出典・完了・上限は試せる。
- **実の回答かを見る新しい opt-in（`E2E_LLM_ANSWERED` など）**: 本文の質は E2E の対象外である（基準書 §6.1。費用は Grafana）。門を増やさない。

## 結果・残余リスク

- 1 実行の呼び出しは、ブラウザが送る要求で 2 以下になる。
- 数えるのは**ブラウザの要求**である。後段の 1 回の質問の中で、再順位付けと回答生成の 2 回 LLM を呼ぶ構成では、ゲートウェイ側の呼び出しはこの数より多い。基準書の数え方（画面の操作の回数）に合わせた。ゲートウェイ側の回数は Grafana で見る。
- 使い捨てのスタックでは、本文は縮退の文である。実の回答の経路（ゲートウェイ → Claude）は PoC で流したときだけ通る。コーディネータの範囲（2026-10-31）により、実鍵での実行はしていない。
