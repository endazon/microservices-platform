# IADR-0506: blocked の再検証期限は issue の定型欄で持ち、台帳ファイルは置かない（#1773）

- 状態: Accepted
- 日付: 2026-10-07
- 決定者: claude（#1773。第 4 回全体監査 B-16 / C-1。作業仕様書 20261007_1773）

## 起点・関連

- 起点 issue: #1773（第 4 回全体監査 B-16 / C-1）
- 上流: 運用ガイド §6「『AI だけでは完結しない』判定には再検証の期限を付ける」「実装リポ側には blocked ラベルと台帳記録を残す」
- 比較対象: AST の `docs/blocked-tasks.md`
- 実現手段: `scripts/backlog-audit.js`（週次。#1347）・棚卸し issue #1356
- 基点コミット: `origin/develop` `cffeef4e`

## コンテキストと課題

- open の blocked 8 件（#380 #457 #1237 #1378 #1396 #1517 #1534 #1740）のどれにも再検証の期限が無かった。`CLAUDE.md` / `AGENTS.md` はガイド §6 の「棚卸しごとに再検証」だけを写し、「期限を付ける」を落としていた。
- 週次棚卸しは `updated_at` で日数を測っていた。ラベル操作で日数が戻り（#1237 / #1378 は 2026-09-26 のラベル付与で戻った）、参照されても戻らない（#1534）。
- MSP には AST の `docs/blocked-tasks.md` に当たる台帳が無い。

### AST の台帳の実測（2026-10-07）

AST の `docs/blocked-tasks.md`（隣接クローン `../ai-stock-trading`）: 785 行、`### ` 見出し 26 個、冒頭の「最終更新」行 14 個、「最後に測った時点」欄 19 個。冒頭の更新履歴の多くは「issue 側で起きたことを台帳へ写した」記録である（例: B-4 の #584 行を解消済みへ、A-14 を是正）。

## 検討した選択肢

| | A. AST 型の台帳（`docs/blocked-tasks.md`）を置く | B. issue の定型欄 ＋ 棚卸しの報告を台帳にする（**採用**） |
| --- | --- | --- |
| 正本の数 | 2 つ（issue と台帳）。片方が古くなる | 1 つ（issue）。報告は毎週作り直される |
| 再測定手順 | 台帳に書く | issue の本文・コメントに既にある（#1237・#1378・#1396 は手順を書き切っている。#1534 は Runbook がある） |
| 「最後に測った時点」 | 手で書く欄 | 最後のコメントからの日数を棚卸しが出す |
| 期限切れの検知 | 人が台帳を読む | 棚卸しが機械で挙げる |
| 費用 | 台帳の維持（AST は 2 か月で更新 14 回） | 欄 1 つと棚卸しの数十行 |

8 件という規模では、A の維持費に見合う利点が無い。A が勝つのは「issue を持たない blocked 項目」（実機の確認手順だけがある等）が多いときだが、MSP の blocked はすべて issue である。

## 決定

1. **台帳ファイルは置かない。** 期限は issue 本文の定型欄（または後からのコメント）に `再検証期限: YYYY-MM-DD` で書く。最後に書かれたものが効く。issue テンプレート（`ai-implementation.yml` / `implementation-task.md`）に任意欄を足す。
2. **ガイド §6 の「台帳記録」は週次棚卸しの報告で満たす。** `scripts/backlog-audit.js` は blocked issue の全件を、ラベル・期限・最後のコメントからの日数つきで並べる。期限が無いもの・期限の日を過ぎたものを指摘として数える。素の `blocked`（種別なし）は報告で目立たせる。
3. **経過日数は最後のコメントの作成時刻から数える**（コメントが無ければ issue の作成時刻）。`updated_at` は使わない。ラベル操作では戻らず、再検証の記録（コメント）で戻る。
4. `CLAUDE.md` / `AGENTS.md` の該当行に「期限を付ける」と欄の名前を足す。

## 結果・影響

- 期限の日以降に走る週次棚卸し（月曜 21:00 UTC）が、その issue を「再検証が要る」として挙げる。8 件の期限は 2026-10-19 にした。
- 棚卸しは blocked issue 1 件につきコメント一覧を 1 回取る（8 件で 8 回）。
- 参照されたこと（他 issue からのリンク）は日数を戻さない。再検証したらコメントを残す。

## 残余リスク

- 期限の読み取りは「`再検証期限` の後の最初の日付」である。本文で別の意味で `再検証期限` と書いて日付を続けると、それを期限と読む。
- 期限を毎回先送りするだけの運用は止められない。報告に最後のコメントからの日数を並べ、人が見て気付く形に留める。
