# IADR-0173: 別紙化は見出しをスタブとして残す（#686 / #623 段 1）

- 状態: Accepted
- 日付: 2026-08-11
- 決定者: claude（起案・実装）

## 起点・関連

- **NFR**（運用保守）。実装 issue: **#686**（**#623 の子**）
- 計画: **[IADR-0172](./IADR-0172_required-rules-slimming-plan.md) 決定 3 の段 1**（#684 で確定）
- 作業仕様書: [20260811_issue-686](../specs/20260811_issue-686_commit-rules-annex.md)

> **★ 値の基準時点は develop `750c877`（2026-08-11 実測）である。**

## 文脈 —— **確定済み記録は「節名」で規約を引いている**

[IADR-0172](./IADR-0172_required-rules-slimming-plan.md) 決定 2 は「**入口のパスを変えない**」を確定した。根拠は
**確定済み記録から 28 件のリンクが張られており、規約上それらを追随させられない**ことである。

**段 1 に着手して、同じ制約が「もう 1 段細かい粒度」でも効くことが分かった。**

**同じ行に `rules/traceability` と節名を併記した引用**を全数で走査した結果:

```
ファイルと節名を併記した引用: 43 件（うち確定済み記録 18 件）
```

| 節 | 計 | **確定済み** |
| --- | ---: | ---: |
| 複数プロジェクトを跨ぐ場合の ID 修飾 | 12 | **5** |
| 起点 ID の種別 | 10 | 4 |
| 採番衝突時の改番手順 | 9 | 5 |
| 是正・追随の母集合の取り方 | 5 | 1 |
| クロスリポジトリの issue / PR 番号の修飾 | 3 | 1 |
| **PR タイトル（スカッシュ後件名）の検査** | 1 | **1**（`IADR-0145:26`） |
| CHANGELOG 生成時の誤記補正・除外規定 | 1 | 0 |
| 検査対象から除外する自動コミット | 0 | 0 |

**`IADR-0145:26` は確定済みの決定であり、次のように引いている。**

```
- 規約: [`.claude/rules/traceability.md`](…)「PR タイトル（スカッシュ後件名）の検査」
```

**節名ごと消すと、この引用が指す先が消える。**
[IADR-0166](./IADR-0166_status-vocabulary-and-record-rewrite-boundary.md) と `.claude/rules/traceability.md` 自身が**確定済み記録の書き換えを禁じている**ため、
**引用側を直す手段が無い。**

> **★ [IADR-0172](./IADR-0172_required-rules-slimming-plan.md) 決定 2 と同じ構造である。** あちらが縛るのは**パス**、こちらは**節名**。
> **リンクが切れないので `check-doc-links.js` は緑のまま通る** —— **機械では捕まらない。**

## ★★ 決定 1: **出した節の見出しは、スタブとして入口に残す**

**本文だけを別紙へ出し、見出しは 1〜2 行のスタブとして入口に置く。**

| | 扱い |
| --- | --- |
| **見出し** | **入口に残す**（確定済み記録の引用が生きる） |
| **本文** | 別紙へ出す |
| **スタブの中身** | **いつ読むか ＋ 別紙へのリンク** |

### ★ スタブは妥協ではない —— 導線そのものである

[IADR-0172](./IADR-0172_required-rules-slimming-plan.md) 決定 4 は「**別紙化するなら『いつ読むか』の導線を入口に残す**」を要求している。
**スタブは、その導線の置き場所として最も自然な位置**（＝もともと本文があった場所）にある。

**1 つの手当てで 2 つを満たす**:

1. **確定済み記録の引用が生き続ける**（本決定）
2. **導線が残る**（[IADR-0172](./IADR-0172_required-rules-slimming-plan.md) 決定 4）

### 棄却した案

| 案 | 棄却理由 |
| --- | --- |
| **A: 節ごと削除する** | **確定済み記録 18 件の引用が指す先を壊す。** 直す手段が規約上無い |
| **B: 引用側を書き換える** | **できない。**[IADR-0166](./IADR-0166_status-vocabulary-and-record-rewrite-boundary.md) が確定済み記録の書き換えを禁じている |
| **C: 別紙側に同名の見出しを置くだけ** | 引用は**入口ファイルを名指ししている**。別紙に置いても入口には無い |

## ★ 決定 2: **規範は別紙へ出さない。出すのは説明・仕様詳細だけ**

[IADR-0172](./IADR-0172_required-rules-slimming-plan.md) 決定 3 は段 1 を「約 11,000B」と見積もっていた。**楽観である。**

**規範（書く側が事前に知らないと CI で落ちるもの）を別紙へ出すと、
「別紙を読まなかった」だけで落ちる。** 機械が止めるのは事実だが、**止まってから読むのでは手戻りになる。**

> **★ 「機械が強制しているから読まなくてよい」が成り立つのは、説明の部分だけである。**

| 区分 | バイト |
| --- | ---: |
| **出す** —— PR タイトルの検査 7,954 ＋ 除外する自動コミット 442 | **8,396** |
| 入口に残す —— 前文 2,172 ／ 採番衝突時の改番手順 794 ／ クロスリポジトリの番号修飾 2,186 | 5,152 |
| **スタブで戻る分** | **約 −300** |

**段 1 の実効は約 8,100B。** 着地は作業仕様書 §着地の実測 に記録する。

## 決定 3: **別紙は `docs/` 配下に置く**

`.claude/rules/traceability.md:164` が **`../../docs/specs/...` を相対リンクで指している**（実測）。
**`.claude/rules/` から `docs/` を指す形は既に成立している**ので、新しい置き場所の規約を作らない。

## ★ 限界（明示する）

- **機械はこの型を検出しない。** 節名ごと消してもリンクは切れず、`check-doc-links.js` は緑のまま通る。
  **本 ADR の決定は回帰テストで固定するが、それは本 PR が出した 2 節に対してだけ**である。
- **別紙化しても総量は減らない**（[IADR-0172](./IADR-0172_required-rules-slimming-plan.md) の限界を引き継ぐ）。**減るのは毎セッション読む量だけ。**
- **走査は「引く式」の側で落ちた。** 初版は `line.includes(見出し)` の一方向で、
  **`IADR-0145:26` を取りこぼした**（見出しは「…の検査**（再発防止）**」、引用側が短い）。
  括弧を除いて正規化し両方向で包含を見る式へ直し、**39 → 43 件**になった。
  **手で見つけた 1 件が走査に出てこないことで気づいた** —— **素の当たり数を信じない。**

## 結果

- 出した 2 節（`PR タイトル（スカッシュ後件名）の検査（再発防止）` / `検査対象から除外する自動コミット`）の
  **見出しをスタブとして入口に残し**、本文を別紙へ移した
- **規範 3 つ**（節の前文 / 採番衝突時の改番手順 / クロスリポジトリの番号修飾）は**入口に残した**
- 回帰テスト: **スタブの存在**・**規範の残存**・**入口のパス不変**を固定する

## 後続への申し送り

**段 3（複数プロジェクトを跨ぐ場合の ID 修飾）は確定済み引用が 5 件で最多である。**
**本決定のスタブ方式が必須**であり、**節ごと消す案は採れない。**
