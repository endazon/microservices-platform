# IADR-0246 封じ込め検査器の不可視領域と、その塞ぎ方の判断

## 状況

`#903` の U4 変異試験で、`scripts/check-backend-libraries.js` に
**現存 0 件だが検査器としては素通りする**領域が 3 種類実測された。

| ID | 内容 | 検査器 | 最終防衛線 |
| --- | --- | --- | --- |
| SX-1 | `dist/` という名のディレクトリ配下の `.cs` | EXIT=0 | MSBuild（`dist\Sneak.cs(1,57): error CS1061`） |
| SX-2 | UTF-16LE の `.cs` | EXIT=0 | MSBuild（`Sneak16.cs(1,59): error CS1061`） |
| A3 / A5 / A6 | 値レベルの変異（代入値・前置の有無・区切り文字） | EXIT=0 | 既存テスト |

## 決定の立て方: 「検査器を強くする」を自明の解にしない

`#885` は「候補 A は精度 1/38 ≈ 2.6% で成立しない、だから足さない」という結論に至っている。
**先例があるから同じ結論、ではない。費用を測ってから決める。**
実測の結果、**同じ「不可視領域」でも費用が真逆**であり、結論が分かれた。

## 決定 1: SX-1 / SX-2 は塞ぐ（費用が実測でゼロ）

### 実測（対照つき）

対照を取ることが要る —— 素通りが「検査器が壊れている」のか「その形を見ていない」のかを分けるため。

| | 塞ぐ前 | 塞いだ後 |
| --- | --- | --- |
| `dist/` 配下に禁止シンボル | EXIT=0 🔴 | **EXIT=1** |
| **同じ内容を `dist/` の外へ**（対照） | EXIT=1 ✓ | EXIT=1 |
| UTF-16LE の `.cs` に禁止シンボル | EXIT=0 🔴 | **EXIT=1** |
| **素の状態**（偽陽性の確認） | EXIT=0 | **EXIT=0** |

### 費用

| 項目 | 実測 |
| --- | --- |
| 追跡下の `dist/` 配下ファイル | **0 件**（検査対象拡張子も 0 件） |
| 作業ツリーの `dist/` 配下 `.cs` / `.csproj`（未追跡込み） | **0 件** |
| `dist` を SKIP から外したときの走査時間 | **118ms → 128 / 131ms**（3000 ファイルの合成 `dist` を置いて計測。`dist` を skip したままの 165ms より速く、**計測ノイズの範囲**） |
| 非 UTF-8 の `.cs` | **0 件**（498 件を BOM で分類: UTF-16 BOM 0 / UTF-8 BOM 15 / BOM なし 483） |

**偽陽性は構造的に増えない**（新たに一致するファイルが 0 件）。
`#885` とは条件が逆である —— あちらは偽陽性が支配的、こちらは偽陽性ゼロ。

`utf8` 固定は「**コンパイラが読めるファイルをスキャナが読めない**」というスキャナ側の素の欠陥である。
UTF-16LE を `utf8` で読むと識別子が NUL 混じりへ化け、**どの正規表現にも一致しない**。

### 🔴 「0 件だから安い」ではなく「0 件である限り安い」

`dist` を SKIP から外す費用がゼロなのは、**たまたま本リポジトリに追跡下の `dist/` が無いから**である。
フロントエンドのビルド成果物が追跡下へ置かれる構成に変わる、あるいは `.cs` を含む `dist/` が
生成される構成になれば、**状況が変わる**。

**次に走査が遅くなったとき、原因を探し直さずに済むよう条件を書いておく** ——
`dist/` 配下のファイル数が増えたら、上の表と同じ形（合成 `dist` を置いて前後を計測）で**測り直すこと**。
走査対象の拡張子（`.cs` / `.csproj` / `.props` / `.targets`）が `dist/` 配下に現れるようになった場合は、
除外の是非そのものを再検討する。

## 決定 2: 値レベル（A3 / A5 / A6）は塞がない

### 実測（3 変異とも `BUILD EXIT=0` を確認したうえで測った）

| 変異 | 検査器 | テスト |
| --- | --- | --- |
| A3 手順 5 の値のみ反転（`AlwaysAllowed` → `NotAllowed`） | EXIT=0 | **1 件**落ちる |
| A5 手順 3 の前置を落とす | EXIT=0 | **2 件**落ちる |
| A6 区切りを `-` へ | EXIT=0 | **3 件**落ちる |

### 塞がない根拠

1. **テストが届かない範囲が無い。** 3 変異すべて既存テストで捕まる。
   強化しても**純粋な二重防護**にしかならない。
2. **偽陽性の費用が高い。** 値レベルの検証は C# ソース中のリテラルを判定することになり、
   `PlatformQueueName` の抽出・定数化・命名変更といった**正当なリファクタで落ちる**。
   SX-1 / SX-2 の「偽陽性ゼロ」とは対照的である。
3. **CLAUDE.md の「検査器・規約の追加は『同型の事故が 2 回起きたら』を条件とする
   （1 回目は記録に留める）」** に対し、**発生 0 回**である。

### 🔴 意図した不検出を、意図として固定する

`--self-test` に「規則 5 は代入値を見ない」「規則 5 は前置の有無を見ない」を**明示的な期待として**置いた。

**これが無いと、後から見た人が「強化したのに値レベルが素通りする」を欠陥として読む。**
**「証明力のない変異」と「検出漏れ」の区別を、機械に埋め込む。**

## 検出しないこと

- **値レベルの正しさ**（決定 2）。テストの責務である。**検査器を「配線の正しさチェック」だと
  誤認して運用しないこと** —— 見ているのは「配線の存在」だけである。
- **BOM 無しの UTF-16。** C# コンパイラも BOM 無し UTF-16 を既定では読まないため射程外とする。
- **`dist/` 以外の名前**でビルド生成物を置いた場合の走査費用。上の条件で測り直す。
- **MSBuild が拾う範囲全般。** 本検査器は静的走査であり、コンパイルの代わりではない。

## 影響

- `SKIP_DIRS` から `dist` が消える（`node_modules` / `bin` / `obj` / `.git` / `coverage` は残る）。
- `.cs` の読み込みが `readSource`（BOM 判定つき）経由になる。
- `--self-test` は 108 → **117 件**。

## 代替案

- **SX-1 を `dist` の除外を残したまま塞ぐ**（パス条件で `src/*/frontend/**/dist` だけ除外する等）
  —— 走査費用が実測でノイズ以下だったため、条件を増やす複雑さに見合わない。
- **`.cs` をすべてバイナリで読んで判定する** —— BOM 判定で足りる。
- **値レベルの検証を検査器へ入れる**（決定 2 で棄却）。
- **追跡下のファイルだけを走査する**（`git ls-files`）—— `dist/` 問題は消えるが、
  **未追跡の `.cs` も MSBuild はコンパイルする**ため別の不可視領域が開く。採らない。
