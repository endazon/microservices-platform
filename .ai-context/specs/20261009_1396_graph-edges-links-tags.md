# 仕様書: 知識グラフの辺を明示リンクと共有タグで結ぶ（#1396）

> 本仕様書は実装着手前に作成する。判断の記録は **IADR-0522**（採番は push 時点の最大 + 1。§採番）に置く。

## 起点となる計画書（トレーサビリティ）

- 要求: **FR-17**（文書間リンク・被参照・型と出所・ホップごと ABAC）。クラスタは FR-18 / FR-10（SC-10 の未要約クラスタ数）と SC-18 の材料。

**結論**: 0 本の直接の原因は「稼働の文書がリンクを持たない」（f-3）と「タグを辺にする経路が無い」（f-1）。リンク側には f-4・f-5 の取りこぼしがあり、Wiki・Obsidian の資料を入れても辺が欠ける。

## 対象範囲

- 対象（GraphService のみ）:
  1. **共有タグの辺**: `DocumentUpdated.Tags` を `graph_document_tags` へ保持し、同じタグを持つ文書の組を `related`（出所は自動抽出）で結ぶ。**ハブの上限**つき。
  2. **Wiki のリンクの解決**: `doc/<GUID>` の形（相対・絶対 URL・ロケール接頭辞つき）を文書 ID で解決する。
  3. **後着の解決**: 文書の新規・改名・撤収・削除のときに、その題名（と `doc/<ID>`）を指すリンクを持つ文書の辺を、保存済みのリンク（種別・アンカー・明示型つき）から作り直す。
  4. 削除・撤収（露出 OFF）でタグと辺を片付ける。利用者付与・AI 承認が共有タグの辺と同じ関係を張るときは、その行を引き取る。
- 対象外: 契約（REST / gRPC / OpenAPI / orval）の変更、SC-18 の表示、同じフォルダ・埋め込み類似度の辺（裁定で不採用）、稼働クラスタでの実行（運用者の手順は IADR §運用）。

## 設計

### 共有タグの辺

- 保持: `graph_document_tags(DocumentId, Tag)`（主キー 2 列・`Tag` に索引）。`Tag` は前後の空白を落として小文字化（不変カルチャ）。空は捨て、200 字で切る。
  **受信のたびに全量で置き換える**（本文指紋に依らない。タグはイベントに載っており本文を読まないので ADR-0050 決定 3 の契機を増やさない）。
- 辺: 2 文書が**ハブでない**タグを 1 つ以上共有するとき、その組に `related`（対称）・出所 `auto` の辺を **1 本**張る。区別のため辺に `AutoSource`（`link` / `tag`。自動抽出以外は NULL）を足す。
- **ハブの上限**: 文書数が `TagEdges:MaxDocumentsPerTag`（既定 **50**＝探索のハブ次数上限 `GraphTraversal.MaxHubDegree` と同値）を**超える**タグからは辺を作らない。
  理由: N 文書のタグは N(N−1)/2 本を作る。上限を超えたタグの所属文書はそれだけで次数が探索のハブ上限を超え、中継点として使われない（ADR-0035 決定 1）—— 行数だけが増えて探索に効かない。
  タグノードは作らない（計画のノードは文書だけ）。
- 差分: 当該文書の組だけを作り直す。**タグの文書数が上限を跨いだ**（ハブになった・ハブでなくなった）ときは、そのタグの所属文書の組も作り直す。
- 同じ組に同じ型・アンカーの辺が既にあれば重ねない（一意索引 `ux_edges`）。リンク抽出が同じ関係を必要としたら共有タグの辺を**引き取って**リンクの辺へ変える（行を消して入れ直さない —— 同じ保存の中の削除と挿入で一意索引に当たらないように）。
  リンクが消えた後に組がタグを共有していれば、同じ保存の中で共有タグの辺へ戻す。
- 利用者付与・AI 承認が共有タグの辺と同じ 5 つ組を張るときは、その行を利用者付与・AI 承認へ引き取る（409 にしない。タグが外れても人の辺は消えない —— ADR-0033 決定 6）。

### Wiki のリンク

- 標準 Markdown リンクの宛先が `…/doc/<GUID>`（先頭スラッシュ・ロケール接頭辞・`http(s)://` の URL を許す）なら、名前を `doc/<GUID 小文字>` とする。
- 解決規則（`LinkTargetMatcher`）の先頭に「`doc/<GUID>` は文書 ID の一致で解決、無ければ不在」を足す。辺を張る側と未解決リンク数の側が同じ規則を通る（IADR-0389 決定 3）。

### 後着の解決

- `document_link_targets` を「名前だけ」から「1 リンク 1 行（名前・種別・明示型・アンカー）」へ広げる（列を足す。既存行は種別 NULL）。未解決リンク数は (起点, 名前) で重複を落として数える。
- 文書の**新規**・**改名**のとき、新旧の題名（大小文字を無視）か `doc/<ID>` を指す行を持つ起点、および当該文書へリンク由来の辺を持つ起点について、保存済みの行から辺を作り直す（本文は読まない）。
  解決の候補は保存前の当該文書の題名で上書きする。**種別 NULL の行（移行前）を持つ起点は作り直さない**（型が分からない行で作ると辺の型を落とすため）。
- 撤収・削除のときも同じ起点を作り直す（候補から当該文書を外す。同名 2 件の曖昧が解ける）。

### ABAC

- 辺は既存の `edges` 表に入るので、読み取りは既存の型ゲート（両端の可視性の連言。IADR-0242）をそのまま通る。新しい読み取り経路を作らない。
- 個人資料は既存どおりクラスタ検出の入力から外れる（ADR-0035 決定 8）。

## 受け入れ基準

1. 同じタグを持つ 2 文書の間に `related`・出所 `auto`・`AutoSource=tag` の辺が 1 本でき、タグを外すと消える（陽性対照つき）。
2. 2 つのタグを共有しても辺は 1 本。大小文字・前後の空白だけが違うタグは同じタグ。
3. 上限を超えたタグからは辺を作らない。上限ちょうどは作る。跨いだときは所属文書の辺が増減する。
4. リンク由来の辺と共有タグの辺が同じ組に重ならない。リンクが消えたら共有タグの辺へ戻る。利用者付与・承認済みの辺を上書きしない。
5. `/doc/<ID>`・`/en/doc/<ID>`・`https://…/doc/<ID>` のリンクが文書 ID で解決する。存在しない ID は未解決に数える。
6. 先に届いた文書のリンクが、後から届いた相手（題名・`doc/<ID>`）へ辺を張る。改名で外れたリンクの辺は消える。種別 NULL の行しか持たない起点は作り直さない。
7. 撤収・削除で当該文書のタグと辺が消え、上限を下回ったタグの所属文書の辺が戻る。
8. 既存の試験（T-01〜T-79）が緑。`dotnet format` 差分なし。マイグレーションがモデルと一致する。
