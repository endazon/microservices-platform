# 仕様書: エッジの /mcp（外部 AI エージェントの入口）（#2045）

> 本仕様書は実装着手前に作成した（着手 2026-10-23）。実装の基点は MSP `origin/develop` `bfca304c`。判断は IADR-0594。

## 起点となる計画書（トレーサビリティ）

- 要求: FR-16（MCP サーバーとして外部 AI エージェントへ公開する）／UC-08・UC-09
- 計画 ADR: **ADR-0024**（入口は Istio Ingress Gateway の `/mcp`）・ADR-0021（入口・ルーティング・レート制限は Istio Ingress Gateway）・
  ADR-0134（`/mcp` はトークンの audience を MCP サーバーに限る）・ADR-0005（メッシュ）
- 関連 IADR: IADR-0348（同期プロトコルの経路＝エッジから内部サービスへ直接通す先例と、その L7 の DENY・opt-in の既定）・
  IADR-0297（「入口は公開していない」を受容として残した記録。本 IADR がそれを解く）・IADR-0516 / IADR-0523（`/mcp` の audience 検証）・
  IADR-0589（egress の既定拒否）・IADR-0590（mTLS STRICT の既定）

## 受け入れ基準（計画と issue から確定）

1. **AC1（ADR-0024・入口）**: 本番像のチャートで、エッジ host の `/mcp`（完全一致）と `/mcp/` 配下が MCP サーバーの Service へ届く経路を持てる。
   **rewrite しない**（公開パス＝`MapMcp("/mcp")` の契約パス）。catch-all（SPA）より前に置く（Istio は先勝ち）。
2. **AC2（露出面）**: エッジから届くのは `/mcp` の面だけである。同じポートに同居する管理 REST（`/mcp-clients*`）・OpenAPI・
   自己申告（`/internal/*`）・ヘルスはエッジから届かない。
   - 経路: 前置を `/mcp` の文字列前置にしない（Istio の `prefix` は文字列の前方一致で `/mcp-clients` を飲む）。`exact: /mcp` と `prefix: /mcp/` に分ける。
   - L7: 経路の制限を VirtualService 1 枚に頼らない。ゲートウェイの Namespace の主体から MCP サーバーへの要求は、`/mcp` と `/mcp/*` 以外を
     `AuthorizationPolicy`（DENY）で落とす。名前空間の中（BFF の管理 API の中継）・プローブは当たらない＝変わらない。
3. **AC3（L3/L4）**: NetworkPolicy の既定拒否の下で、ゲートウェイの Namespace → MCP サーバーの当該ポートだけを開ける（経路と同じ条件・同じ単一情報源）。
4. **AC4（認証なしの公開面を作らない）**: エッジ経由の `/mcp` は、既存の MCP サーバーの認証（`McpAudience` スキーム: 署名・発行元・期限・
   **audience=`mcp-server` だけ**）を必ず通る。エッジは要求をそのまま渡し、認証を緩める・別経路で迂回させる手段を持たない。
   トークン無し・platform の audience のトークンは 401、MCP クライアントのトークンは通る。
5. **AC5（既定）**: 本番像の既定は **opt-in（`edge.mcp.enabled: false`）**。無効なら経路・L7 の門・NetworkPolicy の穴のどれも描かない
   （稼働中の配備は 1 バイトも変わらない）。有効化は運用者の明示の判断とする（理由は IADR-0594: クライアント単位のレート制限が未配備）。
6. **AC6（経路 B）**（経路の絞り込み 1 層だけ。L7 の門・NetworkPolicy は本番像だけ）: ローカルの 2 つのエッジ（Istio の overlay・Traefik の Ingress）にも同じ契約（`/mcp` 完全一致＋`/mcp/` 配下 → mcp-service:8080、rewrite 無し、
   catch-all より前）を置く。compose には置かない（下の「対象外」）。
7. **AC7（門で固定）**: 統合スタック（稼働の Keycloak・稼働のエッジ）で、エッジ経由の `/mcp` が
   (a) トークン無し 401・(b) platform の audience のトークン 401・(c) 無人の MCP クライアントの実トークンで `initialize` が JSON-RPC の結果を返す・
   (d) エッジ経由の `/mcp-clients` が MCP サーバーの管理 API に届かない（JSON の一覧が返らない）、を測る。
8. **AC8（試験で固定）**: チャートの描画を `helm template` で読み、Istio の評価規則で呼び出し元の一覧へ当てる試験を置く。
   経路の制限を外す・from を変える・前置を文字列前置へ戻す・既定を true にする、のいずれでも赤になる（変異）。

## 母集合（規則 9: 誤りの側の文字列で引いた）

- `git grep -n "/mcp"` を `deploy/`・`scripts/`・`docs/`・`.github/` で引いた。エッジの経路定義は 4 つ:
  `deploy/helm/microservices-platform/templates/edge.yaml`（本番像）・`deploy/local/edge-istio/virtualservice-app.yaml`（経路 B の Istio）・
  `deploy/local/edge/platform-frontend-ingress.yaml`（経路 B の Traefik）・`src/platform/frontend/Caddyfile`（compose／frontend Pod の `/bff` の中継）。
  いずれも `/mcp` を持たない（コメントのみ）。
- MCP サーバーの公開ポートと認証: `services.mcp.port: 8080`（chart）／`expose: 8080`（compose）。1 つのポートに `/mcp`（`McpAudience`）・
  `/mcp-clients*`（既定スキーム `platform-api`）・`/openapi/v1.json`・`/internal/introspection`・`/health/*` が同居する（`Program.cs`）。
- NetworkPolicy / AuthorizationPolicy: `templates/networkpolicy.yaml`（`allow-edge-ingress-to-{bff,frontend,document-service}`）・
  `templates/edge.yaml`（`document-service-edge-sync-only`）・`templates/istio-mtls.yaml`（PeerAuthentication）・`networkpolicy-egress.yaml`
  （egress の既定拒否は名前空間の中への応答に影響しない。ゲートウェイからの ingress は既定拒否の対象で、穴が要る）。
- 文書: `docs/api/FR-16_mcp-server.md`（「入口は Ingress Gateway の `/mcp`」＝実体なし）・`docs/security/security.md`（「入口は BFF に一本化。例外は同期の 1 前置だけ」）・
  `deploy/local/edge-istio/README.md`・`deploy/local/edge/README.md`。`.ai-context/adr/IADR-0297` の受容の記述は凍結記録なので書き換えない（IADR-0594 が解く）。

## 対象外（理由つき）

- **クライアント単位のレート制限**（11_mcp-server-integration §5・ADR-0021）。初期値は「実装時に負荷試験で確定」で、負荷試験は未実施（FR-16 の
  p95 と同じ #189 の系統）。クライアント単位に数えるにはエッジでトークンの主体を読む器（JWT の主体をヘッダへ出す・グローバルのレート制限サービス等）が要り、
  リポジトリに先例が無い。**本 PR は入れない。** そのため本番像の既定を opt-in に倒す（AC5）。段取りの裁定は planning#828 へ環流した。
- **エッジでの JWT の再検証（Istio の `RequestAuthentication`）**。IADR-0594 の検討した選択肢を参照（MCP サーバーの Pod へ当てると BFF の管理 API の中継
  〔audience が違う〕を巻き込み、ゲートウェイへ当てると同期プロトコルの不透明トークンを巻き込む。どちらも既存の正当な要求を落とす）。
- **compose**。compose は配備形ではなく、エッジ（Istio）を持たない。frontend の Caddy に `/mcp` の中継を足すと、同じイメージを使う k8s の frontend Pod が
  catch-all 経由で `/mcp` を中継し、本番像の opt-in を迂回する経路になる。置かない。
- **OAuth の保護リソースのメタデータ（RFC 9728）による発見**。MCP サーバーは現在それを返さない。有人のエージェントの対話的な発見は別の作業である（報告の未決事項）。

## 変異（試験が赤になることを確かめる）

- チャートの DENY の `notPaths` を外す／from を別の Namespace にする／経路を `prefix: /mcp` へ戻す／values の既定を true にする → `helm-edge-mcp-entry.test.js` が赤。
- overlay の経路を `prefix: /mcp` へ戻す／catch-all の後ろへ動かす → `k8s-local-up.test.js` が赤。
- 統合スタックの門（M13）の判定関数: 401 を 200 と取り違える・SPA の HTML を JSON-RPC と取り違える → `--self-test` が赤。
