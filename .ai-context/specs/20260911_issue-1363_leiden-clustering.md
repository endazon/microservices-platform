## 設計

### 1. 入力（何をクラスタリングするか）

- **ノード**: `graph_documents` のうち**個人資料でないもの**。
  🔴 `ADR-0035` 決定 8 が「**共有グラフは個人資料を含まない 1 つとする**（決定 3 のクラスタリング
  入力除外と同じ）」と明記している。判定は既存の `GraphDocumentScope.IsPrivateNote`（集合帰属で
  判定する。否定形で書かない）。
- **辺**: 両端点が上のノード集合に入る `edges`。**無向**として扱う（辺の型の対称・非対称は
  コミュニティ検出では区別しない —— コミュニティは「密に繋がった集合」であって向きを持たない）。
- **重み**: 辺の型の `EdgeType.Weight`（`ADR-0035` 決定 2 の「辺の型による重み付け」。既定 0.5）。
  同一ノード対に複数の辺があれば重みを合算する。

### 2. アルゴリズム（Leiden）

`Domain/Clustering/LeidenCommunityDetector.cs`。段は Leiden の原論文どおり 3 つ:

1. **局所移動**（modularity の増分が最大の隣接コミュニティへ移す。改善が無くなるまで）
2. **細分化**（各コミュニティの内部でシングルトンから出発し、**連結している相手にしか併合しない**）
3. **集約**（細分化した部分コミュニティを 1 ノードへ畳み、上位の分割を初期分割として次段へ）

**Louvain との差はこの 2 段目である。** Louvain は「分断されたコミュニティ」を生じ得るため計画が
退けている（`ADR-0035` 決定 3）。細分化はその生成経路を塞ぐ。

**決定性**: 乱択を使わない（IADR-0425 決定 2）。細分化の併合先は確率的選択ではなく**増分最大**を採り、
ノードの走査順は**文書 ID の昇順**で固定する。同じ入力からは常に同じ分割が出る。

### 3. クラスタの同一性（日次再検出をまたぐ）

`ADR-0083` 決定 3 の条件 2「**クラスタ構成が変わった後に再生成されていない**」を判定するには、
**昨日のクラスタと今日のクラスタが同じものか**が要る。

- 検出結果（文書 ID の集合）を、既存クラスタと **Jaccard 係数の降順で貪欲に対応づける**。
  **0.5 以上**を「同じクラスタ」とする（過半の構成員を共有する）。
- 対応がついて**構成が変わっていれば** `CompositionChangedAt` を進める。変わっていなければ触らない。
- 対応がつかない検出結果は**新しいクラスタ**、対応がつかない既存クラスタは**消滅**（所属・要約ごと削除）。

### 4. 永続化

| 表 | 内容 |
| --- | --- |
| `graph_clusters` | `ClusterId` / `DetectedAt`（初出）/ `CompositionChangedAt`（構成が最後に変わった時刻）/ `MemberCount` |
| `graph_cluster_members` | `ClusterId` × `DocumentId`（複合主キー） |
| `graph_cluster_summaries` | `ClusterId` × `Confidentiality` / `GeneratedAt`。**要約本文は持たない** —— `ADR-0035` 決定 5 が要約を別系統（別ストア）に持つと定めており、ここが持つのは**再生成の判定に要る時刻だけ**である |

🔴 **`graph_cluster_summaries` には現時点で書き手が居ない。** 書き手は要約生成バッチ（対象外）と
一緒に来る。**それでも今置く**のは、これが無いと `ADR-0083` 決定 3 の条件 2・3 が**実装不能**になり、
「常に未要約」を焼き付けた生産者しか作れないためである（IADR-0425 決定 4）。

### 5. 日次バッチ

`Features/Clustering/Detect/ClusterDetectionHostedService`。形は既存の
`KnowledgeHealthHostedService` に合わせる（`BackgroundService` ＋ `PeriodicTimer` ＋ 初回は 1 周期後
＋ 排他リースのゲート ＋ `TryRunCycleAsync` を internal にして決定的に検証）。

- **周期は 24 時間**（`ADR-0035` 決定 3「日次」）。
- **排他リース**は PostgreSQL の advisory lock。ナレッジ健全性とは**別のキー**を使う
  （同じキーだと日次のクラスタ検出が毎時の健全性報告を塞ぐ）。

### 6. `unsummarized-clusters` の生産

`KnowledgeHealthCollector.CollectUnsummarizedClustersAsync`。観測値 1 件 ＝ **クラスタ 1 個**。

- `SubjectKey` = クラスタ ID。
- `DocScope` = **常に null**。クラスタリングの入力から個人資料を除いてあるため、
  クラスタに個人資料は 1 件も含まれない（受け手の除外対象にならない）。
- `Dimension` = **未要約の理由**。`ADR-0083` 決定 3 の 3 条件を閉じた語彙で表す:
  `no-summary` / `composition-changed` / `documents-updated`。複数該当するときはこの順で先勝ちとする。
- **しきい値は渡さない**（`ADR-0083` 決定 3 が「置かない」と明記）。

条件 3 の「所属文書の更新」は **`GraphDocument.UpdatedAt`** で測る（`BodyUpdatedAt` ではない）。
理由は IADR-0425 決定 5。
