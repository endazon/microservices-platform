## 判断

### ★★ 判断 1: **重複は「別紙化」ではなく「正本へ畳む」**

**段 1〜5 は別紙を新規に作ってきたが、本件は作らない。**
**`docs/README.md` という正本が既に在り、内容が完全に一致している**からである。

| | |
| --- | --- |
| 段 1〜5 | 入口にしか無い経緯 → **別紙を作って移す** |
| **本件** | **2 箇所に同じ表がある** → **正本を残し、片方を導線に置き換える** |

> **★ 別紙を作ると 3 箇所目になる。** [IADR-0141](../adr/IADR-0141_audit-rounds-and-population-drawing.md) に反する。

### ★ 判断 2: **規範は `CLAUDE.md` に残す**

**出すのは「どの種別がどこへ出力されるか」の一覧だけ**である。次は**文として残す**:

- **着手前に作業仕様書（`docs/specs/`）を作成する**（`/new-spec`）
- **重要な実装判断は実装ADR（`docs/adr/`、`IADR-XXXX`）に必ず残す**
- **計画に影響する決定は `/plan-feedback` で計画側へ環流する**（計画ADR と区別する）
- **各仕様書に起点 ID・計画書リンク・相互リンクを記入する**

**いずれも「読まなかっただけで成果物が壊れる」側**である（[IADR-0173](../adr/IADR-0173_annex-extraction-keeps-heading-stubs.md) 決定 2）。

### ★ 判断 3: **SPA 移行の進捗は [IADR-0121](../adr/IADR-0121_spa-stack-migration-staging.md) へ畳む**（別紙を作らない）

進捗ナラティブ（**5 段のうち第 2 段の項目まで消化済み／完了条件は #452 が引き受け未達**）は
**[IADR-0121](../adr/IADR-0121_spa-stack-migration-staging.md) が正本**である。**`CLAUDE.md` は段の状態を持たない。**

> **★ 進捗は最も速く腐る種類の記述である。** #452 が着地した瞬間に `CLAUDE.md` が嘘になる。
> **規範（React 19 / Vite 6 / Vitest 3 / Node 22 / TanStack Router）は残す。**

### ★★ 判断 4: **`.github/workflows/` の記述は「削る」のではなく「直す」**

**[IADR-0169](../adr/IADR-0169_cross-repo-ref-scan-beyond-markdown.md) が実測で否定した記述が、必読ファイルに残っていた。**

> 誤: `.github/workflows/` は GitHub App 権限では編集不可。

**実測では `.github/workflows/` は繰り返し変更されマージされている**（同 IADR の `git log` 実測）。

**減量のついでに黙って消さない。** **誤りは誤りとして直し、根拠（[IADR-0169](../adr/IADR-0169_cross-repo-ref-scan-beyond-markdown.md)）を指す。**
**消すだけだと「なぜ消えたか」が残らず、同じ記述が将来また書かれる。**

### ★ 判断 5: **50KB 予算の記述を追随させる**（規則 8）

`CLAUDE.md` は「**毎セッション必読の規約は総量 50KB 予算**（本リポは超過中。減量は #623）」と書く。
**本 PR で超過が解消するなら、この括弧が嘘になる。** **着地を実測してから書き換える。**

### ★★ 判断 6: **「出した塊」ではなく「変更の全数と実効」で記録する**（レビュー 🟡 で是正）

**初版は「出す塊 4 件・2,282B」とだけ書き、実際に行った 6 件のうち 2 件を記録していなかった。**

| 漏れた変更 | 実効 | なぜ漏れたか |
| --- | ---: | --- |
| 冒頭のテンプレート注記の圧縮 | −231 | **「塊を出す」という枠に当てはまらなかった**（圧縮であって抽出ではない） |
| 認証の詳細の削除（`AI_SETUP.md` が正本） | −239 | **目標バイト数に足りず追加で削った分**であり、母集合の走査の後に行った |

**`.claude/rules/traceability.md`「母集合の取り方」規則 6**（引いた結果と、除外したものとその理由を作業仕様書に書く）**に反する。**

**→ 記録の単位を改めた**:

| | |
| --- | --- |
| 初版 | **「出した塊」を列挙**（総バイト）。**抽出でない変更が枠から漏れる** |
| 本版 | **変更を 1 件残らず列挙し、旧・新・実効を並べる**。**実効の合計がファイルの増減と一致することを検算する** |

> **★ 検算が閉じることが、漏れの無さの機械的な担保である。**
> 6 件の実効合計 **−1,669B** は `CLAUDE.md` の実際の増減と**一致する**。
> **「4 件・2,282B」では検算のしようがなかった** —— だから漏れに気づけなかった。

> **★ [IADR-0173](../adr/IADR-0173_annex-extraction-keeps-heading-stubs.md) 決定 2 の判断そのものは変わらない。**
> 削った 2 件はいずれも**規範ではない**（メタ指示と、`AI_SETUP.md` にある重複）。**規範は 1 バイトも出していない。**

| 版 | `CLAUDE.md` | 必読合計 | |
