# 作業仕様書 — UC-02 の高機密の行き先（#2115）

> 本仕様書は実装着手前に作成した（着手 2026-10-30。develop `aba2070d`）。親 #2047（指摘 M-18）。

## 計画（裁定済み）

planning#832（closed・2026-10-23 利用者裁定）で次のとおり決まった。

- **越境マトリクスを正とする。** 高機密（`confidential`・`restricted`）は、ティア A かティア B（ZDR を要する）にだけ送る。ティア C には送らない。
- UC-02 の代替フロー（fixed）と SC-08 の注記は、計画の側で改められた（旧文は取り消し線で残っている）。
- 実装側の残作業は 3 つ。SC-08 の UI 文言、翻訳、`RagOrchestrator` のコメントを越境マトリクスに揃える。
- 計画側の残作業は、Claude の ZDR を締結するか恒久的に受け入れるかの判断である（ADR-0140 フォローアップ 2。本番運用へ移行する前に決める）。

issue の推奨は 2 択だった（ティア A の配備の口を作る／ZDR を go-live の条件にする）。裁定は (b) を採った。**ティア A の LLM は opt-in のままにし、配備しない。** したがって、受け入れ基準の案 1（helm の values の口と `helm template` の試験）は**作らない**。

- 理由 1: 裁定で配備が要件でなくなった。
- 理由 2: 計画外の機能を足さない。
- 理由 3: 手元では helm を使わない。

受け入れ基準の案 2（運用文書に ZDR の判断とティア A の配備状態を載せる）は作る。

## 方針

1. **SC-08 の注記**（`AnalysisDashboardPage.tsx`）を、計画の是正後の注記に揃える。新しい文言は次のとおり。
   > 機密区分の高いデータは、ティア A（セルフホスト）かティア B（保護契約済みの外部 API。ゼロ保持を要する）へだけ送り、ティア C（標準の外部 API）へは送りません（AI 分析の代替フロー・データ越境ポリシー）。権限外のデータは黙って対象外になります（存在秘匿）。

   ja / en のカタログは `pnpm run i18n` で生成し直す。en の訳は新しい msgid に付ける。
2. **`RagOrchestrator` の注記**:「機密区分の高いデータは LlmGateway が外部送信を抑止する」を正しい形に改める。正しくは「LlmGateway が越境マトリクスで行き先を絞る。高機密はティア A・B だけで、ティア C へは出さない」である。
3. **運用文書**（`operations.md`）の §LLM ゲートウェイの送信先ティア（Claude）の認定状況に、**本番運用への移行の判定項目**を置く。項目は 2 つ。
   - ① Claude の ZDR の判断（未決。締結するか、標準の保持を恒久的に受け入れるか）。
   - ② ティア A の LLM の配備状態（opt-in で、どの配備定義でも無効。裁定により、高機密の分析はティア B へ出る）。
4. **機能仕様書 FR-11**: 充足の書き方を分ける。切り替えの仕組みは充足している。ティア A の LLM は opt-in で配備されていない。
5. **画面仕様書・テスト仕様書の SC-08、テスト仕様書の UC-02**: 旧い代替フローの文を改める。
6. 新しい IADR は作らない（判断は計画の裁定である）。
