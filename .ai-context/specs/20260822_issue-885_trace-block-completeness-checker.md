# 仕様書: trace ブロックの網羅性検査器を設計し、実測のうえ「足さない」と判断する

## 起点となる計画書（トレーサビリティ）

- 機能要求（FR）: なし（メタ作業。検査器・規約の統制）
- ユースケース（UC）: なし
- 画面（SC）: なし
- 関連 ADR: `ADR-0048` 決定 4（trace ブロックの書式の正本）
- 関連 IADR: `IADR-0234`（本作業の結論）／`IADR-0230`（束ね条件 M-A）／`IADR-0141`（母集合の引き方）
- 起票: #885

## 目的・背景

`docs/**/*.md` の本文を、ある記録（実装ADR・作業仕様書）の決定に沿って書き換えたのに、trace ブロックへその ID を足していない——という追随漏れが 2 回続いた。いずれも AI レビューが捕まえ、CI は素通りした。

本リポジトリの規約「検査器・規約の追加は同型の事故が 2 回起きたら」を満たしたため、#885 が判定規則の設計を求めた。同 issue は**「偽陽性が多いと判明したら『足さない』という結論も可」**と明記している。

## 対象範囲

- **対象**: 判定規則（候補 A・候補 B）の設計、有効母集合全数への適用と実測、変異試験、過去 2 件の再現可否の確認、結論の記録。
- **対象外**:
  - 検査器の実装・`scripts/README.md` への登録・CI ジョブ追加（**結論が「足さない」のため発生しない**）。
  - `claude-code-review.yml` へのレビュー観点追加（`.github/**` は `IADR-0230` の M-A から外れ単独 PR を要する。**別 issue #906 として起票済み**）。
  - 現存する同型の欠落の遡及是正（規約が未裁定のため。`IADR-0234` 決定 3）。
  - `CLAUDE.md` の修正（**走査の結果、修正すべき記述が無かった**。後述）。

## 母集合の引き方（規則 9・10）

🔴 **本件では規則 9 が機械的には効かない。** 規則 9 は「誤りの側の文字列で全文書を走査してから挙げる」だが、**欠落した ID はそもそも文字列として存在しない**。誤りの側の語が無いので、走査対象は「誤りの語」ではなく**「新設された記録 ID の側」**になる。#885 本文もこの点を指摘している。よって母集合は次の 2 本立てで引いた。

### 母集合 1: 判定規則を適用する対象コミット（全数・標本抽出なし）

- **引き方**: `git log --first-parent --format=%H 7b6a234..8abff2e`
- **下限を `7b6a234` にした理由**: trace ブロックを導入した資料再編コミット（#872）である。それ以前に trace ブロックは存在しないので、適用しても意味が無い。
- **結果**: **19 コミット**。**除外は 0 件**（全数に適用した）。
- **`--first-parent` にした理由**: マージ済みの PR 1 本 = 1 コミット（squash マージ）であり、PR 粒度と一致する。

### 母集合 2: HEAD に現存する同型の欠落

- **引き方**: `docs/**/*.md` 全 118 件の trace ブロックを `scripts/lib/trace-blocks.js` で parse し、母集合 1 の各コミットが同時に追加した記録 ID との対を取り、HEAD の trace ブロックに含まれるかを見る。
- **結果**: **作業（仕様書）単位で 5 件／文書単位で 7 件**（1 作業が 3 文書を改稿しているため数が違う。**ADR には両方の単位を明示した**）。
- **参考（遡及分）**: `docs/` 118 文書のうち **61 文書が `specs:` を空または欠く**。資料再編以前の 1 文書 × 1 仕様書の曖昧さの無い対だけでも 66 件。

### 規則 10 の引き直し（この変更で新たに誤りになる自分の記述）

- **#885 本文の事故帰属**が誤っていた（1 件目は #883 ではなく **#881 / `6c1185c`**）。誤りの出所は `.ai-context/specs/20260821_issue-455_integration-tests-production-wiring.md` の記述で、#885 がそれを転記していた。**確定済み記録は書き換えない**規約のため、訂正は `IADR-0234` 側に置いた。
- **#885 の受け入れ基準「`scripts/README.md` に追加し、CI ジョブへ組み込んでいる」**は、結論が「足さない」になったことで**充足対象から外れる**。同 issue の最終項が明示的に許している結末であることを PR 本文にも書く。
- **着手時の前提「`CLAUDE.md` の記載が古い（`docs/specs/` / `docs/adr/` を指している）」は誤りだった。** `grep -n "docs/specs\|docs/adr" CLAUDE.md` は **0 件**（EXIT=1）。`.claude/rules/*.md` も 0 件。CLAUDE.md は既に `.ai-context/specs/` / `.ai-context/adr/` を正しく指している。**実際に古かったのは `.ai-context/adr/README.md:9`**（`本リポ docs/adr/`）であり、そちらを是正した。

## 設計（実施した実測）

### 候補 A（差分ベース）

同一差分内で `.ai-context/specs/` または `.ai-context/adr/IADR-*.md` に**新規追加**があり、かつ `docs/**/*.md` が**変更**されているのに、その文書の trace ブロック `specs:`／`iadrs:` に新規記録が**含まれていない**なら違反。

parse は本番と同じ `scripts/lib/trace-blocks.js`（`findTraceBlocks` / `parseTraceBlockBody`）を使い、独自の正規表現でブロックを読まない。

| 指標 | 実測値 |
| --- | --- |
| 母集合 | 19 コミット（全数） |
| 違反 | 38 件 |
| 赤コミット | 7 / 19（37%） |
| 確認済み真陽性 | 1 件（`74b0f99` #883。`745da0f` #884 が事後に是正） |
| 精度 | **1 / 38 ≈ 2.6%** |
| 単一記録制限を掛けた場合 | 違反 5 件 / 赤 5 コミット（発火対象 11 コミット） |

うち **32 件が単一の束ね PR `d61c5b9`（#878）** の直積（新規記録 8 件 × 改稿 docs 4 件）。

### 候補 B（逆引き）

新設 ID の本文が名指す文書を引き、trace ブロックに ID が無ければ違反。**`IADR-0231` の本文は `docs/` を 0 件しか名指さず**、事故 1 を再現できない。IADR 234 件のうち **47 件（20%）が本文に `docs/` を 1 度も含まない**（全数走査。厳しい基準ならさらに広がるので下限）。

### 過去 2 件の再現

🔴 **マージ後の履歴には是正前の姿が残らない**（2 件とも squash マージ前に AI レビューで是正された）。`refs/pull/<n>/head` を fetch し、是正コミットの直前を見る必要がある。

| 事故 | 是正前 | 結果 |
| --- | --- | --- |
| 1（#881） | `41e067b` | **再現可**。違反 6 件、うち 2 件が `IADR-0231` の欠落 |
| 2（#884） | `144c0ff` | **部分的に再現可**。PR は赤になるが、欠落 2 件のうち**前 PR 由来の 1 件は構造的に検出不能** |

補足: 事故 1 を**是正した後**の PR head（`2963742`）でも**違反が 1 件残る**——事故を正しく直しても緑にならない。

### 変異試験（作法込み）

**変異の前後を parse 結果で assert し**（`before に ID を含む && after に含まない`）、成り立たなければ throw する。陰性対照 0 件 → 変異 1（`specs:`）1 件 → 変異 2（`iadrs:`）1 件 → 変異 3（当たらない変異）throw。作法の詳細と、実際に捕まえたエスケープ落ちの事故は `IADR-0234`「変異試験の作法」に記録した。
