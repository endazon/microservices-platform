## 受け入れ基準

- AC1: ゲートウェイの既定・用途別割当・鎖・`claude-managed` の既定モデルが 5.5 系になる。`Models`（利用許可集合）に新 3 ID を足し、
  **旧 ID は切り戻し用に残す**（足さないと `LlmRouter` が無音で `DefaultModel` へ落ちる）。`NonZdrModels` は空のまま。
- AC2: 単価表に 5.5 系 3 モデルを足し、旧 3 モデルの行を残す。`claude-haiku-5-5` は**要求ごとの入力トークン数**で 2 段
  （≦100,000 は下段、>100,000 は上段）を引き分ける。上段の形は起動時の検証器が検査する。
- AC3: Claude へ出ていく要求本文に `temperature` / `top_p` / `top_k` / `thinking` / `tool_choice` が無く、prefill も無いことを試験で固定する
  （非ストリーム・ストリーム）。
- AC4: 用途別 effort を任意設定（`Llm:PurposeEffort`）で持ち、effort を受け付けるモデルへの要求にだけ `output_config.effort` を足す。
  既定は `rerank: low`。値域外は起動時に落とす。
- AC5: `claude-haiku-5-5` の thinking 先頭の応答を、非ストリーム（サニタイズ）・ストリーム（thinking_delta を無視）の両方で試験する。
- AC6: rerank の `max_tokens` 512 と diagram-coding の 1024 を見直し、変えるなら根拠を IADR に残す。
- AC7: 生きた文書（機能仕様書・テスト仕様書・運用 Runbook・観測仕様書・openapi と生成物）を追随させる。凍結記録は書き換えない。

## 設計

1. **単価の 2 段**: `ModelPriceEntry.LongPrompt { ThresholdInputTokens, InputPerMillionTokens, OutputPerMillionTokens }`（任意）。
   入力トークン数 > 境界の要求だけ入力・出力とも上段。`PriceLookupResult.LongPromptApplied` で段を返す。
   検証器は境界 < 1・上段の負値を落とす。入力トークン数は `usage.input_tokens`（ゲートウェイはキャッシュを使わないので提供元の判定量と一致）。
2. **effort**: `Llm:PurposeEffort`（用途 → effort）を `ClaudePurposeEffortOptions` に束縛し、検証器で値域を閉じる。
   `ClaudeProvider` が用途とモデルから effort を決め（対応モデル集合に無いモデルは送らない）、`AsyncLocal` の文脈に載せる。
   `AnthropicRequestShapingHandler`（`HttpClient` の最も外側）が POST の JSON 本文へ `output_config.effort` を足す。
3. **max_tokens**: rerank 512 → 1024、diagram-coding 1024 据え置き（根拠は IADR-0529 決定 5・6）。
