## 方針

1. **次数**: 変えない。間引き（`by=degree`）の並びもハブ判定も、ABAC で絞らない全辺の次数のままとする（計画 ADR-0137 決定 4。下の追記）。
2. **所有者**: `NodeSidePanel` が既に引いている選択 1 件の文書詳細の属性 `owner` を、現在の利用者と比べる。判定は SC-03 の `PrivateNoteSummary` と同じである。
   - 一致すれば「個人資料（自分のみ）」を表示する。
   - 他人の個人資料、および詳細を読めない（404・読み込み中）ときは付けない。所有者以外に付す誤りの側へ倒さない。
   - 契約（`GraphNodeItem`）は変えない（200 ノード分の所有者を常に運ぶ理由が無い）。
3. **辞書の取得失敗**: `edgeTypes.isError` のとき、警告（`Note tone="warn"`）を出す。文面は「型での絞り込みは使えず、型名は表示できない」とする。グラフは辞書なしでも描けるので、画面は止めない。

## ［2026-10-30 追記］次数の変更を撤回した（計画 ADR-0137 決定 4）

- 当初は間引きの次数を許可済みの辺で数える変更（試験 `Thinning_by_degree_counts_only_authorized_edges`・実装 ADR の起草）を入れた。
- 監査前の確認依頼（ハブ判定の結果は利用者に見えるか）を調べた。
  - ハブ判定の結果は応答に印として出ない（DTO にハブの項目は無い）。
  - ただし間接には見える。ハブ（全辺の次数 > 50）は結果に現れるが次のホップへ進まない（`GraphTraversal.cs` の `MaxHubDegree` の判定）。見えている隣接文書が `hops` の範囲内でも出てこないことから、その文書の次数が権限外を含めて 51 以上だと推せる。
- 計画を読み直すと、この推論は **計画 ADR-0137 決定 4（Accepted・利用者裁定 2026-10-09）が明示して受容している**。
  - 受容の対象は 3 つある。ハブ判定の次数、共有タグの上限の判定、SC-18 の間引き基準「次数が大きい順」の次数である。
  - 理由は「可視の辺だけで数えると、同じ文書が閲覧者によってハブになったりならなかったりする」ことである。「片方だけ禁じても一貫しない」とも書いている。
  - 禁じているのは次数そのもの・権限外を含む個別の件数を応答・画面に出すことと、匿名ノード・グレーアウトである。現行はどちらにも当たらない。
- このため、間引きの次数だけを許可済みの辺で数える変更は **Accepted な計画 ADR に反する**ので撤回した。ハブ判定も変えない。
  - issue の推奨（次数を権限内の辺だけで数える）は ADR-0137 を踏まえていない。
  - 撤回したもの: `GraphTraversal` / `IGraphStore` の変更、試験 1 本、FR-17 の T-92、実装 ADR（新しい実装判断が無くなったため起草せず、番号も取らない）。
  - 撤回後のコードは develop と同じである。間引きの並びの注記に ADR-0137 決定 4 を 1 行足した。
- 受容を変えるには計画側の裁定が要る（ADR-0137 の改定）。本 PR では起票しない。
