## 方式

- 新規 `src/platform/frontend/e2e/shell.smoke.spec.ts`（10 本）。
  - M-012（3 本）: 左ナビをアクセシビリティツリー（`ariaSnapshot()`）から「グループ → 表示名 → 遷移先」へ読み、表と一致を比べる。DOM の構造や CSS には依存しない。
  - M-014（5 本）:
    - 待ちの `role="status"`: 1 回目の応答を route で止めて観測する。
    - 失敗の `role="alert"` と「再試行」: 5xx は自動で 1 回だけ再送するので、最初の 2 回を 500 にする。
    - 押すと 3 回目で本体へ復帰する。
    - 404・403 は自動で再送しない。408・429 は 1 回だけ再送する。
  - M-015（1 本）: 契約に反した応答（`notes` が配列でない）で画面が落ちたときの振る舞いを見る。
    - 画面の位置に「再読み込み」「ホームへ戻る」が出て、共通シェル（左ナビ・アカウント設定）は残る。
    - 再読み込みで復帰し、ホームへ戻るで `/ask` へ遷移する。
    - `pageerror` は 0 件。
  - M-011（1 本）: ブラウザが送った要求を `page.on('request')` で観測し、POST に `X-MSP-CSRF` が付くことを確かめる。
    - 送り先は同一オリジンである。
    - `BffCall` は見出しを持たないので、土台（`support/bffSession.ts`）は変えない。

## 判断

1. **画面側の不具合を 1 件直した**（M-015 の E2E で見つかった）。`RouteErrorComponent` の「再読み込み」が、契約に反した応答で落ちた画面を戻せなかった。
   - 原因: `router.invalidate()` は TanStack Query のキャッシュに触れない。取得は成功扱いで 30 秒は新鮮なので、押しても同じデータで同じ例外へ戻っていた（押しても何も起きないボタン）。
   - 直し方: 押したとき、購読の無い（inactive）キャッシュを捨ててから境界を戻す（`queryClient.removeQueries({ type: 'inactive' })`）。
     - 落ちた画面の購読はもう外れている。
     - 共通シェルが購読中の身元・通知（active）は残す。
   - 単体試験を 1 件足した: inactive だけが消え、active は残ることを確かめる。
     - 変異: 削除の行を外すと赤になる。全件を消す形に変えても赤になる。
   - 既存の単体試験は `QueryClientProvider` の内側で描く形に直した。
   - 既存の意図（同コンポーネントの注記「`reset` だけだと押しても何も起きない」）に実装を合わせる是正なので、新しい IADR は起こさない。
2. 計画の左ナビ「管理」グループの並びは、SC-05/06/07/09/17/12（ユーザー管理 → MCP管理）である。実装は ABAC設定 → MCP管理 → ユーザー管理の順に並ぶ。
   受け入れ基準は集合なので、本 PR では並びを比べず、直さない（報告）。
