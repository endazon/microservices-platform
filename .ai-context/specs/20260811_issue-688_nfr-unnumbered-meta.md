# 作業仕様書: メタ作業の `NFR` 無採番を規約へ明記する（#688）

## 起点

- **NFR**（文書統制。**本作業自身が無採番の対象である**）。実装 ADR: **[IADR-0179](../adr/IADR-0179_unnumbered-nfr-for-meta-work.md)**
- 起点 issue: **#688**（出所: PR #687 の AI レビュー 🟡）
- **予算の制約**: [IADR-0178](../adr/IADR-0178_claude-md-defers-to-docs-readme.md) 決定 4 —— **必読へ加筆するなら同量を削るか正本・別紙へ畳む**

> **★ 値の基準時点は develop `ef60781`（2026-08-11 実測）である。**
> **着手時の必読合計 49,967B（50,000 まで余白 33B）。**

## ★★ 母集合 —— 3 軸で引いた

### 軸 a: **`NFR-01`〜`27` を全数で読んだ** —— **文書統制の番号は 1 件も無い**

`planning/.../02_requirements/01_requirements.md` の 27 件を実測した（走査基準: planning `2cf0795`）。

| 区分 | 番号 | 対象 |
| --- | --- | --- |
| 性能 | `NFR-01`〜`04` | 検索レイテンシ / RAG 初回応答 / 取り込みスループット / GraphRAG |
| 可用性 | `NFR-05`〜`06` | 稼働率 / 縮退運転 |
| スケーラビリティ | `NFR-07`〜`08`, `27` | 利用者規模 / データ規模 / 個人資料の容量 |
| セキュリティ | `NFR-09`〜`18` | 認証認可 / HTTPS / パスワード / 暗号化 / 越境統制 ほか |
| **運用・保守** | `NFR-19`〜`21` | **可観測性 / デプロイ / 障害検出〜復旧** |
| 拡張性 | `NFR-22`〜`26` | LLM 差し替え / コネクタ追加 / 構成組み替え ほか |

**「運用・保守」の 3 件も対象は稼働中のシステム**である。
**規約・検査器・文書統制を扱う番号は 1 件も無い。**

### 軸 b: **現行の運用を全数で引いた** —— **区別は既にできている**

2026-08-09 の裁定以降に develop へ着地した `NFR` スコープのコミットを全数で引いた（基準 `ef60781`）。

| 用途 | 採番 | 件数 |
| --- | --- | ---: |
| **製品の NFR が実際に当たる** | `NFR-xx` | **3**（`NFR-09` / `NFR-19` / `NFR-21`） |
| **無採番** | `NFR` | **21** |

**無採番 21 件の内訳**（**#688 の起票時点は 14 件。本 PR までの減量作業で増えた**）:

| 内訳 | 件数 |
| --- | ---: |
| メタ作業（規約・検査器・文書統制・テスト基盤） | **19** |
| **製品の作業が裸の `NFR` を併記** | **2** |

> **★ #688 は「無採番はいずれもメタ作業」と書いていたが、実測では 2 件だけ違う。**
> `fix(FR-01,...,NFR,SC-05,SC-09,SC-10,IADR-0153)` と `feat(NFR,SC-10,IADR-0164)` は
> **製品側の作業**であり、**当たる `NFR-xx` があった可能性がある。**
> **本 PR はこれを是正しない** —— 規約が**遡及書き換えを禁じている**ためである。
> **記録として残す**（#688 の「射程外」と整合）。

### 軸 c: **規約の置き場所は 1 箇所**

`NFR` の採番規約は `.claude/rules/traceability.md`「起点 ID の種別」節の 2026-08-09 追記だけにある
（`CLAUDE.md` にも `docs/` にも重複が無いことを実測）。**追記先は 1 箇所で確定する。**

## 判断

### ★★ 判断 1: **加筆しながら入口を縮めた**（[IADR-0178](../adr/IADR-0178_claude-md-defers-to-docs-readme.md) 決定 4 の実行）

**余白は 33B しかなく、規範を 1 つ足すだけで超過する。**
**同 決定 4 が定める「同量を削るか正本・別紙へ畳む」を実行した。**

| # | 変更 | 旧 | 新 | 実効 |
| ---: | --- | ---: | ---: | ---: |
| 1 | 既存の導線に「`NFR` 採番の経緯」を追記（**新しい導線を作らない**） | — | — | **＋21** |
| 2 | **採番導入の経緯**（planning#295 の理由と計画側の実測）を別紙 §4 へ移す | 391 | 0 | **−391** |
| 3 | 書式検査の**機構の説明**を圧縮（`ID_PATTERN` の正規表現・「コードの変更は要らない」） | 202 | 95 | **−107** |
| 4 | **新しい規範**（メタ作業は無採番のまま） | 0 | 355 | **＋355** |
| | **計** | | | **−122** |

**★ 実効の合計 −122B は入口の実測増減と一致する**（[IADR-0178](../adr/IADR-0178_claude-md-defers-to-docs-readme.md) 決定 6 の検算）。

**入口は 28,112 → 27,990B。必読合計 49,967 → 49,845B。余白は 33B → 155B へ広がった。**

> **★ 「加筆＝超過」ではない。** **同じ節に、規範ではない説明が残っていた。**
> **規範を足す機会に経緯を出す**のが、予算内で統制を増やす筋である。

### ★ 判断 2: **新しい導線を作らず、既存の導線へ語を足した**

段 5 が同じ節に別紙への導線を既に置いている。**2 本目を作ると読み手が「どちらを読むか」を判断させられる。**
**語を 1 つ足すだけで済む**（＋21B。新規導線なら ＋213B だった）。

### ★ 判断 3: **計画側へ環流する**（#688 の 3 つ目のチェック項目）

**「メタ作業に当たる `NFR` が無い」ことは計画側の関心事**である —— 採番は planning#295 / planning#304 で決まった。
**環流記録を `feedback/` に作成した。**

> **★ 「環流した」と書けるのは、計画リポへのコピーまたは Issue 起票まで済んだときだけ**である
> （`docs/README.md` 運用ルール 5）。**本 PR の時点では記録の作成までで、起票は別途行う。**

### 判断 4: **既存 17 件（現在 24 件）を書き換えない**

規約が「**既存参照の遡及書き換えはしない**」と定めている。**軸 b で見つかった 2 件も直さない。**

### ★★ 判断 5: **加筆で既存の規範を落としかけた** —— 既存の回帰テストが止めた

**採番の経緯を別紙へ出したとき、その文に含まれていた `NFR-01`〜`NFR-27` という
レンジの明示ごと入口から消えた。** **段 5（#695）が固定していた回帰テストが落ちて判明した。**

**新しい規範は当初 `NFR-01`〜`27` と略記しており、レンジの明示を兼ねられていなかった。**
**完全形へ直した**（＋86B）。

> **★ 「加筆のついでに既存の規範を落とす」は最も危ない型である。**
> **本 PR はまさにそれを踏み、前の段が置いたテストに止められた。**
> **回帰テストは自分の PR のためだけに書くのではない** —— **次の PR の加筆から規範を守る。**

> **★ 別紙側でも同型を踏んだ。** §4 の挿入で**連続空行**が生まれ、
> **[IADR-0177](../adr/IADR-0177_entry-exhausted-claude-md-quota.md) 決定 5 の残骸検査（自分が前の PR で足したもの）が止めた。**

- **計画側の Issue 起票** —— **記録の作成までが本 PR**（判断 3）
