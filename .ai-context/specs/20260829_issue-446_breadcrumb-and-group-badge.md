# 仕様書: 共通シェルのパンくず・画面グループバッジ

## 0. 結論（先に書く）

1. **パンくずは宣言データである。** 左ナビの `group` / `label` からは導けない —— 親画面の段と
   動的な葉（文書タイトル）を表現できないためである。`featureRegistry.ts` の契約へ
   **ナビとは別の登録面**（`FeatureBreadcrumb`）を足し、各画面が宣言する。
2. **画面グループのバッジは、パンくずの中のグループ段として 1 要素で描く。**
   モックアップに独立したバッジ要素は無い（後述 §2.2 で実測）。**2 つ目のバッジを発明しない。**
3. 🔴 **パンくずは存在秘匿（IADR-0009）の経路になり得る。** 権限外の画面でパンくずを描くと、
   「`/admin/config-viewer` は実在し、運用グループの構成ビューアである」ことが
   `NotFound` の外側から読める。宣言に `requiresAnyRole` を持たせ、**権限外では
   パンくずを 1 段も描かない**（未知パスと同じ描画になる）。これは着手前の実測で見つけた
   （既存の `Layout.test.tsx` 「produces the same not-found markup」が、素朴に実装すると落ちる）。

### 2.2 「バッジ」の実測 —— 独立したバッジ要素は無い

`<div class="badges">` は **21 画面すべて（crumb を持たない SC-13〜16 を含む）**に 1 個ずつある。
中身は `SC-01` / `FR-03,04,05` / `UC-01, UC-02` / `未着手` / `仕様書 ↗`（計画リポの
`01_screens.md` への外部リンク）であり、**モックアップのメタ情報であって製品 UI ではない**。
CSS も `.bg-sc` / `.bg-fr` / `.bg-uc` / `.bg-spec` / `.bg-todo` と、SC 番号・要求 ID・進捗のための
語彙しか持たない。**crumb を持たない SC-13〜16 にも付いている**ことが決定的である ——
共通シェル適用外の画面にも付く要素は共通シェルの部品ではない。

計画自身も
「**モックの「管理」「運用」等のバッジは画面のグループを示すものであり、閲覧ロールの決定ではない**」
（§共通シェル・2026-08-05 に明記）と書いており、**「モックのバッジ」が指しているのは
crumb の中のグループ段**である（他にその語に当たる要素が無い）。よって
**グループ段をバッジとして描く 1 要素**で、計画の「パンくずと画面グループのバッジ」を両方満たす。

## 5. 設計

### 5.1 契約（`app/routing/featureRegistry.ts`）

```
FeatureBreadcrumb {
  routePath: string                  // TanStack の fullPath。宣言の主キー（'/docs/$id' 等）
  group: NavGroup                    // 画面グループ。'user' はグループ段を描かない
  parents?: readonly BreadcrumbCrumb[]  // 親画面の段（上位から）
  label?: NavLabel                   // 自画面の段。動的な葉を持つ画面は宣言しない
  requiresAnyRole?: readonly string[]   // 権限外ではパンくずを描かない（存在秘匿）
}
BreadcrumbCrumb { label: NavLabel; to: string }
```

- **ナビ項目とは別の登録面である。** SC-03 はナビ項目を持たない（計画が「左ナビに置かない」と
  明記）が、パンくずは持つ。ナビへ相乗りさせると SC-03 を表現できない。
- `routePath` を主キーにするのは、共通シェルが「いま居るルート」しか知らないためである
  （`useRouterState` の `matches` 末尾の `fullPath`）。
- `NavLabel`（`string | MessageDescriptor`）を再利用する。**モジュール初期化時に評価される**
  場所なので、翻訳済み文字列ではなく `MessageDescriptor` を持ち、描画時に解決する
  （`nav.ts` の `PLAN_NAV_GROUP_MESSAGES` と同じ理由）。

### 5.2 登録面（`app/routing/breadcrumbs.ts`）

`nav.ts` と同じ作法で、合成点（`router.tsx`）が起動時に 1 度だけ登録する。
`foundation` は可変ユニットを import しない（IADR-0124 決定 1）。

### 5.3 解決（`breadcrumbTrail()`。純関数・単体テスト対象）

入力 `{ routePath, leaf, roles, declarations }` → 出力 `BreadcrumbSegmentView[]`。
**空配列は「何も描かない」を意味する。**

1. `routePath` が無い / 宣言が無い → `[]`
2. `requiresAnyRole` があり、いずれにも一致しない → `[]`（**存在秘匿**）
3. `ホーム` 段（`to` = `ENTRY_ROUTE_PATH`）
4. `group !== 'user'` のときだけグループ段（`to` を持たない＝リンクにしない）
5. `parents` の各段（`to` を持つ＝リンク）
6. 自画面の段 = `label ?? leaf`。**どちらも無ければ段そのものを出さない**（未確定の文字列を描かない）。
   `to` を持たない＝現在地なのでリンクにしない

グループ段の文言は `PLAN_NAV_GROUP_MESSAGES`（利用者／個人／管理／運用）を再利用する ——
左ナビの見出しと同じ語であり、2 か所で別々に訳すと食い違う。

### 5.5 動的な葉（`app/routing/breadcrumbLeaf.tsx`）

- `Layout` が `useState` で葉を保持し、setter を context で `<Outlet />` 配下へ渡す。
- 画面側は `useBreadcrumbLeaf(title)` を呼ぶ。取得前は `undefined` を渡す＝葉を描かない。
- アンマウント時に `undefined` へ戻す（画面を離れたときに前の文書名が残らない）。
- 葉を使うのは**自分の段を宣言していない画面だけ**なので、取りこぼしがあっても
  他画面へ漏れない（`label` を宣言した画面は `leaf` を見ない）。

### 5.6 描画（`components/ui/Layout.tsx`。`<main>` 内・`<Outlet />` の上）

- `<nav aria-label="パンくず">` ＋ `<ol>`。区切りの `/` は `aria-hidden`。
- 現在地の段に `aria-current="page"`。
- グループ段は `@platform/ui` の `Tag`（**新しいプリミティブを作らない**）。
  🔴 **色だけで意味を持たせない** —— バッジは「管理」「運用」「個人」という**テキスト**を持ち、
  色を落としても意味が読める。
- パンくずが空のときは `<nav>` ごと描かない（空の器を残さない。左ナビの空グループを
  落とすのと同じ作法）。

## 7. 計画書との差異（環流の候補）

1. **モックアップの SC-02 だけ、親画面の段がリンクでない。** 他の親画面段（SC-03 / SC-07 /
   SC-11 / SC-12）は `<a>` である。到達可能な実在画面なのでリンクにする（実装は他 4 画面に揃える）。
2. **SC-18 のパンくずが `知識グラフ`、左ナビと計画の画面名は `ナレッジグラフ(ビュー)`。**
   計画は「同じものに 2 つの名前があると食い違う」ことを名指しで避けている（§用語）。
   実装は `ナレッジグラフ` に揃える。
3. **SC-21 のパンくずは `AI 提案`（空白あり）、左ナビは `AI提案`（空白なし）。** 表記ゆれ。
   パンくずはモック実測の `AI 提案` を採る。
