# 作業仕様書 — SC-19 の一括復元の通知と機密区分の欄（#2324）

> 本仕様書は実装着手前に作成した（着手 2026-10-30）。親 #2146（項目 3）。

## 現状（develop で確認）

- **一括復元の通知**: `PrivateNotesPage.tsx` の `runRestore` は、選んだ件数だけ `restore.mutate` を投げた**直後に**「選択した個人資料を復元しました。」を出す。後段の結果を待たない。
  - 1 件でも失敗すると「復元しました」とエラーが同時に出て、どれが戻ったか分からない。
  - 単票の復元も同じ関数を通る。
- **新規作成の機密区分**: 新規作成の欄はタイトルとパスだけで、機密区分の欄は無い。
  - 計画 §SC-19 の入力表は「機密区分（ABAC属性）| 必須 | 選択 | 定義済み区分のみ。個人資料の既定は `restricted`」とする。
  - 一方、FR-19 の受け入れ基準は「新規に作成した個人資料は、公開範囲＝非公開・**機密区分＝`restricted`**・3 トグルがすべて OFF の状態で作成される」とする。
  - 契約（`CreatePrivateNoteRequest`）は `title` と `vaultPath` だけで、後段は作成時に `restricted` を固定する（`PrivateNoteEndpoints.PrivateNoteDefaults`）。作成後に機密区分を変える口も契約に無い。

## 方針

1. **一括復元の通知**:
   - 選んだ件数の復元を `mutateAsync` で投げ、**すべての結果を受けてから**通知する（`Promise.allSettled`）。
   - 全件が成功したら「選択した個人資料を復元しました。」（従来の文言）。
   - 一部が失敗したら「{n} 件を復元しました。{m} 件は復元できませんでした。」を出す。失敗の理由は既存のエラー欄（直近の失敗）が出す。
   - 選択は全件成功のときだけ外す。失敗したものは選んだまま残し、やり直せるようにする。
   - 結果を待つ間は、一括操作のボタンが既存の `pending` で押せない。
2. **新規作成の機密区分**: **欄を置かない。** 根拠を画面仕様書（§計画との対応）に書く。
   - FR-19 の受け入れ基準が、作成時の機密区分を `restricted` と定める。作成の時点で選ばせる欄は、この基準と食い違う。
   - 計画の入力表の「必須・選択・既定 restricted」が作成時の欄か作成後の変更かは、計画から読み切れない。作成後に変える口は契約に無い。
   - 画面だけで欄を置くと、送る先の無い「操作できるのに何も変わらない」欄になる。
   - 作成後の変更の要否は計画の判断になる。本 PR では起票しない（親 #2146 の報告で判断を仰ぐ）。

## 母集合（規則 9・10）

- **規則 9**:
  - 結果を待たずに成功を出す形: `grep -n "\.mutate(" PrivateNotesPage.tsx` で走査した。`setNotice` を `mutate` の外で呼ぶのは `runRestore` の 1 か所だけである。作成・完全削除は `onSuccess` の中で出す。
  - 同じ形を全フロントで探した: `grep -rn "for (const .* of .*) .*\.mutate("`（試験を除く）で、`runRestore` の 1 か所だけだった。
  - 機密区分の欄: `grep -rn "confidentiality" src/knowledge/frontend/src/features/sc19-private-notes`（試験を除く）で 0 件だった。
- **規則 10**: 既存の試験「一括復元は選択した件数だけ復元を送る」「単票の復元ができる」は送る要求だけを見ているので、そのまま通る。
