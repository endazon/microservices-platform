## 既存実装との関係（車輪を再発明しない範囲の実測）

ADR-0033 決定 9 は「同じ規則を SC-09 のタグ辞書にも適用する」と定めており、**その規則は
DocumentService に既に実装されている**（`TagDictionaryEndpoints.cs` 203 行 / `Tag.cs`。IADR-0152 / IADR-0153、#634 / #635）。

**移植するのは契約であって、コードではない。** 実装形が異なるためである:

| | タグ辞書（既存） | 辺の型辞書（本 issue） |
| --- | --- | --- |
| 参照の持ち方 | `Document.Tags` = jsonb の `List<Guid>` | `edges.edge_type_id` = **実カラム ＋ 外部キー** |
| 使用件数の数え方 | **SQL で数えられない。**全文書の `Tags` をメモリへ読み出して集計（`LoadWithUsageAsync` に「`Tags` は jsonb へ変換した `List<Guid>` なので、SQL 側で展開して数えられない」と明記） | **`COUNT(*) WHERE edge_type_id = @id`**。`ix_edges_type` が効く |
| DB 層の削除ガード | 無し（アプリ層のみ） | **`ON DELETE RESTRICT`**（最後の防壁） |
| 版履歴の扱い | 「版履歴は数えない」判断が要る（append-only で付け替え不能なため、数えると永久に削除できなくなる） | **論点にならない**。辺は最新版のみ保持（ADR-0033 決定 6） |

**共有ヘルパは作らない。** 数え方が根本的に違い、共通化できるのは「409 に使用件数を添える」という
数行の応答形だけである。計画外の抽象化を避ける（CLAUDE.md 禁止事項）。

**継承する契約**（テストで固定する）:

1. **数え方は一覧と削除で同一の母集合**を使う —— 一覧が 0 件と表示したのに削除が 409 を返す（またはその逆）と、管理者は辞書を信用できなくなる（既存実装のコメントが明記）
2. **重複は 409**。正規化後の名前で比較する
3. **検査と保存の間の競合**（同名の同時登録）は一意制約違反を捕捉して 409 に変換する。素の 500 にしない
4. **改名は表示名だけを変える**。識別子は不変で、既存の参照は自動追随する
5. **削除前に使用件数を示す** —— 数だけでも「まず 3 件を外してから消す」と行動できる

## 対象範囲

- 対象: 型辞書の一覧 / 追加 / 改名 / 削除、型別使用件数、未定義型フォールバックの警告件数の読み出し
- 対象外: SC-09 / SC-10 の画面（#452 系。ADR-0039 のゲート対象外だがフロントは別 issue）、BFF 公開（#916）

## 受け入れ基準

- [ ] 参照ありの型の削除が **409 ＋ 使用件数**（`ON DELETE RESTRICT` の例外を素の 500 で漏らさない）
- [ ] 改名後、既存 `edges` の行が 1 行も変化しない（更新時刻を含む）
- [ ] 同名（正規化後）への追加・改名が 409
- [ ] 追加・改名の競合が一意制約違反を 409 に変換する
- [ ] 使用件数エンドポイントと削除ガードが**同一の数**を返す
- [ ] 参照 0 件の型は削除できる

## テスト方針

`EdgeTypeDictionaryTests`（#908 で作成済み。モデルの性質を既に固定）へ API 層のケースを足す。

**InMemory プロバイダは一意索引も外部キーも強制しない**（#908 実装時に確認済み）。したがって:

- **アプリ層のガード**（事前カウント → 409）は InMemory で試験できる
- **DB 層のガード**（`ON DELETE RESTRICT`・一意制約）と**競合の 409 変換**は InMemory では試験できない。
  `Knowledge.IntegrationTests`（Testcontainers + 実 PostgreSQL）側へ置く
- 🔴 **この切り分けを書かずに InMemory だけで緑にすると、「DB 層の防壁を試験した」と誤認する。**

### 変異試験の設計

| 変異 | 落ちるべきテスト | 注意 |
| --- | --- | --- |
| 事前カウントを消す（DB の RESTRICT に任せる） | 409 テスト | **アプリ層を消すと 500 になる**（例外が素通し）。「落ちた」だけでなく**落ち方が 500 であること**まで読む |
| 使用件数の母集合を一覧側とずらす | 一覧と削除の一致テスト | 差が出る件数のフィクスチャが要る（0 件同士では等価変異） |
| 改名で `Id` も振り直す | 改名追随テスト | 既存辺の `EdgeTypeId` が変わる |
| 正規化（`Trim`）を外す | 重複 409 テスト | 前後空白のみ異なる名前のフィクスチャが要る |
