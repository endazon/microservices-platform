# 作業仕様書 — 計画 ADR レンジを `ADR-0001..0119` へ

## 目的と射程

`.claude/rules/traceability.repo.md`「起点 ID の種別（固有）」節の計画 ADR レンジ宣言を `ADR-0001..0115` → `ADR-0001..0119` へ更新する。
計画側に次の 4 件がマージされた。これらを引く作業が件名・trace ブロックで引けるよう、前回（#1565 / #1566）と同じ形で開ける。

- ADR-0116（SC-17 の部門欄は部門グループの所属を変える。外れた利用者の部門属性は消し、属性辞書の部門の値は realm の部門グループから導く。環流 planning#672 / planning#675）
- ADR-0117（MCP のツール定義から endpoint を外し、実行先は申告したサービスとツール名で決める。ツールの実行口は FR-16 の別作業、利用者文脈は本文で運ぶ。環流 planning#677 / planning#679）
- ADR-0118（所要時間の判定の偶然の赤は同じコミットの 1 回の再実行で確かめる。判定の値と起票は変えず、p の分布は月次で実装側に記録する。ADR-0097 決定 1 の部分改定。環流 planning#681 / planning#683）
- ADR-0119（機械クライアントは自分が owner の組織文書に限りメタデータ更新・削除を行ってよい。DocumentService は読み取りに認証を求め内容の ABAC を自ら判定する。環流 planning#680 / planning#684）

**射程はレンジ宣言 1 行と別紙への 1 回分の追記に限る**（#1488 / #1497 / #1522 / #1545 / #1554 / #1566 と同じ形）。判断を伴う決定は無いため IADR は起こさない。

### 2 段で開けた経緯

起票時の出典は `2b25250`（0117 まで）で、PR #1613 の 1 コミット目は `0001..0117` とした。その後 `check-planning-adr-range.js` が `behind`（宣言 0117 / 実物 0118）を返し、
計画側に 0118（`4d08116`）・0119（`1e72bac`）がマージされたため、同じ PR の 2 コミット目で出典を `1e72bac` へ進め `0001..0119` へ広げた。
別紙の記録は 1 回分（`0115 → 0119`・4 件）にまとめた（別紙は PR 単位で 1 項を立てる形であり、同じ PR の途中経過で 2 項に割らない）。本仕様書のファイル名も `…-0117` から `…-0119` へ改めた（未マージの自分の仕様書であり、参照は別紙の trace ブロックだけ）。
