# 作業仕様書: trace 追随の記録単位ルールの裁定（#975）

## 起点

- `#975`。`#885` は trace ブロックの網羅性検査を**精度 1/38 ≒ 2.6%** で棄却した（`IADR-0235`）。
  `#906` の測定で、**同じ窓を「記録単位」で数え直すと桁が違う**ことが分かり、別 issue として切り出した。
- 🔴 **`#906` では精度しか測っていない。** 記録単位の規則は
  「**どれか 1 つの文書に載っていれば良し**」とするので、**5 文書中 3 文書へ足すべきところを
  1 文書だけ足すと素通りする**。**取引の片側しか測っていなかった。**
- 本仕様書は**精度と再現率の両方**を測り、足すかを裁定する。

## 🔴 母集合は後ろへ広げられない

trace ブロックは **`#872`（2026-08-21 02:26 UTC）で導入された**。それ以前に規約は存在しないので、
**有効母集合はそこから現在まで**である。実測で確認した（`git log -S '<!-- trace:' -- docs/` の最古が `#872`）。

**広げられるのは前だけである。** `#885` も本仕様書も、**若く小さい母集合の上で判断している**。

| 項目 | 実測 |
| --- | ---: |
| 有効母集合（記録追加 ＋ docs 変更が同居するコミット） | **25** |

## 実測 —— 2 つの規則を同じ母集合で比べる

- **pair-rule**（`#885` 候補 A）: 変更された**各文書**について、新規記録がその trace ブロックに在るか
- **record-rule**（`#906` の形）: **各記録**について、変更されたいずれかの文書の trace ブロックに在るか

判定は「文書の**本文**がその記録の作業によって書き換わっているか」で行い、**21 件中 18 件は diff を
個別に開いて確認した**（残り 3 件は推定。`#906` から引き継ぎ、flag 集合が同一であることを再確認済み）。

| | pair-rule | record-rule |
| --- | ---: | ---: |
| flag 総数 | **167** | **21** |
| うち `#872`（規約導入・116 docs）由来 | **115** | **0** |
| `#872` を除く | 52 | 21 |
| 本物 | 17 | 16 |
| **精度** | **10.2%**（`#872` 除外時 32.7%） | **76.2%** |
| **再現率** | **100%**（構造上すべて挙げる） | **94.1%**（17 中 16） |

### 🔴 再現率の損失は 1 件だけだった

pair-rule が挙げ record-rule が黙る対（＝再現率の損失候補）は **117 件**あるが、
**115 件は `#872` 1 本**（記録 1 × docs 116）である。**残り 2 件を個別に判定した。**

| PR | 記録 | 文書 | 判定 |
| --- | --- | --- | --- |
| `#893` | `20260821_issue-455_queue-override-fanout` | `docs/tests/FR-14_composability.md` | 🔴 **本物**。行 3c が「テスト未整備」→ `QueueOverrideFanOutTests` を名指しへ変わっており、その記録の作業そのもの |
| `#881` | `20260821_issue-455_awesome-assertions-knowledge` | `docs/tests/TEST_STRATEGY.md` | **偽陽性**。本文の変更は xUnit v3 の話（`IADR-0231` と `xunit-v3-migration` は trace へ入っている）。AwesomeAssertions の記述は変わっていない |

**したがって record-rule の再現率の損失は 17 件中 1 件（5.9%）である。**

### 🔴 偽陽性は 1 本の PR に集中している

record-rule の偽陽性 5 件は、**すべて `#878` 1 本**である
（`feat(ADR-0041,FR-11,NFR): 共有カーネル新設・LLM 用途割当の追随・検査器の fail-open 是正…`）。
**この PR 自身が `IADR-0230_meta-work-bundled-prs` を足した束ね PR** である。

| 母集合 | flag | 本物 | 精度 |
| --- | ---: | ---: | ---: |
| **`#878` を除く 12 PR** | **13** | **13** | **100%** |
| `#878`（束ね PR）のみ | 8 | 3 | 37.5% |

🔴 **通常の PR（`IADR-0116` の「1 issue = 1 PR」）では精度 100%、
偽陽性は束ね PR という宣言された例外категория にだけ現れる。**

### 発生頻度

**有効母集合 25 コミット（2 日）に対し、本物の追随漏れは 17 件**である。
`#885` / `IADR-0235` は「同型の事故が 2 回」を前提に設計されたが、**実際の発生率は桁違いに高い。**
`#906` の実測では **AI レビューの当該クラスの検出率は約 6%**（16 件中 1 件）だった。

## 決定

### 決定 1: 🔴 `#885` の裁定は覆さない。**測られた形が違う**

`#885` が退けたのは **pair-rule** であり、本仕様書の実測でも **10.2%**（`#872` 除外で 32.7%）である。
**その形については `#885` の判断が正しい。** 数値が `1/38` と違うのは母集合と窓が違うためで、
**桁は一致している。**

**新しいのは「record-rule は測られていなかった」という事実**である。

### 決定 2: 足す。**ただしゲートではなく warn で始める**

| 判断材料 | 値 |
| --- | --- |
| 検出率の改善 | AI レビュー **約 6%** → record-rule **94%** |
| 通常 PR での精度 | **100%** |
| 束ね PR での精度 | 37.5% |

🔴 **ゲートにしない決定的な理由は、偽陽性のときに人が取る行動である。**
検査器が「記録 X がどの文書の trace ブロックにも無い」と赤くしたとき、
**無関係な記録に対して人ができるのは「無関係な ID を trace ブロックへ足す」ことだけ**である。
それは**検査器が守ろうとしているメタデータそのものを汚す**。
**自分の目的を壊す失敗様式**なので、**除外の手段を設計するまでゲートにしない。**

`#885` が挙げた「**赤の常態化**」の懸念も、warn なら当たらない。

### 決定 3: warn が無視される危険を、設計で減らす

🔴 **warn は無視される。** 今日それを実測した ——
`k8s-local-up.sh` の `ABACSEED` は best-effort（WARN で通す）で、
**投入器が壊れていたことが数時間見えなかった**（`#984`）。

したがって warn は次を満たす。

1. **記録名と文書名を名指しする**（「どこを直すか」が読めば分かる）
2. **件数を出す**（増減が見える）
3. **0 件走査で静かに緑にしない**（`#664` の門）
4. **束ね PR で件数が増えることを、warn 本文で予告する**（読み手が驚かない）

### 決定 4: 判定は「同一コミット内の同居」だけを見る。遡及しない

既存文書への遡及は求めない。`#885` 候補 A と同じ射程である。

### 決定 5: ゲート化は 1 サイクル測ってから別途判断する

**warn を足した後の実測（無視されたか・偽陽性の分布が変わったか）を経てから決める。**
🔴 **本仕様書は「ゲートにすべきでない」ではなく「まだゲートにしない」と述べている。**

## 受け入れ基準

1. `scripts/check-trace-followthrough.js` が record-rule を実装し、**warn（EXIT=0）**で報告する
2. 実データで **21 件**を報告する（本仕様書の実測と一致）
3. **変異**: 文書の trace ブロックから記録 ID を落とすと、件数が増える
4. **変異**: 0 件走査になる状況で **fail する**（静かに緑にしない）
5. `--self-test` を持ち、pair-rule との違い（束ね PR で潰れること）を回帰として固定する
6. `scripts/README.md` へ追加し、CI の静的検査ジョブへ組み込む

## 🔴 検出しないこと

- **記録と文書が意味的に関係あるかは判定しない。** 機械にはできない。**関係の有無は読み手が判断する**
- **1 つでも載っていれば黙る。** `#893` のように「A には載せたが B にも要る」形は**見逃す**
  （実測で 17 件中 1 件）。**これは設計上の取引であり、欠陥ではない**
- **束ね PR では偽陽性が出る**（実測 37.5%）。**warn である理由がこれである**
- **`#872` のような規約導入コミット**は record-rule では 0 件になる。**pair-rule なら 115 件出る。**
  どちらが正しいかは文脈による —— **record-rule は「1 つでも載っていれば良し」なので黙るのが仕様どおり**
