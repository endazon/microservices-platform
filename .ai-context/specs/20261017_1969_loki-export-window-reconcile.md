# 仕様書: Loki のログ書き出しの取りこぼし（#1969）

## 起点となる計画書（トレーサビリティ）

- NFR-18（運用の口の統制）。ADR-0133（Loki の前段）・ADR-0006（観測スタック）は**変えない**前提として引く。
- 実装判断の記録: [IADR-0555](../adr/IADR-0555_loki-export-split-aligned-windows-and-count-reconcile.md)。道具は [IADR-0543](../adr/IADR-0543_operator-loki-read-path.md)、既定の件数は [IADR-0553](../adr/IADR-0553_loki-grpc-msg-size-and-export-default-limit.md)。
- 起点: #1969（PoC 2026-10-16。8 時間の書き出しで 0.4〜0.75% が欠け、終了コード 0）。関連: #1938・#1965。

## 原因（手元の Loki 3.0.0 で再現・特定した）

- 公式イメージ `grafana/loki:3.0.0` を compose と同じ設定（`deploy/loki-config.yaml`）で起動し、合成のログ 174,648 行（3 job × 3 level の 9 stream・8 時間・ときどき 20〜60 行の塊）を 2 日前の時刻で push して flush した（store から読む形。PoC と同じ）。
- 修正前の書き出し（8 時間・`--limit 1000`）: **174,623 行（−25）・終了コード 0**。欠けた行は 16:00:47 の 2 行と 20:00:02〜20:00:18 の 23 行で、**どれも正時の直後・1 つの stream（`{job, level}`）に固まる**（issue の観察と同じ形）。
- 欠けたページを 1 本ずつ真値と突き合わせた: start=19:57:46.737 の 1 ページ（1000 行）は、`DEBUG/trading` の 20:00:02.317 以降の 21 行を返さず、**代わりに他の stream の 20:00:14.98〜20:00:19.77 の 21 行を返した**。ページの最大時刻が先へ飛ぶので、次のページから取り戻せない。
- 同じ要求を分け目（正時）の両側に分けると、どちらも正しい（19:57:46〜20:00 の 879 行・20:00〜の limit 21/50/121 行のいずれも真値と一致）。limit 100・300・600 は正しく、900・1000・2000 で欠ける。
- 結論: **Loki 3.0.0 の query-frontend が `split_queries_by_interval`（既定 1h）で分けた応答を limit 件にまとめる段で、分け目の後の行を落とす。** 1 要求が分け目を跨がなければ起きない（回避策の「10 分の窓」が効いた理由）。

## 件数（count_over_time）の数え方（実測）

- `sum(count_over_time(<q> [r]))` を時刻 T で評価すると、**両端を含まない (T − r, T)** を数える。窓の始まりちょうど・終わりちょうどの行（境目に置いた行 2 本ずつ）を数えず、終わりの 1 ns 前の行は数える（6 窓で確かめた）。
- 幅に `ns` は使えない（`unknown unit "ns"`）。時刻を 1 ns ずらしてもミリ秒に丸められる（3774 vs 真値 3775）。
- 8 時間の 1 本の件数は 174,784 で、真値 174,792 より 8 少ない（Loki が瞬時のクエリも 1 時間で分け、分け目ちょうどの行を数えない。runbook の「8000 に対し 7997」と同じ現象）。

## 母集合（規則 9・10）

- 誤りの側の文字列で走査した: `git grep -n -E "正は書き出しの行数|目安|ほぼ一致|ページを送って全部書く|exportRange|--limit" -- docs scripts/README.md scripts/export-loki-logs.js .ai-context/adr`（`.ai-context/specs/` は凍結のため除く）。
  - runbook §4 の「スクリプトが古い順にページを送って全部書く」→ 窓と検算を足した。§4-2 の「`<N>` は §4-1 の件数の合計とほぼ一致する … 正は書き出しの行数である」→ **誤りになった**（書き出しも欠けていた）。検算に置き換えた。§4-1 の「job ごとの件数（目安。正は書き出しの行数）」はスクリプトの出力の写しなので、出力の文言（`summarize` の表示）と一緒に「正は書き出しの検算」へ直した。
  - `scripts/README.md` の `export-loki-logs.js` の行 → 窓と検算を足した。
  - IADR-0543・IADR-0553 の「ページ送りは境目の行を 1 度ずつ書く」は凍結記録で、ページ送りそのものの記述としては正しい（変えない。IADR-0555 から引く）。
- 新たに誤りになる自分の記述（規則 10）: スクリプト冒頭の「ページ送り」の説明は窓の中のページ送りとして正しいまま。`summarize` の注記（件数は目安）は残し、原因（分け目と両端）を足した。`--from`/`--to` をミリ秒までにしたので、runbook の時刻の例（秒まで）はそのまま通る。

## 試験（`scripts.repo.test.js`）と変異

偽の Loki に 2 つを足した: (1) `LX_SPLIT` —— 要求が分け目を跨ぐと job b の分け目直後の行を抜く（実測の形）、(2) `sum(count_over_time(q [Nms]))` を両端を含まない区間で数える。

| 変異 | 赤になる試験 |
| --- | --- |
| 窓を揃えない（`b = a + w`） | `#1969 窓を分け目に揃えて`（始まり 30 分・窓 60 分で跨ぐ） |
| 始まりちょうどの行を数えない（`want = open`） | `#1969 窓を…`・`#1969 …検算が合わず`・`#1969 main …` |
| 検算しない | `#1969 …検算が合わず`・`#1969 main …` |
| main が窓を使わない（`exportRange`） | `#1969 main …` |
| 既定の窓を 60 分 | `#1969 main …`・`#1969 --window は既定 10 分` |
| ミリ秒の単位を問わない | `#1969 --window は既定 10 分…` |

既存の `#1935`・`#1965` の試験の `--from`/`--to`（マイクロ秒）をミリ秒の倍数へ直した（行の時刻はナノ秒のまま）。

## 実物の Loki での確認（手元の 3.0.0）

- 修正後の 8 時間（`{job=~"ai-stock-trading\..+"}`・既定）: 174,840 行・192 ページ・48 窓・検算一致・真値と差 0。
- `--limit 500/1000/5000/900` × `--window 10/60/1/30`: どれも 174,840 行・差 0・exit 0。
- 変異（窓を `a + w` にして 13:30 から 60 分の窓＝正時を跨ぐ）: 14:30〜15:30 の窓で `書き出し 21866 行 / Loki の件数 21868 行（差 -2）`、`.partial` を残して exit 1。検算が実物の取りこぼしを捕まえる。
