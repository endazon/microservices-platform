# 仕様書: 自製イメージのタグを不変に固定する（#2132。親 #2047 指摘 M-27）

## 起点となる計画書（トレーサビリティ）

- 非機能要件: NFR-20（運用・保守／デプロイ「サービス単位で独立デプロイ、ロールバック可能」・GitOps（ArgoCD））。
  計画 `origin/main` の `02_requirements/01_requirements.md` 157 行で確認（2026-10-23）。
- 計画 ADR: ADR-0007（GitOps。ArgoCD ＋ Helm ＋ Harbor。「サービス単位で独立デプロイ・ロールバックでき」）、ADR-0008（k3s）。
  ADR-0135（版の固定）は**インフラ製品**の版が対象で、自製イメージは対象外（同 ADR の母集合）。本件と矛盾しない。
- 実装 ADR: IADR-0605（本件の決定）、IADR-0088（再デプロイ安全性。決定 1 の「既定 `latest` を placeholder として維持」を本件が改める）、
  IADR-0369（check-stack-ready の G11）、IADR-0066（経路B のローカルビルド）。

## 目的・背景

全サービス（`services.*` 18 件と `frontend`）が `tag: latest`（19 箇所）＋ `pullPolicy: IfNotPresent` で描かれ、template も
`{{ $svc.tag | default "latest" }}` で倒していた。同じタグの中身が替わってもノードのキャッシュが古い中身を配り続け、どの版が動いているかも
分からず、前の版の指定によるロールバックが成り立たない（NFR-20）。ArgoCD の Application にもタグを注入する口が無かった。

## 方式（利用者裁定: 案 A）

- CD（または配備する人）がビルド時の不変のタグ（git の sha）を `--set-string` で chart に渡す。chart の既定から `latest` を外す。
- Argo CD Image Updater は導入しない（案 B は不採用）。

## 経路B の実行環境

経路B は Linux と macOS（Rancher Desktop / Docker Desktop）の両方で走る。`local-image-tag.sh` は GNU だけの道具に依らない
（`sha256sum` が無ければ `shasum -a 256`、`xargs -r` は使わず `while read -d ''` で回す。レビュー 🟢 の対応）。

## 初回の切り替えのエラー文

タグの宣言が無いリリースへ `--reuse-values` を流す（`scripts/lib/mesh-mtls-mode.sh`・`istio-edge-up.sh` 等）と描画で止まる。
`required` のエラー文に「経路B は `k8s-local-up.sh --live` が渡す・初回の切り替え前は先にそれを流す」を入れ、`mesh-mtls-mode.sh` の
呼び出しの前にも注記した（レビュー 🟡 の対応）。

## pullPolicy の判断

`IfNotPresent` のままにする。タグが不変なら、タグが変わったときに Pod の template が変わって入れ替わり、新しいタグはノードに無いので取りに行く。
`Always` は経路B の擬似レジストリ（`k3d-local`）では存在しないレジストリへ取りに行って起動できない（IADR-0088）。
タグが無いときは描画そのものが落ちるので、pullPolicy が効く局面は無い（「latest ＋ IfNotPresent で古い中身」へ倒れる経路が無い）。

`IADR-0605` §検証を正とする。
