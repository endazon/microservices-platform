# 作業仕様書 — 基盤の他のクライアントも検証つきの TLS で繋ぐ（IADR-0591 段 4b-2 の MSP の分。#2403）

## 母集合（規則 9・10）

- 引き方: `git grep -n -E "KC_DB|DB_HOST|PGHOST|DB_SSL|PGSSL|ast-plain|amqp://|Host=postgres" -- deploy scripts .github`。
- 結果（基盤の DB・ブローカの平文のクライアントで、MSP リポジトリにあるもの）:
  - compose: `x-rabbit-env-ast-plain`（AST の 2 サービスが使う）・AST の 3 サービスの個別の `ConnectionStrings__DefaultConnection`（平文）・keycloak の `KC_DB*`・wiki-js の `DB_*`。
  - helm: `templates/wikijs.yaml` の `DB_*`（values の `wikijs.db`）。
  - 経路B: `platform-backup/postgres/cronjob.yaml` の `PGHOST`。
- 除外とその理由:
  - 経路B の `deploy/local/infra/keycloak.yaml`: `KC_DB_USERNAME=sa` は H2（dev-file）の資格で、postgres へ繋がない。
  - `platform-backup/vault/cronjob.yaml`: 秘匿管理（HTTP）への接続で、段 4b-4 以降の別の話（postgres・rabbitmq ではない）。
  - `deploy/cloud/`: 別セッションが新設中で本 PR では触らない。
  - 統合試験・単体試験の Testcontainers（平文の使い捨ての器）。
- この変更で新たに誤りになる自分の記述（規則 10）: compose の `x-db-env` の注記（AST は平文）・`scripts.repo.test.js` の「AST は段 1 の平文」の試験・統合スタックの門の注記（Keycloak・Wiki.js は平文）・IADR-0591 の段の表の 4b-2 の状態・`deploy/local/README.md` の「AST の接続は変えない」。

## 方式

1. **compose の AST の 3 サービス**: 個別の DB の接続文字列を `SSL Mode=VerifyFull;Root Certificate=/etc/platform-infra-ca/ca.crt` で終える。ブローカは `*rabbit-env`（amqps:5671・`SSL_CERT_DIR`）へ寄せ、`x-rabbit-env-ast-plain` を消す。CA を `*infra-ca-volumes` でマウントする。名前の照合（MSP の共通ヘルパに相当するもの）は AST リポジトリの側で入れる（それまでは連鎖の検証だけが効く）。
2. **compose の Keycloak**: `KC_DB_URL_PROPERTIES=?sslmode=verify-full&sslrootcert=/etc/platform-infra-ca/ca.crt`（pgjdbc）。CA を既存の volumes へ足す。
3. **Wiki.js**: `DB_SSL=true`（Wiki.js 2.5 は `ssl: { rejectUnauthorized: true }` で繋ぐ）と `NODE_EXTRA_CA_CERTS=/etc/platform-infra-ca/ca.crt`（Node の既定の信頼ストアに足す。置き換えない）。名前は node の既定の照合（`DB_HOST` の名前）。helm は `wikijs.db.tls.enabled`（**既定 false＝opt-in**）で描き分け、有効のときだけ `global.infraCa` の ConfigMap を非 optional でマウントする。経路B（`values-local.yaml`）は有効にする —— 起動器は CA の ConfigMap を helm の前に写し、写せなければ止まるので、CA の無いまま Wiki.js が描かれることは無い。
4. **バックアップの CronJob**: `PGSSLMODE=verify-full`・`PGSSLROOTCERT=/etc/platform-infra-ca/ca.crt`。CA は同じ名前空間（platform-infra）の cert-manager の Secret `postgres-tls` からキー `ca.crt` だけを写してマウントする（非 optional。鍵のキーは写さない）。
5. **統合スタックの門**: 基盤の TLS の門で、Wiki.js（利用者 kp・DB wikijs）の接続がすべて TLS で 1 本以上あることを足す。

## 受け入れ基準（試験への写像）

- [x] compose: AST の 3 サービスも DB は VerifyFull ＋ 基盤の CA、ブローカは `*rabbit-env`、CA をマウントする。`x-rabbit-env-ast-plain` が無い（`scripts.repo.test.js`）。
- [x] compose: Keycloak は `KC_DB_URL_PROPERTIES` が verify-full ＋ CA で、CA をマウントする。Wiki.js は `DB_SSL=true` ＋ `NODE_EXTRA_CA_CERTS` ＋ CA のマウント（`scripts.repo.test.js`）。
- [x] helm: 既定（本番像）の Wiki.js は従来の形（`DB_SSL` も CA のマウントも無い）。`wikijs.db.tls.enabled=true` と values-local では `DB_SSL=true` ＋ `NODE_EXTRA_CA_CERTS` ＋ CA の非 optional の 1 キーのマウント。変異（マウントを外す）で赤（`helm-infra-tls.test.js`）。
- [x] バックアップの CronJob: `PGSSLMODE=verify-full` ＋ `PGSSLROOTCERT` が CA のマウント先を指し、Secret `postgres-tls` の `ca.crt` だけを非 optional で写す（`platform-backup.test.js`）。
- [x] 配備の宣言に検証を緩める形が無い（`sslmode=require` 等・`rejectUnauthorized: false`・`NODE_TLS_REJECT_UNAUTHORIZED`）。走査の対象に wikijs.yaml・backup の CronJob を足す（`scripts.repo.test.js`）。
- [x] 統合スタックの門が Wiki.js の接続を判定する（`integration-stack.yml`）。
- [x] 手元の docker で実測（IADR-0675 §実測）: Wiki.js 2.5・Keycloak 26.7.4・pg_dump 16 がいずれも CA と名前の検証つきで繋がり（TLSv1.3）、CA が無い・名前が違うと拒む。
- [ ] 統合スタック（`ISTIO=1`）を PR のブランチで流し、門が緑（流せない場合は理由を PR に書く）。

## 影響範囲

- `deploy/docker-compose.yml`・`deploy/helm/microservices-platform/{values.yaml,templates/wikijs.yaml}`・`deploy/local/values-local.yaml`・`deploy/local/platform-backup/postgres/cronjob.yaml`・`.github/workflows/integration-stack.yml`（門）・試験・`deploy/local/README.md`・IADR-0591 の段の表への注記。
- 稼働のクラスタ（経路B）: 起動器の再実行で Wiki.js（Recreate）が 1 回作り直される。バックアップは次の回から TLS で繋ぐ。サーバは段 1 から併存なので、他のクライアントは変わらない。本番像の helm は既定が従来の形なので、値を有効にするまで何も変わらない。
