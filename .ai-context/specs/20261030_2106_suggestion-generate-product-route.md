# 作業仕様書 — AI 提案の生成の製品の経路（#2106）

> 本仕様書は実装着手前に作成した（着手 2026-10-30。develop `49cffbb2`）。親 #2047（指摘 M-9）。

## 計画（確定済み）

- **ADR-0081 決定 1**: タイミングの選択は実装の裁量である。実装は「要求時」を選んでいる（IADR-0266）。
- **ADR-0081 決定 2**: SC-03 に生成を起動する操作要素を置く場合、押せるのは**その文書を読める利用者**である。
  - 管理者・運用者に限らない。管理者に限ると、管理者のスコープの提案を一般利用者へ見せる形になり、存在秘匿を破るからである。
  - 承認・却下の資格（write または管理者の経路）とは別である。
- **ADR-0081 決定 3**: 要求時なので、費用は前月比と累計で見る（用途 `graph-suggestion` で切り分け済み）。
  - 自動起動・定期実行へ切り替えるなら、計画へ環流する。本 issue は切り替えない。
- 計画 `05_screens` の SC-03 §AI 提案の承認欄にも同じ定めがある（生成の操作要素。2026-09-05）。

## 現状（develop で確認）

- 後段 `POST /graph/suggestions/generate/{documentId}` は read で解決し、起点が見えなければ 404 を返す。これは ADR-0081 決定 2 の資格と一致する。
  - 注釈には「正しいアクションは analyze かもしれず裁定待ち」とあるが、ADR-0081 決定 2（`read`）で裁定は済んでいる。
- BFF の口は計測専用（IADR-0530 決定 1）で、既定は無効、構成の鍵があるときだけルート表に載り、管理者限定である。
- 画面に起動の要素は無い。

## 方針

1. **BFF**: 製品の口 `POST /bff/graph/suggestions/generate/{documentId:guid}` を常に載せる。
   - 群の認証（ロール不問）だけを使う。資格（その文書を読める）は後段が判定する（read。見えなければ 404）。
   - 状態コードと本文は詰め替えない（`ForwardAsync`）。
   - **計測専用の口（構成の鍵・管理者限定）は撤去する**（IADR-0653 が IADR-0530 決定 1 を置き換える）。
     - 同じパスに 2 つの口は置けない。
     - 製品の口があれば、管理者も文書を読める利用者として計測に使える。
     - 鍵 `Measurement:EnableSuggestionGenerate` と helm の `measurement.suggestionGenerate` も外す。残すと効かない鍵になり、「有効にしたのに管理者限定のはず」と誤読される。
2. **openapi**: パスの説明・`x-roles`・`operationId` を製品の口に改める（`bff-graph-suggestion-generate`）。orval で再生成する。
3. **SC-03**: 承認欄（`AiSuggestionPanel`）に「AI に提案を作らせる」ボタンを置く。
   - SC-03 を開けた利用者なら押せる（追加の権限判定を画面に持たない）。
   - 押すと生成し、成功したら提案の一覧を引き直す（無効化）。
   - 生成中は押せない。
   - 失敗したら中立の文言を出す（404 も「生成できませんでした」に寄せる。存在秘匿）。
   - 文言で、LLM を呼ぶことと、提案は閲覧できる文書の範囲で作られることを示す。
   - 🔴 **0 件のときの配置は暫定**（planning#857 の裁定待ち。推奨は (a)）: 0 件のときは見出し・枠を出さず、ボタンと説明 1 行だけを置く。1 件以上のときは欄の中に置く。
     配置は 1 つの部品 `SuggestionGenerateControl` に閉じ、裁定が異なれば配置だけを差し替える。
4. **後段の注釈**: 「裁定待ち」を、ADR-0081 決定 2 で解決済みと改める（振る舞いは変えない）。
5. **運用文書**: east-west の計測の手順書は `measurement.suggestionGenerate` を使っている。「製品の口を管理者として叩く」へ改める。
6. **IADR-0653** を起こす。IADR-0530 決定 1 を置き換える。IADR-0530 の状態欄に後継を併記する（本文は書き換えない）。
