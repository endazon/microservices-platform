# 作業仕様書: 生の NUL バイト混入の検査（#956）

## 起点

- `#956`（自分で 3 回踏んで起票した。**実装中に 4 回目が起きた** —— 下の「実装後に確定した結果」）
- 発生: `#900` の `check-coverage-floor.js` → `#919` の `check-backend-libraries.js` →
  **その是正を記録する仕様書**（同一 PR 内で再発）→ **本検査器そのもの**（本検査器が自分で捕まえた）
- **CLAUDE.md の「検査器・規約の追加は『同型の事故が 2 回起きたら』を条件とする」** に対し
  起票時点で **3 回目**、着地時点で **4 回目**

## なぜ検査するか

生の NUL（`0x00`）が入ると **`git` と `grep` がファイルをバイナリ扱いする**。

```
$ grep -n 'function selfTest' scripts/check-backend-libraries.js
Binary file scripts/check-backend-libraries.js matches      ← 行番号が出ない
```

- `git diff` が中身を出さない（`Binary files differ`）→ **レビューできない**
- `grep` が行番号を出さない → **走査・母集合の引き直しが機能しない**

🔴 **4 回とも実行時挙動は正常で、テストも他の検査器も緑だった。** 気付いたのは `grep` が
`Binary file … matches` を返したときで、**偶然に近い**（4 回目だけは本検査器が捕まえた）。

## 🔴 着手前の実測 —— 偽陽性の費用

`#919` で「偽陽性が構造的に増えない」を測ったのと同じ形で先に測った。

| 項目 | 実測 |
| --- | ---: |
| 追跡下のファイル | **1995 件** |
| **NUL を含む追跡下ファイル** | **0 件** |
| 追跡下のバイナリ拡張子（`png`/`jpg`/`pdf`/`zip`/`dll`/`exe`/`woff`/`ttf` ほか） | **0 件** |

拡張子の内訳（上位）: `md` 825 / `cs` 501 / `ts` 142 / `tsx` 89 / `gitkeep` 87 /
`yaml` 85 / `json` 80 / `js` 60 / `csproj` 41 / `yml` 23 / `sh` 15 …

**このリポジトリは追跡下が全部テキストである。**

## 決定

### 決定 1: 検査範囲は「追跡下すべて」。拡張子の許可リストにしない

**構造的な根拠を採る**（`IADR-0138` が「サフィックスは規約にすぎず、壊れたときに無音になる」として
ディレクトリ（構造）を選んだのと同じ判断）。

- **許可リスト方式**（テキスト拡張子だけ検査）は、**新しいテキスト拡張子が黙って検査対象から外れる**。
  今日の実測でも `.gitkeep` / `Dockerfile` / `.hcl` / `.po` / `.template` など **126 件**が
  「テキスト系候補」から漏れていた。**この失敗は無音である。**
- **追跡下すべて**なら、将来バイナリを追加したときに**落ちる**が、**その失敗は目に見える**。
  失敗メッセージで「バイナリを足したなら `BINARY_EXTENSIONS` へ追加せよ」と案内する。

**無音の見逃しより、目に見える誤検出を選ぶ。**

### 決定 2: 🔴 検査器はバイトで読む。復号しない

**自分が検出したいもので自分が壊れないようにする。** NUL を含むファイルを `utf8` で読むと
内容が化け、実装によっては例外にもなる。`fs.readFileSync(abs)`（Buffer）で読み、
**バイト列を走査するだけ**にする。復号は一切しない。

### 決定 3: 0 件走査で静かに緑にしない

走査件数の下限を置き、**下回ったら fail** する（`#664` の門と同じ作法）。
走査件数と、（もしあれば）除外件数を毎回出す。

## 受け入れ基準

1. 素の状態で **EXIT=0**（偽陽性なし）
2. 任意の追跡下ファイルへ NUL を 1 バイト入れると **EXIT≠0**、**ファイル名と位置（バイトオフセット・行）**を出す
3. **検査器自身が NUL を含むファイルで壊れない**（例外を投げない・復号しない）
4. 0 件走査で fail する（走査件数の下限）
5. `--self-test` を持ち、EXIT=0
6. `scripts.test.js` から呼ばれ、実データ走査も通る

## 実装後に確定した結果

### 🔴 検査器の最初の実捕捉は、作者の 4 回目の同じ事故だった

実装直後、本検査器を `git add` して走らせたところ **自分自身を捕まえた**。

```
[check-nul-bytes] 生の NUL バイトを含むファイルが 1 件あります:
    scripts/check-nul-bytes.js  （10 行目 / バイトオフセット 439）
```

「エスケープ表記と書いたつもりが実バイトになる」を**説明する行**で、また実バイトになっていた。
**4 回目**である。以後この文書と検査器では、エスケープ表記を記号で書かず**語**で書いている。

### 変異試験（ハーネスを 2 度直した）

| 変異 | 結果 |
| --- | --- |
| M1 `docs/README.md` へ NUL 1 バイト | ✓ EXIT=1・ファイル名と行番号を名指し |
| M2 **検査器自身のコメント内**（実際の事故と同じ形） | ✓ EXIT=1・`scripts/check-nul-bytes.js（7 行目）` |
| M3 `src/coverage-floor.json` | ✓ EXIT=1・名指し |
| M3b `.ai-context/adr/README.md` | ✓ EXIT=1・名指し |
| M4 未追跡ファイルへ NUL | ✓ EXIT=0（走査範囲の定義どおり対象外） |
| M5 走査件数の門を無効化 | ✓ 自己試験が落ちる |
| 対照 素の状態 | ✓ EXIT=0 |

🔴 **ハーネスの誤りを 2 件、実測で見つけて直した。**

1. **M2 の当初版は「末尾に NUL を追記」だった。** EXIT=1 になったが、中身は
   **`SyntaxError` で Node が読み込みに失敗しただけ**で、検出ではなかった。
   実際の事故は**コメント内**（構文は壊れない）なので、注入位置をコメント内へ変え、
   **先に `require` が成功することを確認**してから検出を判定する形にした。
   **「検出した」と「起動に失敗した」は別物である。**
2. **M5 の当初版は「空リポジトリで実行する」だった。** `REPO_ROOT` が `__dirname` 基準のため
   **cwd を変えても本リポジトリを走査して緑になり、門を試験できていなかった**。
   下限の判定を純粋関数 `isScanTooSmall` へ切り出し、直接試験する形にした。
