# 仕様書: パスワードリセットの存在秘匿を閉じる（issue #1143）

## 起点となる計画書（トレーサビリティ）

- 画面（SC）: SC-15（パスワードリセット。存在秘匿）／SC-10（運用ダッシュボード・送信失敗の観測）
- 機能要求（FR）: FR-05
- 関連 ADR: ADR-0026（存在秘匿の確定）／ADR-0045 **決定 8**（送信失敗を隠さない）・**決定 9**（開発環境で実送信しない）
- 先行する実装 ADR: IADR-0261 / IADR-0332 / **IADR-0344**（#1144。捕捉用 MTA を dev 既定で配備）

## 目的・背景

`docs/screens/SC-15_password-reset.md` は「存在秘匿（常に『メールを送信しました』）| **する**」と書いているが、
**稼働環境で測ると偽である**。送出に失敗すると**実在する利用者名のときだけ 500** が返り、
**その差だけで利用者名を 1 リクエストずつ列挙できる**。

## 実測（着手前。稼働 k3s・4 状態を対で測った）

`scripts/check-password-reset-mail.js`（#1144 で新設）と直叩きの器で測定。**`-k` は使っていない**
（クラスタのローカル CA を検証に与えた）。

| # | 状態 | 実在する利用者名 | 実在しない利用者名 | 区別できるか |
| --- | --- | --- | --- | --- |
| **A** | 送出経路が生きている ＋ 申請が開いている | **200** | **200** | **できない**（正規化後の本文も一致） |
| **B** | `smtpServer` 未設定 ＋ 申請が開いている | **500**「申し訳ございません」 | **200** | 🔴 **できる**（本 issue） |
| **C** | 送出先へ接続できない ＋ 申請が開いている | **500** | **200** | 🔴 **できる** |
| **D** | 申請が閉じている（`resetPasswordAllowed=false`） | **400** | **400** | **できない**（本文はバイト一致・導線も消える） |

状態 D の本文比較（フローの識別子と入力の再表示だけを伏せて正規化）:

```console
normalized equal = True | lens 3517 3517
```

🔴 **状態 B は「例外的な設定ミス」ではない。** 稼働クラスタで **Keycloak コンテナが再起動した直後は必ず状態 B になる**
ことを実測した（`RESTARTS 3`・H2 はコンテナ層にあり `kcadm` の実行時反映は消える。realm 再インポートが
`resetPasswordAllowed=true` を復元し、`smtpServer` は空のまま）。**放っておくと定期的に脆弱な組へ戻る。**

## 設計

### D0. 「テーマで隠す」「フローを組み替える」は**測って落とした**

| 案 | 却下の根拠（実測・一次情報） |
| --- | --- |
| (a) テーマで失敗時も同じ画面を返す | **HTTP ステータスをテーマは変えられない。** 500 は認証器がエラーページとして組み立てており、テンプレートは本文しか差し替えられない。受け入れ基準 1 は**ステータスの一致**を要求する。加えて IADR-0261 決定 1 は「テンプレート（.ftl）は上書きしない」と定めている（上書きすると本体のセキュリティ修正に追随できなくなる） |
| (a') 認証フローを組み替える | **`reset-credential-email` は `configurable: false` かつ `requirementChoices: ["REQUIRED"]`**（稼働 realm の `authentication/flows/reset%20credentials/executions` を実測）。**ALTERNATIVE にも DISABLED にもできず、設定で挙動を変える余地が無い** |
| (c) BFF で申請端点を包む | **SC-13〜15 の画面は Keycloak テーマ側である**（ADR-0026・`AuthBffEndpoints.cs` 冒頭の宣言）。ブラウザは Keycloak のオリジンへ直接 POST しており、BFF は経路上に居ない。前段へ入れるのは**計画側の決定を要する**（本リポジトリの裁量を超える） |

→ **残るのは (b)「fail-closed で同値」**である（issue 本文が候補として挙げ、「500 をテーマで隠せない場合は (b)」と
書いていた道）。**状態 D が実測で同値であることは上表で確かめた。**

### D1. 不変条件: **申請は、送出経路が使える間だけ開く**

`resetPasswordAllowed = true` は **使える `smtpServer` と一対でしか成立しない**。片方だけの状態（＝状態 B）を
**宣言でも稼働でも許さない**。使えないなら閉じる —— 閉じれば状態 D になり、**両者に同じ 400 を返す**。

### D2. 実効的な根本対策の半分は #1144 が既に入れている

**状態 C（送出先へ接続できない）が現実に起きる形は「上流の実リレーが落ちる」である。** #1144 は
**Keycloak の送出先をクラスタ内の常時受け付ける捕捉用 MTA に固定し、外部の実リレーへ直結させない**
（静的な門つき）。したがって**上流の停止は Keycloak の送出失敗にならない**。
加えて **realm.json が `smtpServer` を持つようになった**ため、**再起動・再インポートは状態 B ではなく状態 A へ戻る**
（上の実測が示した自動復帰の経路を塞いだ）。

### D3. 三層で結合を強制する

| 層 | 何を見るか | 落ち方 |
| --- | --- | --- |
| **宣言（静的）** | `deploy/keycloak/*-realm.json` の `resetPasswordAllowed` と `smtpServer` の対 | `check-realm-constraints.js` が fail。変異試験つき |
| **稼働（実行時）** | 稼働 realm の同じ対（`kcadm` を Pod 内で実行。**資格情報は Pod の env のまま・出力しない**） | `check-password-reset-mail.js` が **応答を測る前に** fail し、**どの状態に居るか**を名指しする |
| **運用（手順）** | 実リレーへ切り替える前後・送出経路が落ちたとき | runbook が「先に閉じる／戻してから開く」を手順として持つ |

### D4. 失敗は消えない（受け入れ基準 3）

realm は `SEND_RESET_PASSWORD` / `SEND_RESET_PASSWORD_ERROR` を `enabledEventTypes` に**既に持っている**（実測）。
送出失敗は監査ログに残り、**利用者向けの応答には出さない**（状態 D では申請自体を受け付けないため、
利用者に見えるのは「機能が使えない」ことだけで、**誰が登録されているかは出ない**）。

## 受け入れ基準

- [ ] **1. 応答の同値性（送出経路が死んでいるとき）** —— `smtpServer` 未設定の状態で、実在／非実在の申請の
      **ステータス・本文・リダイレクト先が区別できない**
- [ ] **2. 応答の同値性（リレー先が落ちているとき）** —— 同上（実値投入後も再発しない）
- [ ] **3. 失敗が消えない** —— 送出失敗は監査ログ／SC-10 で観測でき、利用者向けの応答には出さない
- [ ] **4. 画面仕様書が実測と一致する** —— 「存在秘匿」の行が実測（陽性・陰性対照の対）で裏づけられている
- [ ] **5. 回帰を機械が持つ** —— 実在／非実在の応答同値性を検査するテストがあり、**片方だけ壊すと落ちる**（陽性対照つき）

## 母集合（規則 9・10。**走査してから**挙げた）

```console
$ git ls-files | grep -v '^src/ai-stock-trading/' | xargs grep -ln 'resetPasswordAllowed'   → 8 件
$ git ls-files 'docs/*' 'deploy/*' 'scripts/*' | xargs grep -ln 'メールを送信しました'      → 1 件
$ git ls-files 'docs/*' 'deploy/*' 'scripts/*' | xargs grep -ln 'SEND_RESET_PASSWORD'      → 1 件
```

🔴 **「存在秘匿」での走査は使えない。** 追跡下 200 件超に当たるが、その大半は
**ABAC の「権限が無い資料は 404 で存在を隠す」という別概念**である（IADR-0009 系）。
**同じ語で違うものを数えると母集合が嘘になる**ので、SC-15 に固有の言い回し
（固定文言・列挙・監査イベント種・realm のキー）で引き直した。

| ファイル | 追随 | 理由 |
| --- | --- | --- |
| `deploy/keycloak/microservices-platform-realm.json` | **する** | 結合の当事者（`resetPasswordAllowed` と `smtpServer`）。#1144 で `smtpServer` は入った |
| `docs/screens/SC-15_password-reset.md` | **する** | 「存在秘匿 ｜ しない（測って偽と分かった）」の行と §未決事項（受け入れ基準 4） |
| `docs/tests/SC-15_password-reset.md` | **する** | T-10 の前提（送出経路が生きているとき限定）と、閉じた状態の試験を足す |
| `scripts/check-password-reset-mail.js` | **する** | 実行時の結合の門を足す（どの状態に居るかを名指しする） |
| `scripts/check-realm-constraints.js` | **する**（走査には出ないが結合の門の置き場） | 宣言側の門。**走査で出ないものを足すのは「新設」であって追随ではない**ので、ここに理由を書いて区別する |
| `.ai-context/adr/IADR-0197` / `.ai-context/specs/20260815_*` / `20260831_*` / `20260902_issue-1144_*` | **しない** | **確定済みの凍結記録**。本文を後から書き換えない |

**この変更で新たに誤りになる自分の記述（規則 10）**: 「存在秘匿はしない」「`smtpServer` 未設定では
原理的に検証できない」。前者は本 PR で条件つきの真になり、後者は #1144 で既に偽になっている。

## 計画書との差異

- 差異: **あり（1 件・環流する）**。ADR-0045 決定 2-b は go-live の接続を「Keycloak → `smtp.gmail.com:587`」の
  書式で定めているが、**その構成では上流の停止がそのまま利用者名の判定器になる**（状態 C）。
  実装側は決定 9 の捕捉用 MTA を dev で挟むことで dev の窓を塞いだが、**go-live の topology は計画の領分**である。
  → **project-planning へ issue を起票する**。
- 差異なし: ADR-0026（存在秘匿の要求そのもの）／決定 8（失敗を隠さない）。

## 未決事項

- **送出経路が「開いたまま」落ちた瞬間から、運用が閉じるまでの窓**は残る。自動で閉じるには
  ①Keycloak の SPI（Java 成果物。本リポジトリにビルド基盤が無い）②前段プロキシ
  ③realm を書き換える調停器（`manage-realm` の付与＝IADR-0329 が守った最小権限の後退）
  のいずれかが要る。**いずれも本 issue の裁量を超えるため、記録して環流する。**
