# 作業仕様書 — リストア試験の --rm（#2391）

> 本仕様書は、実装に着手する前に作成した（着手 2026-11-04。develop `6d1f73b7`）。

## 事象

- 稼働 PoC のリストア試験（MSP#1709 の ④）で、`scripts/backup-restore-drill.sh` の `"$cli" run -d --rm --network none …` を nerdctl（Rancher Desktop の containerd）が拒んだ（`flags -d and --rm cannot be specified together`）。
- PoC では、`CONTAINER_CLI` のラッパーで `--rm` を落として通した。

## 方針

- `run` から `--rm` を外す。片付けは、もともと EXIT の trap（`drill_cleanup` の `"$DRILL_CLI" rm -f "$DRILL_NAME"`）が成功・失敗の両方で持つ。
- 自己試験（T-1560-37）の字面 `run -d --rm --network none` を、`run -d --network none` に改める。`run` の行に `--rm` が無いことも固定する。
- 片付けの試験（T-1560-37 の「最後に消す」と T-1560-38 の「失敗しても消す」）は、そのまま残す。

## 受け入れ基準

- [x] 修正の前に、改めた自己試験が赤になる。
- [x] `run` に `--rm` が無く、`-d --network none` で起こす。
- [x] 成功・失敗のどちらでも、使い捨てのコンテナを `rm -f` で消す。

## 母集合（規則 9・10）

- **規則 9**: 走査の語は「`--rm`」「`run -d`」「nerdctl」「CONTAINER_CLI」である。範囲は `scripts`・`docs/operations`・`.ai-context/adr`・`.github/workflows` とした。
  - 改めるのは `scripts/backup-restore-drill.sh`（`run` の行と自己試験）だけである。
  - 対象外:
    - runbook の nerdctl（イメージのビルドと inspect の手順で、別の主題）。
    - ワークフローの `docker run --rm`（CI の moby で動き、`-d` を伴わない）。
- **規則 10**: ドリルの冒頭の注記には、`--rm` に依る記述が無い。

## 残余リスク

- SIGKILL で trap が走らないと、コンテナが残る（`--rm` があっても `-d` のコンテナは残るので、前と同じ）。名前は `platform-backup-drill-<PID>` で見分けられる。
