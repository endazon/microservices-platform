## 起点

- NFR（運用保守。**無採番** —— 工程の統制であり、計画側の非機能要件表に当たる番号が無い。
  `traceability.md`「起点 ID の種別」の 2）
- 実装 ADR: [[IADR-0236]]（レポート跨ぎの重複排除）／[[IADR-0232]] 改定 3（門は回収先に 1 つ）／
  [[IADR-0141]]（検査器は 2 回目で置く）／[[IADR-0418]]（本 PR で新設）
- issue: #1346（出典: planning#574 横断監査 指摘 A-6）

## 現状（実測。`develop` `867ed7ff`。**自分で数え直した**）

### 1. 床値のコメントが 3 か所で腐っている

正本 `src/coverage-floor.json` の `backend` は **line 90 / branch 75**（`#901` で引き上げ済み）。

| 置き場 | 書かれている値 |
| --- | --- |
| `.github/workflows/integration.yml:11` | line 88 / branch 68 |
| `.github/workflows/integration.yml:89` | line 88 / branch 68 |

### 2. 🔴 期待レポート件数が **2 か所とも**実物とずれている

| 置き場 | 書かれている値 |
| --- | --- |
| `.github/workflows/integration.yml` | **16 件** |
| `src/coverage-floor.json` | **17 件** |

**実物は 19 件。** 自分で数えた（規則 7 —— 他人の数えを転記しない）:

```
git ls-files "src/**/*Tests.csproj" | grep -v "^src/ai-stock-trading/" | wc -l  →  19
```

独立した裏取りとして、両ユニットの `dotnet test` を実走したときの出力も
**platform 7 ＋ knowledge 12 = 19** の DLL であった。`templates/` の雛形テストは
探索起点（`src/`）の外なので初めから範囲外である。

### 🔴 これが効いている場所

`#900`（[[IADR-0236]]）の重複排除以降、**同じテストプロジェクトを 2 回実行しても分母は倍にならず、
床は割れない**。二重実行は fail ではなく**無音**になり、
**残る唯一の検知手段が「レポート件数の期待値」だった。**

⇒ その期待値が 2 か所とも間違っている以上、**検知手段そのものが機能していなかった。**

## 母集合（規則 1・2・9・10）

「機械が数えられる値をコメントへ写している箇所」を、**誤りの側の値**（`88` / `68` / `16 件` / `17 件`）
と、正しい側（`90` / `75` / `19`）の**両方**で走査した。

| 走査語 | 結果 |
| --- | --- |
| `88` / `68` を「床」文脈で | `integration.yml` 2 か所 ＋ `ci.yml` 1 か所 |
| 「期待値」＋件数 | `integration.yml` 3 行 ＋ `coverage-floor.json` 1 行 |
| `90` / `75`（正しい側） | `src/coverage-floor.json` の `backend` だけ（＝**正本は 1 つ**） |

### 除外したものと理由（規則 6）

- **`src/coverage-floor.json` の根拠欄に並ぶ過去の実測値**（`line 88.99%` 等）:
  **記録であって検知手段ではない**。腐っても何も検知できなくならない（[[IADR-0418]] の区別）。
  `integration.yml` の当時の実測も同じ理由で「当時の実測」と明記して残した。
- **#1345（床を PR で強制する経路が無い）**: 構造そのものへの政策判断であり、
  **利用者引き取り事項**と issue 自身が書いている。本 PR は現構造に合わせるだけで変えない。
- **#1348（必須チェック表の件数・廃止ジョブ名）**: 同じ「写しが腐る」型だが**ファイル領域が別**
  （`docs/ai-workflow.md` / `docs/DEFINITION_OF_DONE.md` / `scripts/README.md`）。別 PR。

## 決定

[[IADR-0418]] 決定 1〜4 が正本。

1. 期待件数は `check-coverage-floor.js` が**テストプロジェクトを数えて導く**（除外はレポート側と共有）
2. **多い側だけ error**（＝二重実行。床では検知できない）。少ない側は warn（床が捕まえる／部分実行が正当）
3. `--report-only` では落とさない（門は回収先に 1 つ。[[IADR-0232]] 改定 3）
4. 床値もコメントへ写さない（正本を指す）

## 実測（門が実際に働くこと）

擬似 Cobertura レポートを `src/` 配下へ置いて実走した（**スクリプトは無改変**）。

| 置いた件数 | 結果 |
| --- | --- |
| **20 件**（＝19 ＋ 1） | 🔴 **exit 1**。「同じテストプロジェクトを 2 回以上実行している疑いがある」 |
| **19 件**（＝実プロジェクト数） | ✅ exit 0。「レポート件数はテストプロジェクト数（19 件）と一致している」 |
| 20 件 ＋ `--report-only` | warn のみ・**exit 0**（PR 側で門を増やさない） |

🔴 **期待値 19 は検査器が自分で導いた値であり、私が書き込んだ値ではない。**
私の手計算（上の 19）と**独立に一致した**。

自己試験 111 → **118 件**（`compareReportCount` の 4 本 ＋ `findTestProjects` の 2 本 ＋ 陽性対照）。
