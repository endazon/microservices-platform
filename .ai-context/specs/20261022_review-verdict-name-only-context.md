# 仕様書: check-review-verdict の「名前だけ」を読み方の文脈に限る

> 本仕様書は実装着手前に作成した（着手 2026-10-22）。実装の基点は MSP `origin/develop` `147e66fb`。
> 判断は IADR-0538 の範囲内の是正であり、新しい IADR は起こさない（検出の型の誤検知を 1 つ絞るだけで、判定の規則は変えない）。

## 起点

- #2048 の head `c5f4678e` の claude-review（check_run 119322504034）が、🔴/🟡 とも 0 件のレビューを
  「19 ファイルを読んだと申告したが、本文が精読していないと書いている —— 『- 置き換えるのは `E2E_` で始まる名前だけ。』」で落とした。
  問題の一文はコードの挙動（差し込みの口が `E2E_` で始まる名前だけを置き換える）の説明であり、読み方の自認ではない。
- 同型の誤検知は AST で一度起き、AST#1401 で直した（AST develop の `scripts/check-review-verdict.js`）。今回が 2 回目。

## 母集合（規則 9）

- `git grep -n '名前だけ'`（`CHANGELOG.md`・`.ai-context/specs/` を除く）: 検査器は `scripts/check-review-verdict.js` の
  `NOT_READ_PATTERNS[3]` の 1 か所だけ。ほかは IADR の地の文（「名前だけを揃える」「名前だけを返す」等）で、
  いずれも挙動・方針の説明であり、絞った形でも一致しない（＝同じ誤検知の型の実例）。
- 🔍 の節用の配列 `NOT_READ_PATTERNS_IN_NOT_RUN` は添字 3 を**含まない**（依頼文の「280 行付近は絞られている」は実測と違う。
  そもそも引いていない）。よって揃える先は `NOT_READ_PATTERNS` の 1 か所だけである。添字で引く箇所（0・1・2・8・9・11）は変わらない。

## 方法

- `名前だけ` を `名前だけ(?:を|で|に)?(?:見|確認|読|並べ|一覧|目視|照ら)` に絞る（AST#1401 と同じ形）。
  「名前と範囲の確認」「名前を一覧／名前の一覧」は変えない。

- [x] 陽性「テストは名前だけ確認した。」「テスト 4 本は名前だけを見た。」は引き続き赤（`scripts/scripts.test.js` の陽性の表）。
- [x] 陰性「- 置き換えるのは `E2E_` で始まる名前だけ。」（#2048 の実文）と「市場の名前だけを受け付ける」（AST#1400 の同型）は緑（陰性の表）。
- [x] 変異: 絞りを戻す（`名前だけ/`）と、陰性 2 文がともに赤になる（手元で確認。PR 本文に記録）。
- [x] `REQUIRE_REPO_TESTS=1 node scripts/scripts.test.js` が緑。
