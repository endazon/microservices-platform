## 🔴 この期間に踏んだ事故（同じ形を繰り返さないため）

### 1. 「無い」と結論する測定で、探す範囲が足りていなかった（6 回）

| 測ったもの | 誤った結論 | 実際 |
| --- | --- | --- |
| 稼働イメージの LLM 計器 | 「未実装」 | **存在しないファイル名**（`LlmGateway.Api.dll`）で測っていた。実体は `LlmGateway.dll` |
| .NET アセンブリ内の文字列 | 素の `grep` で 0 件 → 「無い」 | **メタデータは UTF-16**。`tr -d '\000'` が要る |
| Istio の sidecar 注入 | `spec.containers` を見て「0 件」 | **1.30 はネイティブサイドカー**で `initContainers` に入る |
| apiserver → Keycloak の到達性 | `curl` が通る → 「問題ない」 | **`curl` は `.localhost` を特別扱いするが Go はしない** |
| Keycloak の永続化 | 「PVC 化は実装されていない」 | **base だけを見て `deploy/local/infra-persistence/` の opt-in オーバーレイを探していなかった** |
| `KeywordSearchAsync` の壊れ方 | 「`catch (RpcException)` が常に成立」 | **コードのコメントを実測と取り違えた。** v1.18.1 では例外は出ず**部分文字列走査へ黙って落ちる**（版上げで挙動が変わっていた） |

**規範**: 「無い / 0 件 / 到達しない」と書く前に、**「有るはずのもの」で同じ測定をして非ゼロが出ることを示す**。
出なければ測り方が壊れている。**このリポジトリは fail-safe な既定＋opt-in オーバーレイを多用するので、base に無い＝実装が無い、ではない。**

### 2. 並行 PR は必ず同じ IADR 番号を採る

`check-adr-numbering.js` は**重複も欠番も許さない連番**を要求する。
**事前に番号を配る方式は失敗した** —— 4 本並行で 2 巡し、各エージェントに 3 回ずつ改番させた。マージ順は CI・衝突・レビューで動くので事前配布は必ず崩れる。

**採った方式**: 各エージェントには「番号は好きに採ってよい・衝突しても気にしなくてよい」と伝え、
**マージ直前にオーケストレータが `develop` の最大値 +1 へ改番して 1 本ずつ入れる。**
🔴 **一括 `sed` をしないこと** —— 同じ番号が「他の PR の正当な ADR」としても本文に現れる。
🔴 **`scripts.test.js` は最初の失敗で止まる。** ADR 採番で落ちると残りが緑か分からないので個別の検査器を直接叩く。

### 3. サブエージェントに worktree を与え忘れた

`isolation: worktree` を指定し忘れると、エージェントはオーケストレータの worktree で作業する。
実際に別作業の未コミット変更の上で `git checkout` / `git merge` を走らせかけた。**必ず指定する。**

### 4. 衝突解決で構文を壊した

`scripts/k8s-local-up.test.js` で、両側が**同じ位置に**検査ブロックを追記していた。
衝突ハンクを機械的に連結したところ**共通の末尾と各側の追加ブロックの境界を取り違え**、`SyntaxError` になった。
**両側の版から共通部分と各々の追加ブロックを取り直して組み直す**のが正しい。**解決後は必ず構文と件数を実測する。**
