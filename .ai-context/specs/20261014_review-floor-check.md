## 目的・背景

- AST は同じ穴を AST#1337（初版）・AST#1346（N/N を申告しつつ精読していない自認）・AST#1347（計画書の除外を計画書だけの文に限る）で塞いだ。これを移植する。

### 🔍 の節の自認（下限の導入前を含む 79 本）

AST は「🔍 実行できなかったこと」の節を見ない（計画書の未検証などが恒常的に書かれる節であるため）。本リポのレビューはこの節に精読していない自認を書く。AST のパターンをこの節へそのまま当てると次が当たる。

| 実文（抜粋） | レビュー | 型 | 本リポでの扱い |

- 決定: 🔍 の節では「読む」ことの自認の型（全行・行単位・精読・未読・差分を読まず・読めていない・流し読み）だけを数える。「…しか確認」「要点だけ」「確認にとどまる」「名前の一覧」「検査器の結果だけ」は 🔍 の節では数えない（冒頭と確認できたことの節では AST どおり数える）。
- 実測: この形で 79 本に当てると、🔍 の節で当たるのは上の「数える」の 13 本（#1886・#1899・#1900・#1901 の 2 本・#1906 の 2 本・#1909 の 2 本・#1912 の 2 本・#1921 の 2 回目・#1924 の 2 回目）だけで、「数えない」の 6 本は当たらない。

## 設計

### AST との差（移植で変えた点）

1. **🔍 の節も見る**（上の表）。AST は冒頭と「確認できたこと」の節だけ。
2. **生成物の語彙**: 本リポの生成物に合わせた。orval の生成物（`api/generated/` 配下）・`pnpm-lock.yaml` を足し、`package-lock.json` を外した（本リポは pnpm）。`orval` を生成物の語に足した。EF の `*.Designer.cs` / `*ModelSnapshot.cs`・Lingui の `messages.ts` / `messages.po`・`CHANGELOG.md`・`openapi.yaml` は AST と同じ。
3. **読む対象でない文の除外**: 計画書に加え「他リポジトリ」を足し、「計画の ADR」（の が挟まる形。#1921 の実文）も計画書として読む。
4. **プロンプト**: 出力フォーマットに `### ✅ 確認できたこと（このセッションで実走）` の節を足した。AST の出力フォーマットには無いが、(c) は節で読むため、書式で節を置かせる。
5. 実文の母集合・フィクスチャ・コメントの issue 番号は本リポのものに差し替えた（AST の番号は `AST#NNN` で修飾）。

### frontend（`pnpm`）の検査を (c) に足すか

- **足さない。** 理由:
  - プロンプトの【検証の下限】に frontend の項目が無い。下限に無いものを検査器だけが求めると、全 frontend PR が赤になる。
  - レビューのジョブは pnpm と依存を用意しておらず（`setup-dotnet` だけ）、`--allowedTools` に `pnpm` も無い。足すならジョブの準備・許可・下限の 3 つを先に揃える必要がある。
  - frontend の typecheck / lint / test は `frontend.yml` / `frontend-tests.yml` が CI で走らせている。レビューでの再実行は二重である。
  - 導入後のレビュー（10 本）に frontend の差分を持つ PR が無く、違反の実例も無い（「同型 2 回」に届かない）。

## テスト方針

- 実文: `scripts/fixtures/review-floor/` の 7 本を `findFloorViolations` に当て、違反の件数と文言を固定する。
- 陽性・陰性: AST の試験の表記揺れを本リポの実文に差し替えて引き継ぐ。🔍 の節の扱いは本リポの試験を足す。
- 実行形: ワークフローと同じく実行ログ（JSON）と `CHANGED_FILES` を渡し、exit と `::error` の行数を固定する。`ALLOW_MISSING_VERDICT` が下限に効かないことも固定する。
- 対: `scripts.repo.test.js` でプロンプトの申告の書式・生成物の例・ステップの `CHANGED_FILES` を固定し、陰性対照で外すと赤になることを確かめる。
