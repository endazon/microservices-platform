### 🔴 自動挿入器の罠（実測。2 回とも同じ形で失敗した）

**挿入先は「診断が指す位置の呼び出し」ではなく「チェーンの最後の引数リスト」である。**

```csharp
// 診断は行頭の factory を指すが、token を受けるのは末尾の GetFromJsonAsync である
await factory.CreateClient().GetFromJsonAsync<List<T>>(url);
```

素朴に「診断位置の直後の `(` 」へ挿すと `CreateClient(token)` になり、**ヘルパは token を
取らないので CS1501 で落ちる**（v1 でこれをやって 410 件のコンパイルエラーを出した）。
チェーンを辿って最後の引数リストを選ぶ実装に直して 312 / 299 件が通った。

**それでも自動化しきれない残りが 4 形ある。**

| 形 | 例 | 直し方 |
| --- | --- | --- |
| ヘルパが token を取らない | `CreateClient(...)` / `SessionAs(user, ...)` / `Client(...)` | ヘルパから外し、後続の `GetFromJsonAsync` の引数へ移す |
| 引数の数が違うメソッド | `KnownTagsAsync(tags, ct)` は 2 引数 | 挿入を戻す（`default` を token へ置き換える） |
| 名前付き引数の後ろ | `NotifyAsync(..., count: 3, deadline: ...)` | `ct:` を明示して渡す |
| 入れ子ジェネリクス | `ReadFromJsonAsync<List<Dto>>()` | チェーン走査が `<` の対応を誤るので拾えない。別途 regex で処理 |

4 形目は `Platform.Bff.Tests` で 12 件出た。**チェーン走査は `text.find('>')` で最初の `>` を
取るため、`List<Dto>>` のような入れ子で必ず失敗する。**

ごと削除する」と書いていた。**これは誤りなので取り消した**（`IADR-0238` の 2026-08-28 追記が正本）。

**母集合（規則 9・10）**: 「完了時に外す / 削除する」の側の文字列で全文書を走査し、

`src/Directory.Build.props` / `IADR-0238` / `IADR-0231` 決定 4 / `docs/tech/tech-requirements.md`。

## 3. baseline 掃き寄せ

### カバレッジ床（フロント）

`pnpm run test:coverage` の実測（AST のフレークで 1 回落ちたため 2 回目の出力を採る）:

| 母数 | lines/statements | branches | functions |
| --- | ---: | ---: | ---: |
| 全ユニット横断 | 98.19%（10110/10296） | 92.22%（2300/2494） | 93.74%（674/719） |
| **MSP 所有分のみ** | **98.25%（7526/7660）** | **93.33%（1680/1800）** | **94.07%（508/540）** |
| AST 分のみ | 98.03%（2584/2636） | 89.34%（620/694） | 92.74%（166/179） |

`src/vitest.config.ts` が既に持つ**導出規則「MSP 所有分の実測から 5pt 下・切り捨て」**を適用:

- lines/statements 98.25 − 5 = 93.25 → **93（据え置き）**
- branches 93.33 − 5 = 88.33 → **88（87 から引き上げ）**
- functions 94.07 − 5 = 89.07 → **89（据え置き）**

🔴 **統括仕様書の波 4 節は「床 93/87/89/93 → 実測 98/92/93/98 へ引き上げ」と書いていたが、
これは誤りなので採らなかった。** 横断の実測へ直接寄せると (a) 既存の導出規則を理由なく捨てる、
(b) 余裕が 0.2pt しか残らない（`src/coverage-floor.json` が「余裕は薄い」を問題として記録している）、
(c) **AST 側のテスト増減だけで本リポジトリの CI が赤くなる**（横断の分母に AST が入るため）。

### 仕様書 status の据え置き検査 → **置かない**

波 3 監査が「同型 2 回目が成立したので波 4 で新設する」と記録していたが、**3 案を実測して
すべて棄却した**。判断・数字・母集合は **`IADR-0287`** が正本、是正の追跡は **#1023**。
波 3 の監査記録にも取り消しの追記を入れた（予定だけが残ると次の監査が再発見するため）。
