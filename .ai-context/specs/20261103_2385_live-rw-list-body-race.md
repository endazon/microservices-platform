# 作業仕様書 — M-114 の一覧の応答の本文の競合（#2385）

> 本仕様書は、実装に着手する前に作成した（着手 2026-11-03。develop `ab4db90c`）。

## 事象（実測）

- 定期の e2e-live（run 41562049850・develop `ab4db90c`・2026-11-03）で失敗した。
  - 試験は `[live-rw] e2e/live/secrets.rw.spec.ts:93`（M-114）。
  - 本試行・再試行とも `secrets.rw.spec.ts:128` の `await list.text()` で落ちた。
  - 失敗の文言は `Protocol error (Network.getResponseBody): No resource with given identifier found`、その説明は `Response body is not available for a response that was navigated away from` である。
- 同じコミット `ab4db90c` の定期の実行（2026-10-31・2026-11-01）は、全件が合格した。
- 2026-10-30 の定期の実行（run 41143412787・develop `fd6a9c5e`）では、**同じ箇所・同じ文言で 1 回落ち、再試行で通った**（flaky）。
- 確かめた範囲は、直近 40 件のうちログを取った 5 件（定期 3 件・PR 2 件）である。間欠的に起きる。コードの退行ではない。

## 原因

- 書き込み（`PUT /bff/secrets/{item}`）が成功すると、SC-22 は一覧の問い合わせを無効にする（`useSecretItems.ts` の `onSuccess` が `invalidateQueries`）。
  - そのため、**再読込の前の文書が `GET /bff/secrets` を取り直す**。
- 試験は再読込の直前に `bffResponse(page, 'GET', '/bff/secrets')` を張る。
  - **取り直しの応答が、張った後・再読込の完了の前に届くと、待ちは前の文書の応答で解ける。**
  - その後、再読込（移動）が前の文書の資源を捨てる。だから `list.text()` が本文を読めない。
- 取り直しが張る前に終わっていれば、待ちは再読込の後の文書の応答で解ける（合格する回）。両者の前後で結果が割れる、競合である。

## 方針

- **本文を、応答が届いた時点で読む。** `waitForResponse` の判定の中で `text()` を読み、読めた応答だけを採る。
  - 読めない応答（移動で捨てられた前の文書のもの）は、判定を偽にして次を待つ。
  - 採った応答の本文は、応答ごとに持つ（判定は並行に走り得るので、1 つの変数に書かない）。
- 採るのは、書き込みの後の一覧の応答である（前の文書の取り直し、または再読込の後の文書の応答）。どちらでも、確かめる内容（値の鍵が無い・書いた値が出ない）は同じに成り立つ。
  - 再読込の後の画面の表示（「設定済み」・最終更新者・DOM に値が無い）は、従前どおり画面で確かめる。
- **再試行・skip・隔離をしない**（試験の再試行の回数も変えない）。待ちの時間も変えない。
- `networkidle` の待ちは使わない（`eslint-plugin-playwright` が止める。終わりを保証しない）。

## 母集合（規則 9・10）

- **規則 9**: 走査の形は「応答の待ちを張った直後（3 行以内）に `page.reload` / `page.goto` があり、その応答の本文（`text()` / `json()`）を読む」である。範囲は `src/platform/frontend/e2e`・`src/knowledge/frontend/e2e` とした。走査して 8 件が当たった。
  - **直す**: `secrets.rw.spec.ts:124`（本件）。前の文書に、同じ端点の取り直し（書き込みの後の無効化）がある。
  - **対象外**:
    - `account.rw.spec.ts:282`（`openDeviceActivity`）: 移動の前の文書は、アカウントコンソールの別の頁（ログイン直後）である。`sessions/devices` を取り直す契機が無い。
    - `private-notes.rw.spec.ts:75`: 読むのは状態だけで、本文を読まない。状態は、本文が捨てられても読める。
    - `knowledge.ro.spec.ts` の 85・231・244・277・350 行: 読み取りだけの層で、前の文書に同じ端点を書き換える操作が無い（無効化の契機が無い）。
- **規則 10**（この変更で新たに誤りになる自分の記述）: ファイル冒頭の注記には、本文の読み方の前提は無い。足すのは helper の注記だけである。

## 残余リスク
