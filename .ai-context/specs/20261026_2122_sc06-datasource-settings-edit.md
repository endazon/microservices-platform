# 作業仕様書 — SC-06 の設定変更（#2122）

> 本仕様書は実装着手前に作成した（着手 2026-10-26）。親は #2047（指摘 M-24 の SC-06）。前提の M-12（#2109。BFF の 400 本文の透過）はマージ済み。
> 進め方はコーディネーターの承認（2026-10-26）による（下記 (A) と編集フォームの設計）。

## 現状（origin/develop で再確認）

- SC-06 の行操作は「手動同期・既定属性・無効化・認証情報を設定（SC-22 への導線）」で、**接続先・`config` を編集する口が無い**。
  画面の注記は「接続先・認証情報の編集は依然として未実装であり、#534 の射程のまま残る」としているが、#534 の後継 issue は無い。
- 計画 SC-06 は次のとおり定める。
  - アクション「登録・**設定変更**・手動同期」。
  - 更新 API の裁定（Q16）は「接続先の変更・サービスアカウントの認証情報ローテーション・同期対象パスの追加はいずれも日常的な運用」とする。
  - 認証情報は Vault 管理で、投入の面は SC-22（ADR-0126）である。
  - 計画は**編集できる項目を列挙していない**（登録・更新フォームが既定属性 3 つと `owner` の写像表を持つ、とだけ定める）。
- 後段の PATCH（`/datasources/{id}`）は「null は現状維持」である。
  - `config` を送ると全置換になるが、秘密キーの `***` は保存せず既存値を保つ（`SecretConfigMask.PreserveMasked`）。
  - `connectionUri` は `ConnectionUriPolicy` が資格情報つき・編集したマスク値を拒否する。
- **`ConnectionUriPolicy` の拒否は `{ "error": "…" }` 形の 400 である。** BFF は透過する（#2109）が、SPA の `parseProblemDetails` は `error` を読まない。
  そのため画面には「入力内容に誤りがあります。」しか出ない（#2280 の (a)）。

## 方針

### (A) 共有の解析で `{ error }` を読む（#2280 のクライアント側。独立のコミット）

- `apiClient.ts` の `parseProblemDetails` は、`error` を**最後の手段として**読む。条件:
  - 呼び出し元が 4xx（400 / 409）だけであること（既存。5xx の本文は読まない）。
  - RFC 7807 の `errors` / `detail`（と従来の `title` / `message`）が無いこと。
  - 空でない文字列であること。
  - **識別子の形（`invalid_transition` などの機械の符号）でないこと。** 後段は 13 種の符号を `error` に入れて画面の分岐に使っている（実測）。符号を文として見せない。分岐は従来どおり `body` で読める。
- 値は `details` の文字列として画面へ渡り、画面は文字として描く（HTML として解釈しない）。
- 試験（共有の解析なので全画面に効く）: `{error}` の 400 が理由になる・RFC 7807 が勝つ・5xx の `error` は出ない・文字列でない／空／符号の `error` は出ない。
  vitest を両ユニットとも全件走らせる。
- #2280 にコメントする（クライアント側は本件のコミットで足りた。サーバ側〔`{error}` を RFC 7807 へ寄せる〕は残る）。

### 編集フォーム（SC-06）

- 行操作「設定」（管理者だけ。既存の「既定属性」と同じ扱いで、画面に 1 つだけ開く）。
- 編集できる項目は **名前・接続先 URI・`config` の非秘密キー**（値の変更・キーの追加・削除）。
- **種別（`sourceType`）は読み取り専用。** 変えるとコネクタが入れ替わる。計画の例（接続先の変更・認証情報のローテーション・同期対象パスの追加）に種別の変更は無い。
- **マスク済みのキー（値が `***`）は読み取り専用。** 「認証情報は Vault で管理し、SC-22 で設定する」と示し、SC-22 への導線を置く。
  送り返すとサーバが既存値を保つので、壊せない。**SPA に秘密キーの判定（正規表現）を複写しない**（`KeyMarkers` は後段の 1 か所）。
- 新しいキーの欄の近くに「パスワード・トークンをここへ書かない（SC-22 で設定する）」と書く。
- **PATCH は変わった項目だけを送る**（名前・接続先・`config` のそれぞれ、変わっていなければ送らない）。何も変わっていなければ送らない。
  `config` は変えたときだけ全量（マスク済みのキーは `***` のまま）を送る。
- 失敗は既存の結果表示（`toMessages`）で出す。(A) により `ConnectionUriPolicy` の理由も出る。
- 画面の注記（「接続先・認証情報の編集は依然として未実装」）を改める。
- 初期ロードの床: 共有の解析の分岐（入口チャンク）と、フォームの文言 13 個の ja / en の訳（入口チャンクのカタログ）で +1.85 kB 増える。
  `check-chunk-budget --update` で床を上げ、帰属を `scripts/chunk-budget-baseline.json` の `$comment` に残す。
