# 作業仕様書 — アカウントコンソール（SC-16）が 401 で開けない

> 本仕様書は実装着手前に作成した（着手 2026-10-15）。基点は MSP `origin/develop` `f40bd9e7`。起点は #1894（#1893 の作業中の実測）。

## 起点（トレーサビリティ）

- 画面: **SC-16**（アカウント設定。Keycloak のアカウントコンソール。ADR-0026 が「Keycloak の既定機能で提供」と定める）。
- 実装 ADR: IADR-0369（realm の後追いと宣言／実行時の境界）・IADR-0524（Keycloak 26.7.4）・IADR-0532（テーマ。§フォローアップで本件を送った）。
  新しい決定は **IADR-0546**（本 PR）に記録する。

## 調査結果（着手前の実測。Keycloak 26.7.4・`start-dev --import-realm`・実 realm）

1. **再現**: `poc-user` でログインすると `GET /realms/platform/account/?userProfileMetadata=true` と `/supportedLocales` が **401**、画面は
   「何らかの問題が発生しました」。テーマに依らない。
2. **原因の切り分け**（稼働 realm へ 1 つずつ足して測った）:
   - 組み込みの `account-console` は **既定スコープが空**（`[]`）。realm import が `clientScopes` を明示すると Keycloak は組み込みスコープを
     作らず（`RealmManager.importRealm`: `rep.getClientScopes()==null` のときだけ `createDefaultClientScopes`）、`account-console` は
     スコープ作成より前に `setupAccountManagement` で作られるため何も付かない。→ `basic` が無く `sub` が無い（401）。
   - `basic` を足すと **401 のまま**。import で作られる利用者は既定ロール（`default-roles-platform`）を**受け取らない**（`poc-user` の割当は空）。
     → `account` の `manage-account` / `view-profile` を足すと **403**（audience は `account-console` 自身の audience 解決で `account` が入る）。
   - **403 の原因**: account API はトークンの `resource_access.account.roles` を見る。realm の `roles` スコープはレルムロールの写像しか持たず、
     `account-console` にはスコープも無いので client ロールが載らない。→ `account` のロールだけを出す写像を `account-console` に足すと **200**。
   - `profile` が無いと画面上部が「匿名」と出る（`preferred_username` が無い）。足すと利用者名が出る。
3. **issue の原因 1（`roles` スコープに audience 解決と client ロールの写像が無い）は、共有スコープを直す形では採らない。**
   `roles` は 23 のクライアント（bff・各サービス・AST・headlamp など）が既定で持つ。そこへ audience 解決と client ロールの写像を足すと、
   それらのトークンに `resource_access` と追加の `aud` が載る（認可の面が広がる）。`account-console` に**直付け**して同じ効果を得る。
4. **宣言で直す形の制約**: `account-console` だけを `clients[]` に宣言すると import が**重複で落ちる**（`Unique index … (REALM_ID, CLIENT_ID)
   … 'account-console'`。実測）。`account` を宣言すると `setupAccountManagement` が丸ごと飛ぶ（`hasAccountManagementClient`）ので、
   `account` のロール・合成・`account-console` のスコープの割当（`clientScopeMappings`）・既定ロールの合成も宣言で持つ必要がある。
   既定ロールの合成に `uma_authorization` を書くと import が落ちる（`Unable to find composite realm role: uma_authorization`。
   そのロールは import の後で Keycloak が作り、既定ロールへ自分で足す）。
5. **既存の realm**: `--import-realm` は同名 realm を飛ばす（`IGNORE_EXISTING`）。後追い（`reconcile-realm.js`）は宣言した client の
   スコープ割当・写像・client ロールを当てるが、**既存の人間の利用者は実行時所有として触らない**（IADR-0369 の境界）。
6. **配備**: realm は compose（ディレクトリのマウント）と k8s ローカル（ConfigMap `keycloak-realms`・起動器 [3/7]）で import され、
   k8s ローカルは起動器が毎回 `reconcile-realm.sh` を呼ぶ（helm の前・fail-closed）。helm chart は Keycloak を持たない（helm は無変更）。

## 対象範囲

- 対象:
  - realm JSON: `account` と `account-console` を**組み込みと同じ形で対に宣言**し、`account-console` に既定スコープ `basic`・`profile`、
    写像（audience 解決・`account` のロールだけを `resource_access.${client_id}.roles` へ）。`account` のロール 8 個（組み込みと同名・同じ合成）、
    `clientScopeMappings`（`account-console` に `manage-account`・`view-groups`）、`defaultRole`（`default-roles-platform`。合成は
    `offline_access` と `account` の `view-profile`・`manage-account`。`uma_authorization` は Keycloak が足す）。
    人の seed 利用者 4 人（admin・poc-user・poc-operator・developer）に `account` の `view-profile`・`manage-account`。
  - `reconcile-realm.js`: 既存の人の seed 利用者へ **`account` の `view-profile`・`manage-account` だけ**を加える（境界の例外。加えるだけ）。
  - 検査: `check-realm-constraints.js` 検査 10（構成の欠落）。`keycloak-realm-reconcile.test.js` に計画器の試験。
  - 文書: SC-16 画面仕様書・`deploy/local/keycloak-setup/README.md`（境界表と適用手順）・IADR-0546・IADR-0369 / IADR-0532 の追記。
- 対象外（理由）:
  - 共有の `roles` スコープへの写像の追加（上の調査 3。他のクライアントのトークンが変わる）。
  - realm の `defaultDefaultClientScopes`（SC-12 が作る MCP クライアントへ継がれる既定。本件と無関係に面が変わる）。
  - AST 専用 realm（`src/ai-stock-trading`。利用者のログインに使わない）。
  - 稼働中に管理コンソールから作られた利用者（Keycloak が既定ロールで `manage-account` を与える。宣言の外）。

## 影響の確認（AC 3）

- **他のクライアントのトークンは変わらない**: 宣言の 25 クライアント × 人の seed 利用者 4 人の例示アクセストークン
  （`evaluate-scopes/generate-example-access-token`）を、旧 realm と是正後の realm で取り、配列の順序を正規化して比べた → **100 件すべて一致**
  （`resource_access` は 0 件、`aud` に `account` が載るものは 0 件）。共有の `roles` スコープを変えていないため。
- **`account-console` のトークン**: `aud=account`・`resource_access.account.roles=[manage-account, manage-account-links]`・`realm_access` 無し
  （`fullScopeAllowed=false` とスコープの割当で `account` のロールだけに絞られる。platform-admin 等のレルムロールは載らない）。
- **`manage-account` の付与範囲**: Keycloak が実行時に作るすべての利用者へ既定ロールで与える基線と同じ（`view-profile`・`manage-account`）。
  効くのは本人のアカウント API（自分のプロフィール・資格情報・セッション）だけで、他人や realm の管理には効かない。
  seed 利用者へは `default-roles-platform` ではなく 2 つを直に付けた —— 既定ロールの `offline_access`・`uma_authorization` まで足すと、
  `fullScopeAllowed` の既定（true）の bff 等のトークンの `realm_access.roles` が変わるため。
- **新規 import の既定ロール**: 宣言後も `default-roles-platform` の合成は `offline_access`・`uma_authorization`・`view-profile`・`manage-account`
  （組み込みの realm と同じ。実測）。SC-12 で作る利用者の振る舞いは変わらない。
