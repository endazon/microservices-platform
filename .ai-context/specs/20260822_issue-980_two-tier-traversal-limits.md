# 仕様書: 探索の二段上限・総数・間引き基準（#980 / #917 の前提・親 #450）

> 本書は**着手前**に作成した。

## 起点となる計画書（トレーサビリティ）

- 機能要求（FR）: **FR-17** / ユースケース: **UC-10** / 画面: **SC-18**（主要素 6「表示上限と間引きの表示」）
- 関連 ADR: **ADR-0049**（`Accepted`・2026-08-22。ADR-0034 の 1 行を改定）/ ADR-0034 / ADR-0035

## なぜ新しい実装が要るのか

**ADR-0049 は上限を緩めたが、その結果として実装に足りないものが生まれた。**

> **「候補を 2,000 まで集めてから 200 を選ぶ」は「200 で打ち切る」とは別の探索である。**
> 現在の実装には**並べ替える母集合が存在しない。**

| ADR-0049 の要求 | 現在の `GraphTraversal`（実測） |
| --- | --- |
| 探索は **ノード 2,000 / 辺 5,000** まで進む | `MaxNodes = 200` / `MaxEdges = 500` で**打ち切る** |
| **総数**を応答で返す | `Truncated: bool` **のみ** |
| 算出用上限に達したら「**2,000 件以上**」の形で示す | 表現が無い |
| **間引き基準**を選べる（距離／更新日／次数） | 引数が無い。BFS の到達順のみ |
| 表示・応答は **200 / 500** のまま | ✅ 一致 |
| ホップ 既定 2 / 最大 3 | ✅ 一致 |

## 🔴 改定されていないもの（守るべき境界）

ADR-0049 が改めたのは **ADR-0034 の次の 1 行だけ**である。

> ~~上限は表示・応答の上限であり、内部の探索も同じ上限で打ち切る。~~

**次は改めていない。むしろ ADR-0049 の前提である。**

> 決定 1 の具体化: 探索は 1 ホップ進むごとに ABAC 判定を行う。**不許可ノードはその場で打ち切り、そのノードを起点とする次ホップへ進まない。**

**したがって:**

- **prune-before-expand はそのまま。** 非許可ノードから展開しない
- **型ゲート（`AuthorizedNode` / `AuthorizedGraphView.Seal`）は緩めない。** 2,000 まで数えるのは**許可済みノードだけ**なので、ゲートは無傷で実装できる
- **数えてよいのは ABAC 判定を通過した品目だけ**（ADR-0049 決定 1 が明記）

## 🔴 属性が揃っている前提を置かない

`AbacNodeFilter` は **missing key = no match（deny-by-default）** である。実データでは
**`owner` / `department` / `lifecycle` / `doc_scope` が 0% 充足で、実効的な認可軸は
`confidentiality` のみ**（#516。`AbacUnenforcedAxisTests` が明示的に固定している）。

> **［2026-08-22］`doc_scope` が 4 件目として加わった**（計画 `ADR-0054`・`Accepted`）。
> **必須は 4 → 5 属性、欠落は 3 → 4 属性。**
> **本単位にコード変更は要らない** —— `AbacNodeFilter` はスコープが返したフィルタを適用するだけで
> 必須属性を列挙しないためである。**新しい必須属性が増えても、述語の形は変わらない。**

**総数は「呼び出し主体に見えている品目の数」であって「グラフ上の関係の数」ではない。**

- **属性を持たない文書（複製未到達）は許可されないので、総数に入らない。** これはバグではなく
  ADR-0034 決定 2 の帰結である —— 権限外と未同期は区別しない
- **認可軸が 1 つしかない現状でも、総数の意味は変わらない**（見えているものを数えるだけ）
- **総数が増える是正（#516 の解消）が入っても、本実装は変えなくてよい** —— 述語が強くなるだけである

**テストで固定する**（T-08）。

## 決めること

### 二段の上限

| 段 | 値 | 意味 |
| --- | ---: | --- |
| **表示・応答** | ノード 200 / 辺 500 | 返す品目の数（従前どおり） |
| **算出用の探索** | ノード **2,000** / 辺 **5,000** | 数えるために進む上限（ADR-0049 決定 3） |

**算出用の上限に達したら、総数を「以上」として示す。** 正確な数を出すために探索を伸ばさない。

### 応答の形

`GraphViewResponse` へ 2 欄を足す（**型ゲートは維持**。`Seal` 以外から作れない）。

| 欄 | 意味 |
| --- | --- |
| `TotalNodes` / `TotalEdges` | **許可済み**の総数 |
| `TotalIsLowerBound` | 算出用上限に達したか（`true` なら「2,000 件以上」の意味） |

**`Truncated` は残す** —— 「表示を打ち切ったか」を表し、総数とは別の情報である。

### 間引き基準

| 値 | 並び |
| --- | --- |
| `distance`（**既定**） | 起点からの距離が近い順（＝現行の BFS 到達順） |
| `updated` | 更新日が新しい順 |
| `degree` | 次数が大きい順 |

**未知の値・未指定は既定へ縮退する**（`SearchModes` / `SearchSorts` と同じ作法）。

> ⚠️ **母集合が算出用の上限で打ち切られている場合、`updated` / `degree` は厳密な上位 200 件ではない。**
> ADR-0049 決定 4 がこの限界を認めている。**`TotalIsLowerBound` が立っていることで読み取れる形にする**
> —— 黙って正確なふりをしない。

## 受け入れ基準

- [ ] 表示は 200 / 500 のまま、探索は 2,000 / 5,000 まで進む
- [ ] **総数が許可済み品目だけを数える**（権限外は 1 件も入らない）
- [ ] 算出用上限に達したとき `TotalIsLowerBound` が立つ
- [ ] 間引き基準 3 択が効く（**既定は現行挙動と同じ**）
- [ ] **ホップごと ABAC・型ゲート・ハブ次数上限が変わらない**
- [ ] BFF と openapi へ透過し、orval 生成物が整合する

## テスト方針

| ID | 内容 |
| --- | --- |
| T-01 | 200 件を超える可視ノードがあるとき、**表示は 200 件・総数はそれより大きい** |
| T-02 | 🔴 **権限外ノードは総数に入らない**（否定形） |
| T-03 | **可視ノードは総数に入る**（T-02 の**陽性対照**） |
| T-04 | 算出用上限（2,000）に達すると `TotalIsLowerBound` が立つ |
| T-05 | 上限未満なら `TotalIsLowerBound` は立たない（T-04 の対） |
| T-06 | `updated` 指定で更新日の新しい順に 200 件が選ばれる |
| T-07 | `degree` 指定で次数の大きい順に選ばれる |
| T-08 | 🔴 **属性を持たない文書は総数に入らない**（deny-by-default の帰結） |
| T-09 | 既定（未指定）の並びが**現行と同じ**（距離が近い順） |
| T-10 | 未知の基準は既定へ縮退する |
| T-11 | ホップ超過は従前どおり 400（**認可より前**に検証する順序も不変） |

### 変異試験の設計

| 変異 | 落ちるべき | 🔴 注意 |
| --- | --- | --- |
| **M-1** 総数を「述語通過前」に数える | **T-02** | **ADR-0049 が名指しで禁じた形** |
| **M-2** 探索上限も 200 のままにする（改定前へ戻す） | T-01 | 総数が 200 で頭打ちになる |
| **M-3** 算出用上限に達しても `TotalIsLowerBound` を立てない | T-04 | 黙って正確なふりをする |
| **M-4** 間引き基準を無視して常に到達順 | **T-06 / T-07** | **T-09（既定）だけでは検出できない** |
| **M-5** 未知の基準で例外を投げる | T-10 | 縮退の作法 |
| **M-6** 非許可ノードからも展開する | 既存の橋テスト | **改定されていない部分が壊れていないこと** |

**M-6 が重要である。** 本単位は探索の中核を触るので、**改定されていない不変条件（ホップごと判定）が
巻き添えで壊れていないこと**を、既存テストが落ちる形で確かめる。

## 未決事項

1. 算出用上限（2,000 / 5,000）は**実測ではない**（ADR-0049 自身が「表示上限の 10 倍を置いた。運用で
   不足または過大と判明した時点で見直す」と明記）。**実データが入ったら測り直す**
2. `updated` の並びに使う日時は `GraphDocument.UpdatedAt`（イベント由来）。**取り込み経路が未配線の間は
   全件が同値になり得る** —— テストは明示的に差を付けたフィクスチャで測る
