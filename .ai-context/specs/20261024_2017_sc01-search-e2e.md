# 作業仕様書 — SC-01 の E2E（E-12）

> 本仕様書は実装着手前に作成した（着手 2026-10-24）。親は #2013。網羅表の行は M-022〜M-028。

## 受け入れ基準（issue #2017）

- [x] ストリーム応答で回答と出典が描かれる（出典の種別・機密区分を含む）。
  - issue の「出典 3 種」のうち個人資料は契約に口が無く、検証できない（§除外）。検証したのは組織文書と Wiki の 2 種と、機密区分の 4 値である。
- [x] ストリームが `error` のとき、縮退の alert が出る。
- [x] 👍/👎 の POST 本文を検証する。

### 除外（理由つき）

- **M-026（「個人資料を含める」トグル）**・**M-022/M-023 のうち個人資料の出典（👤・SC-19 への遷移）**: 実装も契約も持たない。
  - `AskRequest` に切り替えの口が無く、`CitationDto` に個人資料の印も無い。
  - SPA だけでは直せない（後段の契約が要る）。計画の FR-19 着手範囲の解釈も要る（IADR-0119 / IADR-0142）。
  - したがって本 PR では試験を書かず、オーケストレータへ報告する。
- M-021（既存）・M-029〜M-031（live 層）は本 issue の範囲外。

## 方式

- `e2e/support/bffSession.ts` に **SSE の応答 `sse(events)` を足す**（`reply()` と同じ形の印つきの値。既存 API は変えない）。
  - `route.fulfill` は本文を一度に返す。したがって「途中まで流れている」状態は観測しない（単体の担当）。
  - E2E が確かめるのは、イベント列が画面へ届き、`token` が連結され、`done` で確定する経路である。
- `e2e/sc01-search.smoke.spec.ts` へ試験を足す（既存 2 本は残す）。
  - 陽性対照と陰性対照を対で置き、各試験の最後に `expectBffTrafficIsComplete` を呼ぶ。

## 判断

1. （E2E が見つけた実装の欠陥）**出典に機密区分が出ていない。**
   - 契約 `CitationDto.confidentiality` は #541 で入った。しかし画面側の型 `AskCitation` はこの欄を持たず、`CitationList` も描いていない。
   - 計画（FR-04・05_screens §SC-01「出典への機密区分の表示（確定）」）に反する。
   - SPA の局所的な欠落なので、本 PR で直す。直す前に E2E が赤になることを確かめる。
   - 表示名は用語集を正とする。「公開」は既存の msgid（SC-05 の動詞「Publish」）と衝突するので、Lingui の `context` で分ける。

2. 最大長（M-027）の値は計画に無い（「最大長制限」とだけある）。期待値に実装の 1000 を写さず、入力欄が宣言する `maxlength` を読み、それを超えた分が入らないことを確かめる。
3. 回答の欄・出典の欄（`Panel`）は名前つきの region ではない。CSS・XPath で親を辿らずに、見出しの有無と main の中の行（脚注番号 `[n]` で始まる listitem）で読む。
