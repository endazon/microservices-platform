# 作業仕様書 — i18n の en-US とブランド表示名（E-18）

> 本仕様書は実装着手前に作成した（着手 2026-10-24）。親は #2013。網羅表の行は M-020。

## 受け入れ基準（issue #2023）

- [ ] en-US でもブランド表示名が「汎用プラットフォーム」のまま出て、ナビは英語になる（M-020）。

（CI が緑になってから印を付ける。マージをもって完了とする。）

## 期待の表（計画から起こした）

| 行 | 期待 | 出典 |
| --- | --- | --- |
| M-020 | `locale: en-US` でも、ブランド表示名「汎用プラットフォーム」は翻訳されない（固有名詞。翻訳カタログの対象としない）。ナビの文言は英語になる | 05_screens §共通シェル「ブランド表示名」・変更履歴 2026-08-04（追補） |

- 英語の訳語そのもの（"Knowledge graph" など）は、計画が定めない実装の値である。試験は「日本語の文字を含まない」ことで英語であることを判定し、カタログの訳語を写さない。
- ナビのうち「Wiki」は、両方のロケールで同じ固有名詞である。そのため「ja では日本語で、en と違う」か「両方で同じ固有名詞」のどちらかである、という形で判定する。

## 判断

1. **L1 の project 名を `chromium` から `smoke` へ改め、`smoke-en-us`（`locale: 'en-US'`）を足す。**
   - IADR-0569 が「次に `playwright.config.ts` を触る PR で `smoke` へ改める」「ロケールの project は `smoke-<locale 小文字>`」と定めている。本 PR がその PR に当たる。
   - `smoke-en-us` は `e2e/i18n.smoke.spec.ts` だけを走らせる。`smoke` はこの spec を走らせない。ほかの spec は日本語の文言を待つので、en-US では全件が落ちる。
   - `chromium` を project 名として参照する箇所は 0 件である（`frontend.yml` の `playwright install chromium` はブラウザ名）。走査して確かめた。
2. **陽性対照として、同じ画面を ja-JP の文脈（`browser.newContext({ locale: 'ja-JP' })`）でも開く。**
   - en-US だけを見ると、「ナビが英語」がロケールの効果なのか、もともと英語だったのかを区別できない。
