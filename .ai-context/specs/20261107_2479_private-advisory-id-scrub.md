## 設計

### 1. 置換の規則

| 現在の形 | 置き換え |
| --- | --- |
| 単独の参照（`Refs …`・frontmatter の `issue:` を含む） | 「非公開の指摘（MSP）」または「非公開の指摘（AST）」（識別子の帰属に従う） |
| 試験名の接頭辞 | 中立な主題名「CI 堅牢化:」 |
| 試験の一時ディレクトリの接頭辞 | `msp-ci-hardening-` |
| 作業仕様書の名前 | `YYYYMMDD_` の直後にある識別子の部分（前置きの有無を問わない）を除く |
| IADR の見出し・索引の題名 | 識別子の部分だけを中立表記へ（題名の要約は変えない） |

- ファイル名の変更は `git mv` で行い、参照の追随と同じコミットに置く。改名後の名前の衝突は無い（実測）。
- 凍結記録は、触った記録ごとに日付つきの追記を 1 行だけ足し、`updated:` を進める（`updated:` を持たない記録は frontmatter を足さない）。追記には識別子・旧名・置換表を書かない。

### 2. 再混入を止める検査器 `scripts/check-advisory-ids.js`

- 追跡下の全ファイル（`git ls-files`。submodule の中は出ない）の本文で、`GHSA-` で始まる識別子を拾う（大文字小文字を区別しない）。
- **allowlist だけの形にする。** 許すのは公開の第三者 advisory 12 件だけ。
  - 完全形は allowlist と完全一致するときだけ許す。
  - 2 区画の形（先頭の 2 区画だけ）は、allowlist の完全形の先頭 2 区画と一致するときだけ許す。
  - 短縮形（先頭の区画だけ）は、allowlist の先頭の区画と一致するときだけ許す。
  - それ以外は 1 件でも exit 1。規則は取引ユニットの `check-advisory-ids.js` とそろえる。
- 非公開の識別子は検査器にも試験にも書かない。ハッシュ照合は入れない（利用者裁定）。前置きなしの断片はこの形では捕まらない（残余。IADR-0690）。
- NUL を含むファイルは飛ばす。`git ls-files` が失敗したら exit 1。走査件数が下限を下回ったら exit 1（0 件走査で静かに緑にしない。`check-nul-bytes.js` と同じ作法）。
- `--self-test` を持つ（本リポジトリの検査器の形）。CI は `ci.yml` の `check-nul-bytes` と同じジョブに自己試験と本検査の 2 ステップを足す。`scripts/scripts.repo.test.js` に自己試験・実データ・変異試験（架空の識別子を書いた追跡下のファイルで exit 1）を置く。`scripts/README.md` の表に足す。

## テスト方針

- 検査器の自己試験と `scripts/scripts.repo.test.js` に次を置く。
  - allowlist が 12 件ちょうどで、すべて GHSA の完全形であること。
  - allowlist の完全形・2 区画の形・短縮形を許すこと。
  - 陰性対照: 架空の識別子（同じ文字の繰り返し。実在しない形が明らかなもの）を、完全形・2 区画の形・短縮形とも検出すること。先頭の区画が allowlist と同じで 2 区画目が違う 2 区画の形も検出すること。架空の識別子は試験の中で組み立て、ファイルの字面には置かない。
  - 小文字の前置きを検出し、`GHSA-...` のような識別子でない例示は検出しないこと。
  - 実ツリーで 0 件であること。追跡下のファイルへ架空の識別子を書くと exit 1 で名指しすること（変異試験）。
- 試験名・コメントの変更は既存の試験・ビルド・整形の検査で確かめる（名前だけの変更で、件数は変わらない）。
