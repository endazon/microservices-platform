## 何が起きていたか

`IADR-0119` 決定 2 は FR-21 の着手条件を「**計画側が当該要求を確定（`fixed` 扱い）させること**」と定め、
2026-08-07 の追補で「**起案段階（`draft` 相当）のまま → 保留継続**」と判定していた。

**その条件は 2026-08-14 に満たされていた。**

> **FR-21（文書本文の受け入れ経路）は 2026-08-14 に起案段階を脱した**（［2026-08-14 裁定］の共通基準を満たす）。

**8 日間、条件が満たされたまま保留が残っていた。**

## 🔴 なぜ気付かなかったか

| 要因 | 実測 |
| --- | --- |
| 判定表が **planning pin `3e58b97`（2026-08-07）で固定されたスナップショット**である | 本文に明記されている |
| **`check-planning-pin-freshness.js` が `origin/develop` に存在しない** | `ADR-0048` / `ADR-0029` 決定 2 が planning 依存の検査器を退役させた。実測で確認 |
| `IADR-0119` の `updated` は **2026-08-15**（計画変更の翌日） | その追補は FR-19/20 と SC-19 の話で、**FR-21 の条件を測り直していない** |

**「更新した」ことと「測り直した」ことは別である。**

**pin 固定の判定表は、書いた瞬間から古くなり始める。** 検査器が退役した以上、**着手判定のたびに条件を原文で引き直すしかない。**
判定表は「**いつ測ったか**」の記録であって、「**今どうか**」の答えではない。

> ⚠️ ローカルクローンは `origin/main` に対して **19 コミット遅れ**ていた。**fetch せずに読んでいたら、この件自体を見落としていた。**

## 着手方針（FR-21 の実装）

**①〜⑧ を 1 単位として起票する**（本 issue とは別）。サイズは L。

| # | 基準 | 実装の要点 |
| --- | --- | --- |
| ① | 本文を伴う登録で取り込み・分割・埋め込みが起動 | `CreateDocumentRequest` に本文欄。既存経路を壊さない（**任意**） |
| ② | 登録した本文が RAG 検索の結果として返る | 取り込み経路との結線 |
| ③ | 本文と `OriginalUri` が**併存**できる | 排他にしない |
| ④ | 本文はオブジェクトストレージへ、DB は参照のみ | `IObjectStorage`（DocumentService は現在持たない） |
| ⑤ | 一般利用者が自分の文書の本文を投入できる | ABAC の**動的束縛**（`doc.owner ∈ { ${current_user} }`）。ロール判定を追加しない |
| ⑥ | 1 MB 超は **413 で拒否** | **切り詰めて成功を返さない** |
| ⑦ | 1 MB 以下は**切り詰められず全文が索引される** | ⑥ の陽性対照 |
| ⑧ | **別の利用者として同じ文書 ID へ書き込むと拒否** | **認可判定のキャッシュキーに主体が含まれること**の検証 |

🔴 **計画側自身が「⑧⑨⑩ は実装が素直に作ると満たされない性質」と名指ししている。**
⑧＝キャッシュキーに主体を含め忘れる／⑨＝検索結果をそのまま LLM へ渡す構造では分離できない／⑩＝既定値を持たせ忘れる。
**⑧ は FR-21 の射程内なので、本単位で否定形＋陽性対照の対で固める。**
