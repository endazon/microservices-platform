# 仕様書: ルートマニフェストの静的検査（#1013 / トラック 3H）

> **本作業は画面を 1 枚も作らない。** 直すのは **「測っていないものを『固定した』と書いた記述」** と、
> **その記述が生まれる構造**（＝ ルートマニフェストが手書きの列挙であり、足し忘れが誰にも見えないこと）である。
>
> 🔴 **存在秘匿の設計（`catchAllRoute` を `RequireAuth` 配下に置くこと・未知パスの受け皿）は変えない。**
> #1013 が突いたのは設計ではなく**主張**である。検査は現状の設計を**固定する向き**で書く。

## 何が壊れているか（一次情報は #1013 の本文）

複数の E2E スモークが「**この 1 本でルートが実在することも同時に固定できる**」と書いている。

| 状態 | 未認証で開いた結果 |
| --- | --- |
| ルートが実在する | `RequireAuth` が `/login` へ飛ばす |
| **ルートが存在しない** | catchAll →（catchAll は `RequireAuth` 配下）→ **同じく `/login`** |

**区別がつかない。** #918 が SC-21 のパスを改名する変異を当てて **落ちたテスト 0 件**を実測している。

そのうえで #1013 は **2 つ目の欠陥**を指摘している ——
**`router.test.ts` の `PLANNED_ROUTES`（ルートマニフェスト）に SC-18 が入っていない**（#917 の取り残し）。
**列挙は「足し忘れ」を検出できない。** 載っている行は検査されるが、**載らなかった画面は誰にも見えない。**

### 除外したものと理由（規則 6 —— 黙って落とさない）

- **`src/ai-stock-trading/` 配下（軸 A2 で 15 件・A3 で 11 件）**: 別プロジェクトの submodule であり
  本リポジトリから変更できない（`IADR-0120`）。語も無関係（AST 自身の文脈）。
- **軸 A2 の残り 32 件の大半**: 「ID がレンジに実在すること」「通知 ID が実在することが漏れる」等、
  ルートの話ではない。**語が同じだけ**である。1 件ずつ生の出力で確認した。
- **`.ai-context/specs/` の 4 件（#9〜11）**: **確定済みの凍結記録**であり、既存本文の書き換えは不可
  （`IADR-0166` 決定 2 の 2026-08-17 追記の表 2 行目）。同表 1 行目が認める
  **`［YYYY-MM-DD 追記 / #NNN］` 書式の経過追記だけ**を足す。**当時そう書いたという史実は残す。**
- **`.ai-context/specs/20260823_issue-918_…`（#12）**: 誤りであることを既に本文で述べており、是正済み。
- **`docs/tests/SC-21_ai-suggestion-list.md`**: 「ルートの実在は固定しない」「ルートの実在は T-30 が固定する」と
  **正しく**書いてある。**否定形・別担当への委譲を誤検出しないこと**が、後述の検査器の要件になる（陰性対照）。

## 対象範囲

### 対象

1. `PLANNED_ROUTES` へ **SC-18 / SC-19 / SC-20** を足す。
2. `PLANNED_ROUTES` に**載らない画面を「黙って載らない」ままにしない**ための宣言
   （`SCREENS_NOT_IN_THE_ROUTE_TABLE`。SC-04 と理由）を `router.test.ts` へ置く。
3. **静的検査器 `scripts/check-route-manifest.js` を新設**し、上の 2 つを機械で閉じる。
4. live な誤記 8 件（e2e 5 ＋ docs/tests 3）を、**実際に測っていること**へ書き直す。
5. 凍結記録 3 件へ**書式つきの経過追記**を足す。

### 対象外（理由つき）

- **存在秘匿の設計変更**（catchAll を `RequireAuth` の外へ出す等）。#1013 は設計を問題にしていない。
  出すと未知パスが未認証で `NotFound` を返し、**ルートの有無が外から観測できる**ようになる（`IADR-0009` に反する）。
- **E2E スモークを「ルートの実在も測れる」形にすること**。プレビューには BFF も Keycloak も無く、
  認証済みの導線を実走できない（既存 15 本すべて同じ制約）。**測れないものを測れるように見せない。**
- **SC-19 / SC-20 の E2E スモークの新設**。#1013 の射程外（既存の主張の是正であり、本数を増やす作業ではない）。
- **`PLANNED_ROUTES` のパス値そのものを検査器で突き合わせること**（下記「設計」§見送り）。
- **他の検査器本体の改修**。追試は `scripts.repo.test.js` 側へ置く。

## 設計

### 判定 1（新設）: ルートマニフェストの網羅

**画面 feature ディレクトリ名の `SC-NN` と、マニフェストの行を双方向に突き合わせる。**

- 走査対象: `src/*/frontend/src/features/sc<NN>-*/` のうち `createRoute({ … path: '…' })` を持つもの。
  `src/ai-stock-trading`（submodule・旧契約）と `scope-filter` 等の非画面ディレクトリは対象外。
- **順方向**: 画面が `PLANNED_ROUTES` にも `SCREENS_NOT_IN_THE_ROUTE_TABLE` にも無ければ **error**。
  —— これが SC-18 / 19 / 20 を取りこぼした穴である。**列挙は足し忘れを自分では検出できない。**
- **逆方向**: マニフェストの `SC-NN` に対応する feature が無ければ **error**。
  —— **マニフェストの SC 番号はテスト名のラベルにすぎず、間違っていても Vitest は緑のまま**である
  （パスさえ木にあれば通る）。番号の取り違えはここでしか捕まらない。
- **除外には理由の文字列を強制する**（空・短すぎるものは error）。**黙って除外する道を用意しない。**

🔴 **パス値は突き合わせない（意図的な見送り）。** 検査器が feature 側の `path:` を正としてマニフェストへ
写すと、**マニフェストは「計画から書き写した値」ではなく「実装から導出した値」に変わる** ——
実装がパスを改名したとき、検査器は緑のまま「マニフェストを直せ」と促す。
パス値を計画に対して固定するのは **`router.test.ts` の役目**（木に載っているかを実行時に見る）であり、
検査器の役目は**行の有無**である。**2 つの層で別のものを見る。**

### 判定 2（新設）: 誤った主張の再混入を止める（grep-zero）

**5 本の e2e が同一文面のコピーだった**という事実が機序である（次の画面も既存ファイルを複製して作る）。
よって**文面そのもの**を検査対象にする。

- 走査対象: `src/*/frontend/e2e/**/*.ts` と `docs/tests/**/*.md`。
- **Markdown のコードフェンス・インラインコードは対象外**（`.claude/rules/traceability.md` の
  「意図的に誤例を書く場合はインラインコードかコードフェンスに入れる」と同じ逃げ道を用意する）。
- **`.ai-context/` は走査しない。** 凍結記録には是正できない同じ文面が 4 件あり、対象に入れると
  **検査器が「書き換えてはならない記録の書き換え」を要求する**ことになる。
- 🔴 **これは文面のリテラル検査であり、新しい言い回しの誤記は捕まえられない。**
  捕まえるのは**コピー由来の再混入**である。限界を README にもスクリプト冒頭にも書く。

### 何が「陰性対照」か

否定形（「ルートの実在は**固定できない**」）・委譲（「ルートの実在は T-30 が固定する」）を
**落としてはならない**。落とすと、**正しく書いた文書が検査に引っかかる**ため検査器ごと外される。
self-test に陽性・陰性の両方を置く。

## 受け入れ基準

1. `PLANNED_ROUTES` が SC-18 / SC-19 / SC-20 を含み、`router.test.ts` が緑である。
2. `node scripts/check-route-manifest.js` が実データで緑、`--self-test` が通る。
3. **判定 1 の順方向・逆方向、判定 2 の陽性・陰性が、それぞれ変異試験で「壊すと落ちる」ことを実測**している。
4. live な誤記 8 件が「未認証の導線だけを測っている」ことを述べる文面に変わっている。
5. `REQUIRE_REPO_TESTS=1 node scripts/scripts.test.js` / `check-commit-messages` / `check-trace-blocks` /
   `check-doc-links` / `pnpm run typecheck・lint・format:check` が緑である。

## テスト方針

- 検査器: 自己完結の `--self-test`（純関数へ当てる）＋ `scripts.repo.test.js` からの
  実データ走査・0 件走査の門・**実データへの変異**（フィクスチャだけだと「実ファイルの形が想定と違う」
  型の空振りを捕まえられない。`IADR-0130` / #665 の教訓）。
- ルート木: 既存 `router.test.ts` に **`PLANNED_ROUTES` と除外集合が交わらない**ことの検査を足す
  （除外宣言が「マニフェストにも書いたうえで除外もする」形に腐るのを止める）。
