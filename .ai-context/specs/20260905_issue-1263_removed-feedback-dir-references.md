# 作業仕様書: 撤去済み `feedback/` を指す参照の是正（#1263）

## 背景

`ADR-0048` 決定 5 でリポジトリ直下の `feedback/` は撤去され、環流記録は計画リポジトリの
`projects/microservices-platform/10_feedback/` へ移設された（以後の環流は planning の
GitHub issue で行う）。**撤去済みのそのパスを指す参照が追跡下に残っていた。**

既存の検査器は捕まえない。`gen-knowledge-graph.js --check` は frontmatter とリンクの
エッジだけを見ており、**散文中に書かれた in-repo パスは母集合に入らない**。`check-doc-links.js`
も同じくリンク記法だけを見る。

## 母集合（規則 9。**誤りの側の文字列で走査してから挙げた**）

走査（`origin/develop` `3d5f8c99` 時点）:

```
git grep -lI "feedback/" origin/develop -- .
  → 各ファイルを (?<![0-9A-Za-z_./-])feedback/(20\d{6}|README\.md|TEMPLATE\.md) で判定
```

**直前が `/` や英数字のものは別パス**（`10_feedback/` ・ `draft/feedback/` ・
`repo-template/feedback/` ・ submodule `src/ai-stock-trading/`）なので除外した。

| 区画 | ファイル | 行 | 扱い |
| --- | ---: | ---: | --- |
| `.ai-context/specs/` | 61 | — | **(c) 凍結記録として保持。触らない** |
| `.ai-context/adr/` | 20 | — | **(c) 凍結記録として保持。触らない** |
| `docs/` | 18 | 25 | **(b) 移設先へ置き換える** |
| `src/` | 7 | 7 | **(b) 移設先へ置き換える** |
| **合計** | **106** | — | うち是正対象 **25 ファイル / 32 行** |

### 🔴 依頼にあった「117 件」は過大である

素朴に `grep -rln "feedback/2026" docs src .ai-context` を取ると 117 件になるが、

- `10_feedback/2026…` ・ `draft/feedback/2026…` への**部分一致が 19 件**混じる（**計画リポ側の
  正しい参照**であり是正対象ではない）
- 逆に `feedback/README.md` ・ `feedback/TEMPLATE.md` を指す **8 件を取り落とす**

**117 − 19 + 8 = 106。** 他人の数えを検証せずに転記しない（規則 9）。

### 陽性対照

- `.ai-context/superpowers/`（**書き換え不可**の凍結記録）は走査対象に入っている
  —— `planning` で 1 件ヒットする。そのうえで `feedback` は **1 件も含まない**。
  「対象外」は走査漏れではなく実際に無いためである。
- 是正後も `.ai-context/` からは同じ走査で **81 ファイル**が引ける（凍結記録を残した証拠）。

## 分類の根拠

`.claude/rules/traceability.repo.md` §凍結の射程 に従う。`.ai-context/specs/` は
`［YYYY-MM-DD 追記 / #NNN］` 書式の経過追記のみ可、`.ai-context/superpowers/` は不可。
**どちらも本文プロズを後から書き換えない。**

`.ai-context/` の 81 ファイルは**書かれた時点で正しかった記述**であり、当時 `feedback/` は
実在した。後から書き換えると「その時点で何が正しかったか」という記録の値が失われる。
よって **(c) 凍結記録として保持**する。ここに `［追記］` を入れる価値も無い —— 撤去の事実は
`ADR-0048` と `IADR-0228` に、移設先は本仕様書と実装ADR にある。

`docs/` と `src/` は live であり、**読んだ人が実在しないパスを開こうとする**。移設先は
計画リポジトリに 1 対 1 で存在することを隣接クローンで確認した（参照されている 10 件すべて）。
よって **(b) 移設先へ置き換える**。

## 是正の 2 規則

**規則 A（16 行）**: 先行する移設作業が **in-repo の死んだパスを残したまま**移設注記を
後置していた。重複を畳む。

```
feedback/X.md（環流記録。計画リポ `projects/…/10_feedback/X.md` へ移設）
  →  環流記録 `projects/…/10_feedback/X.md`
```

前後のファイル名が食い違う行は触らずに報告する仕掛けにした（**0 件だった**）。

**規則 B（16 行）**: 移設注記が付いていない素の参照を、移設先のパスへ置き換える。
散文はいずれも「環流記録 …」「… に記録した」の形で、パスだけを差し替えれば意味が通る。

## `docs/` の書式

計画 ID・IADR・仕様書名・**修飾付き issue 参照**は表示テキストへ書かない（`ADR-0048` 決定 4）。
本作業が表示テキストへ残すのは**計画リポジトリ内のファイルパス**だけで、上の 4 種のいずれでもない。
既存の同型の記述（先行の移設作業が入れたもの）と同じ形に揃えてあり、`check-trace-blocks.js` は
これを違反としない。

## 検査器を足さないという判断

「散文中の in-repo パスの実在」を検査する仕組みは無い。**足さない。**
規約・検査器の追加条件は「**同型の事故が 2 回**」であり、これは 1 回目である
（`CLAUDE.md` §実装作業の進め方）。**記録に留める** —— 2 回目が起きたときに何を作ればよいかは
実装ADR に書いた。
