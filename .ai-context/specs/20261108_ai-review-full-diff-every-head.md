# 作業仕様書 — 2 回目以後の push でも全差分を読み直させる

> 着手 2026-11-08（develop `95ace5d05`）。判断の記録は IADR-0706。

## 起点

- #2509 の `claude-review`（develop の必須チェック）が、2 回目以後の push で 5 回、検証の下限「変更ファイルは全部読む」の違反で落ちた
  （25/50・44/51・10/55・8/55・1/55）。PR がマージできなくなった。
- 本文は「前回レビュー以後の最新コミット `ff4240de` の差分だけ」「残り 54 ファイルは前回までのレビューで読んだ範囲に拠る」と書いていた。
- 同型の事故は既に 2 回を越えている（運用ガイドの「同型の事故 2 回」）。

## 原因（run 42394244730 のログで確かめた）

- `track_progress: true` のため、アクションは組み込みプロンプト（tag モード）を使う。そこには過去のコメント全部（前回までの AI レビュー本文）が
  `<comments>` に、`<trigger_context>pull request synchronize</trigger_context>` が載る。
- 組み込みプロンプト自体は差分の絞り込みを指示していない（「`git diff origin/develop...HEAD` で変更を見よ」）。
- ワークフローの prompt の【検証の下限】は「変更ファイルは全部読む」とだけ書き、**前回のレビューの結果を流用してよいかを書いていなかった**。
  レビューは渡された前回の本文と synchronize の文脈から「前回以後のコミットだけ」を自分で選び、残りを「前回までに読んだ」とした。
  前回の本文自体が「前回以後の 2 コミットの差分を読んだ」と書いており、回を追うごとに読む範囲が狭まった（10→8→1）。
- 検査器 `check-review-verdict.js` は正しく落としている（申告の M + K < N と「下限を満たしていない」の自己申告）。

## 方式

- prompt の【検証の下限】節の先頭に 1 項目足す: 前回のレビュー（スティッキーコメント・過去のコメント）の結果を流用しない。push のたびに
  この head の `git diff origin/develop...HEAD` の全ファイルを読み直す。前回以後のコミットだけを読むのは下限を満たさない。
  過去のコメントは前回の指摘の解消を確かめる手掛かりにだけ使い、M・確認の根拠・未読の理由に使わない。M はこのセッションで読んだファイルだけ。
- 経緯は送信されない YAML コメント側へ書く（prompt には指示だけ）。
- 検査器は変えない（緩めない）。`track_progress` / `use_sticky_comment` も変えない（IADR-0706 の代替案）。
- 必須チェック名・起動条件は変えない。

## 母集合（規則 9・10）

- 「前回」「前回以後」「過去のコメント」「sticky」「track_progress」で `.github/workflows/claude-code-review.yml`・`scripts/`・`docs/`・`AI_SETUP.md` を走査した。
  prompt に前回のレビューの扱いを書いた箇所は無かった（追随する記述なし）。`docs/` に検証の下限の記述は無い。
- 検査器の挙動は変えないので `scripts/README.md` の記述は誤りにならない。
