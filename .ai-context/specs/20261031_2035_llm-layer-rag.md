## 方針（IADR-0665）

1. **上限は 1 試験 1 呼び出し × 試験 2 件 × retries 0 = 1 実行 2 呼び出し**（基準書 §6.2）。数え方と定数は `support/llmBudget.ts` だけに置く。
2. **数えるだけでなく止める。** `page.route` で `POST /bff/search` と `POST /bff/analysis/*` を受け、上限の内は `continue`、
   超えた要求は **`abort` して後段へ届けない**（超過の要求が費用を出さない）。拒んだ要求は記録して、試験の終わりに fail させる。
3. **索引の待ちは LLM の口を使わない。** 対象範囲の候補（`POST /bff/attribute-values`。索引から引く・LLM を呼ばない）に seed 文書の部門が
   出るまで画面を開き直して待つ。`POST /bff/search` で待つと、待つたびに上限を使う。
4. **縮退の形も通す。** 鍵なしのスタックでは本文が縮退の文になる。判定は「1 回だけ送った・200・出典に seed 文書・失敗の表示が無い」に揃え、
   本文の中身（実の回答か縮退の文か）は見ない。
5. **索引なしは skip**（`E2E_SEARCH_HITS=1` が無ければ 2 件とも理由つきで skip。呼び出し 0）。
6. **L1 の門**（`live-opt-in.smoke.spec.ts`。稼働の環境に触れない）:
   - 値域: 定数が基準書の値（1 試験 1・1 実行 2）であり、`1 実行の上限 = 1 試験の上限 × 試験の件数` が成り立つ。数える口と数えない口の判定。
   - `--list` の件数: `E2E_LAYER=llm` で project `llm` に**ちょうど 2 件**（M-031・M-052）。既定（ro）では `llm` の試験が 0 件。
   - project `llm` の retries が 0（再試行は呼び出しを倍にする）。
