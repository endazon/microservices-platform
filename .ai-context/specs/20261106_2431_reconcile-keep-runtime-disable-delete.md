# 作業仕様書 — 調停が稼働側の無効化・削除を戻さない（#2431）

> 着手 2026-11-06（develop `17565cd0`）。判断の記録は **IADR-0685**（新規）。稼働中のクラスタには何もしない。

## 起点

- 要求 **NFR-18**。前提: **IADR-0369**（宣言と実行時の境界）・**IADR-0570**（試験アカウント）。

## 現状（develop で読み直した）

- `deploy/local/keycloak-setup/reconcile-realm.js` の client の比較は `CLIENT_SKIP_KEYS` に `enabled` を持たない。宣言が `enabled: true`・稼働が無効のとき、`client.update` で有効へ戻す。
- 人の seed 利用者は、稼働に無ければ毎回 `user.create` で作る（宣言へ新しく足したのか、消されたのかを区別しない）。

## 母集合（規則 9）

- `enabled` を持つ宣言の実体: client（宣言 28 件のうち `enabled: false` は投入器 `abac-seeder` の 1 件。起動器が使うときだけ有効にする）、利用者（既存の人の利用者は従来から比べない）、requiredActions（宣言が全集合。本件の対象外）。
- 作り直しに頼る手順: `deploy/local/README.md` の試験アカウントの回し直し（消して調停で作り直す）。これに明示の許可を足す。

## 方針

1. client: 宣言が有効・稼働が無効なら比べない（本文は稼働の無効を運ぶ）。報告する。逆向きは従来どおり。
2. 人の seed 利用者: 調停が在ると確かめた利用者を realm の属性 `reconcile.seeded-users` に記録する（realm の設定の差分と同じ PUT に載せる）。記録に在るのに稼働に無い利用者は作らずに報告する。作り直しは `RECONCILE_RECREATE_USERS`（名前のカンマ区切り）で許す。
3. 戻さなかったものは計画の `kept` に載せ、`kept` の行で出す。drift には数えない。
4. 本件より前の realm（記録が無い）は、最初の調停で在る利用者を記録する（それまでに消された利用者は記録に無いので一度作り直される）。

## 受け入れ基準

- AC-1: 無効にした client を有効へ戻さない。ほかの差分の PUT でも本文は無効のまま。宣言が無効・稼働が有効は無効へ合わせる（試験）。
- AC-2: 記録に在る利用者が消されていたら作らない。明示で許せば作る。記録に無い（新しく宣言した）利用者は作る（試験）。
- AC-3: 記録は realm の設定の差分と 1 本の PUT に載り、門の属性を消さない。記録の済んだ realm は drift 0（試験）。
- AC-4: Job は許可を空の既定で持ち、起動器の口は形の外の値で止まる（試験）。
- AC-5: 既存の調停の試験が通る。

## 残余

1. 記録より前に消された利用者は、最初の調停で一度作り直される。
2. 消した client は作り直す（本件は無効化だけを扱う）。
